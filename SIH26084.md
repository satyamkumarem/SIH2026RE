# Convective Scale Nowcasting for Thunderstorms, Hail & Cloudbursts (06 hr)
**SIH Problem Dossier | Problem Statement ID: SIH26084**

---

## 1. Executive Snapshot

### Summary
Severe convective weather events—including intense thunderstorms, hail, downburst winds, and cloudbursts—represent some of India's most destructive atmospheric hazards [RESEARCHED]. Traditional Numerical Weather Prediction (NWP) physics-based models operate at coarse horizontal resolutions (e.g., 12 km NEPS) and require hours to execute [RESEARCHED], making them inherently incapable of forecasting localized mesoscale storms that initiate and mature within minutes [PS]. 

**ThunderCast-SIH** is a real-time, multi-source data fusion nowcasting architecture designed for the National Centre for Medium Range Weather Forecasting (NCMRWF) and India Meteorological Department (IMD) [INFERENCE]. Operating at a hyper-local **1–3 km spatial grid resolution** with a **0–6 hour lead time** [PS], the system fuses high-frequency Doppler Weather Radar (DWR) reflectivity and velocity fields [PS], INSAT-3D/3DR/3DS geostationary infrared/thermal satellite channels [PS], and ground-based lightning location network feeds [PS]. By combining optical flow advection techniques (pySTEPS) [RESEARCHED] with AI-based Convective Initiation (CI) detection algorithms [INFERENCE], ThunderCast delivers real-time hazard mapping, quantitative severe parameter estimation (hail probability, downburst velocity, cloudburst rain rates), and localized arrival countdown clocks on an interactive web/mobile GIS dashboard [PS].

## 2. Problem Deconstruction

The explicit description in SIH26084 has been decomposed into atomic, actionable system requirements:

* **Requirement R1 (Lead Time & Scale)** [PS]: Build a real-time convective-scale nowcasting system providing early warnings for a **0–6 hour lead time window** at **1–3 km spatial resolution**.
  * *Interpretation*: Traditional NWP model outputs must be augmented or replaced for short lead times using observation-driven extrapolation and statistical/machine learning models [INFERENCE].
  * *Implementation Implication*: Spatiotemporal forecasting algorithms must process spatial arrays at grid increments between 0.01° to 0.03° latitude/longitude [ASSUMPTION].

* **Requirement R2 (Target Convective Hazards)** [PS]: Dynamically detect and forecast four severe meteorological events:
  1. Severe Thunderstorms [PS]
  2. Hail [PS]
  3. Downburst Winds / Gust Fronts [PS]
  4. Cloudbursts (extreme rainfall thresholds) [PS]
  * *Interpretation*: The system must compute specialized diagnostic indices for each hazard type derived from fused radar, satellite, and lightning observations [INFERENCE].
  * *Implementation Implication*: Algorithm output must include Maximum Estimated Size of Hail (MESH) [RESEARCHED], radial wind convergence/shear [RESEARCHED], rain rate $R \ge 100\text{ mm/hr}$ over 20–30 km² [RESEARCHED], and lightning stroke rate density [RESEARCHED].

* **Requirement R3 (Multi-Source Data Fusion Engine)** [PS]: Design a real-time ingestion engine that fuses heterogeneous meteorological data streams:
  * Doppler Weather Radar (DWR) reflectivity ($Z$) and radial velocity ($V$) fields [PS]
  * Geostationary Satellite Imagery: INSAT-3D/3DR/3DS Thermal Infrared (TIR-1, TIR-2) and Water Vapor (WV) channels [PS]
  * Ground-based Lightning Detection Networks (e.g., IITM / Earth Networks / ILDN) [PS]
  * *Interpretation*: Ingestion must handle multi-rate, multi-format spatial data (netCDF4, HDF5, CSV/JSON sferics) arriving at 5–15 minute intervals [RESEARCHED].
  * *Implementation Implication*: Georeferencing, spatial resampling, and temporal synchronization pipeline onto a unified 1–3 km Cartesian grid [INFERENCE].

* **Requirement R4 (Early Convective Initiation - CI Detection)** [PS]: Automatically detect early Convective Initiation prior to mature precipitation radar echoes [PS].
  * *Interpretation*: Radars only detect storms after rain droplets/graupel form. Early CI must be detected 15–45 minutes prior via satellite Brightness Temperature Differences (BTD) and cloud top cooling rates [RESEARCHED].
  * *Implementation Implication*: Monitor INSAT-3D/3DR 10.8 µm (TIR-1) and 6.7 µm (WV) channel temperature tendencies to flag growing updrafts before radar reflectivity exceeds $35\text{ dBZ}$ [RESEARCHED].

* **Requirement R5 (Real-Time Interactive GIS Dashboard)** [PS]: Develop a high-performance web dashboard displaying 1–3 km hazard zones overlaid on interactive GIS maps [PS].
  * *Interpretation*: Map interface must render vector polygons/raster heatmaps representing predicted storm tracks and severity levels without client-side lag [INFERENCE].
  * *Implementation Implication*: Use GeoJSON/Vector Tile formats rendered via MapLibre GL / Leaflet.js with dynamic styling based on threat level [ASSUMPTION].

* **Requirement R6 (Live Arrival Countdown Clocks)** [PS]: Showcase live countdown clocks indicating estimated time of arrival (ETA) for severe hazards at specific target locations [PS].
  * *Interpretation*: System must calculate storm cell velocity vectors, project future cell centroids, intersect them with user locations/districts, and compute $T_{\text{arrival}} = D_{\text{centroid}} / V_{\text{storm}}$ [INFERENCE].
  * *Implementation Implication*: WebSocket-driven real-time countdown timer components pinned to administrative boundaries or user GPS coordinates [INFERENCE].

* **Requirement R7 (Computational Latency Constraint)** [PS]: Bypass slow, physics-based NWP models by utilizing data-driven multi-source fusion [PS].
  * *Interpretation*: Total pipeline latency (ingestion to dashboard visualization) must complete within < 3 minutes of data arrival to remain useful for a 0–6 hr nowcast window [INFERENCE].
  * *Implementation Implication*: Lightweight Python/C++ processing pipeline utilizing GPU-accelerated tensor operations or fast numpy/scipy routines [INFERENCE].

## 6. Research Questions

1. *How can raw IMD Doppler Weather Radar data files be programmatic ingested and converted into standardized Py-ART format?*
   * **Answer**: IMD DWR data is distributed in proprietary or single-sweep netCDF files. The open-source `PyScanCf` library [RESEARCHED] converts individual IMD sweeps into Cf-Radial compliant files [RESEARCHED], which can then be ingested by `Py-ART` [RESEARCHED].
2. *What exact satellite thermal channel thresholds signify early Convective Initiation before radar echoes appear?*
   * **Answer**: Convective initiation (CI) is indicated when the 10.8 µm (TIR-1) brightness temperature drops below $273\text{ K}$, cloud-top cooling rate $\Delta T / \Delta t \le -4\text{ K} / 15\text{ min}$, and the brightness temperature difference $T_{\text{TIR1}} - T_{\text{WV}} \ge -1\text{ K}$ [RESEARCHED].
3. *What is the official IMD meteorological definition of a Cloudburst?*
   * **Answer**: The IMD officially defines a cloudburst as localized rainfall exceeding **100 mm per hour** over an area of approximately **20 to 30 square kilometers** [RESEARCHED].
4. *How can Maximum Estimated Size of Hail (MESH) be calculated from single-polarization vs dual-polarization DWR reflectivity?*
   * **Answer**: MESH uses the Severe Hail Index (SHI), integrating reflectivity $Z$ above the $0^\circ\text{C}$ and $-20^\circ\text{C}$ environmental melting level heights derived from ambient soundings: $MESH = 0.1 \times SHI^{0.5}$ [RESEARCHED].
5. *Can deep learning models run fast enough to deliver a nowcast within 1 minute of data arrival?*
   * **Answer**: Yes. Inference on a pretrained spatiotemporal architecture (such as Earthformer [RESEARCHED] or a ConvLSTM U-Net [RESEARCHED]) takes under 2 seconds on an NVIDIA T4 GPU for a $512 \times 512$ grid array [INFERENCE].

### Approach 1: Pure Extrapolation & Rule-Based Heuristic (pySTEPS + Lucas-Kanade + WDSS-II Rules)
* **Mechanism**: Ingests DWR reflectivity composite, calculates Lucas-Kanade optical flow vectors, advects precipitation fields up to 6 hours using `pySTEPS` [RESEARCHED]. Applies physical threshold rules for MESH hail and cloudburst $R \ge 100\text{ mm/hr}$ [RESEARCHED].
* **Complexity**: Low to Moderate. Python-native (`pySTEPS`, `Py-ART`, `scipy`) [RESEARCHED].
* **Explainability**: Very High. Fully deterministic physical equations [INFERENCE].
* **Drawbacks**: Pure advection cannot model *growth and decay* or *new convective initiation*. Storms appear to freeze in size and merely drift [RESEARCHED].
* **Hackathon Feasibility**: 95/100 [INFERENCE].

### Approach 2: Pure Deep Learning Spatiotemporal Transformer (Earthformer / ConvLSTM)
* **Mechanism**: Feeds sequence of multi-spectral images ($T_{-30\text{m}}$ to $T_0$) into an end-to-end spatiotemporal Transformer (`Earthformer` with Cuboid Attention) [RESEARCHED] to directly generate grid predictions ($T_{+10\text{m}}$ to $T_{+360\text{m}}$).
* **Complexity**: Extremely High. Requires massive multi-modal training datasets (TB-scale) and multi-GPU infrastructure [RESEARCHED].
* **Explainability**: Low (Black box). Difficult for operational meteorologists to audit [INFERENCE].
* **Drawbacks**: Blurs forecast images over longer lead times (> 2 hrs) [RESEARCHED]; risk of severe hallucinations under out-of-distribution monsoon dynamics [INFERENCE].
* **Hackathon Feasibility**: 45/100 (Unrealistic data and compute demands for a 3-day build) [INFERENCE].

### Approach 3 (RECOMMENDED): Hybrid Physics-Informed Optical Flow + ML Convective Growth Model
* **Mechanism**: 
  1. *Kinematic Advection Core*: Uses `pySTEPS` Lucas-Kanade optical flow on DWR reflectivity for robust short-term movement tracking (0–2 hrs) [RESEARCHED].
  2. *Satellite CI & Growth Engine*: Uses a lightweight Convolutional Neural Network (ConvLSTM / UNet) trained on INSAT-3D thermal BTD ($T_{\text{TIR1}} - T_{\text{WV}}$) and cloud-top cooling rates to predict localized cell *intensity growth/decay factors* ($\gamma_{x,y}$) [RESEARCHED].
  3. *Multi-Hazard Diagnostic Layer*: Calculates MESH hail size, microburst velocity divergence, and cloudburst threshold exceedance by combining advecting radar intensity with predicted growth factors [INFERENCE].
* **Complexity**: Moderate. Balances proven physics extrapolation with lightweight ML growth adjustments [INFERENCE].
* **Explainability**: High. Motion is physics-backed; ML only modulates gain/decay and flags new initiation [INFERENCE].
* **Hackathon Feasibility**: 88/100 [INFERENCE].

## 10. Recommended Approach & Why

### Selected Approach: Approach 3 (Hybrid Physics Optical Flow + ML Growth Model)

#### Justification
1. **Solves the Advection Limitation**: Pure optical flow (Approach 1) fails when severe convective storms rapidly develop or collapse within 15–30 minutes [RESEARCHED]. By overlaying a satellite-based ML growth/decay modifier, the system accurately simulates new convective initiation before radar detection [RESEARCHED].
2. **Avoids Deep Learning Over-Smoothing**: Pure spatiotemporal deep learning models (Approach 2) suffer from progressive blurring beyond 1.5 hours and require hundreds of gigabytes of historical training data [RESEARCHED]. Approach 3 uses deterministic physics for spatial transport, preserving sharp high-intensity cores critical for cloudburst and hail alerts [INFERENCE].
3. **Optimized for Hackathon Timeline**: A 4–6 student team can reliably implement `pySTEPS` optical flow within 2 days while training a lightweight CNN/UNet growth classifier on a modest pre-processed sample dataset [INFERENCE].

### Step-by-Step Data Flow Narrative

1. **Ingestion & Standardization**: Raw meteorological files arrive from sources. The backend ingestion daemon detects new files in watched directories or API endpoints. `PyScanCf` converts IMD DWR single sweeps to Cf-Radial netCDF [RESEARCHED]; `h5py` reads INSAT-3D thermal band arrays [RESEARCHED]; incoming lightning sferics are stored in Redis [INFERENCE].
2. **Geospatial Grid Fusion**: All incoming observation channels are spatially interpolated onto a uniform $1\text{ km} \times 1\text{ km}$ Cartesian grid covering the target radar dome domain ($500\text{ km} \times 500\text{ km}$) [ASSUMPTION].
3. **Motion Vector Calculation**: The `pySTEPS` optical flow engine computes motion vectors ($\mathbf{u}, \mathbf{v}$) using the two most recent 10-minute DWR reflectivity grids [RESEARCHED].
4. **Initiation & Growth Modulation**: The Satellite CI module evaluates the 10.8 µm cooling rate ($\Delta T_{\text{TIR1}} / \Delta t$). If $\Delta T \le -4\text{ K}/15\text{ min}$ and $T_{\text{TIR1}} - T_{\text{WV}} \ge -1\text{ K}$ in a non-precipitating area, an Initiation Flag is set, boosting predicted reflectivity in that cell 20 minutes forward [RESEARCHED].
5. **Multi-Hazard Parameterization**:
   * *Rain Rate ($R$)*: $Z = 200 R^{1.6} \implies R = (Z/200)^{0.625}$ [RESEARCHED].
   * *Hail Size (MESH)*: Integrates $Z$ above environmental freezing level $H_0$ obtained from GFS soundings [RESEARCHED].
   * *Downburst Velocity*: Computes radial velocity shear along DWR azimuth lines ($\Delta V_r / \Delta r$) [RESEARCHED].
6. **Vectorization & ETA Intersect**: High-hazard grid clusters ($Z \ge 45\text{ dBZ}$ or $R \ge 50\text{ mm/hr}$) are grouped into storm polygons using contouring/DBSCAN algorithms [INFERENCE]. Cell motion vectors are projected forward in 10-minute steps up to 6 hours. Intersections with target municipality centroids compute the Live Countdown ETA ($T = \text{Distance} / \text{Speed}$) [INFERENCE].
7. **Frontend Push**: Output hazard polygons, reflectivity raster tiles, and countdown state payloads are broadcast via WebSockets to connected MapLibre GL clients [INFERENCE].

## 13. AI/ML Justification

### 1. Satellite Convective Initiation (CI) Classifier
* **Purpose**: Detect developing convective updrafts 15–45 minutes before precipitation echoes appear on Doppler radar [RESEARCHED].
* **Model Type**: 2D Convolutional Neural Network (U-Net architecture) [RESEARCHED].
* **Input**: Multi-spectral tensor $[C \times H \times W]$ containing INSAT-3D 10.8 µm (TIR-1), 6.7 µm (WV), and time-derivative channels ($\Delta T_{\text{TIR1}} / \Delta t$) [RESEARCHED].
* **Output**: Probability map $P(\text{CI}_{x,y}) \in [0, 1]$ representing convective initiation likelihood within the next 30 minutes [RESEARCHED].
* **Data Required**: Historical INSAT-3D HDF5 files aligned with subsequent IMD DWR radar reflectivities [RESEARCHED].
* **Why AI is Preferable**: Hard threshold rules fail under variable atmospheric moisture conditions; CNNs capture complex spatial cloud-top texture and contextual moisture gradients [RESEARCHED].
* **Evaluation Metric**: Critical Success Index (CSI) and Probability of Detection (POD) [RESEARCHED].
* **Failure Mode**: False positives in high cirrus cloud shields.
* **Human Oversight**: Meteorological forecaster toggle switch to override ML initiation flags on the dashboard [INFERENCE].

### 2. Storm Cell Growth & Decay Modulator
* **Purpose**: Modulate optical flow advection intensity to account for storm intensification or dissipation over 0–6 hrs [RESEARCHED].
* **Model Type**: ConvLSTM / Light Spatiotemporal Encoder-Decoder [RESEARCHED].
* **Input**: Sequence of past 4 radar reflectivity grids ($T_{-30\text{m}}$ to $T_0$) + satellite TIR channels [RESEARCHED].
* **Output**: Gain multiplier array $\gamma_{x,y} \in [0.2, 2.0]$ applied to projected optical flow reflectivities [INFERENCE].
* **Data Required**: Paired historical radar sequence frames [RESEARCHED].
* **Why AI is Preferable**: Pure physics equations for convective growth require full 3D atmospheric thermodynamic modeling (NWP), which is computationally too slow for real-time nowcasting [PS].
* **Evaluation Metric**: Root Mean Square Error (RMSE) against actual $T_{+1\text{h}}$ radar reflectivity [RESEARCHED].
* **Failure Mode**: May over-predict intensification if dry air entrainment occurs.
* **Human Oversight**: Dynamic gain bounds enforced ($\gamma \le 2.0$) to prevent runaway intensity predictions [INFERENCE].

### Explicit Identification: Where AI Should NOT Be Used
* **DO NOT use AI for Motion Advection**: Lucas-Kanade optical flow (`pySTEPS`) is faster, completely deterministic, and physically robust for tracking existing storm vector movements [RESEARCHED].
* **DO NOT use AI for Countdown Timer Calculation**: Arrival times must be calculated using exact kinematic vector math ($\text{Distance} / \text{Velocity}$ vector) to guarantee deterministic predictability [INFERENCE].
* **DO NOT use AI for Cloudburst Threshold Exceedance**: Cloudburst alerts must strictly adhere to the deterministic physical definition ($R \ge 100\text{ mm/hr}$) [RESEARCHED].

### Offline & Low-Network Optimization Strategy

```
  +-------------------------------------------------------------------------+
  |                   OFFLINE / LOW-BANDWIDTH DATA ARCHITECTURE             |
  +-------------------------------------------------------------------------+
    Server (GeoServer / FastAPI)
        │
        │ [1. Serve Compact Vector Tiles (PBF) instead of Rasters]
        ▼
    Client Web Browser / PWA (Service Worker)
        │
        ├── [2. Cache Map Basemaps in CacheStorage]
        ├── [3. Store Storm Vector Polygons in IndexedDB]
        └── [4. Client-side JS Kinematic Engine runs Countdown Clocks Offline]
```

1. **Protobuf Vector Tiles (MVT)**: Instead of streaming heavy 10 MB PNG radar raster overlays, the server extracts storm contours ($Z \ge 35, 45, 55\text{ dBZ}$) into Mapbox Vector Tiles (`.pbf`). Tile sizes are reduced by 90% (< 50 KB per tile) [INFERENCE].
2. **Client-Side Countdown Kinematics**: Once the browser downloads the storm vector array and cell velocity vector $(\mathbf{u}, \mathbf{v})$, the local JavaScript engine computes the countdown clock locally every second without needing active network requests [INFERENCE].
3. **PWA Service Worker & IndexedDB Caching**: All UI components, basemap vector tiles, and district boundaries are cached locally via Service Workers. If network drops during a severe storm, the dashboard remains fully functional, displaying the last known storm trajectory and continuing offline countdown calculations [INFERENCE].
4. **Retry & Backoff Strategy**: WebSocket connections attempt reconnection using exponential backoff ($1\text{s}, 2\text{s}, 4\text{s}, 8\text{s}, \text{max } 30\text{s}$) upon signal drop [INFERENCE].
