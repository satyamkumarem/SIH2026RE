## 1. Executive Snapshot

### Executive Summary
Rapid urbanization and population growth in Indian municipalities have strained legacy waste management and public sanitation infrastructures [KNOWN]. The Ministry of Environment, Forest and Climate Change (MoEF&CC) has mandated four-stream source segregation (Wet, Dry, Sanitary, and Special Care Waste) under the Solid Waste Management (SWM) Rules 2026 [RESEARCHED]. However, municipal local bodies (ULBs) struggle with low source segregation compliance, unverified door-to-door waste collection logistics, and unmonitored public sanitation facilities [INFERENCE]. This dossier provides a comprehensive technical architecture and execution blueprint for **SwachhDrishti (CleanFlow)**—an offline-first, edge-AI powered, multi-stakeholder civic operating platform. The system combines web-based edge computer vision for real-time citizen waste classification, lightweight mobile applications for waste collectors, automated public toilet hygiene scorecards via computer vision proof, and an integrated GIS dashboard for Urban Local Bodies (ULBs).

### Deconstructed Atomic Requirements

1. **Sub-Problem 1: Waste Segregation (Source Classification & Awareness)**
   * **Source Text:** *"Solutions could be in the form of waste segregation..."* [PS]
   * **Interpretation:** The system must assist citizens and bulk waste generators (BWGs) in correctly identifying waste streams prior to disposal [INFERENCE].
   * **Implementation Implication:** Implement a lightweight WebAssembly / TensorFlow.js / ONNX computer vision classifier running directly inside the user's browser or mobile app. The classifier must categorize items into the four mandatory Streams defined by SWM Rules 2026: Wet (Biodegradable), Dry (Recyclable), Sanitary, and Special Care / Domestic Hazardous Waste [RESEARCHED].
   * **Confidence:** [PS] for requirement; [RESEARCHED] for SWM 2026 four-stream mapping.

2. **Sub-Problem 2: Waste Disposal & Logistics Tracking**
   * **Source Text:** *"...disposal..."* [PS]
   * **Interpretation:** The system must ensure that collected waste is verified from the household/commercial pickup point through transit to Material Recovery Facilities (MRFs), composting units, or licensed landfills [INFERENCE].
   * **Implementation Implication:** Build a Progressive Web App (PWA) for sanitation workers and collection vehicle drivers featuring offline GPS location logging, QR code scanning for door-to-door pickup verification, vehicle fill-level estimation, and route verification to prevent illegal roadside dumping [INFERENCE].
   * **Confidence:** [PS] for requirement; [INFERENCE] for logistics workflow implementation.

3. **Sub-Problem 3: Public Sanitization System Improvement**
   * **Source Text:** *"...and improve sanitization system."* [PS]
   * **Interpretation:** The system must provide mechanisms to maintain and monitor the hygiene of public sanitation infrastructure (e.g., public toilets, community sanitation facilities, and street sweeping zones) [INFERENCE].
   * **Implementation Implication:** Implement a caretaker mobile workflow and citizen feedback mechanism (QR-code based or app-based) coupled with AI-assisted visual proof verification (e.g., checking floor cleanliness, urinal maintenance, water availability) to enforce Service Level Agreements (SLAs) for ward sanitary inspectors [INFERENCE].
   * **Confidence:** [PS] for requirement; [INFERENCE] for sanitation inspection architecture.

## 5. Constraints & Environment Realities

1. **Connectivity Realities:**
   * Municipal field collectors work in narrow alleys, basements, and rural fringe wards where cellular data (4G/5G) is intermittent or non-existent [KNOWN].
   * *System Adaptation:* All field mobile tools must operate 100% offline using IndexedDB / SQLite, syncing data when a network connection becomes available [INFERENCE].

2. **Hardware & Operating Device Constraints:**
   * Field workers frequently use budget Android devices (2GB–3GB RAM, entry-level Processors) [KNOWN].
   * *System Adaptation:* Client-side AI models must be quantized (INT8/TFLite Nano or ONNX WebAssembly) under 15MB size, consuming minimal CPU/battery [INFERENCE].

3. **Language & Digital Literacy:**
   * Sanitation staff have varying literacy levels and speak regional Indian languages [KNOWN].
   * *System Adaptation:* The worker application relies on high-contrast iconography, color-coded status badges (Green = Wet, Blue = Dry, Red = Hazardous, Yellow = Sanitary), and voice prompts in regional languages [INFERENCE].

4. **Physical Field Conditions:**
   * Phones are operated with wet or gloved hands in dusty/dirty environments [KNOWN].
   * *System Adaptation:* Touch targets must be at least 48x48 dp; workflow steps must require minimal button taps [INFERENCE].

5. **Regulatory Alignment:**
   * System must comply with the MoEF&CC Solid Waste Management Rules 2026 (mandating 4-stream source segregation) and align with Swachh Survekshan evaluation toolkits [RESEARCHED].

### Approach A: Cloud-Centric Mobile Application + Server-Side AI
* **Mechanism:** Mobile client captures image, uploads to AWS/GCP server running heavy PyTorch model; backend returns classification and routes complaints.
* **Evaluation:**
  * *Problem Fit:* Moderate. Fails in low-connectivity areas.
  * *Accuracy:* High (92–95% on server-side ResNet/YOLO).
  * *Complexity & Cost:* High cloud API bandwidth and GPU instance costs.
  * *Hackathon Feasibility:* High.
  * *Production Feasibility:* Low due to cloud bandwidth expenditure and network drops in the field [INFERENCE].

### Approach B: IoT Hardware-Automated Segregation Bins
* **Mechanism:** Custom smart dustbin equipped with Raspberry Pi, inductive/capacitive sensors, camera, and servo motors that physically direct waste into 3 internal compartments.
* **Evaluation:**
  * *Problem Fit:* High for public hotspots, zero fit for household door-to-door collection.
  * *Accuracy:* Moderate (mechanical jams, sensor degradation over time).
  * *Complexity & Cost:* Very High CAPEX (~₹15,000 per bin).
  * *Hackathon Feasibility:* Moderate (fragile hardware demo).
  * *Production Feasibility:* Poor for city-wide scale due to maintenance overheads [INFERENCE].

### Approach C: Unified Edge-AI Browser Classifier + Offline-First PWA + Open GIS Platform (RECOMMENDED)
* **Mechanism:** Zero-install WebApp / PWA executing quantized YOLOv8n / TensorFlow.js in the client browser. Local SQLite/IndexedDB stores logs offline. Geotagged scans verify worker pickups and caretaker sanitation inspections. Open API connects to ULB dashboards.
* **Evaluation:**
  * *Problem Fit:* Comprehensive. Solves segregation, disposal tracking, and public toilet governance.
  * *Accuracy:* High (85–90% on quantized edge vision models).
  * *Complexity & Cost:* Extremely low cloud cost; zero client hardware cost (uses existing mobile web browsers).
  * *Scalability:* Infinite client-side compute scaling.
  * *Hackathon Feasibility:* High (demonstrable in 30 seconds via phone camera).
  * *Production Feasibility:* High. Matches SWM 2026 mandates and Swachh Survekshan framework [INFERENCE].

```

                                                                                            │
                                                                                    3. Household Disposal
                                                                                            │

1. **Citizen Waste Sorting Flow:**
   * Citizen opens `swachhdrishti.app` in any web browser.
   * Camera feed stream passes to client-side ONNX WebAssembly runtime loaded with quantized YOLOv8n weights (`12.4 MB`).
   * Inference executes locally in under 60ms. Bounding box overlay identifies item (e.g., "Plastic Water Bottle -> DRY WASTE - Blue Bin") with proper disposal guidance.
2. **Door-to-Door Collection Flow:**
   * Collector arrives at household; scans fixed QR code mounted on door frame using worker PWA.
   * PWA logs scan event, geotag coordinates, and waste status (Segregated / Mixed / Absent) into local IndexedDB.
   * When device enters network coverage area, background service worker batches and pushes queue to `/api/v1/logistics/collect`.
3. **Public Sanitation Monitoring & Escalation Flow:**
   * Citizen scans QR code posted outside public toilet block; selects issues ("No Water", "Floor Dirty").
   * Ticket generated with automated 2-hour resolution SLA assigned to registered caretaker.
   * Caretaker cleans facility, captures geotagged photo via caretaker app interface.
   * AI inspection service runs image verification check for cleanliness score. Upon validation, ticket auto-closes; if score fails, alert escalates to Ward Sanitary Inspector [INFERENCE].

```

+----------------------------------+------------------------------------------------+
| Component 1: Waste Classifier    | USED: YOLOv8n ONNX Web (Instant Edge Detection)|

### 1. Computer Vision Waste Stream Classifier
* **Purpose:** Classify user waste items in real-time into mandatory 4 streams (Wet, Dry, Sanitary, Hazardous) [RESEARCHED].
* **Model Type:** YOLOv8n (Nano) converted to INT8 quantized ONNX model (`12.4 MB`).
* **Input:** Live camera feed frame (`640x640x3` RGB tensor).
* **Output:** Bounding boxes, class label, confidence score (0.0 to 1.0), and disposal stream color code.
* **Data Required:** TACO + TrashNet + Indian urban trash custom dataset (~12,000 images) [RESEARCHED].
* **Why AI is Preferable:** Manual search or static rule charts are too slow and confusing for citizens holding trash.
* **Evaluation Metric:** Target mAP@50 > 85%, inference speed < 80ms on budget phone.
* **Failure Mode & Oversight:** If confidence < 65%, UI displays fallback prompt: *"Uncertain item: Is it organic/food waste? If yes, place in GREEN bin."*

### 2. Sanitation Inspection Proof Verification
* **Purpose:** Verify caretaker uploaded cleaning proof photos to prevent fraudulent check-ins [INFERENCE].
* **Model Type:** Lightweight Binary Classifier (MobileNetV3 transfer-learned on clean vs dirty facility surfaces).
* **Input:** Geotagged high-resolution photo uploaded by caretaker.
* **Output:** Cleanliness Index score (0 to 100) + anomaly flags (e.g., litter detected, standing water detected).
* **Data Required:** 2,000 paired sample photos of public toilets before and after cleaning [ASSUMPTION].
* **Why AI is Preferable:** Prevents manual inspector bottlenecks where thousands of daily photos require human review.
* **Failure Mode & Oversight:** Photos scoring between 40–70 are flagged for manual review by the Ward Sanitary Inspector.

### 3. Explicit Non-AI Decision: Waste Fleet Route Optimization
* **Decision:** **Do NOT use AI/Reinforcement Learning for collection truck routing.**
* **Justification:** Vehicle routing problems (VRP) with capacity and time windows are efficiently solved using deterministic heuristic solvers like **Google OR-Tools** or **Dijkstra/A* graph algorithms** [KNOWN]. Rule-based solvers guarantee mathematical optimality without model hallucination or unpredictable route detours [INFERENCE].

### Offline Synchronization & Conflict Resolution
* **Local Storage Layer:** Field apps write scan events into **RxDB / IndexedDB** wrapped in a transactional Queue [INFERENCE].
* **Synchronization Protocol:**
  1. Each record receives a client-side generated `UUIDv4`, a `created_at_utc` timestamp, and a hash sequence [INFERENCE].
  2. When internet connectivity is detected (via `navigator.onLine` listener), service worker fires POST request to `/api/v1/sync` carrying batch array [INFERENCE].
  3. **Conflict Handling Strategy (Last-Write-Wins with Server Verification):** Server checks `property_id` and `scanned_at` timestamp window. If duplicate scans exist for the same household within 4 hours, server deduplicates using client scan UUID, retaining the initial scan [INFERENCE].
  4. **Bandwidth Optimization:** Images captured offline are converted to WebP format (`60% quality`, `max 1024px width`), reducing raw camera file size from ~3.5MB down to ~120KB before queueing for transit [INFERENCE].
