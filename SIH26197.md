## 1. Executive Snapshot

### Summary
Problem Statement **SIH26197** ("Student Innovation-Ideas that showcase the rich cultural heritage and traditions of India") is an open innovation challenge issued by AICTE / Ministry of Education's Innovation Cell (MIC) under the *Heritage & Culture* theme `[PS]`. While existing government platforms like the *Indian Culture Portal (ICP 2.0)* `[RESEARCHED]` and *Digital District Repository (DDR)* `[RESEARCHED]` provide extensive centralized archives, they struggle with grassroots crowdsourcing of living oral traditions, real-time multilingual voice interaction for low-literacy rural artisans, and resilient offline field operation at remote heritage sites. 

To win SIH 2026, the team proposes **SanskritikSetu (संस्कृतिकसेतु)**: a lightweight Progressive Web Application (PWA) and Android mobile platform combining **BHASHINI voice AI** for 22 scheduled Indian languages `[RESEARCHED]`, **on-device Computer Vision** for monument/craft classification `[INFERENCE]`, **OpenStreetMap (OSM) spatial tagging** `[RESEARCHED]`, and a **crowdsourced community verification workflow** `[INFERENCE]`. This dossier provides the complete architectural, data, and implementation blueprint for a 4–6 student team to build and demonstrate a winning prototype by September 30, 2026 `[PS]`.

```

+--------------------+--------------------+--------------------+--------------------+
|  Network Bandwidth | Device Hardware    | Linguistic Diversity| Field Conditions  |

+--------------------+--------------------+--------------------+--------------------+
```

1. **Connectivity Realities**: Remote heritage sites (e.g., Bhimbetka caves, rural Hampi outskirts, North-East tribal villages) often suffer from zero cellular signal or throttled 2G data `[KNOWN]`. The client interface must store maps, audio snippets, and metadata locally in IndexedDB using service workers `[INFERENCE]`.
2. **Hardware Constraints**: Rural artisans and field volunteers primarily operate low-end Android smartphones with limited memory (< 3 GB RAM) and processors `[KNOWN]`. High-poly 3D WebGL scenes or heavy LLM inference engines executed on-device will crash the browser. AI processing must be lightweight or offloaded via cloud microservices `[INFERENCE]`.
3. **Linguistic & Literacy Barriers**: Over 50% of rural artisans cannot read or type text fluently in standard English or Hindi `[KNOWN]`. UI/UX must be strictly iconographic, voice-guided, and localized into regional scripts `[INFERENCE]`.
4. **Lighting & Field Conditions**: Field workers taking photos of monuments or crafts operate in harsh direct sunlight, dusty conditions, and varying angles `[KNOWN]`. Vision models must be resilient to noise, shadows, and low resolution `[INFERENCE]`.

## 10. Recommended Approach & Why

### Selection: Approach C (Hybrid Voice AI + GIS Crowdsourced PWA)

The team selects **Approach C**. It directly addresses the core objective of showcasing India's rich cultural heritage `[PS]` while solving the real-world barriers that existing government portals face `[INFERENCE]`.

#### Why Alternatives Were Rejected:
1. **Approach A (Static Web Portal)** was rejected because it offers low innovation. Merely building another CRUD web directory fails to impress SIH judges and fails to engage non-literate rural folk custodians `[INFERENCE]`.
2. **Approach B (Heavy AR/VR Metaverse)** was rejected due to severe technical risk during a hackathon. Creating photogrammetric 3D scans requires specialized hardware, massive bandwidth, and high-end smartphones, rendering it unusable for rural field conditions and unscalable for thousands of local traditions `[INFERENCE]`.

#### Winning Value Proposition of Approach C:
- **Voice-First Inclusivity**: Integrates BHASHINI to allow a Baul singer from Bengal or a Warli painter from Maharashtra to record their story in their native voice, automatically converting it into 22 Indian languages `[RESEARCHED]`.
- **Geospatial Story Mapping**: Anchors folklore and monuments to exact spatial coordinates using OpenStreetMap, creating an interactive "Living Cultural Map of India" `[RESEARCHED]`.
- **Offline Field Readiness**: Operates reliably in zero-network rural heritage pockets via PWA Service Workers and local storage sync `[INFERENCE]`.

### Step-by-Step Data Flow Narrative

1. **Voice Story Ingestion**:
   - A local folk artist opens the PWA on their mobile device, clicks the microphone icon, and speaks a 2-minute folktale in Marathi `[INFERENCE]`.
   - The WebAudio API captures the speech, compresses it to WebM/Ogg format, and stores a local copy in IndexedDB if offline `[INFERENCE]`.
2. **Multilingual Processing via BHASHINI**:
   - Upon network connection, the client POSTs the audio file to the FastAPI backend API Gateway `[INFERENCE]`.
   - The backend routes the audio stream to the **BHASHINI STT API** (Marathi model), receiving the transcribed Marathi text `[RESEARCHED]`.
   - The transcribed text is sent to the **BHASHINI NMT API**, generating translations in English, Hindi, Tamil, and 18 other scheduled languages `[RESEARCHED]`.
3. **Geospatial Anchoring & Indexing**:
   - The user's GPS coordinates (or manual monument pin drop) are validated against PostGIS using `ST_SetSRID(ST_MakePoint(lng, lat), 4326)` `[INFERENCE]`.
   - The metadata, spatial coordinates, and audio URLs are saved to PostgreSQL with status `PENDING_CURATION` `[INFERENCE]`.
4. **Moderation & Public Map Rendering**:
   - A regional curator logs into the Web Dashboard, reviews the audio and translation, and marks it as `VERIFIED` `[INFERENCE]`.
   - The Leaflet.js spatial map queries the spatial bounding box via GeoJSON endpoint, rendering a interactive custom map pin for tourists `[INFERENCE]`.

## 13. AI/ML Justification

```
+-----------------------------------------------------------------------------------+
|                               AI/ML MODULES                                       |
+-----------------------+-----------------------+-----------------------------------+
| 1. BHASHINI Engine    | 2. MobileNetV3 Vision | 3. Automated Tagging              |
| STT -> NMT -> TTS     | On-Device Artifact    | TF-IDF / Keyphrase Extraction     |
| (22 Indic Languages)  | Classifier (ONNX)     | (Category Suggestion)             |
+-----------------------+-----------------------+-----------------------------------+
```

### Component 1: BHASHINI Multilingual Voice Pipeline
1. **Exact Problem Solved**: Eliminates text literacy barriers for rural storytellers and enables cross-lingual exploration for tourists `[INFERENCE]`.
2. **Input**: Raw voice audio (WebM/WAV) in any of 22 Indian languages `[RESEARCHED]`.
3. **Output**: Transcribed native text + translated text in English/Hindi + TTS synthesized audio stream `[RESEARCHED]`.
4. **Why Simpler Rule System Fails**: Language translation and speech recognition cannot be solved by static regex or lookup dictionaries due to dialectical variations `[KNOWN]`.
5. **Required Data**: Pre-trained ULCA/BHASHINI pipeline models provided by MeitY `[RESEARCHED]`.
6. **Evaluation Metric**: Word Error Rate (WER) < 15% for primary dialects; BLEU score > 30 for translation `[INFERENCE]`.
7. **When It Is Wrong**: Raw audio is preserved; users can manually edit transcriptions or flag translations `[INFERENCE]`.
8. **Training/Fine-tuning/RAG**: Uses pre-hosted BHASHINI REST endpoints; no custom training required `[RESEARCHED]`.
9. **Human Oversight**: Mandatory curator review for all crowdsourced transcripts before public publishing `[INFERENCE]`.

### Component 2: On-Device Monument & Craft Classifier
1. **Exact Problem Solved**: Instantly identifies architectural styles (e.g., Dravidian vs Nagara temple tower) or craft types (e.g., Madhubani vs Warli art) from photos `[INFERENCE]`.
2. **Input**: 224x224 RGB image captured via mobile camera `[INFERENCE]`.
3. **Output**: Top-3 predicted cultural categories with confidence percentages (e.g., "Warli Painting: 88%") `[INFERENCE]`.
4. **Why Simpler Rule System Fails**: Visual feature extraction from pixel data requires convolutional feature maps `[KNOWN]`.
5. **Required Data**: Transfer learning dataset of ~3,000 images across 10 distinct Indian heritage categories `[ASSUMPTION]`.
6. **Evaluation Metric**: Top-1 Accuracy > 85%, inference time < 300ms on mobile device `[INFERENCE]`.
7. **When It Is Wrong**: UI displays "Uncertain classification" and allows manual selection from a dropdown list `[INFERENCE]`.

### WHERE AI SHOULD NOT BE USED:
- **Historical Fact Verification**: AI LLMs hallucinate historical dates and dynasties. Fact checking must rely strictly on verified curator databases and published academic records `[INFERENCE]`.
- **Geospatial Proximity Calculations**: Spatial distance must use exact PostGIS mathematical algorithms (`ST_DistanceSphere`), not AI approximations `[INFERENCE]`.

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL + PostGIS)

```sql
-- Core Heritage Sites Table
CREATE TABLE heritage_sites (
    site_id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    category VARCHAR(100) NOT NULL, -- Monument, Temple, Fort, Craft Hub
    location GEOMETRY(Point, 4326) NOT NULL,
    district VARCHAR(100) NOT NULL,
    state VARCHAR(100) NOT NULL,
    description_json JSONB NOT NULL, -- Multilingual descriptions
    verified_status VARCHAR(20) DEFAULT 'PENDING',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Spatial Index for Fast Map Queries
CREATE INDEX idx_heritage_location ON heritage_sites USING GIST(location);

-- Crowdsourced Oral Stories Table
CREATE TABLE oral_stories (
    story_id SERIAL PRIMARY KEY,
    site_id INT REFERENCES heritage_sites(site_id),
    artisan_name VARCHAR(150),
    language_code VARCHAR(10) NOT NULL, -- mar, hin, tam, etc.
    original_audio_url VARCHAR(500) NOT NULL,
    transcript_text TEXT NOT NULL,
    translated_text_json JSONB, -- Translations in 22 languages
    curator_id INT,
    status VARCHAR(20) DEFAULT 'PENDING',
    uploaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Offline & Synchronization Mechanism

```
+-----------------------------------------------------------------------------------+
|                             OFFLINE SYNC WORKFLOW                                 |
+--------------------+--------------------+--------------------+--------------------+
| Field User Capture | Write to Local     | Background Sync    | Server Ingestion &|
| (Voice / Photo)    | IndexedDB Queue    | Service Worker     | PostGIS Indexing   |
+--------------------+--------------------+--------------------+--------------------+
```

1. **Local Storage**: Uses `IndexedDB` via `idb-keyval` to store pending audio uploads, offline map tiles (raster/vector protobufs), and form submissions `[INFERENCE]`.
2. **Synchronization Strategy**:
   - The PWA Service Worker registers a `sync` event listener (`sync-story-upload`) `[INFERENCE]`.
   - When network connectivity returns, the Service Worker drains the IndexedDB queue in chronological sequence using exponential backoff retry logic `[INFERENCE]`.
3. **Conflict Handling**: Crowdsourced submissions are append-only with unique client-generated UUIDs; server timestamps resolve ordering without overwriting existing verified records `[INFERENCE]`.
4. **Bandwidth Reduction**: Images are resized on-client to 1080p WebP format before upload; audio is encoded in compressed mono Ogg/Opus format (under 500 KB per minute) `[INFERENCE]`.
