# SATQUERY AI - SIH26167 RESEARCH & ARCHITECTURE DOSSIER

## 1. Executive Snapshot

SatQuery AI is an agentic, multimodal vision-language ecosystem engineered for the Indian Space Research Organisation (ISRO) to democratize high-resolution Earth Observation (EO) analysis [PS]. Traditional satellite interpretation requires deep GIS expertise, manual band composition, and complex model pipelines; SatQuery AI replaces this with a natural-language query interface backed by an intelligent routing agent and domain-adapted AI models [PS, INFERENCE]. The system ingests single-modality optical/SAR imagery, co-registered optical–SAR pairs, and bi-temporal image series in native GeoTIFF/TIFF formats (as well as benchmark PNG/JPEG formats) [PS]. By dynamically validating input metadata, sequencing task-specific specialist models (VQA, captioning/grounding, change detection, and SAR–optical cross-modal fusion), and aggregating textual and visual feedback (bounding boxes, change masks, confidence scores), SatQuery AI produces evidence-grounded, auditable intelligence reports [PS]. Adapted using the multi-sensor `BigEarthNet.txt` dataset and evaluated on public benchmarks (`VRSBench`, `RSVQA`, `CDVQA`) as well as ISRO/SAC's proprietary `Cartosat-2S` optical and `RISAT` C-band SAR evaluation dataset, SatQuery AI bridges the gap between raw satellite telemetry and operational decision-making [PS, RESEARCHED].

## 2. Problem Deconstruction

The problem description provided by ISRO was deconstructed into atomic functional and non-functional requirements. Every explicit requirement is preserved with its exact lettered prefix where applicable.

*   **[REQ-A] Remote Sensing Domain Adaptation:** The system must include a vision or vision-language component that is fine-tuned or domain-adapted using `BigEarthNet.txt` or open-source remote sensing datasets to handle satellite spectral bands, polarizations, and spatial structures [PS].
*   **[REQ-B] Single-Image Visual Question Answering (Mandatory Baseline):** The system must answer natural language questions for a single optical, multispectral, or Synthetic Aperture Radar (SAR) image [PS].
*   **[REQ-C] Secondary Single-Image Task:** The system must implement at least one additional single-image capability: either detailed natural language scene captioning OR text-guided region grounding (predicting spatial bounding boxes/polygons for queried land features) [PS].
*   **[REQ-D] Multi-Image Bi-Temporal Change Analysis:** The system must perform change description or change-based visual question answering (CDVQA) on a bi-temporal pair of images acquired at different times over the same geographic area [PS]. Where reference masks or alignment permit, it should additionally generate a spatial change map [PS].
*   **[REQ-E] Cross-Modal Pair Analysis (Optical + SAR):** The system must perform joint information extraction and cross-modal analysis on co-registered optical/multispectral and SAR image pairs (e.g., leveraging SAR cloud penetration and optical spectral signatures) [PS].
*   **[REQ-F] Agentic Model and Tool Orchestration:** The backend must feature an automated controller that:
    1.  Interprets user intent and classifies the requested remote-sensing task [PS].
    2.  Validates input image count, modality (optical/SAR), format, spatial resolution, projection system, and compatibility [PS].
    3.  Selects and sequences appropriate specialist tools/models from a predefined tool registry [PS].
    4.  Configures only permitted task parameters and executes the workflow [PS].
    5.  Combines textual answers and visual grounding maps, calculates confidence estimates, and returns visual evidence [PS].
    6.  Generates an auditable execution summary containing selected tasks, model/tool names, and execution parameters [PS].
*   **[REQ-G] Supported File Formats:** The system must support native geospatial formats (`GeoTIFF` / `TIFF`) containing multi-band geospatial metadata [PS]. Benchmark formats (`PNG` / `JPEG`) are accepted strictly for public evaluation datasets (`VRSBench`, `RSVQA`, `CDVQA`) [PS].
*   **[REQ-H] Interactive User Interface & Deliverables:** An interactive web GUI or web application must be delivered, capable of visualization, confidence displaying, execution auditing, and downloading PDF/JSON reports [PS].
*   **[REQ-I] Evaluation Compliance:** System performance will be evaluated on public test splits (`VRSBench`, `RSVQA`, `CDVQA`) and an undisclosed ISRO Space Applications Centre (SAC) evaluation set featuring co-registered `Cartosat-2S` (optical, 0.6m-1.6m) and `RISAT` (C-band SAR) image pairs [PS, RESEARCHED].

## 5. Constraints & Environment Realities

*   **Geospatial Data Formats & Coordinate Reference Systems (CRS):** Satellite imagery comes in `GeoTIFF` format with embedded spatial metadata (bounding coordinates, affine transform, EPSG projections) [PS, KNOWN]. Modern deep learning models expect standard 3-channel RGB uint8 arrays [KNOWN]. The system must dynamically convert multi-band 11-bit/12-bit floating-point rasters into normalized displayable and model-digestible arrays without dropping geographic alignment [PS, INFERENCE].
*   **Sensor Modality Discrepancies:** Optical sensors (Cartosat-2S: 0.65m PAN, 1.6m MS; Sentinel-2: 10m RGB-NIR) capture reflected solar light, which is obstructed by clouds and night [KNOWN, RESEARCHED]. SAR sensors (RISAT-1 C-band, Sentinel-1) emit active microwave signals and measure backscatter in polarizations (VV, VH, HH), functioning through cloud cover and at night [KNOWN, RESEARCHED]. Combining these requires handling distinct physics, dynamic ranges, and speckle noise [INFERENCE].
*   **Compute & VRAM Limitations:** Fine-tuning and running large Vision-Language Models (e.g., 7B-14B parameter MLLMs) on high-resolution satellite tiles requires substantial GPU memory [KNOWN]. During a hackathon demo, real-time inference must be kept under 3 seconds per query, necessitating parameter-efficient fine-tuning (LoRA/QLoRA) and lightweight specialized vision heads [INFERENCE, ASSUMPTION].
*   **Bandwidth & Deployment Environment:** Field workers and regional authorities often operate in low-bandwidth or disconnected environments [KNOWN]. High-resolution satellite tiles (which can exceed 100 MB each) cannot be transferred repeatedly over weak networks; tiled Web Map Service (WMS/WMTS) streaming or client-side caching is required [INFERENCE, ASSUMPTION].
*   **Strict No-Hallucination & Auditability Rules:** ISRO applications demand verifiable visual evidence [PS]. Models cannot simply "claim" an area changed or a building exists without highlighting the exact pixel region or providing an execution trace detailing which tool generated the inference [PS, INFERENCE].

1.  **RQ-1:** How can a single vision encoder digest multi-spectral optical data (4–12 bands) and dual-polarization SAR data (VV/VH or HH/HV) without discarding non-RGB information? [RESEARCHED]

3.  **RQ-3:** How can the agentic orchestrator reliably parse complex user intent into valid tool parameters without relying on unpredictable internal LLM thinking text? [PS, INFERENCE]
4.  **RQ-4:** What feature-level or decision-level fusion architecture yields the highest accuracy when resolving spatial queries on co-registered `Cartosat-2S` optical and `RISAT` C-band SAR pairs under cloud cover? [RESEARCHED, INFERENCE]
5.  **RQ-5:** How do benchmark coordinates in `VRSBench` (normalized 0–100 or 0–1000) translate back to geospatial coordinates (Latitude/Longitude or EPSG:3857) on high-resolution GeoTIFF rasters? [RESEARCHED, INFERENCE]

## 9. Candidate Solution Approaches

### Approach 1: Monolithic Multi-Task RS-VLM
*   **Mechanism:** Single large Vision-Language Model (e.g., Qwen2-VL 7B fine-tuned across all tasks simultaneously) taking concat images directly into visual tokens.
*   **Problem Fit:** Moderate [INFERENCE]. Concatenating multi-temporal and multi-modal images into a single vision encoder rapidly exhausts token windows and reduces spatial resolution [KNOWN].
*   **Accuracy Potential:** 68–74% on VQA; poor on fine-grained change mask segmentation [INFERENCE].
*   **Complexity & Effort:** Low system complexity, high fine-tuning compute requirements [INFERENCE].
*   **Hackathon Feasibility:** Medium; heavy VRAM requirements (24GB+) [INFERENCE].
*   **Production Feasibility:** Low due to monolithic inflexibility when adding new sensor types [INFERENCE].

### Approach 2: Pipeline Rule-Based Router + Specialized ML Modules
*   **Mechanism:** Hardcoded Python router that parses query keywords (e.g., "changed" -> Change Model; "where is" -> Grounding Model) and calls specific PyTorch models.
*   **Problem Fit:** Sub-optimal [INFERENCE]. Fails on complex, ambiguous, or multi-intent user queries [INFERENCE].
*   **Accuracy Potential:** High on narrow tasks, zero robustness on un-modeled phrasing [INFERENCE].
*   **Complexity & Effort:** Low AI orchestration complexity, high manual rule maintenance [INFERENCE].
*   **Hackathon Feasibility:** High; easily runnable [INFERENCE].
*   **Production Feasibility:** Poor; brittle interface unsuitable for broad natural language [INFERENCE].

### Approach 3: Agentic Orchestrator + Fine-Tuned RS Foundation Backbone + Tool Registry (RECOMMENDED)
*   **Mechanism:** An agentic controller (LangGraph / Function Calling agent) acts as the central coordinator. It validates image formats/metadata, classifies query intent, dynamically selects specialized micro-models (RemoteCLIP VQA, VisTA Change Grounder, SAR-Optical Fusion Net) from a tool registry, executes the parameter pipeline, and aggregates results [PS, INFERENCE].
*   **Problem Fit:** Perfect [PS, INFERENCE]. Directly satisfies explicit ISRO requirement [REQ-F] for agentic orchestration with observable execution traces [PS].
*   **Accuracy Potential:** Superior (82–89%+ across benchmarks); specialized models handle spatial masks and VQA with high precision [INFERENCE].
*   **Complexity & Effort:** High architectural design effort; modular implementation [INFERENCE].
*   **Hackathon Feasibility:** Excellent for 4–6 student team; division of labor across UI, Agent Router, VQA Tool, and Change Tool [INFERENCE].
*   **Production Feasibility:** High; new specialized tools (e.g., Hyperspectral PRISMA tool) can be registered without retraining the core agent [INFERENCE].

### Detailed Data-Flow Narrative

1.  **Ingestion & Validation:** User uploads satellite imagery (e.g., `t1_optical.tif` and `t2_optical.tif` for change detection, or `optical.tif` + `sar.tif` for cross-modal analysis) via the React dashboard [PS, ASSUMPTION]. The `Rasterio` validation middleware extracts raster metadata: width, height, band count, data type, coordinate reference system (CRS), and affine transform matrix [PS, KNOWN].
2.  **Query & Routing:** User submits a textual query (e.g., *"What built-up structures changed between these two dates and where?"*) [PS]. The LangGraph Agentic Controller parses the text alongside the validated image metadata [PS, INFERENCE].
3.  **Tool Selection & Execution:** The orchestrator recognizes a bi-temporal input pair + change query [PS]. It selects `Tool_3_BiTemporal_Change_Engine` and configures permitted parameters (threshold = 0.5, resolution = native) [PS, ASSUMPTION].
4.  **Inference & Grounding:** `Tool_3` executes a forward pass through the Siamese vision backbone, generating a textual change summary and a binary 2D change probability matrix [RESEARCHED, INFERENCE].
5.  **Geospatial Vectorization:** The visual output is passed to `Tool_6_Geospatial_Converter`, which uses the image's affine matrix to map pixel change masks into GeoJSON polygons or bounding box coordinates [INFERENCE, KNOWN].
6.  **Audit Trace & Response Construction:** The orchestrator logs an auditable trace (`task_type`, `model_name`, `parameters_used`, `execution_time_ms`, `confidence_score`) and packages the final payload containing textual answers, GeoJSON vector layers, and confidence metrics to the GUI [PS, INFERENCE].

## 13. AI/ML Justification

### 1. Single-Image VQA & Captioning Engine
*   **Purpose:** Answers natural language questions and provides detailed LULC descriptions for optical or SAR rasters [PS].
*   **Model Type:** Adapted Vision-Language Transformer (Qwen2-VL / RemoteCLIP backbone) [RESEARCHED].
*   **Input:** Normalized 3-band RGB/False-Color array + Text Prompt [PS, INFERENCE].
*   **Output:** Textual answer string + Confidence score [PS].
*   **Data Required:** `RSVQA` and `VRSBench-VQA` [PS, RESEARCHED].
*   **Why AI is Necessary:** Rule-based keyword matching cannot interpret unstructured natural language questions over complex visual satellite patterns [INFERENCE].
*   **Evaluation Metric:** Accuracy, BLEU-4, METEOR, CIDEr [RESEARCHED].
*   **Failure Mode & Fallback:** Low confidence prompt triggers request for query clarification or defaults to general LULC scene description [INFERENCE].
*   **Human Oversight:** High for operational mission decisions; automated trace shown to user [PS].

### 2. Visual Grounding / Bounding Box Predictor
*   **Purpose:** Identifies and localizes specific queried features (e.g., "Highlight the water body") [PS].
*   **Model Type:** Object Detection / Referring Expression Head (GeoChat / Grounding-DINO style adapter) [RESEARCHED].
*   **Input:** Image array + Target query term [PS].
*   **Output:** Bounding box coordinates `[x1, y1, x2, y2]` normalized to [0-100] or GeoJSON BBox [PS, RESEARCHED].
*   **Data Required:** `VRSBench-Ref` dataset [PS, RESEARCHED].
*   **Why AI is Necessary:** Traditional spectral thresholding (e.g., NDVI) cannot isolate specific semantic objects like individual ships or buildings [KNOWN].
*   **Evaluation Metric:** mean IoU (Intersection over Union) @ threshold 0.5 [RESEARCHED].
*   **Failure Mode:** False positive bounding boxes over clutter [INFERENCE].

### 3. Bi-Temporal Change Detection & CDVQA Engine
*   **Purpose:** Identifies "what changed and where" between time $T_1$ and time $T_2$ [PS].
*   **Model Type:** Siamese Feature Extractor + Vision-Language Transformer Decoder (VisTA architecture) [RESEARCHED].
*   **Input:** Pair of co-registered bi-temporal rasters ($T_1, T_2$) + Text Query [PS].
*   **Output:** Textual change explanation + 2D spatial change probability mask [PS, RESEARCHED].
*   **Data Required:** `CDVQA` and `QAG-360K` datasets [PS, RESEARCHED].
*   **Why AI is Necessary:** Simple image subtraction flags seasonal vegetation changes or shadow differences as false changes [KNOWN].
*   **Evaluation Metric:** F1-Score for change mask, BLEU-4 for textual change VQA [RESEARCHED].

### 4. Cross-Modal Optical–SAR Fusion Module
*   **Purpose:** Combines optical spectral detail with SAR structural backscatter for day/night and cloud-resilient analysis [PS].
*   **Model Type:** Cross-Attention Multi-Modal Encoder [RESEARCHED].
*   **Input:** Co-registered Optical array (4-band) + SAR array (VV, VH polarizations) [PS].
*   **Output:** Fused latent representation fed into VQA/Grounding heads [INFERENCE].
*   **Data Required:** `BigEarthNet.txt` (co-registered Sentinel-1 SAR & Sentinel-2 Optical) [PS, RESEARCHED].
*   **Why AI is Necessary:** Optical and SAR measure entirely different physical phenomena (reflectance vs. microwave backscatter); physics-based fusion requires complex manual calibration [KNOWN, INFERENCE].

### Explicit Non-AI Component Identification:
*   **Raster Compatibility & CRS Verification:** Solved strictly via deterministic `Rasterio`/`GDAL` checks (affine transform matrix, EPSG code match, band count). **AI MUST NOT BE USED HERE** [INFERENCE].
*   **Coordinate Transformation (Pixel to Lat/Lon):** Matrix multiplication using affine matrix. **AI MUST NOT BE USED HERE** [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Spatial Data Schema (PostgreSQL / PostGIS)

```sql
-- Core Imagery Table
CREATE TABLE satellite_rasters (
    raster_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    filename VARCHAR(255) NOT NULL,
    modality VARCHAR(50) CHECK (modality IN ('OPTICAL', 'SAR', 'CROSS_MODAL_PAIR', 'BITEMPORAL_PAIR')),
    acquisition_date TIMESTAMP,
    sensor_name VARCHAR(100), -- Cartosat-2S, RISAT-1, Sentinel-1, Sentinel-2
    spatial_resolution_m NUMERIC(5,2),
    crs_epsg INT DEFAULT 4326,
    bounds GEOMETRY(Polygon, 4326),
    file_path VARCHAR(512) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Agentic Query Execution Audit Table
CREATE TABLE query_audit_logs (
    log_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    raster_id UUID REFERENCES satellite_rasters(raster_id),
    user_query TEXT NOT NULL,
    detected_task VARCHAR(100) NOT NULL,
    selected_tool VARCHAR(100) NOT NULL,
    execution_parameters JSONB NOT NULL,
    execution_time_ms INT NOT NULL,
    estimated_confidence NUMERIC(4,3),
    output_text TEXT,
    output_vector_geojson JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Offline & Low-Network Synchronization Strategy
1.  **Client-Side Vector Rendering:** Rather than streaming full high-resolution altered rasters back over the network, the backend converts change masks and bounding boxes into compressed GeoJSON vectors (typically < 20 KB) [INFERENCE, ASSUMPTION].
2.  **Local Tile Caching (IndexedDB):** The web GUI caches base map vector tiles locally in the browser's IndexedDB, allowing smooth pan/zoom without re-fetching underlying imagery [INFERENCE, ASSUMPTION].
3.  **Progressive Web Application (PWA) Offline Mode:** Operational field users can queue natural language queries locally when connectivity drops; queries execute automatically once network heartbeats resume [INFERENCE, ASSUMPTION].
