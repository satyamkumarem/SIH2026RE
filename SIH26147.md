## 1. Executive Snapshot

### Summary
The National Technical Research Organisation (NTRO) requires an advanced, automated Software Defined Radio (SDR) and digital signal processing system capable of ingesting raw off-the-air terrestrial signals (HF, VHF, UHF bands) in both `.IQ` (raw complex I/Q samples) and `.wav` (PCM/stereo I/Q audio stream) formats [PS]. Currently, signal parameter identification is performed manually, leading to insufficient feature extraction and low confidence in characterizing parameters like sampling rate, modulation scheme, Forward Error Correction (FEC), and interleaving [PS]. 

This project proposes a unified desktop application built on a hybrid architecture: a Python/C++ core with GNU Radio integration for high-throughput Digital Signal Processing (DSP) and spectral visualization, a deep residual neural network (ResNet1D) for Automatic Modulation Classification (AMC), and deterministic algorithmic engines for de-interleaving, Viterbi/Reed-Solomon/LDPC FEC decoding, and bitstream cross-correlation [INFERENCE]. The system features an interactive GUI that generates real-time spectral displays (Waterfall, Spectrogram, Constellation, Eye Diagrams) and enables end-to-end automated physical layer and link layer analysis down to bitstream header/payload extraction [PS].

## 5. Constraints & Environment Realities

* **Operating Environment & Offline Reality:** NTRO SIGINT installations often operate in air-gapped, high-security classified environments without internet access [INFERENCE]. The entire application, model weights, and DSP libraries must run completely offline without relying on cloud APIs [INFERENCE].
* **Input File Format Heterogeneity:**
  * **`.IQ` Files:** Raw binary streams usually lack header metadata. Sample format can vary between complex float32, signed int16, or unsigned int8 (RTL-SDR standard) [RESEARCHED].
  * **`.wav` Files:** RIFF containers store sample rate in the header, but I/Q baseband data is split into Left (I) and Right (Q) audio channels. Over-the-air audio captures may be real-valued single-channel baseband, requiring Analytic Signal conversion via Hilbert Transform [RESEARCHED].
* **Signal-to-Noise Ratio (SNR) Variations:** Signals intercepted off-the-air in HF, VHF, and UHF bands suffer from multipath fading, Doppler shifts, atmospheric noise, and adjacent channel interference [PS]. Demodulation and FEC engines must operate effectively down to sub-zero dB SNR levels [INFERENCE].
* **Computational Hardware Constraints:** Processing multi-megabyte raw IQ captures at high sample rates ($>10\text{ MSps}$) requires vectorized C++ SIMD instructions (AVX2/NEON) and efficient RAM buffering to prevent GUI freeze [INFERENCE].
* **Field / Deployment Conditions:** System must run seamlessly on standard workstation PCs (Intel i7/i9 or AMD Ryzen, 16GB-32GB RAM, dedicated or integrated GPU) running Linux (Ubuntu 22.04/24.04 LTS) or Windows 11 [ASSUMPTION].

## 6. Research Questions

1. **How to reliably distinguish between 2-channel `.wav` audio baseband vs. 2-channel `.wav` stereo I/Q recording?**
   * *Investigation:* Read RIFF header `nChannels` and `nSamplesPerSec`. Perform spectral symmetry check: real audio signals have symmetric positive/negative spectrum, whereas complex I/Q baseband signals exhibit asymmetric power spectrum around DC [KNOWN].
2. **What deep learning architecture yields the highest classification accuracy for digital modulation under low SNR (-10 dB to +20 dB)?**
   * *Investigation:* Research shows ResNet1D and CNN-Transformer hybrid models trained on RadioML 2016.10a / 2018.01a datasets achieve $>90\%$ accuracy above 0 dB SNR [RESEARCHED].
3. **How to blindly identify interleaving parameters (matrix rows and columns) without prior knowledge of the transmission protocol?**
   * *Investigation:* Apply bit-level autocorrelation and entropy distribution analysis across candidate row lengths $N$. Spikes in bit correlation indicate matrix frame boundaries [RESEARCHED].
4. **Which open-source FEC library provides the fastest C++ implementation for Viterbi, Reed-Solomon, and LDPC decoding?**
   * *Investigation:* `libcorrect` (for Viterbi and RS) and `OpenFEC` / `AFF3CT` (for LDPC and Concatenated codes) provide C/C++ SIMD-optimized routines [RESEARCHED].

## 9. Candidate Solution Approaches

### Approach 1: Pure Classical DSP & Rule-Based Heuristics Pipeline
* **Mechanism:** Uses classical statistical signal processing. Carrier frequency $f_c$ and sample rate $F_s$ estimated via Spectral Autocorrelation; modulation classified using Higher-Order Cumulants (HOC) and decision trees; demodulation via standard PLLs; FEC and de-interleaving solved via brute-force hypothesis testing across standard polynomials [KNOWN].
* **Complexity:** Low to Medium [INFERENCE].
* **Cost:** Free / Open Source [INFERENCE].
* **Explainability:** 100% transparent mathematical rules [INFERENCE].
* **Strengths:** Lightweight, requires zero neural network training data, deterministic execution [INFERENCE].
* **Weaknesses:** Fails catastrophically at low SNR ($<0\text{ dB}$); rule-based modulation classifiers struggle with high-order QAM/PSK schemes in fading channels [RESEARCHED].

### Approach 2: Deep Learning End-to-End Neural Pipeline
* **Mechanism:** Raw I/Q samples are fed into a multi-task deep neural network (1D ResNet + Transformer) that directly outputs modulation type, sample rate, FEC scheme, and estimated bit sequence end-to-end [RESEARCHED].
* **Complexity:** Very High [INFERENCE].
* **Cost:** Requires GPU hardware for inference [INFERENCE].
* **Explainability:** Low ("black box" predictions) [INFERENCE].
* **Strengths:** High resilience to noise and non-linear channel distortions [RESEARCHED].
* **Weaknesses:** End-to-end neural bit extraction exhibits high Bit Error Rates (BER) compared to deterministic decoders; cannot guarantee bit-exact error correction required for cryptographic frame correlation [INFERENCE].

### Approach 3: Recommended Hybrid Architecture (Fast Classical DSP + DL Classification + Modular C++ Decoding Engine)
* **Mechanism:** A multi-stage hybrid pipeline:
  1. **Format Engine:** Standardizes `.IQ` and `.wav` into a unified internal SigMF complex float32 stream [INFERENCE].
  2. **AI Estimator:** 1D ResNet model predicts modulation type (BPSK, QPSK, 16QAM, 2FSK, etc.) while spectral algorithms calculate exact sample rate $F_s$ and symbol rate $R_s$ [RESEARCHED].
  3. **Demodulation:** Software-Defined Radio pipeline (GNU Radio / Liquid-DSP C++ routines) performs carrier/timing recovery and symbol slicing [KNOWN].
  4. **De-interleaver & FEC Engine:** Deterministic C++ engines execute Block/Convolutional/Diagonal/Pseudo-Random de-interleaving, followed by Viterbi, Reed-Solomon, or LDPC decoding [RESEARCHED].
  5. **Bitstream Correlator:** XOR sliding-window cross-correlation matches preambles/headers and isolates payloads [INFERENCE].
  6. **PyQt6 Visualizer:** Displays real-time Waterfall, Spectrum, Constellation, and Eye plots [INFERENCE].
* **Complexity:** Moderate / High [INFERENCE].
* **Hackathon Feasibility:** High (Modular separation allows team members to build UI, ML, DSP, and FEC concurrently) [INFERENCE].

## 10. Recommended Approach & Why

The **Hybrid Architecture (Approach 3)** is selected as the winning strategy [INFERENCE].

### Justification & Rejection of Alternatives
* **Why Approach 1 was rejected:** Classical higher-order cumulant classifiers fail when processing low SNR signals intercepted off-the-air in noisy HF/VHF bands [RESEARCHED]. Moreover, brute-force hypothesis testing for unknown FEC and interleaving without ML assistance leads to combinatorial explosion [INFERENCE].
* **Why Approach 2 was rejected:** Neural networks are inherently probabilistic and cannot replace exact, deterministic mathematical algorithms like Viterbi decoding, Reed-Solomon error correction, and CRC validation [INFERENCE]. A neural network outputting bitstreams produces hallucinated bits that break payload extraction [INFERENCE].
* **Why Approach 3 Wins:** Approach 3 assigns tasks to their optimal engines: AI is used where it excels (pattern recognition for modulation classification in noisy signals), while deterministic C++/Python math engines handle timing synchronization, de-interleaving, Viterbi/RS/LDPC decoding, and bitwise cross-correlation [INFERENCE].

### Detailed Data-Flow Narrative
1. **File Ingestion:** User opens a raw `.IQ` or `.wav` file in the GUI. The **Ingestion Module** inspects file extensions and headers [INFERENCE]. If `.wav`, it extracts sample rate $F_s$ and audio channels. If 1-channel real baseband, it applies a Hilbert transform to construct complex I/Q samples $I + jQ$ [KNOWN]. If `.IQ`, it reads raw binary buffers and creates a SigMF meta sidecar file [RESEARCHED].
2. **Spectral Processing & Visuals:** The complex array is passed to NumPy/CuPy FFT routines to render time-frequency waterfall plots, PSD graphs, constellation charts, and eye diagrams in real-time via PyQtGraph [INFERENCE].
3. **Parameter Extraction:**
   * **Sample Rate & Symbol Rate:** Estimated via FFT magnitude autocorrelation spikes and squared-signal spectral line analysis [RESEARCHED].
   * **Modulation Type:** A 128-sample sliding window of normalized I/Q complex values is fed into the ResNet1D model, predicting modulation (e.g., QPSK, 16QAM, 2FSK) with a confidence percentage [RESEARCHED].
4. **Demodulation:** The selected demodulator runs carrier phase locking (Costas Loop) and symbol clock synchronization (Gardner Timing Error Detector) to convert continuous I/Q samples into a raw digital symbol/bitstream [KNOWN].
5. **De-Interleaving:** The raw bitstream passes through the selected de-interleaver (Block, Convolutional, Diagonal, or Pseudo-Random), re-ordering scrambled bits into continuous codeword frames [KNOWN].
6. **FEC Error Correction:** Codewords are processed by the appropriate decoder: Viterbi for short convolutional codes, Reed-Solomon for block codes, Concatenated RS+Viterbi, or Min-Sum LDPC belief propagation [PS]. Errors introduced by channel noise are corrected [KNOWN].
7. **Bitstream Correlation & Payload Extraction:** The corrected bitstream is cross-correlated with known header sync patterns (e.g., 0x1ACFFC1D or custom user preambles) [INFERENCE]. When correlation spikes exceed a threshold, the system extracts the header fields (length, source ID) and slices out the clean payload data for user viewing or file export [INFERENCE].

## 13. AI/ML Justification

### AI Component 1: Automatic Modulation Classification (AMC) Model
* **Purpose:** Automatically identify the digital/analog modulation scheme (2FSK, 4FSK, BPSK, QPSK, 8PSK, 16QAM, 64QAM) from short windows of I/Q samples [PS].
* **Model Type:** **ResNet1D (Deep 1D Convolutional Residual Network)** [RESEARCHED].
* **Input:** Floating-point array of shape `(2, 128)` or `(2, 1024)` representing normalized In-Phase (I) and Quadrature (Q) time-series samples [RESEARCHED].
* **Output:** Softmax probability vector across target modulation classes + top predicted class label + confidence score (\%) [INFERENCE].
* **Data Required:** RadioML 2016.10a / 2018.01a datasets containing synthetic and real RF captures across -20 dB to +18 dB SNR [RESEARCHED].
* **Why AI is Preferable:** Classical higher-order cumulants (HOC) fail under low SNR and phase noise conditions. ResNet1D learns invariant spatial-temporal feature representations from complex time-series data [RESEARCHED].
* **Evaluation Metrics:** Classification Accuracy, Confusion Matrix across SNR levels, Inference Latency ($<10\text{ ms}$) [INFERENCE].
* **Failure Mode:** At SNRs below -10 dB, model confidence drops below 40%.
* **Human Oversight:** The GUI displays the softmax probability distribution. The user can override the predicted modulation scheme via a dropdown menu [INFERENCE].

### AI Component 2: Cyclic Spectral Feature & Sample Rate Estimator
* **Purpose:** Estimate symbol rate $R_s$ and aid sampling frequency $F_s$ validation [PS].
* **Model Type:** Classical FFT Autocorrelation & Peak Detection (Non-AI Mathematical Algorithm) [RESEARCHED].
* **Input:** Power Spectral Density array [KNOWN].
* **Output:** Estimated Sample Rate ($Hz$) and Symbol Rate ($Baud$) [INFERENCE].
* **Why AI is NOT Used Here:** Fourier analysis and spectral autocorrelation provide exact mathematical peaks. Using neural networks for simple spectral peak detection introduces unnecessary opacity and error [INFERENCE].

### Where AI Should NOT Be Used
* **De-Interleaving:** De-interleaving requires deterministic matrix transpose or delay-line reordering [KNOWN].
* **Forward Error Correction (Viterbi, Reed-Solomon, LDPC):** Error correction requires strict Galois Field arithmetic and parity matrix check equations [KNOWN]. AI models introduce probabilistic bit errors [INFERENCE].
* **Bitstream Correlation:** Frame synchronization requires bitwise XOR matching [KNOWN].
