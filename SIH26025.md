## 1. Executive Snapshot

### Executive Summary
Surface subsidence resulting from underground coal extraction (longwall and depillaring of bord & pillar panels) represents a major geotechnical hazard in Indian coalfields such as Jharia, Raniganj, Singrauli, and Korba [KNOWN]. Traditional subsidence monitoring in India relies on periodic manual levelling surveys, total station measurements, and post-facto visual damage inspections [PS]. These traditional methods are labor-intensive, discrete, non-continuous, and incapable of issuing pre-failure early warnings before catastrophic ground collapse or surface fissuring occurs [PS]. This dossier presents a complete technical blueprint for an indigenous, low-cost, real-time mine subsidence monitoring and early warning platform [PS]. The solution centers around a wireless surface mesh sensor network deployed over underground mine panels [PS], using dual-mode ESP32/LoRa nodes equipped with multi-parameter geotechnical sensors [INFERENCE], an edge-cloud AI engine for non-linear deformation forecasting [INFERENCE], and a GIS-based real-time dashboard with offline store-and-forward capabilities [PS].

## 2. Problem Deconstruction

The explicit description and requirements defined in the official problem statement `[PS]` are decomposed below into atomic requirements:

*   **REQ-01: Low-Cost Smart Sensor Node Design** `[PS]`
    *   *Source Text*: "development of low cost smart sensor nodes using readily available hardware platforms (e.g., Arduino/ESP32/Raspberry Pi)" `[PS]`
    *   *Interpretation*: Hardware nodes must be built using COTS (Commercial Off-The-Shelf) microcontrollers like ESP32 to maintain low unit cost (< ₹3,500 per node) `[INFERENCE]`.
    *   *Implementation Implication*: Design a multi-sensor printed circuit board (PCB) or modular breadboard shield integrating microcontrollers, battery management, and low-power sleep modes `[ASSUMPTION]`. `[Confidence: PS]`
*   **REQ-02: Multi-Parameter Surface Deformation Sensing** `[PS]`
    *   *Source Text*: "Each node may be equipped with sensors such as: tilt/inclination sensors, vibration sensors, displacement/stretch sensors, crack detection sensors, optional low cost positioning modules." `[PS]`
    *   *Interpretation*: Sensor nodes must sample angular tilt, acceleration/vibration, linear displacement across ground joints, crack opening width, and GNSS position `[PS]`.
    *   *Implementation Implication*: Integrate IMU (MPU6050/ADXL355) for tilt/vibration, linear potentiometer/draw-wire encoder for stretch, conductive resistive strip/optical break for cracks, and NEO-6M/M8N for low-cost location tagging `[INFERENCE]`. `[Confidence: PS]`
*   **REQ-03: Localized Wireless Mesh Network** `[PS]`
    *   *Source Text*: "These nodes will communicate through a wireless mesh communication network (such as LoRa/Zigbee/Wi-Fi mesh), enabling continuous real time monitoring of micro ground movements over the mine panel." `[PS]`
    *   *Interpretation*: Nodes must form a self-healing, multi-hop mesh network over open surface terrain (1 km x 1 km panel) without relying on existing cellular infrastructure `[INFERENCE]`.
    *   *Implementation Implication*: Implement LoRa Mesh (e.g., RadioLib Mesh or ESP-NOW multi-hop mesh) operating at 865-867 MHz (License-free India ISM band) `[RESEARCHED]`. `[Confidence: PS]`
*   **REQ-04: Continuous Anomaly Detection** `[PS]`
    *   *Source Text*: "The system should continuously detect: abnormal ground tilt, change in relative distance between nodes, early crack initiation, unusual vibration signatures" `[PS]`
    *   *Interpretation*: Sensor telemetry must be processed locally or at the gateway to detect micro-deformations indicative of impending subsidence `[PS]`.
    *   *Implementation Implication*: Set dynamic differential thresholds on tilt rates (degrees/min), baseline distance expansion (mm/min), high-frequency shock spikes, and circuit continuity breaks `[INFERENCE]`. `[Confidence: PS]`
*   **REQ-05: AI/ML-Based Subsidence Prediction & Severity Estimation** `[PS]`
    *   *Source Text*: "Using Artificial Intelligence / Machine Learning, the platform should: identify abnormal deformation patterns, predict possible subsidence zones, estimate severity and progression" `[PS]`
    *   *Interpretation*: Time-series telemetry combined with historical panel extraction maps must feed ML models to predict subsidence trough development, maximum settlement ($S_{max}$), and residual subsidence `[INFERENCE]`.
    *   *Implementation Implication*: Implement lightweight time-series forecasting models (LSTM / XGBoost) trained on Knothe subsidence profile equations and historical coalfield monitoring datasets `[RESEARCHED]`. `[Confidence: PS]`
*   **REQ-06: GIS-Based Deformation Mapping & Interactive Visualization** `[PS]`
    *   *Source Text*: "GIS based visualization of live deformation maps and risk zones; interactive dashboards for mine operators, planners, and regulators" `[PS]`
    *   *Interpretation*: Live telemetry must be spatialized on geo-referenced maps (WebGIS) showing heatmaps of ground strain, contour maps of tilt, and panel boundaries `[PS]`.
    *   *Implementation Implication*: Use Leaflet.js / Mapbox GL JS with GeoJSON layers overlaying satellite basemaps (e.g., ISRO Bhuvan or OpenStreetMap) `[INFERENCE]`. `[Confidence: PS]`
*   **REQ-07: Automated Multi-Channel Early Warning System** `[PS]`
    *   *Source Text*: "automated early warning alerts through SMS/email/mobile app notifications; support timely operational decisions" `[PS]`
    *   *Interpretation*: The system must automatically trigger real-time escalation alerts to safety personnel, mine managers, and nearby residents based on severity thresholds `[PS]`.
    *   *Implementation Implication*: Integrate Twilio / Fast2SMS API for cellular SMS, Firebase Cloud Messaging (FCM) for mobile pushes, and Nodemailer for email dispatches `[INFERENCE]`. `[Confidence: PS]`
*   **REQ-08: Offline Capability & Synchronization** `[PS]`
    *   *Source Text*: "offline capability with periodic cloud synchronization" `[PS]`
    *   *Interpretation*: Surface field gateways must operate autonomously during cellular/internet outages, caching telemetry locally and syncing to the cloud upon connection restoration `[INFERENCE]`.
    *   *Implementation Implication*: Implement an edge gateway (Raspberry Pi 4 or ESP32 Gateway with SD card) running SQLite / Embedded DB and a Store-and-Forward sync queue `[INFERENCE]`. `[Confidence: PS]`
*   **REQ-09: Robustness, Low Power, & Indian Geo-Mining Conditions** `[PS]`
    *   *Source Text*: "The solution should be robust, low power, scalable, and suitable for Indian geo-mining conditions." `[PS]`
    *   *Interpretation*: Outdoor enclosures must withstand extreme monsoons, high ambient dust, and temperatures (0°C to 50°C), powered by solar-rechargeable LiFePO4 batteries `[KNOWN]`.
    *   *Implementation Implication*: IP67/IP68 weather-proof enclosures, 3.2V 6000mAh LiFePO4 cells, 5V solar panels, deep-sleep duty cycling (e.g., wake every 5-15 mins during normal state, switch to continuous 1s sampling during alert state) `[INFERENCE]`. `[Confidence: PS]`

## 5. Constraints & Environment Realities

*   **Geographical & Environmental Realities**: Indian coalfields (e.g., Jharia in Jharkhand, Raniganj in West Bengal, Korba in Chhattisgarh) experience severe monsoon rain (up to 1,500 mm annually), ambient summer temperatures exceeding 45°C–48°C, and heavy fly ash/coal dust [KNOWN]. Enclosures must be IP67 rated, UV resistant, and thermally isolated [INFERENCE].
*   **Connectivity Constraints**: Cellular connectivity (4G/5G) above active underground mine panels is often patchy, intermittent, or completely non-existent [KNOWN]. The system CANNOT rely on continuous cloud connectivity for local alert triggers [INFERENCE].
*   **Power Constraints**: Grid power is non-existent across unpaved surface terrain over underground coal panels [KNOWN]. Sensor nodes must be 100% solar self-powered with low-power sleep management to survive up to 5 consecutive cloudy monsoon days [INFERENCE].
*   **Topographical & Vegetation Obstructions**: Surface terrain over underground mine panels includes agricultural fields, forest cover, scrubland, and uneven ground subsidence troughs [KNOWN]. Line-of-Sight (LoS) RF propagation at sub-GHz (865 MHz) LoRa is superior to 2.4 GHz (Wi-Fi/Zigbee) for penetrating foliage and undulating terrain [RESEARCHED].
*   **Regulatory & Statutory Constraints**: Operational safety in Indian coal mines is regulated by the Directorate General of Mines Safety (DGMS) under the Mines Act 1952 and Coal Mines Regulations (CMR 2017) [RESEARCHED]. While surface-deployed equipment over mine panels does not strictly require underground Flameproof/Intrinsically Safe (Ex d / Ex ia) certification, it must comply with outdoor electrical safety and surge protection guidelines [INFERENCE].

### 1. Conventional Field Surveys (Dumpy Level / Total Station)
*   *Description*: Mine surveyors periodically measure optical levels at fixed benchmark pins on the ground surface over active mine panels [KNOWN].
*   *Strengths*: High millimeter-level accuracy at discrete survey points; standard accepted practice [KNOWN].
*   *Weaknesses*: Labor-intensive, time-consuming (conducted once every 15-30 days), zero real-time alerting capability, unsafe during active ground collapse [KNOWN].
*   *Relevance*: Represents the baseline status quo that SIH26025 aims to replace [PS].
*   *Remaining Gap*: Lack of continuous real-time monitoring and dynamic early warning [PS].
*   *Source*: DGMS Strata Control Guidelines & CMPDI survey manuals [RESEARCHED].
*   *Confidence*: `[KNOWN]`

### 2. Satellite SAR Interferometry (SBAS-InSAR / Sentinel-1)
*   *Description*: Processing Synthetic Aperture Radar (SAR) imagery from satellite constellations (e.g., Sentinel-1) to measure surface deformation [RESEARCHED].
*   *Strengths*: Wide-area spatial coverage without ground equipment installation; historical archive access [RESEARCHED].
*   *Weaknesses*: Long revisit intervals (6 to 12 days), complete decorrelation in heavy vegetation/agricultural fields, inability to issue instantaneous real-time alerts [RESEARCHED].
*   *Relevance*: Provides excellent macro-level baseline validation, but insufficient for immediate hazard warning [INFERENCE].
*   *Remaining Gap*: High latency and spatial decorrelation over dense tropical vegetation [RESEARCHED].
*   *Source*: MDPI Remote Sensing / ESA Copernicus documentation [RESEARCHED].
*   *Confidence*: `[RESEARCHED]`

### 3. Commercial Geotechnical Cable/Wired Extensometers (e.g., GeoKon, Soil Instruments)

## 9. Candidate Solution Approaches

### Approach 1: High-Frequency LoRa Mesh + Edge-Threshold Engine + WebGIS
*   *Mechanism*: ESP32 + SX1276 LoRa nodes forming a multi-hop mesh network. Telemetry is evaluated against hardcoded dynamic thresholds at the gateway [INFERENCE].
*   *Required Data*: Accelerometer tilt, linear potentiometer displacement, crack status [PS].
*   *Architecture*: Microcontroller Mesh -> Gateway -> Rule Engine -> Web GIS [INFERENCE].
*   *Complexity*: Low [INFERENCE].
*   *Cost*: Extremely Low (~ ₹3,000 per node) [INFERENCE].
*   *Explainability*: 100% deterministic rule-based explainability [INFERENCE].
*   *Scalability*: Moderate (limited mesh depth) [INFERENCE].
*   *Hackathon Feasibility*: Very High (easily buildable in 36 hours) [INFERENCE].
*   *Production Feasibility*: Moderate (lacks predictive capacity for gradual non-linear settlement) [INFERENCE].
*   *Risks*: High false-alarm rate due to environmental noise or accidental disturbance [INFERENCE].

### Approach 2: Wi-Fi/Zigbee Surface Nodes + Direct Cellular Gateway + Cloud Deep Learning (CNN-LSTM)
*   *Mechanism*: Nodes transmit data via Wi-Fi or Zigbee to local cellular routers, streaming high-frequency raw vibration/tilt to a cloud-hosted PyTorch CNN-LSTM model [INFERENCE].
*   *Required Data*: High-frequency 100Hz vibration/accelerometer streams, cloud database [INFERENCE].
*   *Architecture*: Sensors -> Local Cellular Gateways -> Cloud Server -> ML Inference -> React Dashboard [INFERENCE].
*   *Complexity*: High [INFERENCE].
*   *Cost*: High (cellular data charges per node + continuous cloud GPU runtime) [INFERENCE].
*   *Explainability*: Low (black-box deep neural network) [INFERENCE].
*   *Scalability*: High (cloud horizontal scaling) [INFERENCE].
*   *Hackathon Feasibility*: Low (complex hardware setup and cloud dependencies) [INFERENCE].
*   *Production Feasibility*: Low (fails completely during cellular connectivity blackout) [INFERENCE].
*   *Risks*: Single point of failure at cellular link; high power drain on nodes [INFERENCE].

### Approach 3: Dual-Mode ESP-NOW/LoRa Surface Mesh + Edge Anomaly Filter + Knothe-Calibrated AI (XGBoost/LSTM) + Offline PWA (RECOMMENDED)
*   *Mechanism*: Hybrid mesh network using ESP-NOW for close-range cluster nodes and 865 MHz LoRa for long-range inter-cluster forwarding. Edge gateway runs an Isolation Forest model for instantaneous anomaly detection. Cloud/Local server runs XGBoost/LSTM trained on time-series telemetry fused with Knothe empirical subsidence curves [INFERENCE].
*   *Required Data*: Sensor telemetry (tilt, stretch, vibration, crack), node coordinates, historical panel extraction speed [PS].
*   *Architecture*: Multi-Sensor ESP32 Nodes -> Dual LoRa/ESP-NOW Mesh -> Edge Gateway (SQLite + Edge AI) -> Cloud Synchronization -> WebGIS & PWA Dashboard [INFERENCE].
*   *Complexity*: Moderate-High [INFERENCE].
*   *Cost*: Low (~ ₹3,500 per node) [INFERENCE].
*   *Explainability*: High (combines deterministic edge rules with feature-attribute ML predictions) [INFERENCE].
*   *Scalability*: Excellent (hierarchical mesh clusters) [INFERENCE].
*   *Hackathon Feasibility*: High (realistic MVP with 3 physical nodes + simulated mesh expansion) [INFERENCE].
*   *Production Feasibility*: High (robust against power and network outages) [INFERENCE].
*   *Risks*: Mesh packet collision under high node density (mitigated by slotted ALOHA / TDMA framing) [INFERENCE].

### Justification & Rejection of Alternatives
*   **Why Approach 1 was rejected**: While highly feasible for a hackathon, a simple rule-based system cannot capture the complex, non-linear spatiotemporal progression of strata deformation [INFERENCE]. It produces excessive false positives due to ambient vibrations (e.g., heavy coal transport trucks driving nearby) [INFERENCE].
*   **Why Approach 2 was rejected**: Direct cellular/Wi-Fi deployment per node is economically unviable and technically flawed for Indian mine fields [INFERENCE]. Continuous cloud dependence guarantees system failure during frequent cellular dropouts in rural coalfields [KNOWN].
*   **Why Approach 3 Wins**:
    1.  **Resilience**: The sub-GHz LoRa mesh penetrates foliage and obstacles over 1+ km distance without cellular infrastructure [RESEARCHED].
    2.  **Edge Intelligence**: Autonomous edge gateway ensures critical alerts trigger in sub-second time even during complete cloud disconnect [INFERENCE].
    3.  **Domain Grounding**: Fusing ML with the Knothe empirical subsidence model aligns with Indian CMPDI strata engineering standards [RESEARCHED].
    4.  **Cost Efficiency**: Standard ESP32 + SX1276 hardware keeps node BOM under ₹3,500, fulfilling CIL's low-cost requirement [PS].

### Step-by-Step Data-Flow Narrative

1.  **Sensing & Sampling**: Every 5 minutes (or 1 second during active alarm states), the ESP32 node wakes from deep sleep, powers the sensor rail via a MOSFET switch, samples angular tilt ($\theta_x, \theta_y$), linear displacement ($\Delta L$), vibration amplitude ($g$), crack continuity, and GNSS fix [INFERENCE].
2.  **Local Pre-Processing**: Raw analog/I2C signals undergo digital low-pass filtering on the ESP32 to eliminate transient noise [INFERENCE].
3.  **Mesh Transmission**: The payload is serialized into a 32-byte compact binary structure and transmitted across the 865 MHz LoRa mesh using multi-hop routing until it reaches the Edge Gateway [INFERENCE].
4.  **Edge Processing & Buffering**: The Edge Gateway receives the packet, logs it to a local SQLite database, and executes the Isolation Forest anomaly detector [INFERENCE]. If an emergency threshold is breached (e.g., tilt > 2°/min or crack continuity broken), the gateway immediately triggers a local audio-visual siren and dispatches an emergency SMS via an attached GSM module [INFERENCE].
5.  **Cloud Synchronization**: When cellular connectivity is active, the gateway flushes buffered SQLite records to the cloud MQTT broker via TLS-encrypted MQTT [INFERENCE].

## 13. AI/ML Justification

### 1. Edge Anomaly Detection (Isolation Forest)
*   **Purpose**: To identify sudden, abnormal multi-sensor deformation spikes (e.g., abrupt tilt combined with vibration shock) in real time at the gateway [INFERENCE].
*   **Model Type**: Unsupervised Isolation Forest (Scikit-Learn / Micro-ML) [INFERENCE].
*   **Input**: 5-dimensional feature vector: $[\Delta \theta_x, \Delta \theta_y, \Delta L, \text{Vibration}_{RMS}, \Delta t]$ [INFERENCE].
*   **Output**: Anomaly Score (-1 for anomaly, +1 for normal) [INFERENCE].
*   **Data Required**: 10,000 baseline normal sensor readings under varying ambient temperatures [INFERENCE].
*   **Why AI is Preferable**: Fixed thresholds trigger false alarms due to thermal expansion or passing heavy machinery. Anomaly detection learns normal correlated multi-sensor behavior [INFERENCE].
*   **Evaluation**: Precision, Recall, F1-Score on synthetic failure injection tests [INFERENCE].
*   **Failure Mode**: Sensor calibration drift causing false anomalies -> Gateway auto-recalibrates baseline using a 24-hour sliding median filter [INFERENCE].
*   **Human Oversight**: Mine safety overman receives anomaly alerts and must physically confirm ground status on GIS dashboard [PS].

### 2. Time-Series Subsidence Depth & Progression Predictor (Knothe-LSTM / XGBoost)
*   **Purpose**: To predict maximum surface settlement ($S_{max}$) and subsidence velocity over the next 24 to 72 hours [INFERENCE].
*   **Model Type**: Hybrid Knothe Empirical Model + Long Short-Term Memory (LSTM) Recurrent Neural Network [RESEARCHED].
*   **Input**: Historical 14-day sequence of tilt, stretch rates, coal seam depth ($H$), seam extraction thickness ($m$), and face advance rate ($v$) [RESEARCHED].
*   **Output**: Predicted settlement depth $S(t+24h)$ in millimeters and risk class (Low, Medium, High, Critical) [INFERENCE].
*   **Data Required**: Historical subsidence profile curves from Indian coalfields (CMPDI published data) combined with simulated Knothe time-function curves [RESEARCHED].
*   **Why AI is Preferable**: Pure Knothe equations assume homogenous overburden, whereas deep learning adapts to site-specific non-linear strata relaxation and fault lines [RESEARCHED].
*   **Evaluation**: Root Mean Square Error (RMSE in mm) and Mean Absolute Percentage Error (MAPE) [INFERENCE].
*   **Failure Mode**: Out-of-distribution geological anomaly -> System falls back to conservative empirical Knothe formula calculations [INFERENCE].
*   **Human Oversight**: Strata control engineers review prediction trends before issuing structural evacuation orders [INFERENCE].

### Where AI Should NOT Be Used
*   **Hard Critical Safety Triggers**: Physical crack circuit continuity breaks or tilt rates exceeding structural collapse thresholds (> 5° in 1 min) MUST immediately trigger sirens via hardcoded deterministic logic on the node/gateway, bypassing AI inference to guarantee zero latency and 100% deterministic reliability [INFERENCE].
*   **Battery & Node Diagnostics**: Battery voltage monitoring and packet loss counting must use simple rule-based thresholds [INFERENCE].

```sql
-- Sensor Nodes Metadata
CREATE TABLE sensor_nodes (
    node_id VARCHAR(32) PRIMARY KEY,
    panel_id VARCHAR(32) NOT NULL,
    hardware_version VARCHAR(16),

-- Time-Series Sensor Telemetry
CREATE TABLE node_telemetry (
    id BIGSERIAL PRIMARY KEY,
    node_id VARCHAR(32) REFERENCES sensor_nodes(node_id),
    timestamp TIMESTAMP WITH TIME ZONE NOT NULL,
    tilt_x_deg FLOAT,
    tilt_y_deg FLOAT,
    stretch_displacement_mm FLOAT,
    vibration_rms_g FLOAT,
    crack_detected BOOLEAN,
    temperature_c FLOAT,
    raw_payload_hex TEXT
);
CREATE INDEX idx_telemetry_node_time ON node_telemetry(node_id, timestamp DESC);

-- Spatial Risk Zones & Predictions
CREATE TABLE subsidence_predictions (
    prediction_id BIGSERIAL PRIMARY KEY,
    panel_id VARCHAR(32) NOT NULL,
    prediction_timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    target_timestamp TIMESTAMP WITH TIME ZONE NOT NULL,

    risk_level VARCHAR(16), -- LOW, MEDIUM, HIGH, CRITICAL

);
```

### Local Storage & Offline Store-and-Forward Flow

```
+------------------------------------------------------------------------------------+
|                         OFFLINE STORE-AND-FORWARD FLOW                             |
+------------------------------------------------------------------------------------+
| [SENSOR NODE]                                                                      |
|  • Reads sensors -> Packs binary packet -> Sends over LoRa Mesh                    |
+------------------------------------------------------------------------------------+
                                       │
                                       ▼
| [EDGE GATEWAY (Raspberry Pi)]                                                      |
|  1. Receives packet via SX1276 LoRa Module                                         |
|  2. Writes packet to local SQLite DB: "telemetry_queue" (is_synced = 0)             |
|  3. Evaluates local Rule Engine / Isolation Forest                                 |
|  4. IF Alert Detected -> Trigger Local GSM SMS + Hardware Siren                    |
|  5. Check Cloud Connectivity (Ping MQTT Broker)                                    |
|     ├── CONNECTED: Read UNSYNCED batch (up to 100 rows) -> Publish MQTT ->         |
|     │              Set is_synced = 1 upon ACK                                      |
|     └── DISCONNECTED: Retain in SQLite DB (Max 500,000 records / ~30 days buffer) |
+------------------------------------------------------------------------------------+
```

### Bandwidth & Power Optimization Strategies
*   **Binary Payload Structure**: Telemetry data is packed into a compact 24-byte binary C-struct instead of JSON, reducing LoRa airtime by 80% and extending battery life [INFERENCE].
*   **Adaptive Sampling Duty Cycling**:
    *   *Normal State* (Tilt < 0.5°, No Crack): Node sleeps for 15 minutes, wakes for 2 seconds to sample and transmit [INFERENCE].
    *   *Alert State* (Tilt > 1.5° or Crack Tripped): Node switches to continuous 5-second sampling and high-priority mesh broadcast [INFERENCE].
*   **Collision Handling**: LoRa nodes utilize Random Additive Delay + CSMA (Carrier Sense Multiple Access) before transmission to prevent mesh packet collisions [RESEARCHED].
