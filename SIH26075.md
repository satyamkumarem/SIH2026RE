## 1. Executive Snapshot

CAPACITY CONNECT is a centralized, web-based Digital Capacity Building and Learning Management Portal designed to standardize, manage, and scale specialized scientific and technical training across the Ministry of Earth Sciences (MoES) and the India Meteorological Department (IMD) [PS]. The platform integrates role-based workflows for Trainees, Trainers, and Admins, offering comprehensive profile tracking, course delivery, media library management, deadline-enforced MCQ evaluations, and admin analytics [PS]. Beyond standard LMS capabilities, CAPACITY CONNECT solves the critical organizational challenge of trainer discovery by incorporating an automated competency mapping engine that pairs course subject requirements with qualified trainer profiles based on verified qualifications, experience, and domain expertise [PS, INFERENCE]. Built with a modern responsive frontend, scalable API backend, and offline-resilient assessment engine, it enables continuous skill development across both central offices and bandwidth-constrained remote meteorological observatories [INFERENCE].

## 5. Constraints & Environment Realities

* **Geography & Station Distribution:** IMD operates over 500 observational stations, Doppler Weather Radars (DWR), and regional meteorological centers across India, including remote island and high-altitude posts (e.g., Leh, Agatti, Port Blair) [KNOWN].
* **Connectivity Restrictions:** Primary headquarters (New Delhi, Pune) enjoy gigabit fiber, but remote observatories frequently experience high latency or intermittent 3G/4G cellular connections [INFERENCE]. System design must minimize asset payload sizes and support offline quiz caching [INFERENCE].
* **Hardware Profile:** End-users utilize government-provisioned Windows desktop PCs, standard Android mobile tablets, and personal smartphones [KNOWN]. The interface must render cleanly on displays ranging from 360px mobile viewports to 1080p desktop monitors [INFERENCE].
* **Power Constraints:** Frequent power fluctuations in field stations mandate automatic client-side progress saving during timed MCQ assessments so trainees do not lose progress during unexpected shutdowns [INFERENCE].
* **Language & Compliance:** Primary instructional materials are in English and Hindi [KNOWN]. System UI elements must follow Guidelines for Indian Government Websites (GIGS) for accessibility (WCAG 2.1 AA standard) [RESEARCHED].
* **Cybersecurity Standards:** Must comply with CERT-In security guidelines, avoiding unauthenticated API exposures or plain-text file storage [RESEARCHED].

## 6. Research Questions

1. *How does IMD structure its internal technical training curriculum across its premier institute (Meteorological Training Institute - MTI Pune) and regional centers?*  
   *Findings:* MTI Pune conducts specialized long-term and short-term courses (e.g., Advanced Meteorological Training Course - AMTC, Forecasters Training Course - FTC, Integrated Met Training Course - IMTC) covering General Meteorology, Hydrometeorology, Radar Meteorology, and Telecommunications [RESEARCHED].
2. *What official competency framework is mandated for Indian central government ministries?*  
   *Findings:* The Capacity Building Commission (CBC) enforces the Karmayogi Competency Model (KCM) under Mission Karmayogi, utilizing a Framework of Roles, Activities, and Competencies (FRAC) categorized into Domain, Functional, and Behavioral competencies [RESEARCHED].
3. *What are the technical storage and bandwidth considerations for video lecture streaming across government networks?*  
   *Findings:* High-definition raw video uploads overload regional office bandwidth. Storage must utilize HTTP Live Streaming (HLS) with adaptive bitrate encoding (360p to 720p) to preserve network bandwidth [INFERENCE].
4. *How can automated trainer matching prevent biased or inaccurate assignments?*  
   *Findings:* Pure keyword matching fails when skill terms differ (e.g., "Radar Systems" vs "Doppler Weather Observation"). A hybrid vector similarity model combining TF-IDF/cosine similarity with structured experience weighting ensures transparent, deterministic match scores [INFERENCE].

## 10. Recommended Approach & Why

**Selected Strategy:** Approach 2 — **Modern Full-Stack Architecture with a Dedicated Competency Matching Engine** [ASSUMPTION].

### Core Justification
Approach 2 achieves the optimal balance between rapid hackathon execution and production-grade engineering [INFERENCE]. By utilizing a React/Next.js responsive frontend connected to a RESTful Node.js/Express API backed by PostgreSQL, the team can deliver a slick, responsive user experience across all three user personas [INFERENCE]. The competency mapping requirement is solved using an explainable Vector Cosine Similarity algorithm that compares subject skill vectors against trainer competency vectors, augmented by experience weighting [INFERENCE].

### Rejection of Alternatives
* *Rejection of Approach 1 (Moodle):* Modifying Moodle requires wrestling with legacy PHP code, making custom UI building for the admin approval queue and specialized competency mapping cumbersome during a time-constrained hackathon [INFERENCE].
* *Rejection of Approach 3 (Serverless + LLM):* Relying on generative LLM APIs introduces non-deterministic outputs in assessment generation, potential data privacy violations regarding government employee profiles, unpredictable token billing, and internet latency bottlenecks unsuitable for low-connectivity observatories [INFERENCE].

### Data-Flow Narrative

1. **User Authentication & Role Activation:**  
   * User registers via the signup portal selecting a role (`Trainee` or `Trainer`) [PS].  
   * The record is created with `is_approved = false` in PostgreSQL [INFERENCE].  
   * Admin reviews the user in the Admin Dashboard and approves the account [PS].  
   * Upon login, the server issues a signed JWT containing `user_id`, `email`, and `role` [INFERENCE].

2. **Trainer Course & Quiz Setup Flow:**  
   * An approved Trainer logs in, creates a new course module, and uploads study slides (PDF) and recorded lectures (MP4) [PS].  
   * Multer middleware streams media to Object Storage and returns accessible URLs [INFERENCE].  
   * Trainer constructs an MCQ assessment, defines pass thresholds, correct answer indices, and sets a submission deadline [PS].

3. **Trainee Learning & Assessment Flow:**  
   * Trainee browses the course catalog, enrolls in a subject, views lecture slides, and streams video content [PS].  
   * Service Worker caches the quiz structure locally [INFERENCE].  
   * Trainee attempts the subject-wise MCQ test. Answers are auto-graded upon submission against stored answer keys [PS].  
   * Pass/fail results and numerical scores are recorded in `assessment_attempts` table, updating user progress metrics [INFERENCE].  
   * Trainee completes a star-rating and text feedback form for the course [PS].

4. **Competency Mapping Flow:**  
   * Admin or System requires a trainer for a new subject (e.g., "Doppler Radar Data Analysis") [PS, INFERENCE].  
   * The subject's required skill tags are converted into a TF-IDF skill vector [INFERENCE].  
   * The Competency Engine queries all approved Trainer profiles, calculates Cosine Similarity scores between trainer skill vectors and subject requirements, weights the score by years of experience and past course feedback ratings, and returns a ranked list of recommended trainers [INFERENCE].

```
                      [ Weighted Final Ranking Score ]
      Final Score = (0.6 * Sim) + (0.25 * Norm_Exp) + (0.15 * Avg_Rating)
                                      |
                                      v
                   [ Output: Ranked Trainer Recommendation List ]
```

### Competency Mapping Subsystem Analysis

1. **What exact problem does AI/Algorithmic matching solve?**  
   It automates the search for subject matter experts across MoES/IMD departments by matching training requirements with candidate trainer qualifications and experience [PS, INFERENCE].
2. **What is the input?**  
   Subject required competencies (tags/description) and a pool of Trainer profiles containing qualifications, listed skills, years of experience, and past course feedback ratings [PS, INFERENCE].
3. **What is the output?**  
   A ranked list of trainers with calculated match percentages (0–100%) and breakdown justifications [INFERENCE].
4. **Why can a simpler rule/system not solve it?**  
   Exact keyword matching fails when skill descriptions differ slightly (e.g., "Doppler Navigation" vs "Doppler Radar Processing"). Vector mapping captures textual overlap nuances [INFERENCE].
5. **What data is required?**  
   Structured skill taxonomy list, trainer self-declared skills, academic qualification metadata, and historical feedback scores [PS, INFERENCE].
6. **How will it be evaluated?**  
   Mean Reciprocal Rank (MRR) and Precision@K when evaluated against expert manual trainer assignments [INFERENCE].
7. **What happens when it is wrong?**  
   The system provides a fallback list sorted by general experience, allowing administrators to manually override assignments [INFERENCE].
8. **Does it require training?** No fine-tuning or deep neural network training required; uses pre-built TF-IDF vectorization [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Core Database Schema (PostgreSQL DDL)

```sql
-- Users Table (Handles all 3 roles)
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    full_name VARCHAR(150) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) CHECK (role IN ('TRAINEE', 'TRAINER', 'ADMIN')) NOT NULL,
    is_approved BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Trainee Profiles
CREATE TABLE trainee_profiles (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id) ON DELETE CASCADE,
    qualifications TEXT[],
    work_experience_years INT DEFAULT 0,
    interests TEXT[],
    skills TEXT[],
    certificates_json JSONB DEFAULT '[]'::jsonb
);

-- Trainer Profiles
CREATE TABLE trainer_profiles (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id) ON DELETE CASCADE,
    designation VARCHAR(100),
    department VARCHAR(100),
    expertise_skills TEXT[],
    years_experience INT DEFAULT 0,
    average_rating NUMERIC(3,2) DEFAULT 0.00
);

-- Courses Table
CREATE TABLE courses (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    category VARCHAR(100),
    created_by INT REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Questionnaires / Assessments
CREATE TABLE assessments (
    id SERIAL PRIMARY KEY,
    course_id INT REFERENCES courses(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    deadline TIMESTAMP NOT NULL,
    pass_mark INT DEFAULT 50,
    questions_json JSONB NOT NULL -- Array of {q_id, question, options[], correct_idx}
);

-- Assessment Attempts
CREATE TABLE assessment_attempts (
    id SERIAL PRIMARY KEY,
    assessment_id INT REFERENCES assessments(id) ON DELETE CASCADE,
    user_id INT REFERENCES users(id) ON DELETE CASCADE,
    score INT NOT NULL,
    passed BOOLEAN NOT NULL,
    submitted_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Course Feedback
CREATE TABLE course_feedback (
    id SERIAL PRIMARY KEY,
    course_id INT REFERENCES courses(id) ON DELETE CASCADE,
    user_id INT REFERENCES users(id) ON DELETE CASCADE,
    rating INT CHECK (rating BETWEEN 1 AND 5),
    comments TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Low-Network & Offline Resiliency Design

* **Client-Side Quiz Caching:** Assessment structure and question payloads are fetched once upon opening the test and stored in IndexedDB via Service Worker [INFERENCE].
* **Local State Auto-Save:** Every MCQ selection is automatically stored in `localStorage`. If power or network drops, answers remain intact upon browser refresh [INFERENCE].
* **Background Submission Sync:** Submissions offline are queued in Background Sync API. Once network connectivity re-establishes, answers automatically POST to `/api/trainee/submit-quiz` [INFERENCE].
* **Bandwidth Optimization:** Presentation slides are compressed into optimized lightweight PDFs (<5MB). Video streaming utilizes adaptive HLS chunks [INFERENCE].

## 15. Security, Privacy & Governance

* **Data Encryption Standards:** All network communication enforced over TLS 1.3 [INFERENCE]. Passwords hashed using Argon2id with unique salt values [INFERENCE]. User credentials stored at rest using AES-256 encryption [INFERENCE].
* **Role-Based Access Control (RBAC):** Middleware checks JWT payload claims before allowing execution on protected routes. Trainees cannot access creation APIs (`/api/trainer/*`) or admin queues (`/api/admin/*`) [INFERENCE].
* **Admin Approval Workflow:** New accounts default to inactive status (`is_approved = false`), blocking system access until verified by an Administrator, preventing unauthorized external access [PS, INFERENCE].
* **Audit Logging:** Critical administrative actions (role modifications, account approvals, score overrides) write immutable log entries into an `audit_logs` database table [INFERENCE].
* **Regulatory Compliance:** Designed in accordance with CERT-In guidelines for web application security, mitigating OWASP Top 10 vulnerabilities (SQL Injection, XSS, CSRF) [RESEARCHED].
