# Sovereign On-Premise Agentic AI Workbench using Open-Weight Multimodal LLMs for Confidential Industrial Work

## 1. Executive Snapshot

### Summary
Mangalore Refinery and Petrochemicals Limited (MRPL) and other strategic public sector undertakings (PSUs) require an air-gapped, self-hosted agentic AI workbench to automate routine but highly sensitive knowledge work—including engineering drawing reviews (P&IDs), scanned inspection reports, approval notes, financial calculations, and internal tool development [PS]. Cloud-based LLM services (e.g., ChatGPT, Claude) are strictly prohibited due to severe data confidentiality risks regarding unreleased designs, vendor negotiations, and plant safety schematics [PS]. The proposed solution, **SovereignBench**, is a fully offline, multi-model agentic AI platform deployed on local enterprise GPU hardware [INFERENCE]. It dynamically routes tasks to specialized open-weight models (e.g., vision-language models for scanned drawings/notes, coding models for sandboxed script execution, and reasoning models for document synthesis) [INFERENCE]. Operating through a deterministic tool-calling agent framework (LangGraph), the platform reads local documents, searches internal SOPs via a local vector database, executes code inside isolated containers, generates native Microsoft Office deliverables (`.docx`, `.xlsx`, `.pptx`), and provides live GUI-integrated network monitoring to prove zero outbound network calls [INFERENCE].

## 5. Constraints & Environment Realities

### Operational Environment Constraints
1. **Air-Gap Strictness:** PSU enterprise networks at refinery locations (e.g., MRPL Mangalore) strictly disable outbound internet traffic on industrial networks [KNOWN]. The workbench must function cleanly with network interfaces physically disconnected or blocked by enterprise firewalls [PS].
2. **GPU Hardware Budget:** While production deployment may utilize multi-A100/H100 clusters, hackathon evaluation occurs on workstations with mid-range consumer or workstation GPUs (e.g., single NVIDIA RTX 4090 24GB or RTX A6000 48GB) [PS]. Total VRAM constraints require model quantization (4-bit GGUF or AWQ) and offloading strategies [RESEARCHED].
3. **Power and Thermal Resilience:** Industrial GPU servers operate in climate-controlled server rooms, but hackathon evaluation hardware may face thermal throttling under continuous multi-model inference [INFERENCE].
4. **Data Formats in Refining:** Documents include legacy scanned PDFs from the 1990s, skewed P&IDs (A0/A1 blue-prints), multi-page Excel sheets with complex macro formulas, and handwritten maintenance logs in varying handwriting styles [KNOWN].
5. **Language & Terminology:** Documents contain specialized petrochemical engineering terminology (e.g., FCCU, hydrocracker, ASME standards, ISA-5.1 P&ID symbols) requiring domain-accurate grounding [KNOWN].

### Approach 1: Monolithic Single-Model Pipeline with Script-Based Orchestration
* **Mechanism:** Single large model (e.g., Llama-3.1-70B or Qwen2.5-72B quantized) loaded into VRAM, handled by a fixed Python sequential script.
* **Accuracy Potential:** Medium-Low. A single generalist quantized model underperforms compared to specialized models (e.g., Qwen2.5-Coder for code, Qwen2.5-VL for P&IDs) [RESEARCHED].
* **Complexity:** Low implementation complexity.
* **Resource Overhead:** Extremely high VRAM requirements (requires >40GB VRAM, impossible on single consumer GPU) [RESEARCHED].
* **Hackathon Feasibility:** Poor due to hardware constraints on venue workstations [INFERENCE].

### Approach 2: Dual-Model Dynamic Routing Agentic Workbench with Containerized Sandbox (RECOMMENDED)
* **Mechanism:** A lightweight intent classifier routes tasks to specialized quantized models hosted concurrently on Ollama/vLLM. Coding goes to `Qwen2.5-Coder-14B`, multimodal P&ID/scanned PDF vision goes to `Qwen2.5-VL-7B`, and general orchestration/reasoning uses `DeepSeek-R1-Distill-Qwen-14B` [RESEARCHED]. A LangGraph state graph orchestrates ReAct tool loops, invoking local tools (Docling OCR, Pyodide/Docker execution, `python-docx` file generation) [RESEARCHED].
* **Accuracy Potential:** Extremely High. Specialized open-weight models match or exceed general models in their respective domains [RESEARCHED].
* **Complexity:** Moderate. Decoupled microservices architecture.
* **Resource Overhead:** Optimized VRAM (~18–22 GB total VRAM), allowing execution on a single 24GB GPU (RTX 4090/A5000) [RESEARCHED].
* **Hackathon Feasibility:** Excellent. Demonstrates true dynamic routing, multimodal intelligence, and full air-gap security within standard hackathon GPU budgets [INFERENCE].

### Approach 3: Cloud-Fallback Hybrid Architecture
* **Mechanism:** Tries local LLM first; falls back to cloud API (e.g., OpenAI/Anthropic) if local task fails.

## 10. Recommended Approach & Why

**Selected Architecture: Approach 2 (Dynamic Multi-Model Agentic Workbench)**

### Technical Justification
1. **Fits Hardware Realities:** By deploying quantized specialized models (e.g., `Qwen2.5-Coder-14B-Instruct-Q4_K_M` ~9GB VRAM + `Qwen2.5-VL-7B-Instruct-Q4_K_M` ~5GB VRAM + `bge-large-en-v1.5` ~1.3GB VRAM), total VRAM footprint remains under 18GB [RESEARCHED]. This enables smooth performance on a single 24GB GPU without VRAM thrashing [RESEARCHED].
2. **Superior Domain Performance:** Specialized models beat generalist models of larger sizes in specific domain benchmarks (`Qwen2.5-Coder-32B/14B` matches top propriety coders; `Qwen2.5-VL` excels at document structure and spatial graphic understanding) [RESEARCHED].
3. **True Agentic ReAct Execution:** Using LangGraph, the agent can autonomously generate code, test it in the sandbox, read error tracebacks, fix its code, and output verified results without stopping at an initial incorrect response [RESEARCHED].
4. **Defensible Air-Gap Compliance:** The decoupled local container architecture makes it simple to bind all services to local loopback interfaces (`127.0.0.1` / Docker internal bridge) and display network interface activity in real time [INFERENCE].

### Detailed Data-Flow Narrative

1. **Task Submission:** A process engineer uploads a scanned PDF inspection report with an engineering drawing and enters a prompt: *"Extract findings, calculate pipe corrosion rate, and generate an executive approval note (.docx)."*
2. **Intent Classification & Model Selection:** FastAPI backend receives the request. The Intent Router inspects the payload. Detecting an image/scanned PDF upload and a document generation task, it selects `Qwen2.5-VL-7B` for vision extraction and `DeepSeek-R1-Distill-14B` for reasoning and drafting [INFERENCE].
3. **Multimodal Ingestion:** The file is routed to the local Docling/PaddleOCR engine. Layout parsing extracts image regions, tables, and handwritten text layers locally [RESEARCHED].
4. **Agent Planning & Knowledge Retrieval:** The LangGraph ReAct agent initializes state. It queries the local Qdrant vector database using `bge-large-en-v1.5` to retrieve MRPL corrosion allowance standards from internal SOPs [RESEARCHED].
5. **Tool Call - Sandboxed Math Calculation:** The agent formulates a Python script to compute corrosion rates based on extracted inspection numbers. It passes the script to the Docker/Pyodide Sandbox Tool. The script runs locally, verifies mathematical outputs, and returns structured JSON [INFERENCE].
6. **Tool Call - Office Deliverable Generation:** The agent passes structured findings to the `python-docx` Tool, applying the official MRPL approval note template. The file `Approval_Note_Corrosion_Report.docx` is written to local disk (`/data/deliverables/`) [INFERENCE].
7. **Verification & UI Rendering:** The backend returns the final response, displaying execution steps, intermediate calculations, inline previews, and a direct download link for the generated `.docx` file [INFERENCE].
8. **Continuous Air-Gap Audit:** Throughout the transaction, the eBPF/iptables network monitor logs network traffic on all network cards, rendering a live graph showing 0 outbound bytes to external IPs [INFERENCE].

### Where AI Should NOT Be Used
* **Calculations:** Mathematical formula execution (corrosion rates, pressure drop, financial totals) **must NOT** rely on LLM arithmetic generation. The LLM must write a Python script, which is executed deterministically in the sandbox to guarantee 100% mathematical precision [INFERENCE].
* **File Formatting:** Layout formatting for `.docx`, `.xlsx`, and `.pptx` files **must NOT** be generated as raw raw text. Standardized Python libraries (`python-docx`, `openpyxl`) must deterministically build documents from JSON schema outputs [INFERENCE].
* **Network Security Verification:** Network monitoring **must NOT** involve AI prediction. It uses raw Linux kernel packet counters (`iptables` / `eBPF`) [INFERENCE].

4. **Resilient Local Queueing:** If a heavy vision job is processing, backend background tasks manage GPU memory locks to prevent VRAM out-of-memory crash loops [INFERENCE].

## 15. Security, Privacy & Governance

### Air-Gap Enforcement & Network Firewall
* **Kernel Level Rules:** The deployment script configures `iptables` rules blocking all outbound TCP/UDP traffic except local loopback:
  `iptables -A OUTPUT -o lo -j ACCEPT`
  `iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT`
  `iptables -P OUTPUT DROP` [RESEARCHED].
* **Live Network Monitor Widget:** The frontend embeds a WebSocket-based packet auditor querying `/api/v1/network/stats`. It displays real-time bandwidth (0 KB/s outbound), open ports, and dropped outbound packet counters to convince hackathon judges [INFERENCE].

### Sandboxing & Code Execution Security
* **Docker Container Isolation:** Code generated by the coding LLM is executed inside an ephemeral Docker container running under a restricted non-root user (`nobody`), with `--net=none` (zero network access), `--memory=512m`, `--cpus=1.0`, and read-only filesystem mounts (except `/tmp`) [RESEARCHED].
* **Process Timeout Limits:** Sandbox execution is terminated after 10 seconds to prevent infinite loops or memory leaks [INFERENCE].

### Access Control & Audit Governance
* **Role-Based Access Control (RBAC):** Users log in via local OAuth2 / JWT session handling. Roles include `Engineer` (can run workflows, view deliverables), `SOP Admin` (can upload new manuals to vector store), and `CISO Auditor` (can view execution logs and network audit trails) [INFERENCE].
* **Immutable Execution Audit Logs:** Every LLM prompt, tool call, code execution stdout/stderr, and file generated is logged to a local SQLite audit table with SHA-256 hash checks to prevent tampering [INFERENCE].
