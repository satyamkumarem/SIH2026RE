# 1. Executive Snapshot

### Summary
The National Technical Research Organisation (NTRO) requires an artificial intelligence software framework to perform **Deep Learning-Based Super Resolution Mapping (SRM)** on medium-resolution satellite imagery [PS]. Specifically, the framework must take freely available **10m Sentinel-2 multispectral imagery** (bands B2-Blue, B3-Green, B4-Red, B8-NIR) and reconstruct high-resolution (<4m, targetting **2.5m Ground Sampling Distance**) spatial products [PS]. Medium-resolution imagery provides wide spatial coverage and frequent revisit times but lacks the ground detail required for fine-scale remote sensing tasks, such as identifying small building footprints, narrow roads, localized disaster damage, and field boundaries [PS]. The central technical challenge is to achieve spatial sharpening without introducing generative hallucinations or altering original spectral/radiometric properties [PS]. The proposed solution features a **Hybrid Swin-Transformer Generative Architecture with a Spectral-Constraint Loss Head** and an **Ensemble-based Pixel-Wise Uncertainty Estimator**. This pipeline converts raw Sentinel-2 scenes into georeferenced, spectral-consistent, high-resolution GeoTIFFs, complete with spatial confidence maps and downstream building/road extraction capabilities [INFERENCE].

# 6. Research Questions

1. **How can deep learning architectures increase spatial resolution by $4\times$ while avoiding the creation of false structures (hallucinations)?**
   * *Investigation Goal:* Evaluate loss function combinations (L1 + SSIM + Spectral Angle Mapper + VGG Perceptual Loss) to find the optimal balance between sharpness and fidelity [RESEARCHED].
2. **What is the most effective approach for estimating pixel-level spatial uncertainty in satellite super-resolution?**
   * *Investigation Goal:* Compare Monte Carlo (MC) Dropout, Deep Ensembles, and Latent Diffusion variance maps in terms of computational speed and calibration accuracy [RESEARCHED].
3. **Does super-resolving Sentinel-2 imagery actually improve downstream computer vision tasks (building extraction, road segmentation) compared to bicubic upsampling?**
   * *Investigation Goal:* Benchmark U-Net / Mask2Former performance on raw 10m inputs vs 2.5m SR outputs across standard remote sensing test sets [RESEARCHED].
4. **How can multi-spectral fidelity (RGB + NIR) be strictly preserved across channels during generative upscaling?**
   * *Investigation Goal:* Test cross-channel attention mechanisms and channel-wise normalization layers in Swin-Transformers [RESEARCHED].

# 10. Recommended Approach & Why

### Selection: Hybrid Swin-Transformer Architecture with Spectral Constraint & Integrated Uncertainty Estimator (SwinIR-SRM) [INFERENCE]

The **Hybrid Swin-Transformer (Approach 2)** is selected as the optimal architecture for this problem statement [INFERENCE]. 

#### Justification:
1. **Superior Contextual Detail:** Satellite imagery features complex spatial relationships (e.g., long linear road networks, regular urban grid layouts, field borders). Swin-Transformer’s self-attention mechanism captures these long-range spatial dependencies far more effectively than standard local CNNs [RESEARCHED].
2. **Rejection of Pure Diffusion Models (Approach 3):** While diffusion models produce visually striking images, their iterative sampling mechanism is too slow for interactive web applications (~3.5s per tile vs ~0.18s for SwinIR) [4.2]. Furthermore, diffusion models carry a high risk of generating realistic-looking but completely fake ground details, which is unacceptable for NTRO defense and intelligence applications [INFERENCE].
3. **Rejection of Pure CNNs (Approach 1):** Standard CNNs (like EDSR/RCAN) tend to produce oversmoothed, blurry edges when upscaling by $4\times$, failing the requirement to identify narrow roads and small building footprints [PS].
4. **Spectral & Radiometric Fidelity:** By introducing a dual-loss objective incorporating **L1 Loss + Structural Similarity Index (SSIM) + Spectral Angle Mapper (SAM) Loss**, SwinIR-SRM guarantees that upscaled RGB+NIR bands maintain correct physical reflectance ratios [INFERENCE].
5. **Integrated Uncertainty Mapping:** Through Monte Carlo Dropout inference ($N=8$ forward passes with active dropout at inference), the model outputs a co-registered **Pixel Uncertainty Map** [4.2]. High-variance pixels (e.g., highly complex ambiguous textures) are visually highlighted, satisfying the explicit requirement to manage inferred details [PS].

### Detailed Data-Flow Narrative

1. **Data Acquisition:** The user selects an Area of Interest (AOI) and date range via the MapLibre web frontend. The backend queries the **Copernicus Data Space Ecosystem STAC API** [2.4] to retrieve 10m Sentinel-2 L2A scenes (B2, B3, B4, B8).
2. **Pre-processing & Tiling:** The raw GeoTIFF is ingested using `Rasterio`. Clouds are masked using the Sentinel-2 Scene Classification Layer (SCL). The raster is cropped into $256 \times 256$ pixel overlapping tiles with coordinate transformation matrices preserved [INFERENCE].
3. **Super-Resolution Inference:** Each $256 \times 256 \times 4$ tensor is fed into the **SwinIR-SRM Model**. The model computes a $1024 \times 1024 \times 4$ super-resolved tensor (2.5m GSD).
4. **Uncertainty Generation:** During inference, Monte Carlo Dropout executes 8 stochastic passes per tile. The pixel-wise variance across these passes forms the **2D Spatial Uncertainty Map** [INFERENCE].
5. **Georeferencing & Stitching:** Output tiles are re-assembled into a unified Cloud-Optimized GeoTIFF (COG). The GeoTransform matrix is modified by dividing the pixel pixel resolution parameters by 4 ($10\text{m} \rightarrow 2.5\text{m}$), preserving exact EPSG map projection [INFERENCE].
6. **Downstream Analytics & Web Streaming:** The generated COG is passed to the **Downstream Vectorization Module** (U-Net) to generate GeoJSON building footprints and road polylines. **TiTiler** serves the super-resolved raster and uncertainty map as WMTS map tiles to the frontend viewer [INFERENCE].

# 13. AI/ML Justification

### 1. SwinIR-SRM Generator
- **Purpose:** Upscale 10m Sentinel-2 multispectral bands (B2, B3, B4, B8) to 2.5m resolution [PS].
- **Model Type:** Shifted-Window Vision Transformer (SwinIR) with multi-head spectral cross-attention [INFERENCE].
- **Input:** $256 \times 256 \times 4$ normalized float tensor (10m resolution).
- **Output:** $1024 \times 1024 \times 4$ enhanced float tensor (2.5m resolution).
- **Data Required:** SEN2VENµS dataset (132k paired 10m/5m patches) [1.2] and WorldStrat dataset (SPOT 1.5m pairs) [1.11].
- **Why AI is Necessary:** Mathematical interpolation (bicubic) cannot invent or reconstruct high-frequency spatial detail from sub-pixel mixed signals; deep neural networks learn underlying spatial textures and structural patterns from paired Earth Observation data [RESEARCHED].
- **Evaluation Metrics:** PSNR ($>31\text{ dB}$), SSIM ($>0.88$), SAM ($<3.5^\circ$), ERGAS ($<3.0$) [RESEARCHED].
- **Failure Mode & Mitigation:** Blurring on unencountered terrain types; mitigated by fine-tuning on diverse global biomes from WorldStrat [1.11].
- **Human Oversight:** High uncertainty pixels trigger mandatory human analyst review in the UI [INFERENCE].

### 2. Monte Carlo Uncertainty Quantification Module
- **Purpose:** Generate a 2D spatial confidence map highlighting inferred vs observed features [PS].
- **Model Type:** Bayesian Neural Network approximation via Monte Carlo Dropout at inference time [RESEARCHED].
- **Input:** $256 \times 256 \times 4$ LR tensor passed through $N=8$ forward passes with dropout $p=0.1$.
- **Output:** $1024 \times 1024 \times 1$ variance tensor normalized to $[0, 1]$.
- **Data Required:** Same inference input tensor; no additional training data needed.
- **Why AI is Necessary:** Standard deterministic models produce a single output without indicating confidence; probabilistic variance provides an accountable estimate of model hallucination [4.2].
- **Evaluation Metrics:** Prediction Interval Coverage Probability (PICP) and Mean Normalized Prediction Interval Width (MPIW) [RESEARCHED].
- **Failure Mode & Mitigation:** Overestimating uncertainty in dark shadows; mitigated by calibrating variance thresholds against reference error maps [INFERENCE].
- **Human Oversight:** Displayed as a red/yellow/green confidence overlay on the frontend [INFERENCE].

### 3. Downstream Feature Segmentation Module
- **Purpose:** Extract building footprints and road networks to prove analytical utility gains [PS].
- **Model Type:** U-Net / Mask2Former with ResNet-34 backbone [4.7, 4.9].
- **Input:** 2.5m SR output raster tensor vs 10m LR raw raster tensor.
- **Output:** Binary semantic segmentation masks (Buildings & Roads) and GeoJSON vectors.
- **Data Required:** SpaceNet building/road vector datasets and OpenStreetMap ground truth.
- **Why AI is Necessary:** Rule-based thresholding fails under complex urban reflectance and variable shadows.
- **Evaluation Metrics:** Intersection over Union (IoU) and F1-Score improvement on SR vs LR data [4.5].
- **Failure Mode & Mitigation:** Fragmented road lines; mitigated by morphological post-processing re-connection algorithms [4.4].
- **Human Oversight:** Analysts can edit vector geometries in the web GIS interface.

- **Cloud Masking:** Implemented via standard deterministic thresholds on Sentinel-2 SCL (Scene Classification Layer) or QA60 bitmask bands [INFERENCE].
- **Georeferencing & Spatial Reprojection:** Implemented using deterministic affine transform matrix multiplication in GDAL/Rasterio [INFERENCE].

# 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL + PostGIS)

```sql
-- Table: AoiJobs
CREATE TABLE AoiJobs (
    job_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id VARCHAR(64) NOT NULL,
    aoi_geometry GEOMETRY(Polygon, 4326) NOT NULL,
    acquisition_date DATE NOT NULL,
    status VARCHAR(20) DEFAULT 'PENDING', -- PENDING, PROCESSING, COMPLETED, FAILED
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Table: SuperResolutionProducts
CREATE TABLE SuperResolutionProducts (
    product_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    job_id UUID REFERENCES AoiJobs(job_id),
    lr_sentinel_id VARCHAR(128) NOT NULL,
    sr_cog_path VARCHAR(512) NOT NULL,
    uncertainty_cog_path VARCHAR(512) NOT NULL,
    psnr_score FLOAT,
    ssim_score FLOAT,
    sam_score FLOAT,
    resolution_gsd FLOAT DEFAULT 2.5,
    bounding_box GEOMETRY(Polygon, 4326) NOT NULL,
    processed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Table: DownstreamVectors
CREATE TABLE DownstreamVectors (
    vector_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id UUID REFERENCES SuperResolutionProducts(product_id),
    feature_type VARCHAR(32) NOT NULL, -- 'BUILDING' or 'ROAD'
    geom GEOMETRY(Geometry, 4326) NOT NULL,
    confidence_score FLOAT
);
```

### Local Storage & COG Caching
- **Local Tiling Cache:** Tiled sub-regions processed during inference are stored locally as Cloud-Optimized GeoTIFFs (COGs) using `DEFLATE` compression and internal overviews ($2\times, 4\times, 8\times$) [INFERENCE].
- **Tile Streaming:** The frontend requests $256 \times 256$ PNG web tiles dynamically rendered from COGs by **TiTiler**, avoiding client-side download of multi-gigabyte raster files [INFERENCE].

### Offline & Low-Network Synchronization
- **Air-Gapped Deployment:** In low-connectivity or secure military environments, raw Sentinel-2 granules are ingested via local USB/NAS storage rather than STAC cloud endpoints [INFERENCE].
- **Vector Caching:** Extracted building and road GeoJSON geometries are cached locally using `IndexedDB` in the browser client, enabling full offline map viewing once loaded [INFERENCE].
