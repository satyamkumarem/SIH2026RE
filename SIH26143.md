# 1. Executive Snapshot

### Executive Summary
Marine oil spills inflict massive ecological and economic damage on coastal environments [PS], yet polluters often escape liability due to the difficulty of attributing slicks to moving vessels across vast ocean domains [PS]. This dossier presents an intelligence and response platform designed for the **National Technical Research Organisation (NTRO)** [PS]. The solution integrates Synthetic Aperture Radar (SAR) deep learning segmentation (Swin-UNet / DeepLabv3+) [RESEARCHED] to detect and characterize oil slicks, a Lagrangian hydrodynamic particle tracking engine (**OpenOil / OpenDrift**) [RESEARCHED] driven by ocean current, wind, and wave forcing (CMEMS, ERA5, INCOIS) [RESEARCHED] to perform backward hindcasting and forward drift forecasting [PS], and a spatial-temporal AIS trajectory analysis engine [PS] to filter irrelevant traffic and calculate composite suspect probability scores for vessels around the slick origin window [PS]. Built on open geospatial standards (PostGIS, MapLibre, FastAPI) [RESEARCHED], this system provides NTRO analysts and maritime enforcement agencies with actionable, legally defensible attribution dossiers [INFERENCE].

# 5. Constraints & Environment Realities

1. **Satellite Revisit Time & Latency**: Sentinel-1 SAR ground revisit frequency ranges from 1 to 6 days depending on latitude over Indian EEZ [KNOWN]. Real-time detection is constrained by satellite pass schedules; imagery is typically available 1.5–3 hours post-acquisition via Copernicus / ISRO ground stations [RESEARCHED].
2. **SAR Image Artifacts & Look-Alikes**: Low wind areas ($<2-3 m/s$), natural biogenic films, upwelling, grease ice, and wind shadows produce dark patches on SAR imagery identical to oil slicks [RESEARCHED]. The ML engine must differentiate true mineral oil from look-alikes [INFERENCE].
3. **AIS Signal Coverage & Dark Ships**: Terrestrial AIS receivers cover ~20-50 nautical miles from shore [KNOWN]. In deep sea, AIS relies on Satellite-AIS (S-AIS) which suffers from message collisions in high-density corridors [RESEARCHED]. Furthermore, rogue vessels intentionally switch off AIS transponders ("going dark") prior to illegal tank washing [RESEARCHED].
4. **Met-Ocean Model Resolution**: Global ocean current models (CMEMS Global / HYCOM) have grid resolutions of ~1/12° (~9 km) [RESEARCHED], while coastal models (INCOIS ROMS) offer ~2.3 km resolution [RESEARCHED]. Micro-scale coastal eddies smaller than the grid resolution introduce drift uncertainty [INFERENCE].
5. **Compute & Security Environment**: NTRO operational servers run on air-gapped or secure private cloud infrastructure without unrestricted public internet access [INFERENCE]. Algorithms must run locally or on sovereign cloud infrastructure without cloud vendor lock-in [INFERENCE].

# 9. Candidate Solution Approaches

### Approach 1: Heuristic Buffer & Linear Back-Projection
- **Mechanism**: Detects dark patches using thresholding (Otsu/Adaptive). Back-projects slick along inverse average wind vector over past hours. Draws spatial buffer around back-projected point and selects all AIS vessels inside buffer.
- **Required Data**: SAR image, average wind speed/direction, raw AIS points.
- **Architecture**: Simple Python script with OpenCV and GeoPandas.
- **Complexity**: Low ($O(N)$ spatial query).
- **Explainability**: High (simple geometric buffer).
- **Drawbacks**: Ignores ocean currents, oil weathering, non-linear trajectories, and complex hydrodynamic drift physics; high false positive rate [INFERENCE].

### Approach 2: Classical ML (Random Forest/XGBoost) + Single-Particle Hydrodynamic Backtracking
- **Mechanism**: Extracts Haralick texture features and geometric parameters from SAR; classifies oil vs look-alike using Random Forest [RESEARCHED]. Runs deterministic single-particle reverse advection driven by CMEMS currents and ERA5 windage. Correlates AIS points along the single line trajectory.
- **Required Data**: Sentinel-1 SAR, CMEMS 2D currents, ERA5 10m wind, MarineCadastre AIS.
- **Architecture**: Python FastAPI backend, Scikit-learn, Scipy ODE solver, PostGIS.
- **Complexity**: Moderate.
- **Explainability**: Moderate.
- **Drawbacks**: Fails to capture stochastic ocean turbulence, particle dispersion, wave entrainment, and weathering properties (evaporation/emulsification); single line path yields poor spatial origin envelopes [INFERENCE].

### Approach 3 (Proposed): Deep Learning Segmentation + OpenOil Lagrangian Weathering Hindcast + Spatio-Temporal AIS Anomaly Scoring Engine
- **Mechanism**: 
  1. **SAR Segmentation**: Deep learning model (Swin-UNet / Mask2Former) trained on SAR patches segments slick boundary and calculates geometric properties [RESEARCHED].
  2. **Stochastic Hindcast Simulation**: Ingests slick polygon into **OpenOil / OpenDrift** framework [RESEARCHED]. Releases 5,000–10,000 Monte Carlo Lagrangian particles backwards in time ($-\Delta t$) driven by 3D ocean currents, windage (3% rule + wave drag), and Stokes drift [RESEARCHED]. Calculates physical weathering (evaporation loss, viscosity changes) to estimate slick age $t_{age}$ [RESEARCHED].
  3. **Origin Density Kernel Estimation**: Computes spatial probability density function (PDF) at origin window $t_0 = t_{detection} - t_{age}$.
  4. **AIS Trajectory Reconstruction & Anomaly Scoring**: Reconstructs vessel tracklines using PostGIS. Filters non-candidate traffic. Evaluates candidates using multi-factor scoring: $S = w_1 \cdot \text{Proximity} + w_2 \cdot \text{Trajectory Alignment} + w_3 \cdot \text{Speed Anomaly} + w_4 \cdot \text{AIS Dark Gap} + w_5 \cdot \text{Draft Change}$.
- **Required Data**: Sentinel-1 SAR (Zenodo dataset), CMEMS currents, ERA5 wind/waves, MarineCadastre AIS (GeoParquet).
- **Architecture**: Microservices architecture using PyTorch, OpenDrift framework, PostGIS, FastAPI, Celery distributed tasks, and MapLibre GL frontend.
- **Complexity**: High (state-of-the-art production standard).
- **Explainability**: High (probabilistic heatmaps and transparent feature score breakdowns).

# 10. Recommended Approach & Why

### Selection: Approach 3 (Hybrid Deep Learning + OpenOil + AIS Anomaly Engine)
Approach 3 is selected because marine oil attribution is fundamentally a **non-linear spatial-temporal reverse transport problem** combined with **probabilistic vessel trajectory matching** [INFERENCE]. 

### Why Alternatives Were Rejected
1. **Approach 1 Rejected**: Ocean drift is governed by Ekman spiral dynamics, Stokes drift, and windage [RESEARCHED]. Linear back-projection along wind vector alone fails in presence of strong ocean currents (e.g., Monsoon currents in the Arabian Sea / Bay of Bengal), leading to attribution errors up to tens of kilometers [INFERENCE].
2. **Approach 2 Rejected**: Deterministic single-particle models ignore turbulent diffusion and oil weathering processes [RESEARCHED]. Without Monte Carlo particle ensembles, the system produces a single point origin rather than a realistic probabilistic origin area, leading to misidentification or missing dark ships operating nearby [INFERENCE].

### Detailed Data-Flow Narrative
1. **Ingestion & Preprocessing**: Sentinel-1 SAR GRD files (or Zenodo patches) are uploaded/ingested. Preprocessing applies speckle filtering (Refined Lee filter), radiometric calibration to backscatter $\sigma^0$ (dB), and terrain correction [RESEARCHED].
2. **Slick Segmentation & Characterization**: The preprocessed SAR raster is passed through the Swin-UNet model. Slicks are segmented, converted to GeoJSON polygons, and geometrical features (area, perimeter, centroid, length) are extracted [INFERENCE].
3. **Met-Ocean Forcing Fetch**: The backend automatically queries the spatial-temporal bounding box of the slick against CMEMS (ocean currents) and ERA5 (10m wind $u, v$ components, wave height) NetCDF files [RESEARCHED].
4. **Lagrangian Backward Drift Simulation**: **OpenOil** initializes 5,000 particles across the slick polygon [RESEARCHED]. The simulation runs backwards in time ($-\Delta t$) incorporating advection, windage, and turbulent diffusion [RESEARCHED]. Physical weathering calculations estimate the slick age $t_{age}$, defining the origin time window $T_{origin} = [t_{detection} - t_{age} - \delta, t_{detection} - t_{age} + \delta]$ [INFERENCE].
5. **Origin Kernel Density Estimation (KDE)**: The spatial distribution of back-tracked particles at $t_{age}$ generates a 2D probability density map identifying the high-confidence origin zone $Z_{origin}$ [INFERENCE].
6. **AIS Reconstruction & Filtering**: PostGIS queries historical AIS records within $Z_{origin}$ during $T_{origin}$. Ships outside the spatial envelope or time window are discarded ($>95\%$ filtering efficiency) [INFERENCE].
7. **Trajectory Interpolation & Suspect Scoring**: Continuous trajectories are interpolated for candidate ships. The scoring engine calculates proximity score, trajectory heading alignment with slick drift vector, speed drops (indicating discharge operations), and AIS transmission gaps ("dark ship" indicator) [INFERENCE].
8. **Visualization & Dossier Generation**: Ranked suspect vessels are pushed via WebSockets to the MapLibre frontend UI, allowing analysts to visually step through the drift simulation timeline and export legal evidence dossiers [INFERENCE].

# 13. AI/ML Justification

### Deep Learning SAR Oil Slick Segmentation Model

1. **Exact Problem AI Solves**: Automated extraction of oil slick boundaries from high-resolution C-band Synthetic Aperture Radar (SAR) imagery while discriminating true mineral oil from marine look-alikes (low wind areas, biogenic films, internal waves) [RESEARCHED].
2. **Input**: Preprocessed 2-channel SAR image patches ($\sigma^0$ VV polarization, VH polarization, or VV/VH ratio) [RESEARCHED].
3. **Output**: Binary/Multiclass segmentation mask ($256 \times 256$ or $512 \times 512$) representing probability of oil slick pixels vs background/look-alike pixels.
4. **Why Simpler Rule/System Cannot Solve**: Simple intensity thresholding (e.g., Otsu) fails because dark SAR patches caused by low wind ($<3 m/s$) or natural slicks have identical backscatter decibel values as oil [RESEARCHED]. AI captures spatial context, shape geometry, texture, and edge gradients [RESEARCHED].
5. **Data Required**: Zenodo Sentinel-1 SAR Oil Spill Dataset (3,225 oil objects across 1,365 patches + 2,290 look-alike patches) [PS, RESEARCHED].
6. **Evaluation Metrics**: Mean Intersection over Union (mIoU), F1-Score / Dice Coefficient, and False Positive Rate on look-alike test sets [RESEARCHED].
7. **What Happens When Wrong**:
   - *False Positive*: System initiates hindcast for a non-existent spill (waste of compute time, flagged by analyst during manual review) [INFERENCE].
   - *False Negative*: Real oil spill missed by automated scan (mitigated by setting lower detection threshold for operator review) [INFERENCE].
8. **Training Required**: Yes, supervised training on labeled SAR datasets [RESEARCHED].
9. **Fine-tuning Required**: Yes, fine-tuning pretrained Swin-Transformer / ResNet backbones on Sentinel-1 C-band imagery [RESEARCHED].
10. **RAG Required**: No.
11. **Computer Vision Required**: Yes (2D Convolutional / Transformer Semantic Segmentation) [RESEARCHED].
12. **Speech Processing Required**: No.
13. **Forecasting Required**: No (Predictive physical forecasting handled by OpenOil physics engine, not ML) [RESEARCHED].
14. **Human Oversight Required**: Yes. All AI detections must present confidence scores to NTRO operators before dispatching legal alerts [INFERENCE].

### Explicit Non-AI Components
- **Physical Drift Hindcasting & Forecasting**: Uses deterministic physical equations of motion (Eulerian-Lagrangian particle advection: $\frac{dx}{dt} = \vec{u}_{current} + \alpha \vec{u}_{wind} + \vec{u}_{stokes}$) and empirical weathering equations (evaporation, emulsification) inside **OpenOil** [RESEARCHED]. AI is **NOT** used for fluid dynamics or drift trajectory generation because physical conservation laws guarantee higher reliability and legal defensibility [INFERENCE].
- **Spatio-Temporal Filtering**: Handled using pure spatial SQL PostGIS queries (`ST_DWithin`, `ST_Intersects`) [RESEARCHED].

# 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostGIS)

```sql
-- 1. SAR Imagery Metadata
CREATE TABLE sar_imagery (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    granule_name VARCHAR(255) NOT NULL,
    acquisition_time TIMESTAMP WITH TIME ZONE NOT NULL,
    satellite_id VARCHAR(50) DEFAULT 'SENTINEL-1A',
    footprint GEOMETRY(Polygon, 4326) NOT NULL,
    storage_path VARCHAR(512) NOT NULL
);
CREATE INDEX idx_sar_footprint ON sar_imagery USING GIST(footprint);

-- 2. Detected Oil Slicks
CREATE TABLE oil_slicks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sar_id UUID REFERENCES sar_imagery(id),
    detection_time TIMESTAMP WITH TIME ZONE NOT NULL,
    confidence_score FLOAT NOT NULL,
    slick_area_km2 FLOAT NOT NULL,
    slick_geometry GEOMETRY(Polygon, 4326) NOT NULL,
    estimated_age_hours FLOAT,
    status VARCHAR(50) DEFAULT 'UNVERIFIED'
);
CREATE INDEX idx_slicks_geom ON oil_slicks USING GIST(slick_geometry);

-- 3. AIS Broadcast Points
CREATE TABLE ais_broadcasts (
    id BIGSERIAL PRIMARY KEY,
    mmsi INT NOT NULL,
    base_date_time TIMESTAMP WITH TIME ZONE NOT NULL,
    lat DOUBLE PRECISION NOT NULL,
    lon DOUBLE PRECISION NOT NULL,
    location GEOMETRY(Point, 4326) NOT NULL,
    sog FLOAT, -- Speed over ground (knots)
    cog FLOAT, -- Course over ground (degrees)
    heading FLOAT,
    vessel_name VARCHAR(100),
    imo INT,
    vessel_type INT,
    draft FLOAT
);
CREATE INDEX idx_ais_mmsi_time ON ais_broadcasts(mmsi, base_date_time);
CREATE INDEX idx_ais_location ON ais_broadcasts USING GIST(location);

-- 4. Reconstructed Vessel Trajectories
CREATE TABLE vessel_trajectories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    mmsi INT NOT NULL,
    start_time TIMESTAMP WITH TIME ZONE NOT NULL,
    end_time TIMESTAMP WITH TIME ZONE NOT NULL,
    trajectory GEOMETRY(LineString, 4326) NOT NULL
);
CREATE INDEX idx_traj_geom ON vessel_trajectories USING GIST(trajectory);

-- 5. Suspect Scoring Results
CREATE TABLE suspect_scores (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slick_id UUID REFERENCES oil_slicks(id),
    mmsi INT NOT NULL,
    suspect_rank INT NOT NULL,
    composite_score FLOAT NOT NULL,
    proximity_score FLOAT,
    trajectory_score FLOAT,
    speed_anomaly_score FLOAT,
    dark_gap_score FLOAT,
    draft_anomaly_score FLOAT,
    computed_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### Offline & Low-Network Operations
- **Local Tiling & Caching**: Pre-render base maps as Vector Tiles (`.pbf`) stored locally on the server using MBTiles, removing reliance on external Mapbox/OSM tile APIs [INFERENCE].
- **Client-Side Persistence**: Frontend uses IndexedDB (`PouchDB` / `Dexie.js`) to store active incident analysis states locally [INFERENCE].
- **Bandwidth Reduction**: AIS trajectories sent to the browser are compressed using GeoJSON simplification algorithms (Ramer-Douglas-Peucker) and binary Protocol Buffers (`Protobuf`) [INFERENCE].
- **Synchronization**: Sync engine maintains a local outgoing queue for user annotations and status updates, flushing to the primary PostgreSQL database upon network re-establishment [INFERENCE].
