# SIH 2026 Problem Statement Dossier: AI-Based Early Warning and Landslide Risk Monitoring System in NER

---

## 1. Executive Snapshot

The North Eastern Region (NER) of India is geologically fragile and experiences severe rainfall-triggered landslides, slope failures, and road blockages during monsoons, leading to loss of life, infrastructure damage, and multi-day isolation of remote villages [PS, KNOWN]. Current monitoring relies heavily on manual, reactive post-disaster reporting with minimal predictive early warning capabilities [PS]. The proposed solution is **ResiLand-NER**, an integrated, cloud-native AI/ML geospatial platform coupled with an offline-first mobile crowdsourcing application [INFERENCE, ASSUMPTION]. ResiLand-NER ingests multi-source data including IMD weather feeds, Copernicus Sentinel SAR satellite deformation indices, CARTO-DEM terrain slope parameters, and crowdsourced field photos to calculate dynamic spatial risk heatmaps [INFERENCE]. It delivers real-time Common Alerting Protocol (CAP 1.2) compliant SMS/app alerts in regional NER languages and provides disaster authorities with road connectivity and emergency response prioritization dashboards [INFERENCE].

## 5. Constraints & Environment Realities

### Operational Constraints in North Eastern Region (NER)

1. **Cellular Connectivity & Latency:** Remote hilly districts along international borders (e.g., Arunachal Pradesh, Nagaland, Mizoram) suffer from frequent 2G/3G degradation or complete signal loss during severe monsoon storms [RESEARCHED, KNOWN]. *Implication:* The field reporting mobile application must be strictly offline-first. Mobile alerts must fall back to basic SMS protocols when data connection drops [INFERENCE].
2. **Power Grid Vulnerability:** Monsoon downpours and slope failures frequently knock out electrical transformers in rural hill blocks for days [KNOWN]. *Implication:* Edge mobile clients must optimize battery power; cloud servers must reside in reliable multi-region infrastructure outside the immediate disaster zone [INFERENCE].
3. **Geological & Terrain Complexity:** Young, highly weathered, steep Himalayan and Indo-Burmese flysch formations exhibit extreme spatial variability in slope stability [RESEARCHED]. *Implication:* Micro-zonation requires high-resolution DEMs (30m CARTO-DEM/Copernicus DEM) rather than coarse regional grids [RESEARCHED, INFERENCE].
4. **Linguistic Diversity:** The 8 states of NER host dozens of major languages and local dialects [KNOWN]. *Implication:* Alert engines cannot rely solely on English or Hindi; key local languages (Assamese, Bengali, Manipuri, Khasi, Garo, Mizo) must be natively supported [PS, INFERENCE].
5. **Digital Literacy & Device Constraints:** Rural citizens and field workers frequently use lower-tier Android smartphones with restricted storage and processing memory [INFERENCE, ASSUMPTION]. *Implication:* Mobile application must be lightweight (<5MB storage footprint), packaged as a Progressive Web App (PWA), and avoid heavy client-side ML computation [INFERENCE].

## 8. Existing Solutions & Gap Analysis

### 1. Geological Survey of India (GSI) LEWS & Bhooskhalan App
* **Description:** GSI operationalized prototype Landslide Early Warning Systems (LEWS) under the LANDSLIP project for selected regions (Darjeeling, Nilgiris, Kalimpong) and launched the 'Bhooskhalan' mobile app and 'Bhusanket' portal [RESEARCHED].
* **Strengths:** Grounded in terrain-specific empirical rainfall thresholds (I-D curves) and official geological mapping authority [RESEARCHED].
* **Weaknesses:** Primarily relies on rainfall threshold triggers alone; lacks real-time multi-modal fusion of spaceborne InSAR ground displacement, dynamic soil moisture, and crowdsourced photo telemetry [RESEARCHED, INFERENCE].
* **Relevance:** Serves as the official benchmark for rainfall-induced landslide forecasting in India [RESEARCHED].
* **Gap Remaining:** Slow rollout in remote NER states; limited integration with road-network routing engines and crowdsourced citizen incident verification [INFERENCE].
* **Source:** PIB Press Release (Dec 2021); Times of India (July 2024) [RESEARCHED]. Confidence: `[RESEARCHED]`.

### 2. ISRO Bhuvan Landslide Portal & Landslide Atlas of India
* **Description:** Geoportal hosted by NRSC/ISRO providing historical landslide inventories (~80,933 mapped landslides from 1998–2022) and static Landslide Hazard Zonation (LHZ) maps [RESEARCHED].
* **Strengths:** Comprehensive historical spatial database; high credibility and satellite remote sensing coverage across NER (Mizoram, Nagaland, Arunachal Pradesh) [RESEARCHED].
* **Weaknesses:** Static historical repository and periodic map viewer; lacks real-time weather-driven dynamic risk prediction, automated alert broadcasting, and multi-lingual public push notifications [RESEARCHED, INFERENCE].
* **Relevance:** Essential source for historical landslide target labels and terrain baseline layers [RESEARCHED, INFERENCE].
* **Gap Remaining:** Does not provide real-time dynamic risk updates or two-way offline field reporting tools [INFERENCE].
* **Source:** ISRO Landslide Atlas of India (March 2023) [RESEARCHED]. Confidence: `[RESEARCHED]`.

### 3. NESAC FLEWS & NERDRR Portal
* **Description:** North Eastern Space Applications Centre (NESAC) operates the Flood Early Warning System (FLEWS) and North East Regional Data Repository & Resource (NERDRR) portal [RESEARCHED].
* **Strengths:** Specifically tailored for North Eastern geography, incorporating regional hydrological models and GIS overlays [RESEARCHED].
* **Weaknesses:** FLEWS is heavily optimized for riverine flash floods in Assam plains rather than slope failure dynamics along hill roads [RESEARCHED, INFERENCE].
* **Relevance:** Proves feasibility of geospatial decision systems in NER [RESEARCHED].
* **Gap Remaining:** Lack of a dedicated, localized landslide ML engine coupled with automated CAP SMS alerts for remote hill habitations [INFERENCE].
* **Source:** ResearchGate NESAC FLEWS Publication (2026); NERDRR Portal [RESEARCHED]. Confidence: `[RESEARCHED]`.

## 10. Recommended Approach & Why

### Recommended Selection: Approach 2 (Machine Learning & Geospatial Fusion Framework)

**Justification:** Approach 2 strikes the optimal balance between predictive accuracy, system explainability, hackathon buildability, and real-world operational reliability in NER [INFERENCE]. It combines supervised machine learning (XGBoost / Random Forest) trained on static geological/terrain factors with dynamic hydrometeorological inputs (antecedent rainfall index, soil water content) and satellite SAR change detection indices [INFERENCE].

#### Why Alternatives Were Rejected:
* **Rejection of Approach 1 (Static Threshold Engine):** While extremely easy to build, rule-based I-D rainfall thresholds trigger frequent false alarms across vast districts whenever monsoon rains hit, leading to "alert fatigue" among local citizens and district officials [INFERENCE]. It completely ignores pre-existing soil saturation, slope inclination, vegetation cover, and ground deformation history [INFERENCE].
* **Rejection of Approach 3 (Deep CNN-LSTM Network):** Deep spatiotemporal neural networks require massive, continuous, gap-free training datasets and dense ground sensor networks (IoT tiltmeters/piezometers) that do not exist across the vast, rugged terrain of NER [PS, RESEARCHED]. Furthermore, black-box deep learning models are difficult to audit when district officials require transparent justification before ordering costly village evacuations or highway closures [INFERENCE].

### Step-by-Step Data-Flow Narrative

1. **Data Ingestion (ETL):** Background Celery workers execute every 3 hours to fetch real-time rainfall data from IMD/Open-Meteo APIs, volumetric soil moisture rasters from ERA5/GEE, and 24-72 hour Quantitative Precipitation Forecasts (QPF) [INFERENCE].
2. **Feature Matrix Construction:** Spatial processing workers overlay dynamic rainfall data onto static 30m grid tiles pre-populated with slope, elevation, aspect, land-use/land-cover (LULC), distance to faults, and distance to roads [INFERENCE].
3. **ML Risk Inference:** The XGBoost microservice ingests the 30m cell feature matrix, computing probability scores ($0.0 - 1.0$). If the 3-day Antecedent Rainfall Index (ARI) exceeds critical geological thresholds, risk scores are scaled upward [INFERENCE].
4. **GIS Heatmap & Routing Execution:** Probability scores are converted into a spatial GeoJSON grid layer stored in PostGIS. The routing engine (pgRouting) intersects high-risk polygons ($Score > 0.75$) with OSM road network vectors to automatically tag affected road segments as "High Failure Risk" or "Blocked" [INFERENCE].
5. **Crowdsourced Field Validation:** Field workers/citizens upload photos of road cracks via the offline PWA. On reconnecting, the photo, GPS coordinates, and EXIF timestamp sync to the server. A YOLOv8 microservice verifies if the photo contains structural slope cracks or road debris [INFERENCE].
6. **Alert Generation & Dissemination:** When grid cells covering inhabited villages or critical road arteries cross the "High" or "Extreme" risk threshold, the Alert Gateway auto-generates an OASIS CAP 1.2 XML payload. It dispatches geo-targeted SMS messages via telecom API and pushes FCM app notifications in the localized language of that district [RESEARCHED, INFERENCE].

## 13. AI/ML Justification

### AI Component 1: Dynamic Landslide Susceptibility Model (XGBoost)
* **Exact Problem Solved:** Predicts probability ($0.0 - 1.0$) of rainfall-triggered landslide occurrence for spatial 30m grid cells across NER districts [INFERENCE].
* **Input Features:** Elevation, Slope, Aspect, Curvature, Distance to Faults, Distance to Roads, LULC type, 24h Rainfall, 72h Antecedent Rainfall Index (ARI), Volumetric Soil Moisture [INFERENCE].
* **Output:** Pixel-level hazard classification score (Low, Moderate, High, Extreme) [INFERENCE].
* **Why AI is Necessary:** Non-linear interactions between terrain slope, geological rock type, and dynamic soil moisture saturation cannot be captured by static linear rule thresholds without massive false positives [INFERENCE].
* **Evaluation Metrics:** ROC-AUC ($\ge 0.90$), Precision-Recall curve, Confusion Matrix [INFERENCE].
* **Failure Mode & Safeguard:** If rainfall data feed fails, model falls back to static Landslide Hazard Zonation (LHZ) base risk. Human oversight: DDMAs must confirm "Extreme" level evacuation alerts before triggering public sirens [INFERENCE].

### AI Component 2: Crowdsourced Image Verification Model (YOLOv8 Small)
* **Exact Problem Solved:** Automatically scans uploaded citizen photos to detect presence of road cracks, debris slides, or blocked highways [INFERENCE].
* **Input:** Field uploaded JPEG images ($640 \times 640$ pixels) [INFERENCE].
* **Output:** Bounding boxes with labels (`slope_crack`, `road_debris`, `flooded_road`) and confidence score [INFERENCE].
* **Why AI is Necessary:** Prevents spam and irrelevant uploads (e.g., selfies, random objects) from cluttering district emergency dashboard queues [INFERENCE].
* **Evaluation Metrics:** mean Average Precision (mAP50 $\ge 0.82$) [INFERENCE].
* **Failure Mode & Safeguard:** Images with confidence $<0.50$ are flagged for manual human verification by PWD/district admins [INFERENCE].

### Explicit Non-AI Decision:
* **Where AI MUST NOT be used:** Emergency evacuation routing and final disaster severity declaration. Route calculation must use deterministic spatial algorithms (`pgRouting` Dijkstra / A*) based on strict physical road blockages rather than probabilistic AI models to guarantee route safety [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL + PostGIS)

```sql
-- 1. Spatial Grid Tiles (30m x 30m Resolution)
CREATE TABLE spatial_grid_tiles (
    tile_id BIGSERIAL PRIMARY KEY,
    district_name VARCHAR(100) NOT NULL,
    state_name VARCHAR(100) NOT NULL,
    geom GEOMETRY(Polygon, 4326) NOT NULL,
    slope_deg FLOAT NOT NULL,
    elevation_m FLOAT NOT NULL,
    aspect_deg FLOAT NOT NULL,
    lulc_class VARCHAR(50),
    dist_to_road_m FLOAT,
    dist_to_fault_m FLOAT,
    static_lhz_score FLOAT NOT NULL
);
CREATE INDEX idx_spatial_grid_geom ON spatial_grid_tiles USING GIST(geom);

-- 2. Dynamic Weather Telemetry
CREATE TABLE weather_telemetry (
    telemetry_id BIGSERIAL PRIMARY KEY,
    station_id VARCHAR(50) NOT NULL,
    recorded_at TIMESTAMP WITH TIME ZONE NOT NULL,
    rainfall_1h_mm FLOAT DEFAULT 0.0,
    rainfall_24h_mm FLOAT DEFAULT 0.0,
    soil_moisture_percentage FLOAT,
    geom GEOMETRY(Point, 4326) NOT NULL
);

-- 3. Dynamic Hazard Risk Inferences
CREATE TABLE hazard_risk_inferences (
    inference_id BIGSERIAL PRIMARY KEY,
    tile_id BIGINT REFERENCES spatial_grid_tiles(tile_id),
    calculated_at TIMESTAMP WITH TIME ZONE NOT NULL,
    ari_3day_mm FLOAT NOT NULL,
    risk_score FLOAT NOT NULL, -- 0.00 to 1.00
    risk_level VARCHAR(20) NOT NULL -- LOW, MODERATE, HIGH, EXTREME
);

-- 4. Crowdsourced Field Incidents
CREATE TABLE field_incidents (
    incident_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    reporter_name VARCHAR(100),
    reporter_phone VARCHAR(20),
    incident_type VARCHAR(50) NOT NULL, -- CRACK, BLOCKAGE, SLOPE_FAILURE
    description TEXT,
    photo_url VARCHAR(255),
    ai_verified BOOLEAN DEFAULT FALSE,
    ai_confidence FLOAT,
    status VARCHAR(30) DEFAULT 'PENDING', -- PENDING, VERIFIED, CLEARED
    geom GEOMETRY(Point, 4326) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL,
    synced_at TIMESTAMP WITH TIME ZONE
);
```
