# Real-time Airfare Price Index (APIx) Dossier for CPI Augmentation

## 1. Executive Snapshot

### Summary
The Ministry of Statistics and Programme Implementation (MoSPI) and the National Statistical Office (NSO) currently calculate the 'Transport and Communication' sub-group of India's Consumer Price Index (CPI) using manual price collection from offline travel agencies and physical ticketing counters [PS]. However, over 90% of domestic air tickets in India are now purchased online through airline websites (such as IndiGo, Air India, Air India Express, Akasa Air, and SpiceJet) and Online Travel Aggregators (OTAs) [PS]. Airfares in India are dynamically priced and can fluctuate by 200% to 400% within a single day based on factors such as advance booking window (T+1 to T+45 days), day of week, seasonal demand, and fuel surcharges [PS]. Manual collection fails to capture this real-time dynamic pricing, creating a significant structural lag in national retail inflation measurements used by the Reserve Bank of India (RBI) for monetary policy decisions [PS]. 

To solve this, we propose the **Real-time Airfare Price Index System (APIx)**—an enterprise-grade, automated data pipeline and analytics dashboard. The platform features an ethical, multi-source web scraping engine built with Python Playwright and Scrapy that respects web compliance (`robots.txt`, rate limits) while navigating dynamic CAPTCHAs and anti-bot measures [PS, INFERENCE]. It ingests price quotes across top DGCA-weighted city-pair routes (e.g., DEL-BOM, DEL-BLR, BOM-BLR) across multiple advance-purchase windows [PS]. An automated cleaning pipeline isolates base fares from taxes, User Development Fees (UDF), and convenience charges, eliminating outliers and sold-out anomalies [PS]. The system calculates elementary indices using Jevons geometric means and aggregates them using a Laspeyres passenger-traffic weighted index derived from DGCA statistics [RESEARCHED, INFERENCE]. The platform provides real-time REST APIs for MoSPI and RBI consumption, visualizes price trends and elasticity curves, and includes a 30-day historical backtesting engine against official DGCA average fare data [PS].

## 6. Research Questions

To ensure technical feasibility, five critical research questions were identified and investigated:

1. **How do Indian airline and OTA portals implement dynamic pricing and unbundled fare breakdowns?**
   * *Finding:* Indian carriers follow dynamic yield management where base fare rises exponentially as seat capacity depletes [KNOWN]. Taxes comprise CGST/SGST ($5\%$ on economy, $12\%$ on premium), User Development Fee (UDF, set by AERA per airport), Aviation Security Fee (ASF), and OTA convenience fees ($\approx \text{₹}300-\text{₹}400$ per passenger) [RESEARCHED]. The CPI index requires tracking base fare + obligatory statutory taxes while stripping optional fees (seat selection, meals) and OTA convenience fees [INFERENCE].
2. **What are the top domestic city-pairs by DGCA passenger volume?**
   * *Finding:* DGCA annual and monthly traffic statistics confirm the top domestic routes by passenger volume are: DEL-BOM (Delhi-Mumbai), DEL-BLR (Delhi-Bengaluru), BOM-BLR (Mumbai-Bengaluru), DEL-CCU (Delhi-Kolkata), BLR-HYD (Bengaluru-Hyderabad), and MAA-DEL (Chennai-Delhi) [PS, RESEARCHED]. These six routes represent over $35\%$ of total Indian domestic passenger traffic [RESEARCHED].
3. **What statistical index formula is recommended by international standards (IMF/ILO CPI Manual) for web-scraped price quotes?**
   * *Finding:* For elementary aggregates (unweighted quotes within a single route and advance window), the **Jevons Index** (unweighted geometric mean of price ratios) is standard, as it eliminates elementary substitution bias [RESEARCHED]. For higher-level aggregation across routes, a **Laspeyres Index** using base-period DGCA Passenger Statistics Data (PSD) traffic weights is utilized [RESEARCHED].
4. **How do major airlines (IndiGo, Air India) and OTAs (MakeMyTrip, EaseMyTrip) protect against web scraping?**
   * *Finding:* Portals use Akamai Bot Manager, Cloudflare Turnstile, and DataDome [KNOWN]. Simple HTTP `requests` fail due to JavaScript rendering and TLS fingerprinting [KNOWN]. Evasion requires Playwright with `--disable-blink-features=AutomationControlled`, rotating residential proxies, randomized request intervals, and Playwright-Stealth browser context patches [RESEARCHED].
5. **How can a 30-day backtest against DGCA average fare data be conducted?**
   * *Finding:* DGCA publishes monthly domestic air transport statistics including total passengers and carrier traffic, while the MoCA/DGCA Tariff Monitoring Unit tracks monthly average fares across 72 domestic sectors [RESEARCHED]. The team can aggregate daily scraped APIx values into a monthly geometric mean and evaluate correlation ($R^2 \ge 0.85$, MAPE $\le 5\%$) against DGCA published sector averages [INFERENCE].

## 10. Recommended Approach & Why

### Selection: Approach 2 (Multi-Tier Hybrid Ingestion Engine)
We recommend **Approach 2: Multi-Tier Hybrid Ingestion Engine** as the winning architecture for the hackathon team [INFERENCE].

### Justification & Rejection of Alternatives

1. **Why Approach 2 Wins:**
   Approach 2 leverages rapid network XHR/JSON response interception (reverse-engineered internal search endpoints used by React/Vue frontends of OTAs like EaseMyTrip, Yatra, and Ixigo) as the primary ingestion method [INFERENCE]. This allows fetching search results in under $2$ seconds per route window without rendering heavy JavaScript images and CSS [INFERENCE]. When an airline portal (such as IndiGo or Air India) employs heavy anti-bot protections or obfuscated payload tokens, the system seamlessly falls back to a **Playwright-Stealth headless browser collector** that renders the complete page and extracts DOM price elements [INFERENCE]. This dual strategy delivers high speed, minimal proxy bandwidth consumption, and complete extraction reliability [INFERENCE].

2. **Why Alternatives Were Rejected:**
   * **Approach 1 (Pure Direct Playwright Headless Scraping) Rejection:** Relying *exclusively* on full headless browser rendering for all 3,600 daily target queries ($6 \text{ carriers/OTAs} \times 12 \text{ routes} \times 5 \text{ windows} \times 10 \text{ runs}$) requires substantial RAM ($>16 \text{ GB}$) and high proxy bandwidth, making it unnecessarily slow and prone to timing timeouts during a live hackathon demonstration [INFERENCE].
   * **Approach 3 (Distributed Serverless Cloud Swarm) Rejection:** AWS Lambda / GCP Cloud Run serverless Chromium containers suffer from significant cold-start delays ($5-10 \text{ seconds}$), large container image sizes ($>500 \text{ MB}$ due to Chromium dependencies), and complex session state management [INFERENCE]. Anti-bot platforms like Cloudflare frequently flag ephemeral serverless IP ranges, causing high failure rates without expensive static residential proxy tunnels [RESEARCHED, INFERENCE].

### Detailed Data-Flow Narrative

1. **Query Generation Trigger:** Every night at 00:01 AM, the Celery Scheduler calculates target dates for every monitored route ($6 \text{ core routes}$) across 5 advance booking windows ($T+1, T+7, T+15, T+30, T+45$) [INFERENCE]. This generates $30$ search parameter tuples per carrier/OTA [INFERENCE].
2. **Ingestion & Extraction:** The Celery workers pull jobs from Redis. Workers attempt fast async XHR JSON requests using `httpx` with randomized headers [INFERENCE]. If a target portal returns a 403 Forbidden, Cloudflare challenge, or dynamic JS wall, the task escalates to a `Playwright-Stealth` browser context with proxy rotation [INFERENCE].
3. **Raw Quote Storage:** Scraped raw payloads (HTML/JSON) are saved in the `raw_fare_quotes` table with scrape timestamps, status codes, and execution duration [INFERENCE].
4. **ETL Cleaning & Unbundling:** The processing worker extracts fare components using regex and JSON selectors [INFERENCE]. It isolates Base Fare, Taxes (GST), Airport Fees (UDF/ASF), and strips optional ancillary fees (meals, seat selection, convenience fees) [PS, INFERENCE]. It applies an IQR statistical filter to drop corrupt zero-fares or erroneous surge spikes ($>500\%$ deviation) [PS, INFERENCE].
5. **Elementary Index Calculation:** For each route $r$ and advance window $w$, the system computes the geometric mean of price ratios across carriers using the **Jevons Index formula** [RESEARCHED, INFERENCE].
6. **Higher-Level Aggregation:** The APIx engine combines elementary route indices into the headline **Real-time Airfare Price Index (APIx)** using base-period DGCA passenger traffic weights $W_r$ via a **Laspeyres Index formula** [PS, RESEARCHED, INFERENCE].
7. **API & Dashboard Delivery:** Cleaned indices are pushed to PostgreSQL and cached in Redis. The FastAPI service exposes JWT-authenticated endpoints for NSO/RBI systems, while the Next.js web application renders interactive elasticity graphs, heatmaps, and backtest comparison overlays [PS, INFERENCE].

```sql
-- Core Schema Definition for APIx System

CREATE TABLE city_pairs (
    route_id SERIAL PRIMARY KEY,
    origin_code VARCHAR(3) NOT NULL, -- e.g. DEL
    destination_code VARCHAR(3) NOT NULL, -- e.g. BOM
    dgca_psd_weight NUMERIC(6,4) NOT NULL, -- e.g. 0.1850 for DEL-BOM
    is_active BOOLEAN DEFAULT TRUE
);

CREATE TABLE carriers (
    carrier_id SERIAL PRIMARY KEY,
    carrier_name VARCHAR(50) NOT NULL, -- e.g. IndiGo, Air India
    code VARCHAR(10) UNIQUE NOT NULL,
    is_ota BOOLEAN DEFAULT FALSE
);

CREATE TABLE raw_fare_quotes (
    quote_id BIGSERIAL PRIMARY KEY,
    carrier_id INT REFERENCES carriers(carrier_id),
    route_id INT REFERENCES city_pairs(route_id),
    advance_window_days INT NOT NULL, -- 1, 7, 15, 30, 45
    flight_date DATE NOT NULL,
    scrape_timestamp TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    raw_payload JSONB NOT NULL,
    http_status_code INT NOT NULL
);

CREATE TABLE cleaned_fare_quotes (
    cleaned_id BIGSERIAL PRIMARY KEY,
    quote_id BIGINT REFERENCES raw_fare_quotes(quote_id),
    route_id INT REFERENCES city_pairs(route_id),
    carrier_id INT REFERENCES carriers(carrier_id),
    advance_window_days INT NOT NULL,
    flight_date DATE NOT NULL,
    base_fare NUMERIC(10,2) NOT NULL,
    taxes_and_gst NUMERIC(10,2) NOT NULL,
    user_development_fee NUMERIC(10,2) NOT NULL,
    convenience_fee NUMERIC(10,2) DEFAULT 0.00,
    total_effective_fare NUMERIC(10,2) NOT NULL,
    is_outlier BOOLEAN DEFAULT FALSE
);

CREATE TABLE daily_index_values (
    index_id SERIAL PRIMARY KEY,
    calculation_date DATE UNIQUE NOT NULL,
    apix_headline_value NUMERIC(8,4) NOT NULL, -- e.g. 104.5200
    weekly_moving_avg NUMERIC(8,4),
    monthly_moving_avg NUMERIC(8,4),
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```
