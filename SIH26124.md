# SIH Problem Analysis & Solution Architecture Dossier

## 1. Executive Snapshot

### Summary
Public transport buses traverse almost every major urban roadway daily, offering an ideal mobile platform for city-wide sensing [PS]. Modern buses carry cameras covering the front, rear, sides, and passenger cabin, but these cameras currently act as passive incident recorders rather than intelligent sensing networks [PS]. Meanwhile, municipal authorities rely on static CCTV, periodic manual road inspections, and reactive citizen complaints, leading to delayed repairs, incomplete situational awareness, and inefficient traffic management [PS]. This dossier presents an **AI-Powered Mobile Urban Intelligence Platform** that equips public transit fleets with edge-AI inference units to analyze multi-camera video streams in real time [PS, INFERENCE]. The onboard edge unit detects road defects (potholes, damaged pavement, missing dividers, missing zebra crossings, damaged traffic signs, waterlogging), measures traffic density, identifies bottlenecks, detects vulnerable pedestrians, and tracks hit-and-run or rash driving incidents with Automatic Number Plate Recognition (ANPR), timestamping, and GPS tagging [PS]. Critical alerts and compressed metadata are transmitted via low-bandwidth cellular MQTT to a centralized Geographic Information System (GIS) command dashboard deployed within Bharat Electronics Limited’s (BEL) Smart City Integrated Command and Control Centre (ICCC) architecture [PS, RESEARCHED].

## 10. Recommended Approach & Why

### Selection
**Approach 3: Hybrid Edge-AI Framework with Real-Time Event Telemetry & Depot Sync** [PS, INFERENCE].

### Why Alternatives Were Rejected
1. **Approach 1 (Full-Cloud Streaming)** was rejected because streaming continuous 1080p multi-camera video over 4G/5G from hundreds of moving buses is cost-prohibitive, unreliable in dead zones, and violates the explicit requirement to *"minimize bandwidth through intelligent edge processing"* [PS, INFERENCE].
2. **Approach 2 (Pure Offline Depot Store-and-Forward)** was rejected because delaying alert transmission until depot docking violates the requirement to *"securely share alerts with a central command system"* during critical incidents like hit-and-run, rash driving, or immediate pedestrian hazards [PS, INFERENCE].

### Why Approach 3 Wins
Approach 3 executes all heavy computer vision processing (defect detection, traffic counting, school zone monitoring, ANPR) on the onboard edge processor [PS, INFERENCE]. When a defect or incident is detected, it package-encodes a micro-payload (JSON containing event type, GPS coordinates, timestamp, confidence score, and compressed 50 KB keyframe) and transmits it instantaneously over MQTT via 4G [INFERENCE]. Heavy video recordings are stored in a rolling 48-hour onboard NVMe buffer and automatically dumped to city depot servers over high-speed Wi-Fi 6 when docking, providing the perfect balance between instant situational awareness and low operational expense [INFERENCE].

### Detailed Data Flow Narrative
1. **Video & GPS Acquisition**: Front, side, and rear IP cameras stream video via RTSP over an onboard Ethernet switch to the NVIDIA Jetson edge processor at 1080p, 25 FPS [INFERENCE]. Simultaneously, an onboard GPS module feeds continuous NMEA location data over serial/USB at 1 Hz [INFERENCE].
2. **Edge Inference Pipeline**: The video ingestion pipeline decodes frames into GPU memory via GStreamer/DeepStream [INFERENCE]. TensorRT-optimized deep learning neural networks analyze the frames:
   - **Road Hazard Model**: Scans road surface for potholes, cracks, missing dividers, missing zebra crossings, damaged signboards, and waterlogging [PS, INFERENCE].
   - **Vehicle Density Engine**: Detects, tracks, and counts passing vehicles across virtual lanes, calculating lane occupancy rates [PS, INFERENCE].
   - **Pedestrian Safety Model**: Flags pedestrians, specifically children in proximity to roadways or unmarked crossing zones [PS, INFERENCE].
   - **ANPR Incident Module**: Continuously monitors vehicle motion trajectories; if a collision or erratic high-speed maneuver (rash driving) is detected, the license plate area of the offending vehicle is cropped, processed via PaddleOCR, and assigned a confidence score [PS, INFERENCE].
3. **Telemetry Packaging & MQTT Dispatch**: When a defect or incident condition exceeds a threshold (e.g., pothole confidence > 0.70 or incident alert), the edge unit binds the GPS coordinate, timestamp, bus ID, event category, and confidence score into a lightweight JSON packet [INFERENCE]. It attaches a compressed JPEG keyframe (50 KB) and transmits it over an encrypted MQTT connection via a 4G modem [INFERENCE].
4. **Ingestion & Spatial Clustering**: The central EMQX broker routes incoming MQTT packets to the FastAPI backend [INFERENCE]. The spatial clustering module maps incoming coordinates onto an Uber H3 spatial index [INFERENCE]. If multiple buses flag the same defect within a 5-meter radius over multiple days, the system aggregates them into a single high-confidence maintenance ticket, increasing its severity score [INFERENCE].
5. **GIS Visualization & Command Action**: The central command dashboard updates live via WebSockets [INFERENCE]. Municipal operators view color-coded road health layers, live traffic congestion heatmaps, OD flow matrices, and emergency incident cards [PS, INFERENCE]. Clicking an incident card reveals the cropped license plate, confidence rating, timestamp, snapshot, and exact location for law enforcement dispatch [PS, INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL + PostGIS)

```sql
-- Fleet Vehicles Table
CREATE TABLE bus_fleet (
    bus_id VARCHAR(32) PRIMARY KEY,
    depot_id VARCHAR(32) NOT NULL,
    license_plate VARCHAR(16) NOT NULL,
    camera_count INT DEFAULT 3,
    status VARCHAR(16) DEFAULT 'ACTIVE'
);

-- Real-Time Defect Logs Table
CREATE TABLE road_defects (
    defect_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    bus_id VARCHAR(32) REFERENCES bus_fleet(bus_id),
    defect_type VARCHAR(32) NOT NULL, -- Pothole, Missing_Divider, Missing_Zebra, Damaged_Sign, Waterlogging
    confidence FLOAT NOT NULL,
    location GEOMETRY(Point, 4326) NOT NULL,
    h3_index VARCHAR(16) NOT NULL,
    image_keyframe_url TEXT,
    reported_at TIMESTAMPTZ NOT NULL,
    status VARCHAR(16) DEFAULT 'REPORTED' -- REPORTED, VERIFIED, REPAIRED
);

-- Traffic Incidents Table (Hit & Run / Rash Driving)
CREATE TABLE traffic_incidents (
    incident_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    bus_id VARCHAR(32) REFERENCES bus_fleet(bus_id),
    incident_type VARCHAR(32) NOT NULL, -- HIT_AND_RUN, RASH_DRIVING
    offending_plate_number VARCHAR(16),
    plate_confidence FLOAT,
    location GEOMETRY(Point, 4326) NOT NULL,
    timestamp TIMESTAMPTZ NOT NULL,
    snapshot_url TEXT,
    alert_status VARCHAR(16) DEFAULT 'UNACTIONED'
);

-- Spatial Indexing for Fast GIS Aggregation
CREATE INDEX idx_defects_spatial ON road_defects USING GIST(location);
CREATE INDEX idx_defects_h3 ON road_defects(h3_index);
```

### Local Storage, Caching & Offline Synchronization Flow
1. **Onboard SQLite Store**: If 4G connectivity drops, the edge unit inserts unsent alert payloads into a local encrypted SQLite database (`unsent_events.db`) [INFERENCE].
2. **Exponential Backoff Retry**: An onboard MQTT daemon periodically pings the central broker; upon connection restoration, buffered JSON packets are published in chronological order with QoS 1 (At least once delivery) [INFERENCE].
3. **Depot Wi-Fi Sync**: When the bus enters the depot (geofenced range), the edge unit connects to the high-speed depot Wi-Fi network and establishes an SSH/rsync or S3 multi-part upload pipeline, transferring high-resolution video archives and system logs [INFERENCE].
4. **Bandwidth Reduction Techniques**:
   - Transmit raw frames **ONLY** when an anomaly/incident occurs [PS, INFERENCE].
   - Aggregate vehicle density counters onboard; transmit 1-minute averaged traffic stats rather than per-frame counts [INFERENCE].
   - Compress keyframes using WebP format (< 40 KB per image) [INFERENCE].
