# SIH26037 Technical Dossier & Solution Architecture

## 1. Executive Snapshot

### Summary
Navigating autonomous vehicles (AVs) on Indian roads requires overcoming fundamental flaws in standard autonomous driving stacks, which heavily rely on clear lane markings, structured road geometry, and predictable vehicular behaviors [PS]. Indian road environments feature dense, highly heterogeneous mixed traffic—including cars, buses, trucks, auto-rickshaws, two-wheelers, pushcarts, pedestrians, and stray animals [PS]. These agents routinely perform non-lane-based maneuvers, informal merging, wrong-way driving, and sudden cross-walking [PS]. 

This project delivers a closed-loop co-simulation pipeline in MATLAB, Simulink, and RoadRunner that enables safe, real-time adaptive path planning and collision avoidance in unstructured Indian traffic [PS]. The solution integrates multi-sensor perception (Camera, LiDAR, Radar) [PS], deep-learning-based non-lane trajectory forecasting [PS], a Stateflow supervisory behavioral manager [PS], a non-lane Frenet-Lattice local path planner [PS], and a 3-DOF dynamic vehicle controller [PS]. The system is validated across five challenging, realistic Indian scenarios—including an unmarked village road, an unsignaled urban intersection, a highway merge with slow vehicles, a dense market area, and a sudden cattle-crossing event [PS].

## 2. Problem Deconstruction

The explicit problem statement requirements are deconstructed into atomic requirements:

*   **`[REQ-1.0]` Perception & Object Identification:**
    *   *Source Text:* "perceive the environment using a multi-sensor setup such as camera, LiDAR, and radar, and identify diverse road users and obstacles, including auto-rickshaws, pushcarts, pedestrians, and animals." [PS]
    *   *Interpretation:* The platform must simulate synchronized multi-sensor feeds and perform multi-class object detection and tracking for structured and unstructured entities [PS].
    *   *Implementation Implication:* Implement sensor models in Automated Driving Toolbox, fuse point clouds, radar detections, and camera tracks using Sensor Fusion and Tracking Toolbox, and train multi-class detectors via Deep Learning Toolbox [PS, INFERENCE].
    *   *Confidence:* `[PS]`

*   **`[REQ-2.0]` Short-Term Motion Prediction:**
    *   *Source Text:* "predict the short-term motion of surrounding agents, including non-lane-based and irregular movement patterns" [PS]
    *   *Interpretation:* Trajectory forecasting cannot rely on lane association or map constraints [PS]. It must predict multi-modal future trajectories (1.5s–3.0s horizon) for irregular movers like swerving auto-rickshaws or crossing cattle [INFERENCE].
    *   *Implementation Implication:* Construct a spatial-temporal sequence model (e.g., LSTM/Transformer or Social Force model) in Deep Learning Toolbox using historic object tracks to output dynamic occupancy bounding regions [INFERENCE].
    *   *Confidence:* `[PS]`

*   **`[REQ-3.0]` Adaptive Path Planning & Dynamic Replanning:**
    *   *Source Text:* "generate a safe, collision-free path that can be replanned in real time... handle practical driving situations such as missing lane markings, informal merging, sudden pedestrian movement, and unexpected obstacles on the road." [PS]
    *   *Interpretation:* The motion planner must evaluate drivable spatial corridors without assuming asphalt lane lines and recompute valid trajectories dynamically when obstacles block the path [PS, INFERENCE].
    *   *Implementation Implication:* Deploy a sampling-based or optimization-based planner (e.g., Frenet-Lattice Planner or Timed Elastic Band) from Navigation Toolbox, operating in a dynamic reference path frame [INFERENCE].
    *   *Confidence:* `[PS]`

*   **`[REQ-4.0]` Scenario Design & RoadRunner Scenes:**
    *   *Source Text:* "validate their solution using at least five realistic Indian road scenarios, such as an unmarked village road, a busy urban intersection without signals, a highway merge involving slow-moving vehicles, a dense market area with mixed traffic, and a sudden cattle-crossing event. Teams should create... at least two detailed RoadRunner scenes such as a village road and an urban intersection" [PS]
    *   *Interpretation:* Must author 3D road scenes in RoadRunner with non-standard geometry and configure five distinct logic-driven dynamic scenarios using RoadRunner Scenario [PS].
    *   *Implementation Implication:* Build high-fidelity 3D meshes and OpenDRIVE maps in RoadRunner, import custom Indian actor models (cows, auto-rickshaws, pushcarts), and set actor trajectories [INFERENCE].
    *   *Confidence:* `[PS]`

*   **`[REQ-5.0]` Closed-Loop Co-Simulation Pipeline:**
    *   *Source Text:* "build a working simulation pipeline that integrates perception, prediction, path planning, decision logic, and vehicle motion in MATLAB and Simulink." [PS]
    *   *Interpretation:* Execution must be closed-loop: planned controls feed into the vehicle dynamics model, updating the ego-vehicle position in RoadRunner, which in turn updates raw sensor signals [PS, INFERENCE].
    *   *Implementation Implication:* Utilize Automated Driving Toolbox RoadRunner Scenario co-simulation blocks, passing actor states into Simulink and returning ego pose [INFERENCE].
    *   *Confidence:* `[PS]`

*   **`[REQ-6.0]` Quantitative Performance Evaluation & Deliverables:**
    *   *Source Text:* "present results that show safe and reliable navigation... performance results with metrics such as replanning latency, path smoothness, and scenario completion rate, a short technical report... and a demonstration video" [PS]
    *   *Interpretation:* Quantitative logging must prove safety, stability, and real-time computation across all five scenarios [PS].
    *   *Implementation Implication:* Implement automated logging scripts in MATLAB to extract execution time per step (ms), lateral/longitudinal jerk ($m/s^3$), curvature continuity, clearance distance (m), and scenario success/fail flags [INFERENCE].

## 5. Constraints & Environment Realities

*   **Non-Lane Geometry & Missing Road Boundaries:** Village roads and market streets lack painted lane lines or clear kerbs [PS]. Planners cannot use standard centerline offset formulations [INFERENCE].
*   **Agent Heterogeneity & Kinematic Disparity:** Speeds range from 3 km/h (walking cattle, pushcarts) to 80 km/h (highway cars), with vastly different acceleration bounds and turning radii [PS, KNOWN].
*   **High Trajectory Stochasticity:** Pedestrians and two-wheelers execute lateral swerves without signalling or looking [PS]. Predictors must maintain wide spatial uncertainty bounds [INFERENCE].
*   **Sensor Noise & Environmental Interference:** Dust, mud splash, poor illumination in rural areas, and heavy monsoon spray corrupt optical camera lenses and LiDAR point clouds [KNOWN].
*   **Real-Time Compute Bounds in SIL:** The combined MATLAB/Simulink/RoadRunner simulation must execute within acceptable step-times ($<50\,\text{ms}$ step execution for 20 Hz control rate) on a standard engineering workstation [ASSUMPTION].
*   **Physical Kinematic Feasibility:** An AV cannot stop instantaneously; vehicle dynamics (steering inertia, actuator delays, maximum lateral acceleration $a_y \le 0.3g$) limit aggressive evasive maneuvers [KNOWN].

## 6. Research Questions

1. How can local path planning maintain continuous, collision-free paths when formal lane centers are completely absent?
2. What trajectory prediction architecture best captures non-lane-bound, interactive behaviors of Indian traffic actors (e.g., auto-rickshaws, cattle) with minimal latency?
3. How should Stateflow decision logic balance defensive driving (yielding to cattle/pedestrians) with avoiding freeze-robot deadlocks in ultra-dense market environments?

5. How can path smoothness be mathematically constrained in a Frenet frame when the reference path itself is generated on-the-fly from unpaved road edge estimation?

## 9. Candidate Solution Approaches

### Approach A: Rule-Based State Machine + Static Grid/Sampling Planner (A* / RRT*)
*   *Mechanism:* Sensor fusion outputs static occupancy grids. A Stateflow state machine switches behaviors (Stop, Follow, Go), while 2D A* or RRT* plans paths around grid obstacles [INFERENCE].
*   *Problem Fit:* Low to Moderate. Fails in dynamic mixed traffic because static grids do not anticipate agent velocity [INFERENCE].
*   *Accuracy Potential:* Low in dynamic scenarios; high chance of freezing or collision with moving cattle/autos [INFERENCE].
*   *Data Requirements:* Minimal; requires basic sensor detections [INFERENCE].
*   *Complexity:* Low [INFERENCE].
*   *Explainability:* Very High [INFERENCE].
*   *Cost:* Low [INFERENCE].
*   *Scalability:* Poor [INFERENCE].
*   *Hackathon Feasibility:* Very High (1–2 weeks) [INFERENCE].
*   *Production Feasibility:* Unusable for Level 4 AVs [INFERENCE].

### Approach B: Pure End-to-End Deep Reinforcement Learning (PPO / SAC in Simulink)
*   *Mechanism:* RL agent trained in RoadRunner co-simulation using Deep Learning Toolbox / Reinforcement Learning Toolbox. Inputs bird's-eye view (BEV) images; outputs continuous steering/acceleration control actions [INFERENCE].
*   *Problem Fit:* High theoretical fit; poor practical fit for hackathon constraints [INFERENCE].
*   *Accuracy Potential:* High if converged, but training convergence is erratic [INFERENCE].
*   *Data Requirements:* Massive synthetic simulation iterations ($>10^6$ steps) [INFERENCE].
*   *Complexity:* Extremely High [INFERENCE].
*   *Explainability:* Extremely Low (Black-box) [INFERENCE].
*   *Cost:* High compute overhead [INFERENCE].
*   *Scalability:* Uncertain [INFERENCE].
*   *Hackathon Feasibility:* Low (High risk of non-convergence before deadline) [INFERENCE].
*   *Production Feasibility:* Low due to safety certification barriers [INFERENCE].

### Approach C: Hybrid Architecture — Deep Learning Motion Forecasting + Stateflow Behavioral Manager + Non-Lane Frenet-Lattice Planner + 3-DOF Dynamic Controller (RECOMMENDED)
*   *Mechanism:* 
    1. Multi-sensor fusion yields tracked objects [PS].
    2. Deep Learning spatial-temporal model (LSTM/Encoder-Decoder) predicts 2-second trajectory occupancy distributions [PS, INFERENCE].
    3. Stateflow supervisory logic determines behavioral mode (Corridor Following, Nudging, Unsignaled Intersection Gap Acceptance, Yield to Cattle, Emergency Stop) [PS, INFERENCE].
    4. Frenet-Lattice Planner generates candidate trajectories mapped to an estimated drivable surface boundary rather than lane lines, picking the minimum cost jerk-free path [PS, INFERENCE].
    5. Vehicle Dynamics Blockset 3-DOF bicycle model executes low-level closed-loop control [PS, INFERENCE].
*   *Problem Fit:* Optimal [INFERENCE]. Handles non-lane geometry, dynamic prediction, and robust safety [PS, INFERENCE].
*   *Accuracy Potential:* High [INFERENCE].
*   *Data Requirements:* IDD/Mendeley for object detection fine-tuning; synthetically generated RoadRunner trajectories for trajectory predictor training [PS, INFERENCE].
*   *Complexity:* Moderate-High, but modular [INFERENCE].
*   *Explainability:* High (Deterministic state machine and explicit optimization cost function) [INFERENCE].
*   *Cost:* Moderate [INFERENCE].
*   *Scalability:* High [INFERENCE].
*   *Hackathon Feasibility:* High for a 4–6 student team using MathWorks toolboxes [INFERENCE].
*   *Production Feasibility:* High; aligns with modern automotive SIL design patterns [INFERENCE].

## 10. Recommended Approach & Why

### Selection
**Approach C (Hybrid Architecture)** is selected as the winning architecture [ASSUMPTION].

### Why Alternatives Were Rejected
*   *Approach A (Rule-Based + Static A\*) Rejection:* Purely static occupancy grids treat moving auto-rickshaws and cattle as stationary obstacles at time $t_0$. In an unsignaled urban intersection or market area, this leads to collision or "freeze-robot" paralysis because the planner cannot anticipate that an agent is clearing the intersection [INFERENCE].
*   *Approach B (Pure End-to-End DRL) Rejection:* Training an end-to-end RL agent closed-loop across five complex RoadRunner scenarios requires hundreds of CPU/GPU compute hours and lacks guaranteed convergence within the deadline [INFERENCE]. Furthermore, automobile OEMs reject non-explainable end-to-end controllers due to ISO 26262 functional safety standards [KNOWN].

### Why Approach C Wins
1. **Toolchain Alignment:** Directly leverages the suggested MathWorks stack: RoadRunner (scenarios), Automated Driving Toolbox (sensors/fusion), Deep Learning Toolbox (trajectory prediction), Navigation Toolbox & Stateflow (planning & decision logic), and Vehicle Dynamics Blockset (motion execution) [PS].
2. **Safety & Explainability:** The Stateflow state machine acts as an explicit safety supervisor, guaranteeing that safety rules (e.g., minimum TTC threshold) override ML model predictions if an error occurs [INFERENCE].
3. **Non-Lane Capability:** The Frenet-Lattice planner decouples lateral ($d$) and longitudinal ($s$) motion along an estimated drivable road edge spline, freeing the AV from dependence on painted lane lines [INFERENCE].

### Detailed Data-Flow Narrative
1. **Environment Feed:** RoadRunner passes world states (ground truth positions, orientations, and velocities of surrounding vehicles, pedestrians, and cattle) to Simulink at every simulation timestep ($dt = 0.05\,\text{s}$) [PS, INFERENCE].
2. **Perception Processing:** Automated Driving Toolbox sensor blocks corrupt ground truth with realistic noise parameters (LiDAR range error, Radar azimuth error, Camera detection dropouts) [INFERENCE]. Multi-object tracker outputs tracked state vectors: $[x, y, v_x, v_y, \text{length}, \text{width}, \text{class\_id}]$ [INFERENCE].
3. **Motion Forecasting:** Deep Learning Toolbox LSTM model ingests a sliding window of 10 historic steps ($0.5\,\text{s}$) of object tracks and outputs future spatial coordinate predictions for $t + 0.5\,\text{s}, t + 1.0\,\text{s}, \dots, t + 2.0\,\text{s}$ for each agent [INFERENCE].
4. **Behavioral Decision Logic:** Stateflow evaluates ego position relative to drivable area boundaries and predicted object trajectories. If an auto-rickshaw encroaches laterally, Stateflow transitions the vehicle from `LANE_FOLLOW` to `NUDGE_LEFT`. If a cow enters the forward safety corridor, Stateflow commands `YIELD_AND_WAIT` [INFERENCE].
5. **Frenet Path Generation:** The Frenet-Lattice Planner samples candidate polynomials in lateral displacement ($d$) and longitudinal velocity ($s$). Trajectories colliding with predicted object occupancy boxes or exceeding road boundaries are discarded [INFERENCE]. The trajectory minimizing cost function $C = w_j J + w_t T + w_d d^2 + w_v (v - v_{\text{target}})^2$ is selected [INFERENCE].
6. **Execution & Closed-Loop Feedback:** Control blocks compute steering angle ($\delta$) and throttle/brake commands ($a$), passing them to the 3-DOF Vehicle Dynamics model. The calculated ego vehicle kinematic state is pushed back to RoadRunner Scenario to advance the simulation loop [PS, INFERENCE].

## 13. AI/ML Justification

### AI Component 1: Multi-Class Object Identification in Complex Indian Scenes
*   **Purpose:** Classify non-standard entities (auto-rickshaws, pushcarts, stray cattle, two-wheelers) from camera and LiDAR feeds [PS].
*   **Model Type:** YOLOv8n / MobileNetV3 Object Detector [RESEARCHED].
*   **Input:** RGB Camera Frame ($640 \times 640 \times 3$) + LiDAR Point Cloud ROI [INFERENCE].
*   **Output:** 2D/3D Bounding Boxes with class labels and confidence scores [INFERENCE].
*   **Data Required:** Fine-tuned on Indian Driving Dataset (IDD) and Mendeley Road Obstacle dataset [PS, RESEARCHED].
*   **Why AI is Preferable:** Classical geometric clustering cannot distinguish between a cow, a pushcart, and a large rock; visual feature learning is required [INFERENCE].
*   **Evaluation Metric:** mean Average Precision ($\text{mAP}@0.5 > 85\%$) [INFERENCE].
*   **Failure Mode:** False negative on obscured animal; mitigated by LiDAR spatial clustering backup [INFERENCE].
*   **Human Oversight:** SIL automated verification; confidence thresholds set $> 0.60$ [INFERENCE].

### AI Component 2: Spatial-Temporal Trajectory Prediction for Non-Lane Agents
*   **Purpose:** Forecast 2-second future positions of erratic moving agents (swerving autos, pedestrians, cattle) [PS].
*   **Model Type:** Encoder-Decoder LSTM or Social-GAN Network [RESEARCHED].
*   **Input:** 10 historical trajectory steps $[x_{t-9 \dots t}, y_{t-9 \dots t}, v_{x, t-9 \dots t}, v_{y, t-9 \dots t}]$ per agent [INFERENCE].
*   **Output:** Bivariate Gaussian trajectory distributions ($\mu_x, \mu_y, \sigma_x, \sigma_y, \rho$) for $t+1 \dots t+4$ ($2.0\,\text{s}$) [INFERENCE].
*   **Data Required:** Synthetic trajectory logs extracted from RoadRunner multi-agent simulations [PS, INFERENCE].
*   **Why AI is Preferable:** Kinematic linear extrapolation ($x = x_0 + vt$) fails completely when pedestrians or cattle suddenly change direction [INFERENCE].
*   **Evaluation Metric:** Average Displacement Error ($\text{ADE} < 0.4\,\text{m}$), Final Displacement Error ($\text{FDE} < 0.8\,\text{m}$) [INFERENCE].
*   **Failure Mode:** Out-of-distribution agent maneuver; mitigated by inflating safety bounding envelopes [INFERENCE].
*   **Human Oversight:** Deterministic Stateflow safety supervisor checks TTC; triggers emergency braking if prediction error violates minimum safety distance [INFERENCE].

### Explicit Non-AI Boundary
**AI MUST NOT be used for direct low-level actuator control (steering angle, throttle, braking) or emergency stop decisions [INFERENCE].** Path execution and safety overrides rely strictly on deterministic control theory (Model Predictive Control / Stanley Controller) and verified Stateflow logic to satisfy ISO 26262 requirements and prevent unpredictable model behavior [KNOWN, INFERENCE].

### Bus Specifications & Data Handling
*   **In-Memory Bus Communication:** Data exchanged between Simulink subsystems uses typed `Simulink.Bus` objects to minimize serialization overhead and enforce strict interface typing [INFERENCE].
*   **Local Spatial Mapping:** Instead of relying on active cloud mapping or GPS networks, the vehicle generates an online local spatial occupancy map ($200\,\text{m} \times 200\,\text{m}$ grid centered at ego) using fused LiDAR/Camera ground-plane estimation [INFERENCE].
*   **Bandwidth Reduction:** Sensor data is processed locally at the edge (Simulink SIL node). Only metric summaries (latency, jerk, completion status) are logged to disk via MAT-files [INFERENCE].
*   **Offline Operation:** The entire perception, planning, and control architecture operates completely offline without internet or cloud connection requirements during runtime [INFERENCE].
