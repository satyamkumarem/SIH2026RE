## 1. Executive Snapshot

### Summary
Marginalized artisans, weavers, and micro-entrepreneurs supported by the Ministry of Social Justice and Empowerment (MoSJE) face severe economic stagnation due to reliance on seasonal physical exhibitions like Shilp Samagam and Dilli Haat [PS]. The transition to year-round digital commerce is blocked by low digital literacy, language barriers, and an inability to create professional e-commerce product listings [PS]. This dossier presents **CraftVeda AI** (working title), a cross-platform mobile application and scalable microservices backend that serves as an intelligent "virtual business manager" for rural artisans [PS]. The solution integrates on-device AI image enhancement (background removal, light correction) [PS, RESEARCHED], multilingual voice-to-cataloging via Government of India's Bhashini engine [PS, RESEARCHED], ML-driven price recommendation considering market trends and material costs [PS, INFERENCE], and direct multi-channel dispatch to the Open Network for Digital Commerce (ONDC) and Government e-Marketplace (GeM) [PS, RESEARCHED]. Designed for low-bandwidth, low-literacy environments [PS, INFERENCE], this blueprint provides a student hackathon team with an actionable roadmap to build an MVP for SIH 2026.

## 5. Constraints & Environment Realities

* **Connectivity:** Micro-entrepreneurs frequently operate in rural areas with intermittent 2G/3G or spotty 4G connectivity [KNOWN, INFERENCE]. *Mitigation:* The mobile app must allow full offline photo capture and voice recording, queuing data locally using SQLite, and running edge image background removal before background sync when connection resumes [INFERENCE, ASSUMPTION].
* **Device Hardware:** Artisans typically own budget or entry-level Android smartphones (2GB–4GB RAM, entry-level Processors) [KNOWN, INFERENCE]. *Mitigation:* Avoid heavy client-side deep learning models (>100MB). Use quantized ONNX models (<20MB) or offload heavy GPU processing to cloud endpoints with auto-downscaled preview uploads [RESEARCHED, ASSUMPTION].
* **Language & Digital Literacy:** High rate of low literacy in official English/Hindi scripts; regional dialects dominant (e.g., Bhojpuri, Odia, Marathi, Tamil, Bengali) [KNOWN]. *Mitigation:* Zero required keyboard typing. All inputs accepted via voice notes, and outputs read aloud back to the artisan via Bhashini Text-To-Speech (TTS) [RESEARCHED, INFERENCE].
* **Power Availability:** Frequent power outages in rural cluster villages [KNOWN]. *Mitigation:* Optimate mobile app battery consumption by deferring non-urgent background sync operations until battery level is above 20% [INFERENCE].

## 10. Recommended Approach & Why

**Selected Approach:** **Approach 2: Lightweight Hybrid AI Microservices Architecture** [INFERENCE, ASSUMPTION].

### Justification
1. **AI Image Studio:** On-device camera capture uses Flutter to compress images locally, sending them to an asynchronous FastAPI backend running **BRIA RMBG-1.4** (or edge ONNX runtime fallback) [RESEARCHED]. This achieves background removal and lighting correction in <2 seconds without requiring $0.50/image commercial APIs like remove.bg [RESEARCHED].
2. **Multilingual Voice-to-Catalog:** Integrates directly with MeitY's **Bhashini API** [RESEARCHED]. Regional speech (e.g., Hindi, Marathi, Odia, Tamil) is converted to text, translated to English/Hindi, and passed through an Indic-Llama-3/Mistral-7B LLM instance to generate structured SEO titles, bulleted features, and search tags [RESEARCHED, ASSUMPTION].
3. **Dynamic Pricing:** Implements an **XGBoost regressor** combining tabular cost inputs (voice-extracted raw material costs + labor hours) with image embeddings (ResNet/CLIP features for craft complexity) to output a recommended price range with upper/lower bounds [RESEARCHED, INFERENCE].
4. **Market Linkage:** Exposes an **ONDC Beckn Protocol Adapter** and **GeM API Gateway** that converts approved listings directly into valid retail/handicraft catalog payloads [RESEARCHED].

### Rejection of Alternatives
* *Approach 1 (Cloud-Centric Heavy AI)* was rejected due to high recurring commercial API costs, vulnerability to network drops during rural capture, and the risk of generative hallucinations in product specifications [INFERENCE].
* *Approach 3 (Rule-Based)* was rejected because simple OpenCV thresholding cannot isolate complex handloom fabrics, wood carvings, or brassware from cluttered rural backgrounds [INFERENCE].

### Detailed Data-Flow Narrative

1. **Step 1: Capture & Offline Buffer**
   The artisan opens CraftVeda AI, selects their native language via voice prompt, and taps a single giant button to snap a product photo [INFERENCE]. The image is downscaled to 1080p and stored in local SQLite along with a raw audio voice note detailing craft type, material, and creation time [INFERENCE].

2. **Step 2: Secure Transmission**
   When network connectivity is detected, the background sync service pushes the binary payload over HTTPS (TLS 1.3) with JWT bearer token authentication to the API Gateway [INFERENCE].

3. **Step 3: Parallel AI Processing**
   * *Path A (Image Processing):* The Image Studio service runs the frame through BRIA RMBG-1.4 to strip cluttered rural backgrounds, applies adaptive histogram equalization (CLAHE) for studio lighting, and centers the craft on a neutral studio background [RESEARCHED].
   * *Path B (Voice Processing):* The NLP service streams audio to Bhashini STT (Speech-to-Text), receiving a transcript in the local language [RESEARCHED]. The text is translated to Hindi and English using Bhashini NMT [RESEARCHED]. An LLM parses key parameters (Material: Teakwood, Labor: 12 hours, Craft: Saharanpur Wood Carving) and constructs SEO-optimized product titles, descriptions, and tags [INFERENCE].

4. **Step 4: Dynamic Price Computation**
   The Dynamic Pricing microservice combines extracted material cost and labor hours with visual complexity vectors from CLIP [RESEARCHED]. The XGBoost engine queries historical marketplace price distributions for similar craft categories and outputs a recommended price (e.g., ₹1,450) with an adjustable range slider (₹1,200 – ₹1,700) [INFERENCE].

5. **Step 5: Voice Feedback & Validation**
   The system speaks back the generated title, description, and suggested price in the artisan's native language using Bhashini TTS [RESEARCHED]. The artisan confirms approval with a single voice command ("Sahi Hai" / "Confirm") [INFERENCE].

6. **Step 6: Network Dispatch**
   The core service updates PostgreSQL, uploads studio images to MinIO/S3, and formats the listing into Beckn protocol JSON payloads, broadcasting the inventory to ONDC buyer apps and pushing candidate catalogs to the GeM portal [RESEARCHED].

## 13. AI/ML Justification

### 1. AI Image Enhancer & Studio
* **Purpose:** Convert raw photos taken in poor rural environments into e-commerce compliant studio images [PS].
* **Model Type:** Semantic Segmentation (BRIA RMBG-1.4 / IS-Net) + Contrast Limited Adaptive Histogram Equalization (CLAHE) [RESEARCHED].
* **Input:** Raw RGB photo (JPG/PNG, up to 1080p).
* **Output:** Studio RGBA photo (Transparent background / Clean studio backdrop, corrected lighting, 1:1 aspect ratio).
* **Data Required:** Pre-trained weights; zero additional fine-tuning needed for base segmentation [RESEARCHED].
* **Why AI is Preferable:** Color thresholding or manual cropping is impossible for low-literacy artisans and fails on fine textures like loom threads and wood carvings [INFERENCE].
* **Evaluation Metric:** Mean Intersection over Union (mIoU > 0.92) on artisan product test set [RESEARCHED].
* **Failure Mode:** Occluded product edges or false cutout. *Mitigation:* Visual preview screen allowing one-tap background color toggle (White / Beige / Neutral Wood) or manual retry.
* **Human Oversight:** Artisan approves final enhanced photo before listing creation [INFERENCE].

### 2. Voice-to-Catalog Multilingual NLP Engine
* **Purpose:** Eliminate typing by converting raw regional voice notes into structured bilingual e-commerce listings [PS].
* **Model Type:** Bhashini ASR (Conformer-based STT) + Bhashini NMT + Indic-Llama-3 (8B) / Mistral [RESEARCHED, ASSUMPTION].
* **Input:** Raw WAV audio voice note in regional language (e.g., Bhojpuri audio: *"Ye haath se bana maati ka matka hai, pakaaya hua, 50 rupya maati laga hai"*).
* **Output:** Structured JSON containing:
  * Title (Hindi & English): "हस्तनिर्मित पकी मिट्टी का मटका / Terracotta Clay Pot"
  * Description: Professional SEO bullet points.
  * Extracted Features: Material = Terracotta Clay; Raw Material Cost = ₹50.
* **Data Required:** Audio samples in target languages + craft domain taxonomy [RESEARCHED].
* **Why AI is Preferable:** Manual typing in English/Hindi is impossible for non-literate regional artisans [PS, INFERENCE].
* **Evaluation Metric:** Word Error Rate (WER < 15%) for STT; BLEU score (>32) for translation [RESEARCHED].
* **Failure Mode:** Misinterpretation of spoken numbers or craft terms. *Mitigation:* Bhashini TTS reads back extracted fields to artisan for audio confirmation [RESEARCHED, INFERENCE].
* **Human Oversight:** Audio confirmation prompt ("Sahi hai" / "Badlo").

### 3. Dynamic Pricing Assistant
* **Purpose:** Provide fair, competitive market pricing recommendations to prevent under-pricing or over-pricing by artisans [PS].
* **Model Type:** XGBoost Regressor with CLIP visual embeddings [RESEARCHED].
* **Input:** Extracted craft category, raw material cost (₹), estimated labor hours, regional location, and 512-dim CLIP visual embedding of product image [RESEARCHED, INFERENCE].
* **Output:** Recommended selling price (₹) with Upper/Lower confidence bounds (e.g., Target: ₹1,250, Min: ₹1,100, Max: ₹1,400).
* **Data Required:** Historical craft pricing database (e.g., 1,000 craft listings curated from GeM / ONDC / Handicraft boards) [RESEARCHED, ASSUMPTION].
* **Why AI is Preferable:** Artisans lack access to real-time e-commerce market trends and wholesale benchmark pricing [PS, INFERENCE].
* **Evaluation Metric:** Mean Absolute Percentage Error (MAPE < 12%) [RESEARCHED].
* **Failure Mode:** Outlier recommendation due to unique luxury art piece. *Mitigation:* Dynamic price is presented as a *suggestion slider*; artisan retains 100% final pricing override authority.
* **Human Oversight:** Artisan manually adjusts or confirms final listing price.

### Explicit Non-AI Component
* **Order Management & Inventory Stock Keeping:** Pure deterministic relational database logic (PostgreSQL). AI must NOT be used for inventory stock increments, financial ledger calculations, or order status state transitions to prevent hallucinated transactions [INFERENCE].

### Database Schema (Entity-Relationship Highlights)

```sql
-- Artisan / Beneficiary Table
CREATE TABLE artisans (
    artisan_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    mosje_beneficiary_id VARCHAR(50) UNIQUE NOT NULL,
    full_name VARCHAR(100) NOT NULL,
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    state VARCHAR(50) NOT NULL,
    district VARCHAR(50) NOT NULL,
    preferred_language VARCHAR(10) DEFAULT 'hi',
    corporation_type VARCHAR(20) CHECK (corporation_type IN ('NSFDC', 'NBCFDC', 'NSKFDC', 'OTHER')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Product Inventory Table
CREATE TABLE products (
    product_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    artisan_id UUID REFERENCES artisans(artisan_id) ON DELETE CASCADE,
    raw_audio_url TEXT,
    original_image_url TEXT NOT NULL,
    studio_image_url TEXT,
    title_hi VARCHAR(200),
    title_en VARCHAR(200),
    description_hi TEXT,
    description_en TEXT,
    craft_category VARCHAR(100) NOT NULL,
    material_cost NUMERIC(10, 2),
    labor_hours NUMERIC(5, 1),
    recommended_price NUMERIC(10, 2),
    final_price NUMERIC(10, 2) NOT NULL,
    stock_quantity INT DEFAULT 1,
    ondc_item_id VARCHAR(100),
    sync_status VARCHAR(20) DEFAULT 'DRAFT' CHECK (sync_status IN ('DRAFT', 'PENDING_SYNC', 'PUBLISHED', 'FAILED')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Local SQLite Schema (Mobile Device Storage)
CREATE TABLE local_drafts (
    draft_id TEXT PRIMARY KEY,
    local_image_path TEXT NOT NULL,
    local_audio_path TEXT,
    craft_category TEXT,
    material_cost REAL,
    sync_state INTEGER DEFAULT 0 -- 0: Unsynced, 1: Syncing, 2: Synced
);
```

### Offline & Synchronization Architecture
* **Local Caching:** Artisans can capture photos and record audio fully offline. Data is saved in binary files and cataloged in mobile SQLite [INFERENCE].
* **Background Sync Strategy:** Uses Flutter `WorkManager` to trigger an exponential backoff retry sync whenever an active internet connection (Wi-Fi or cellular) is detected [INFERENCE, ASSUMPTION].
* **Conflict Handling:** Server-side timestamping ensures that local edits are applied linearly. If an inventory item is modified offline while an order is received on ONDC, the server status supersedes local drafts [INFERENCE].
* **Bandwidth Optimization:** Before transmitting images over low-speed rural 2G/3G networks, images are compressed to WebP format (max 1024x1024 resolution, ~150KB payload) [INFERENCE]. Audio notes are encoded in AAC format (~30KB per 15-second clip) [INFERENCE].
