# SIH Solution Research Dossier: AI-Powered Vernacular Pedagogy & Real-Time Translation Tool

## 1. Executive Snapshot

An AI-driven, offline-first vernacular pedagogy and real-time bidirectional translation ecosystem designed for government primary schools in Jharkhand's tribal belts [PS, KNOWN]. The solution bridges the communication and pedagogical gap between Hindi-medium trained primary teachers and young tribal children who speak Ho, Mundari, and Santhali [PS]. The system translates Hindi Foundational Literacy and Numeracy (FLN) curriculum content into contextually accurate text and synthesized speech, enables sub-3-second voice-to-voice classroom dialogue, auto-generates NIPUN Bharat-aligned bilingual worksheets and visual flashcards, and operates completely offline on low-spec Android tablets (<= 2 GB RAM, Android 9+) [PS].

## 2. Problem Deconstruction

### Background Context
- Jharkhand's PALASH Mother Tongue-Based Multilingual Education (MTB-MLE) programme has demonstrated measurable improvements in foundational literacy among tribal children [PS, RESEARCHED].
- Scaling the PALASH programme is severely bottlenecked by a critical shortage of teachers proficient in tribal languages, specifically Ho, Mundari, and Santhali (languages with limited digital NLP resources) [PS, KNOWN].
- The vast majority of teachers assigned to tribal-area primary schools are Hindi-medium trained and lack the linguistic tools to deliver mother-tongue-based instruction [PS].
- Without a technological bridge, the pedagogical intent of MTB-MLE cannot be realized at scale, and children in over 5,000 tribal-area primary schools continue to receive instruction in a language they do not comprehend at home [PS].

### Atomic Requirements
- **Requirement (a):** Develop an AI-assisted translation and curriculum-generation software suite enabling non-native speaking primary school teachers to deliver mother-tongue-based instruction in Ho, Mundari, and Santhali without prior language training [PS].
- **Requirement (b):** Include an NLP engine capable of translating standard Hindi Foundational Literacy and Numeracy (FLN) curriculum content—including lesson scripts, activity instructions, and assessment prompts—into contextually accurate text AND synthesized audio in target tribal languages [PS].
- **Requirement (c):** Implement a real-time voice-to-voice translation feature allowing a teacher speaking Hindi to conduct interactive classroom dialogue with tribal-language-speaking students, with end-to-end latency not exceeding three seconds (< 3s) [PS].
- **Requirement (d):** Auto-generate bilingual worksheets and visual flashcard sets aligned to the NIPUN Bharat learning outcomes framework [PS].
- **Requirement (e):** Ensure full offline functionality on low-cost tablets (<= 2 GB RAM, Android 9+) after initial content synchronization [PS].
- **Requirement (f) - Prototype Deliverables:** A working software application demonstrating Hindi-to-tribal-language translation (minimum one tribal language at prototype stage), real-time voice translation with sub-3-second latency, auto-generated bilingual worksheet output, full offline operation on a low-end Android tablet, submitted with a demo video and GitHub repository [PS].

## 5. Constraints & Environment Realities

- **Geography & Network Connectivity:** Primary schools in target districts (e.g., West Singhbhum, Dumka, Khunti, Simdega) are located in dense forest and hilly terrains with zero or erratic cellular network coverage (2G/EDGE or dead zones) [RESEARCHED, INFERENCE]. All core features MUST work 100% offline without cloud API roundtrips [PS].
- **Hardware Profile:** Government-issued low-cost Android tablets with <= 2 GB RAM, Quad-Core ARM Cortex-A53 processors, and Android 9.0 (API 28+) [PS]. Deep learning models exceeding 400 MB RAM will trigger Android's Low Memory Killer (LMK), causing app termination [INFERENCE].
- **Power Realities:** Electricity supply in rural schools is intermittent [INFERENCE]. The app must optimize CPU utilization to prevent rapid battery drain during 4–5 hours of daily school operation [INFERENCE].
- **Linguistic & Script Complexities:**
  - **Santhali:** Officially written in Ol Chiki script, but Devanagari is also used in government primary textbooks in Jharkhand [RESEARCHED].
  - **Ho:** Written in Warang Chiti script and Devanagari script [RESEARCHED].
  - **Mundari:** Written in Mundari Bani script and Devanagari script [RESEARCHED].
  - **Pedagogical Requirement:** The app MUST provide dual-script rendering (Native Script + Devanagari Transliteration) so Hindi-speaking teachers can pronounce native words correctly [INFERENCE].
- **Digital Literacy:** Primary teachers possess basic smartphone familiarity; the UI must be single-tap, voice-activated, and completely uncluttered [INFERENCE].

## 8. Existing Solutions & Gap Analysis

### 1. AI4Bharat IndicTrans2 / Bhashini Framework
- **Description:** Open-source transformer NMT models covering 22 scheduled Indian languages, including Santhali (sat_Olck) [RESEARCHED].
- **Strengths:** High translation quality for scheduled Indic languages; open weights [RESEARCHED].
- **Weaknesses:** Models are large (>1 GB); require cloud server / GPU infrastructure; do not support non-scheduled languages like Ho and Mundari natively in lightweight sizes [RESEARCHED].
- **Relevance:** Foundation for Santhali translation weights.
- **Gap:** Cannot run offline on 2GB RAM Android tablets; lacks streaming real-time sub-3s voice-to-voice pipeline; no native Ho/Mundari NMT weights [INFERENCE].

### 2. Google Translate / Meta NLLB-200
- **Description:** Massively multilingual neural translation engines [RESEARCHED].
- **Strengths:** High translation coverage across global languages [RESEARCHED].
- **Weaknesses:** Cloud-dependent API calls fail completely in offline rural schools [PS]; lack specialized FLN primary education vocabulary; high network latency [INFERENCE].
- **Relevance:** Comparative baseline.
- **Gap:** Entirely unusable in offline deployment environments [PS].

### 3. DIKSHA Platform (Ministry of Education)
- **Description:** National digital infrastructure providing e-content and multilingual teacher training modules [RESEARCHED].
- **Strengths:** Vast repository of NIPUN Bharat learning materials and SCERT video lessons [RESEARCHED].
- **Weaknesses:** Static PDF/video content; requires active internet streaming; no real-time voice translation tool for spontaneous classroom dialogue [INFERENCE].
- **Relevance:** Source for FLN learning outcomes and curriculum structure.
- **Gap:** Does not enable real-time interactive bilingual communication between non-native teachers and tribal children [INFERENCE].

## 9. Candidate Solution Approaches

### Approach 1: Pure Deep Learning Edge Stack
- **Mechanism:** On-device quantized Whisper-tiny ASR (Hindi), ONNX-quantized IndicTrans2/NLLB-200 NMT (320M int8), ONNX VITS TTS.
- **Required Data:** Large parallel text corpora and acoustic audio datasets.
- **Architecture:** 3-stage ONNX execution pipeline managed via Android NDK C++.
- **Complexity:** Extremely High.
- **Cost:** Low (open-source models).
- **Explainability:** Low (black-box neural model errors).
- **Scalability:** High if hardware permits.
- **Hackathon Feasibility:** Medium for Santhali; Low for Ho/Mundari due to missing NMT weights.
- **Production Feasibility:** High risk of memory crashes on 2GB RAM tablets (pipeline memory footprint > 800 MB RAM, triggering Android LMK) [INFERENCE]. Latency exceeds 4.0 seconds on Cortex-A53 processors [INFERENCE].

### Approach 2: Rule-Based & Phrase-Dictionary Engine with Static Audio
- **Mechanism:** Exact match FLN phrase database + slot-filling template substitution + pre-rendered audio playback.
- **Required Data:** Curated dictionary of 2,000 FLN sentences & vocabulary.
- **Architecture:** SQLite database lookup + string substitution + Android MediaPlayer.
- **Complexity:** Low.
- **Cost:** Very Low.
- **Explainability:** High (100% deterministic).
- **Scalability:** Low (fails completely on unscripted, spontaneous teacher speech).
- **Hackathon Feasibility:** Very High.
- **Production Feasibility:** Fails Requirement (c) requiring real-time voice-to-voice interactive classroom dialogue [PS].

### Approach 3: Hybrid Neuro-Symbolic & Quantized Light-NMT Engine (RECOMMENDED)
- **Mechanism:**
  - **ASR:** Streaming Hindi ASR using Sherpa-ONNX Zipformer-int8 (~40 MB RAM, ~150ms latency) [RESEARCHED].
  - **MT:** Two-Tier Neuro-Symbolic Translation Engine. *Tier 1:* SQLite FLN Domain Phrase & Pattern Matcher (0-10ms latency, 100% accurate for standard curriculum). *Tier 2:* Micro-Quantized NMT ONNX int8 Model (IndicTrans2-dist, ~80 MB RAM) for spontaneous out-of-domain teacher speech.
  - **TTS:** Quantized Lightweight Phoneme TTS (Piper-ONNX / VITS-int8, ~35 MB RAM, ~250ms latency).
  - **Worksheets:** Android Native Canvas & PDFDocument vector layout engine.
- **Complexity:** Moderate-High.
- **Explainability:** High for core FLN curriculum; moderate for open conversation.
- **Hackathon Feasibility:** Very High (Santhali fully functional via IndicTrans2-dist ONNX int8; Ho and Mundari functional via FLN phrase-table + rule-transliteration fallback).
- **Production Feasibility:** Excellent. Total RAM usage < 350 MB (fits comfortably within 2 GB RAM); End-to-End Latency ~ 850ms - 1.5s (well below the < 3.0s requirement) [INFERENCE].

---

## 10. Recommended Approach & Why

**Selected Approach:** Approach 3 (Hybrid Neuro-Symbolic Architecture).

### Rejection Justification
- **Approach 1 (Pure Deep Learning)** was rejected because running Whisper + IndicTrans2 + VITS concurrently on a 2 GB RAM Android 9 tablet consumes over 800 MB - 1.2 GB RAM, triggering Android's Low Memory Killer (LMK) and causing app termination [INFERENCE]. Furthermore, sequential CPU execution on Quad-Core ARM Cortex-A53 chips results in latency between 3.8s and 5.2s, violating the explicit < 3-second latency limit [PS, INFERENCE].
- **Approach 2 (Pure Rule-Based/Pre-recorded)** was rejected because it cannot support spontaneous interactive classroom dialogue, directly violating Requirement (c) [PS].

### Winning Criteria for Approach 3
1. **Guaranteed Sub-3-Second Latency:** Average end-to-end processing time is ~1.2s on Cortex-A53 hardware [INFERENCE].
2. **Pedagogical Determinism:** Tier 1 SQLite lookup guarantees 100% accurate, uncorrupted translation for standard SCERT FLN lesson scripts and NIPUN assessment prompts [INFERENCE].
3. **Low Memory Footprint:** Total RAM consumption stays below 350 MB, leaving ample headroom on 2 GB RAM tablets [INFERENCE].

### Detailed Data-Flow Narrative
1. **Interactive Classroom Dialogue (Voice-to-Voice):**
   - Teacher presses 'Talk' button in Hindi. The Android `AudioRecord` API captures 16kHz PCM audio stream [INFERENCE].
   - Local VAD (Voice Activity Detection) trims silence and routes the stream to Sherpa-ONNX Zipformer ASR running via C++ JNI bindings (~200ms) [RESEARCHED, INFERENCE].
   - Extracted Hindi text string is passed to the Neuro-Symbolic MT Manager [INFERENCE].
   - *Tier 1 Check:* System checks indexed SQLite database for exact/fuzzy FLN phrase matches (0-10ms) [INFERENCE].
   - *Tier 2 Fallback:* If unscripted, Tier 2 executes the 80 MB quantized IndicTrans2-dist ONNX model (~400ms) [RESEARCHED, INFERENCE].
   - Translated text (in native script and Devanagari transliteration) is passed to Piper-ONNX TTS synthesizer (~250ms) [RESEARCHED, INFERENCE].
   - Audio buffer plays back via `AudioTrack`. Total pipeline latency: ~850ms - 1.4s (< 3.0s target) [PS, INFERENCE].

2. **Curriculum Script & Lesson Audio Delivery:**
   - Teacher selects a NIPUN Bharat FLN topic (e.g., "Grade 1 Literacy - Letter Sounds").
   - App loads Hindi text, target tribal text (Ol Chiki/Warang Chiti/Devanagari), and triggers pre-synthesized audio playback.

3. **Worksheet & Flashcard Generation:**
   - Teacher selects learning competency (e.g., "Grade 2 Math - Addition with Visual Objects").
   - Android Canvas populates pre-designed vector templates with bilingual text prompts and graphic assets [INFERENCE].
   - Android `PdfDocument` compiles printable A4 PDFs stored locally [INFERENCE].

## 13. AI/ML Justification

### Component 1: Hindi Speech-to-Text (ASR)
- **Purpose:** Convert teacher's spoken Hindi audio into clean Hindi text for real-time translation [PS].
- **Model Type:** Sherpa-ONNX Zipformer-Transducer (Quantized int8) [RESEARCHED].
- **Input:** 16kHz PCM mono audio stream.
- **Output:** Hindi UTF-8 string.
- **Data Required:** Hindi acoustic speech corpus (e.g., Common Voice Hindi / IndicSuperb) [RESEARCHED].
- **Why AI:** Handles classroom ambient noise, pitch variations, and regional accents that acoustic rule engines cannot decode [INFERENCE].
- **Evaluation Metric:** Word Error Rate (WER < 12%) on primary classroom speech samples [INFERENCE].
- **Failure Mode:** Background classroom noise causes transcription errors.
- **Human Oversight:** Real-time UI displays transcribed Hindi text above translation, allowing the teacher to tap to edit or re-speak [INFERENCE].

### Component 2: Machine Translation Engine (Hindi -> Tribal)
- **Purpose:** Translate Hindi FLN lesson content and spontaneous teacher dialogue into target tribal languages [PS].
- **Model Type:** Neuro-Symbolic Hybrid (Tier 1: SQLite pattern matcher; Tier 2: ONNX Quantized IndicTrans2-dist Transformer) [RESEARCHED, INFERENCE].
- **Input:** Hindi text string + Target Language Code.
- **Output:** Translated text in native script (Ol Chiki/Warang Chiti/Mundari Bani) + Devanagari transliteration.
- **Data Required:** AI4Bharat BPCC parallel text dataset for Santhali; FLN parallel dictionary for Mundari and Ho [RESEARCHED, ASSUMPTION].
- **Why AI:** Translates open-ended classroom conversations where static dictionaries fail [INFERENCE].
- **Evaluation Metric:** BLEU score (>28) / chrF++ score on FLN benchmark test set [RESEARCHED, INFERENCE].
- **Failure Mode:** Out-of-vocabulary (OOV) terms translated incorrectly or phonetically.
- **Human Oversight:** Standard NIPUN Bharat curriculum phrases always bypass neural inference via Tier 1 rule lookup, ensuring 100% pedagogical accuracy for core lessons [INFERENCE].

### Component 3: Tribal Text-to-Speech (TTS)
- **Purpose:** Synthesize natural audio in Santhali, Mundari, and Ho for primary students [PS].
- **Model Type:** Piper-ONNX VITS int8 Phoneme Synthesizer [RESEARCHED].
- **Input:** Target language text string + Phoneme map.
- **Output:** 22.05kHz WAV audio stream played through device speakers.
- **Data Required:** Single-speaker phonetically balanced tribal speech dataset (2–5 hours per language) [RESEARCHED].
- **Why AI:** Concatenative rule-based audio sounds unnatural and robotic, hindering early childhood listening comprehension [INFERENCE].
- **Evaluation Metric:** Mean Opinion Score (MOS > 3.8 / 5) for speech naturalness and intelligibility [INFERENCE].
- **Failure Mode:** Mispronunciation of rare phoneme combinations.
- **Human Oversight:** Pre-rendered audio clips for static curriculum lessons validated by native speakers [INFERENCE].

### Where AI Should NOT Be Used
- **Worksheet Layout & Competency Mapping:** Layout generation, template alignment, and NIPUN Bharat goal mapping MUST use deterministic code and vector SVG templates. Generative AI layout engines introduce unpredictable visual overlaps and hallucinated educational targets [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Local SQLite Database Schema
```sql
-- Core FLN Lessons
CREATE TABLE fln_lessons (
    lesson_id INTEGER PRIMARY KEY,
    grade INTEGER CHECK (grade IN (1, 2, 3)),
    subject TEXT CHECK (subject IN ('LITERACY', 'NUMERACY')),
    nipun_goal_code TEXT NOT NULL,
    hindi_title TEXT NOT NULL,
    hindi_script TEXT NOT NULL,
    santhali_olchiki TEXT,
    santhali_deva TEXT,
    mundari_text TEXT,
    ho_text TEXT,
    audio_asset_path TEXT
);

-- Fast Tier 1 Phrase Dictionary
CREATE TABLE phrase_dictionary (
    phrase_id INTEGER PRIMARY KEY,
    category TEXT NOT NULL, -- e.g., 'GREETING', 'INSTRUCTION', 'QUESTION'
    hindi_text TEXT UNIQUE NOT NULL,
    santhali_olchiki TEXT NOT NULL,
    santhali_deva TEXT NOT NULL,
    mundari_deva TEXT NOT NULL,
    ho_deva TEXT NOT NULL
);

-- Worksheet Templates
CREATE TABLE worksheet_templates (
    template_id INTEGER PRIMARY KEY,
    competency_code TEXT NOT NULL,
    hindi_prompt TEXT NOT NULL,
    santhali_prompt TEXT NOT NULL,
    graphic_asset_name TEXT NOT NULL
);
```

### Synchronization & Low-Network Strategy
- **Zero-Dependency First Boot:** App is shipped fully functional with pre-populated SQLite database and ONNX model weights in APK / expansion files [INFERENCE].
- **Delta Update Sync:** When the tablet connects to Wi-Fi at a Block Resource Centre (BRC), Android `WorkManager` executes a background check fetching compressed JSON differential update bundles (< 500 KB) [INFERENCE].
- **Read-Only Database Integrity:** Mobile app uses read-only curriculum database tables, eliminating client-side write conflicts during synchronization [INFERENCE].

## 15. Security, Privacy & Governance

- **Child & Student Audio Privacy:** Voice-to-voice translation processes teacher and student audio completely in-memory (RAM) via local C++ buffers. Zero audio recordings are written to persistent disk storage or uploaded to remote servers [INFERENCE].
- **Authentication:** Offline PIN-based local authentication bound to the tablet ID; eliminates password failure issues in remote areas [INFERENCE].
- **Local Data Encryption:** Local SQLite database encrypted using SQLCipher (AES-256) to prevent unauthorized tampering of educational content [INFERENCE].
- **Governance & Pedagogical Validation:** All translated FLN curriculum content and NIPUN Bharat alignments must be reviewed and approved by SCERT Jharkhand and Tribal Research Institute (TRI) Ranchi prior to full-scale deployment [INFERENCE].
