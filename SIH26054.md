# Research & Solution Architecture Dossier

## 1. Executive Snapshot

This research and architecture dossier provides an actionable, defense-grade blueprint for developing an AI-enabled, real-time Digital Twin (DT) system tailored for aero piston engines operating on Medium Altitude Long Endurance (MALE) Unmanned Aerial Vehicles (UAVs) [PS]. Traditional UAV propulsion monitoring relies on static, reactive thresholds that only trigger after component degradation or thermal limits have already been breached [PS]. This system replaces reactive alarms with a hybrid, physics-informed digital twin framework that fuses real-time CAN bus/FADEC telemetry with thermodynamic behavior models (thermodynamic performance maps) and deep learning prognostics [PS]. Operating across an onboard edge computer and a Ground Control Station (GCS) HMI, the platform delivers real-time engine state estimation, early anomaly detection (e.g., misfires, cooling degradation, injector drift), Remaining Useful Life (RUL) estimation, and post-flight mission replay capabilities under varying operational and environmental profiles [PS].

**Fundamental System Objective:**  
To establish a continuously synchronized, physics-informed digital twin intelligence layer that ingests real-time CAN bus telemetry from MALE UAV aero piston engines to predict failures before occurrence, estimate Remaining Useful Life (RUL), simulate mission profiles under extreme environmental conditions, and enable post-flight mission replay within defense-grade Ground Control Station (GCS) architectures [PS].

## 5. Constraints & Environment Realities

1. **Tactical Data Link Bandwidth Limitations:** In MALE UAV operations (e.g., TAPAS-BH-201 / Heron), line-of-sight (LOS) C-band data links or Satellite Communications (SATCOM) offer restricted bandwidth (often < 64 kbps allocated for engine health telemetry) [RESEARCHED]. Transmitting raw 100 Hz multi-channel CAN bus telemetry to ground control is impossible [INFERENCE].
2. **Onboard Compute & SWaP-C Constraints:** The onboard UAV hardware faces strict Size, Weight, Power, and Cost (SWaP-C) limits [KNOWN]. High-power GPUs cannot be hosted on the aircraft; onboard edge analytics must execute on lightweight embedded nodes (e.g., NVIDIA Jetson Orin Nano / NXP i.MX8 / ARM Cortex-R5) consuming < 15W [INFERENCE].
3. **Severe Operating Envelopes:** Aero piston engines in MALE UAVs (e.g., Rotax 914 / 915 Turbocharged series) operate at altitudes up to 30,000 feet [RESEARCHED]. At high altitudes, ambient pressures drop to ~30 kPa, ambient temperatures drop to -40°C, and turbochargers must operate near maximum compressor speeds to maintain manifold pressure [RESEARCHED]. Rapid throttle transitions at high altitude risk engine stall, vapor lock, or thermal shock [KNOWN].
4. **Air-Gapped Operational Environment:** Defense Ground Control Stations (GCS) operate in strict air-gapped networks [KNOWN]. Cloud-based SaaS platforms (AWS/Azure) cannot be used in production [INFERENCE]. All GCS analytics, digital twin execution, and data storage must run fully locally on ruggedized x86 workstations [INFERENCE].
5. **Real-Time Latency Deadlines:** Failure detection for critical states like oil pressure drops or extreme CHT thermal runaway must execute within < 100 ms to enable automated cockpit alerts or automated ECU thrust derating [INFERENCE].

## 6. Research Questions

1. *Physics Modeling:* How can a 1D thermodynamic aero piston engine model be computationally compressed to execute in real time (< 10ms execution loop) on an embedded edge hardware target while maintaining < 3% error against physical test bench data? [INFERENCE]
2. *Data Prioritization over SATCOM:* What feature extraction and edge anomaly filtering techniques best compress raw 100 Hz CAN telemetry into a low-bandwidth (< 5 kbps) telemetry packet without losing critical transient spike signatures during high-altitude throttle transitions? [RESEARCHED]
3. *Sensor Fault Differentiation:* How can the system reliably distinguish between a true mechanical failure (e.g., actual oil pressure drop due to pump failure) and a sensor failure (e.g., oil pressure transducer wiring drift) using spatial-temporal cross-sensor correlations? [INFERENCE]
4. *Interoperability Standards:* How can the Digital Twin framework comply with NATO STANAG 4586 (UAV Control System Interfaces) and ARINC 825 (Aeronautical CAN bus) standards to allow seamless drop-in deployment into DRDO/Defence GCS architectures? [RESEARCHED]

### Approach 1: Pure Data-Driven Machine Learning Architecture
* **Mechanism:** Ingest CAN telemetry directly into deep neural networks (Convolutional Autoencoders for anomaly detection, Bi-LSTM with Attention for RUL, XGBoost for fault classification) [RESEARCHED].
* **Data Requirements:** Massive historical run-to-failure telemetry datasets under all flight regimes [INFERENCE].
* **Complexity:** Moderate software complexity; zero domain physics modeling required [INFERENCE].
* **Explainability:** Low (Black-box neural network outputs hard to certify for military airworthiness) [INFERENCE].
* **Scalability:** High across similar data distributions [INFERENCE].
* **Hackathon Feasibility:** High (Easy to train on NASA C-MAPSS or synthetic data) [INFERENCE].
* **Production Feasibility:** Low (Fails unpredictably when exposed to unmodeled high-altitude flight regimes outside training data distribution) [INFERENCE].

### Approach 2: Pure Thermodynamic Physics-Based Simulation Engine
* **Mechanism:** Build a full 1D thermodynamic differential equation solver (Mean Value Engine Model / Lumped-Parameter Thermal Network) running in real time [RESEARCHED]. Calculates theoretical $P_V$ diagrams, CHT, EGT, and fuel burn based on ambient conditions [INFERENCE].
* **Data Requirements:** Precise engine geometry, valve timing curves, heat transfer coefficients, and compressor maps [RESEARCHED].
* **Complexity:** Extremely high mathematical and computational complexity [INFERENCE].
* **Explainability:** 100% physically explainable [INFERENCE].
* **Scalability:** Poor (Requires recalibration for every minor engine variant) [INFERENCE].
* **Hackathon Feasibility:** Low (Difficult to implement and tune real-time 1D thermodynamic differential solvers within hackathon timeline) [INFERENCE].
* **Production Feasibility:** Medium (Computationally heavy for embedded edge hardware; cannot adapt dynamically to unmodeled mechanical wear or sensor drift) [INFERENCE].

### Approach 3: Hybrid Physics-Informed Digital Twin (PINN + Edge/GCS Dual Layer) — RECOMMENDED
* **Mechanism:** Fuses thermodynamic domain models with data-driven AI [RESEARCHED]. A lightweight thermodynamic state estimator runs on the onboard edge to calculate physical expectation residuals ($\Delta \text{CHT} = \text{CHT}_{\text{measured}} - \text{CHT}_{\text{physics}}$). These residuals are passed into a Physics-Informed Neural Network (PINN) and Autoencoder running on the GCS to detect subtle anomalies, estimate RUL, and drive high-altitude mission simulations [INFERENCE].
* **Data Requirements:** Medium (Requires base engine thermodynamic maps + modest synthetic training data) [INFERENCE].
* **Complexity:** High, but highly structured and modular [INFERENCE].
* **Explainability:** High (Faults are flagged alongside physical residual deviations, e.g., "EGT spike exceeds thermodynamic enthalpy balance by 14%") [INFERENCE].
* **Scalability:** Excellent (Physics constraints ensure reliable generalization to unseen flight altitudes) [INFERENCE].
* **Hackathon Feasibility:** High for a 4-6 student team using Python/FastAPI, PyTorch, and WebGL [INFERENCE].
* **Production Feasibility:** Extremely high (Fully meets DRDO / defense airworthiness expectations) [INFERENCE].

## 10. Recommended Approach & Why

The **Hybrid Physics-Informed Digital Twin Architecture (Approach 3)** is the selected solution [INFERENCE].

### Trade-Off Evaluation & Rejection Rationale
* **Why Pure Data-Driven (Approach 1) was Rejected:** Defence airworthiness authorities (e.g., CEMILAC / DGCA) reject pure black-box neural networks for mission-critical aircraft propulsion [RESEARCHED]. If a MALE UAV encounters an unprecedented atmospheric transition at 28,000 feet, a pure deep learning model may hallucinate false health indices or fail to detect catastrophic knock/misfires [INFERENCE].
* **Why Pure Physics (Approach 2) was Rejected:** Pure thermodynamic differential models cannot automatically learn or adapt to physical degradation over time (e.g., gradual piston ring friction accumulation, injector nozzle coking, or sensor calibration drift) [RESEARCHED]. They require constant manual recalibration and are computationally prohibitive on embedded edge controllers [INFERENCE].

### Why Approach 3 Wins
Approach 3 leverages the strengths of both paradigms:
1. **Physical Safety Bounds:** The physics layer enforces thermodynamic conservation laws (energy balance, volumetric efficiency limits), eliminating AI hallucinations [RESEARCHED].
2. **Predictive AI Flexibility:** The deep learning layer models non-linear component degradation (RUL) and complex multi-sensor cross-correlations that are mathematically intractable in pure physics equations [RESEARCHED].
3. **Optimized Bandwidth & Compute:** The onboard edge compute calculates compact physical residuals, allowing low-bandwidth telemetry transmission over SATCOM while preserving full diagnostic fidelity at the Ground Control Station [INFERENCE].

### Detailed Data-Flow Narrative
1. **Ingestion & Frame Parsing:** The onboard engine sensor suite or synthetic flight bench broadcasts raw CAN frames onto the vehicle bus at 100 Hz [PS]. The Onboard Edge Engine reads frames via SocketCAN (`vcan0`), unpacks binary bitfields, applies scaling offsets, and validates frame checksums [INFERENCE].
2. **Onboard Physics Residual Computation:** The edge node executes a low-latency thermodynamic validation pass [INFERENCE]. Measured values are compared against theoretical lookup tables (e.g., expected CHT based on RPM, fuel flow, and ambient pressure) [INFERENCE]. Physical residuals ($\Delta \text{CHT}, \Delta \text{EGT}, \Delta P_{\text{oil}}$) are derived [INFERENCE].
3. **Telemetry Downsampling & Transmission:** When operating nominally, steady-state telemetry is downsampled to 1 Hz and packed into encrypted STANAG 4586 UDP telemetry packets for SATCOM transmission [RESEARCHED]. If an anomaly or rapid throttle transient is detected on the edge, telemetry rate automatically bursts to 50 Hz [INFERENCE].
4. **GCS Telemetry Ingestion & Stream Distribution:** The GCS Telemetry Receiver ingests incoming UDP packets, validates military signatures, and pushes telemetry into a Redis in-memory Pub/Sub stream [INFERENCE].
5. **AI/ML Prognostics Pipeline:** The AI Analytics Service consumes the Redis stream [INFERENCE]:
   * The **Autoencoder** evaluates sensor vector reconstruction errors to detect misfires or sensor drift within < 100 ms [RESEARCHED].
   * The **PINN Engine** classifies thermodynamic failure modes (e.g., valve leakage vs. cooling degradation) [RESEARCHED].

### Component 1: Anomaly Detection Engine
* **Purpose:** Detect subtle, multi-sensor operational anomalies (misfires, sensor drift, combustion instability) prior to threshold breaches [PS].
* **Model Type:** Deep Convolutional Autoencoder [RESEARCHED].
* **Input Vector:** Normalized 12-channel time-series window (RPM, CHT1-4, EGT1-4, Oil Press, Fuel Flow, Vibration) over 50 time steps [INFERENCE].
* **Output:** Reconstruction Mean Squared Error (MSE) score + Anomaly Binary Flag + Sensor Attribution Mask [INFERENCE].
* **Data Required:** 10,000 nominal flight cycles across varying throttle profiles [INFERENCE].
* **Why AI is Necessary:** Multi-sensor cross-correlations (e.g., EGT dropping in Cylinder 2 while vibration spikes) are too complex for static single-parameter threshold rules [INFERENCE].
* **Evaluation Metrics:** Precision, Recall, F1-Score, Receiver Operating Characteristic (ROC-AUC) [KNOWN].
* **Failure Mode:** False positive flags under violent gust turbulence [INFERENCE].
* **Human Oversight:** Operator can suppress false alarms; system logs raw telemetry window for post-flight audit [INFERENCE].

### Component 2: Remaining Useful Life (RUL) Estimator
* **Purpose:** Predict remaining operational hours before component failure (injectors, piston rings, bearings) [PS].
* **Model Type:** Bidirectional LSTM with Temporal Attention Mechanism [RESEARCHED].
* **Input Vector:** Extracted multi-flight trend features (smoothed baseline CHT rise, oil pressure decay rate, vibration RMS growth) [INFERENCE].
* **Output:** Continuous predicted RUL in operational flight hours + 95% Confidence Interval bound [INFERENCE].
* **Data Required:** Multi-flight degradation trajectory datasets (e.g., NASA C-MAPSS or synthetic run-to-failure series) [RESEARCHED].
* **Why AI is Necessary:** Component wear is highly non-linear and depends heavily on historical flight stress (high altitude vs. low sea level cruise) [INFERENCE].
* **Evaluation Metrics:** Root Mean Squared Error (RMSE) in operational hours, NASA PHM Scoring Function [RESEARCHED].
* **Failure Mode:** Underestimating RUL on new components with steep break-in wear curves [INFERENCE].
* **Human Oversight:** RUL outputs serve as maintenance advisories; mandatory physical inspection required before replacing components [INFERENCE].

### Component 3: Physics-Informed Fault Diagnoser (PINN)
* **Purpose:** Classify exact root-cause failure modes while enforcing thermodynamic conservation of energy [PS].
* **Model Type:** Physics-Informed Neural Network (PINN) integrating 1D IC Engine thermodynamic equations into loss functions [RESEARCHED].
* **Input Vector:** Thermodynamic state vector (Mass air flow, manifold pressure, RPM, measured EGT/CHT, fuel energy input) [INFERENCE].
* **Output:** Probabilistic failure classification (Injector Clogging, Cooling Radiator Fouling, Lubrication Pump Failure, Blow-by Leakage) [INFERENCE].
* **Data Required:** Engine thermodynamic performance maps + fault-injected simulation cycles [INFERENCE].
* **Why AI is Necessary:** Pure physics models cannot solve inverse multi-parameter diagnostic equations in real time [INFERENCE].
* **Evaluation Metrics:** Diagnostic Classification Accuracy, Physics Loss Residual ($\mathcal{L}_{\text{physics}}$) [RESEARCHED].
* **Failure Mode:** Misclassifying novel composite failure modes [INFERENCE].
* **Human Oversight:** Displays physical residual graph alongside AI diagnosis so propulsion engineers can verify physical sanity [INFERENCE].

### Where AI Must NOT Be Used
* **Hard Emergency Limits:** Hard safety redlines (e.g., engine overspeed > 5800 RPM, catastrophic oil pressure loss < 1.5 bar, extreme CHT > 135°C) MUST NOT rely on AI predictions [INFERENCE]. These must be governed by deterministic, hard-coded safety logic in the edge watchdog node [INFERENCE].

    cooling_hi REAL CHECK (cooling_hi BETWEEN 0 AND 1),
    electrical_hi REAL CHECK (electrical_hi BETWEEN 0 AND 1),

SELECT create_hypertable('health_indices', 'time');

-- Fault Alert Log
CREATE TABLE fault_events (
    event_id UUID PRIMARY KEY,
    timestamp TIMESTAMPTZ NOT NULL,
    uav_id VARCHAR(32) NOT NULL,

    fault_code VARCHAR(32) NOT NULL,

    recommended_action TEXT NOT NULL,

### Local Storage, Buffer & Synchronization Strategy
1. **Onboard Edge Circular Buffer:** The edge node maintains a 60-second circular RAM buffer of full 100 Hz raw telemetry [INFERENCE]. If an anomaly trigger occurs, the buffer is dumped to onboard NVMe flash as a permanent "blackbox" diagnostic log [INFERENCE].
2. **Bandwidth Reduction via Delta Encoding:** Unaltered steady-state parameters are transmitted at 1 Hz using delta-compression (only transmitting parameter changes exceeding noise thresholds) [INFERENCE]. This reduces SATCOM link payload by > 85% [INFERENCE].
3. **Offline Re-synchronization & Retry Strategy:** If the SATCOM data link breaks during flight, telemetry packets are queued in an onboard SQLite transactional buffer [INFERENCE]. Upon link restoration, the edge and GCS execute a chunked delta sync protocol, prioritizing fault events first and backfilling background telemetry second [INFERENCE].
4. **GCS Offline Client Caching:** The React frontend utilizes Service Workers and IndexedDB to cache telemetry streams locally [INFERENCE]. Operators maintain full interactive access to historical mission trends and replay tools even if the central database connection undergoes temporary maintenance [INFERENCE].
