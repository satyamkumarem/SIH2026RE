# SIH 2026 Solution Dossier: Low Latency and Efficient Voice Activator for Edge Devices

---

## 1. Executive Snapshot

### Summary
This project delivers an end-to-end, privacy-preserving hybrid voice activation and streaming architecture engineered for resource-constrained edge devices [INFERENCE]. Designed for the Indian Space Research Organisation (ISRO), the system runs a custom, ultra-lightweight Keyword Spotting (KWS) model built using TensorFlow Lite for Microcontrollers (TFLM) directly on microcontrollers operating with strictly less than 256KB RAM and under 10% idle CPU utilization [PS]. Upon detecting a user-defined custom wake-word (e.g., "Vyom" or "Vikram"), the edge device instantly switches from local continuous listening mode to streaming mode [INFERENCE]. It transmits a pre-roll audio buffer and subsequent voice stream over a low-overhead, low-latency transport (WebSocket/UDP with Opus or raw PCM framing) to a self-hosted Automated Speech Recognition (ASR) server running Faster-Whisper [INFERENCE]. The architecture eliminates cloud reliance during idle monitoring, protects user privacy, and minimizes bandwidth overhead while guaranteeing sub-200ms end-to-end activation latency [INFERENCE].

## 2. Problem Deconstruction

### Explicit Requirements
* **[REQ-1] Local Edge Keyword Spotting (KWS):** Build an ultra-lightweight, highly accurate KWS model that runs locally on low-power devices [PS].
* **[REQ-2] Instant Streaming to Remote ASR:** Upon keyword detection, the system must instantly and efficiently stream subsequent audio to a remote Automated Speech Recognition (ASR) server with minimal data overhead and latency [PS].
* **[REQ-3] Memory Footprint Limit:** The edge software application must run smoothly within an environment restricted to less than 256KB of RAM [PS].
* **[REQ-4] Idle CPU Usage Limit:** The system must consume under 10% CPU utilization while idling in continuous listening mode [PS].
* **[REQ-5] Physical Hardware Target:** Solutions will be formally evaluated on physical low-power microcontrollers (e.g., Raspberry Pi or ESP32) [PS].
* **[REQ-6] Software Framework Restrictions (Open-Source Only):** Proprietary, closed-source, or commercial voice-activation SDKs (e.g., Picovoice Porcupine, Sensory, Snowboy commercial) are strictly prohibited [PS].
* **[REQ-7] Allowed Frameworks:** Pipelines must be built using open-source ML/TinyML frameworks, specifically TensorFlow Lite for Microcontrollers, PyTorch Mobile, or similar open-source runtimes [PS].
* **[REQ-8] Custom Keyword Requirement:** No pre-trained global keywords (e.g., 'Hey Google', 'Alexa'). Teams must train the KWS model on a custom keyword [PS].
* **[REQ-9] Metric Evaluation (Efficiency, Accuracy, Latency):** Evaluated on model size (RAM/Flash footprint), idle CPU usage, high true-positive rate with near-zero false activations, and time delta between keyword ending and cloud ASR receiving the audio stream [PS].

### Implicit & Derived Implications
* **[IMP-1] Pre-roll Circular Buffer:** To prevent clipping the first syllable of post-keyword command speech, the device must maintain a continuous 300–500ms audio ring buffer in RAM [INFERENCE].
* **[IMP-2] Quantized Int8 Inference:** Meeting the <256KB RAM requirement alongside digital signal processing (DSP) arrays mandates full 8-bit integer (int8) quantization for weights and activations [INFERENCE].
* **[IMP-3] Microcontroller Audio Front-End:** Capturing quality audio on ESP32 requires I2S digital MEMS microphones (e.g., INMP441) rather than noisy analog ADC inputs [INFERENCE].
* **[IMP-4] Audio Compression vs. Latency:** Uncompressed 16kHz PCM consumes 256 kbps bandwidth; using lightweight Opus/ADPCM encoding on ESP32 reduces network overhead by 80% while staying under CPU budgets [RESEARCHED].

## 5. Constraints & Environment Realities

* **Strict Memory Constraints (<256KB RAM):** The entire microcontroller application—including FreeRTOS kernel tasks, TCP/IP stack, I2S DMA buffers, audio feature extraction buffers (MFCC/Spectrogram), and TFLM static tensor arena—must reside within 256KB RAM [PS].
* **Strict CPU Overhead (<10% Idle Utilization):** Continuous FFT/MFCC calculations every 20ms–50ms can easily consume 30–50% CPU if not optimized using CMSIS-DSP SIMD intrinsics or ESP-DSP assembly extensions [RESEARCHED].
* **No Proprietary Binary Blobs:** The implementation cannot rely on closed-source libraries like Picovoice or Alexa Voice Service SDK [PS]. Full C++ source code must be compiled from open-source tools [PS].
* **Wi-Fi / Network Latency Variations:** Edge streaming must handle Wi-Fi packet jitter or micro-dropouts without dropping frames or stalling the microcontroller execution loop [INFERENCE].
* **Acoustic Noise Environments:** Industrial cleanrooms or rocket assembly facilities feature ambient HVAC noise, fan hums, and reverberation, necessitating background noise suppression and data-augmentation during model training [INFERENCE].

## 10. Recommended Approach & Why

### Selection
**Approach 2 (Quantized Int8 Depthwise Separable CNN with TFLM, FreeRTOS Double-Buffering, and WebSocket Streamer)** is selected as the optimal architecture.

### Justification & Rejections
1. **Rejection of Approach 1 (Energy Thresholding):** Fails the fundamental requirement of on-device keyword spotting [PS]. Streaming raw audio whenever sound exceeds a decibel threshold floods the local network, wastes power, and violates privacy [INFERENCE].
2. **Rejection of Approach 3 (Heavy BC-ResNet with Opus):** While BC-ResNet offers slightly higher accuracy, compiling full LibOpus encoding along with deep residual convolutions pushes the idle CPU usage close to or above the strict 10% threshold on standard 240MHz ESP32 microcontrollers [1.2, PS].
3. **Why Approach 2 Wins:**
   * **Resource Footprint:** An 8-bit quantized Depthwise Separable CNN (DS-CNN) with ~38,000 parameters requires only ~45KB of Flash memory and a static TFLM Tensor Arena of ~24KB [3.3, 3.11].
   * **CPU Efficiency:** Computing 10 MFCC features every 30ms using optimized CMSIS-DSP or ESP-DSP functions consumes only ~5–7% CPU on an ESP32-S3 or Cortex-M4 at 160MHz [1.8, PS].
   * **Deterministic Latency:** WebSocket framing over Wi-Fi provides low framing overhead (<1ms) and instant socket transmission, achieving sub-50ms delta between keyword completion and ASR server packet arrival [RESEARCHED].

### Step-by-Step Data Flow Narrative
1. **Audio Acquisition:** The INMP441 I2S MEMS microphone continuously outputs raw 16-bit PCM audio sampled at 16,000 Hz. The microcontroller’s I2S peripheral uses Direct Memory Access (DMA) to stream audio chunks into dynamic ping-pong RAM buffers without involving the CPU [4.6, 4.9].
2. **Circular Pre-Roll Buffering:** Audio frames are continuously written to a 500ms ring buffer in volatile MCU RAM. When the buffer is full, older audio frames are overwritten [2.3, 2.5].
3. **Signal Processing & Feature Extraction:** Every 20ms, the DSP task reads a 30ms window (480 samples). It applies a Hanning window, computes a Fast Fourier Transform (FFT), and generates 10 Mel-Frequency Cepstral Coefficients (MFCCs) using hardware-accelerated fixed-point math (`esp-dsp` / `CMSIS-DSP`) [1.9, 2.4].
4. **TinyML Keyword Inference:** Every 100ms, the 49x10 MFCC tensor representing 1 second of audio is fed into the TFLM interpreter executing the quantized DS-CNN model [1.5, 1.7]. If the output probability for "Vyom" exceeds 0.88 across 2 consecutive frames, a "KEYWORD_DETECTED" event is fired [INFERENCE].
5. **Streaming Transition & Handshake:** The edge state machine transitions from IDLE_LISTENING to STREAMING mode [INFERENCE]. It immediately establishes or wakes the persistent WebSocket socket connection [4.2, 3.3].
6. **Pre-Roll & Live Audio Packetization:** The network task flushes the 500ms pre-roll buffer first, ensuring the beginning of speech isn't clipped, followed immediately by continuous live PCM audio chunks [INFERENCE].
7. **Server-Side Transcription:** The FastAPI WebSocket gateway receives raw audio, applies Silero VAD to detect speech termination, and streams chunks into Faster-Whisper (INT8) for real-time text transcription [3.2, 3.4].

## 13. AI/ML Justification

### Edge KWS Model Analysis
1. **Exact Problem Solved:** Continuous acoustic classification of a 1-second sliding audio window to detect the presence of the specific custom wake-word "Vyom" while ignoring off-target speech, background noise, and phonetically similar words [PS].
2. **Input:** A 2D feature matrix of shape `[49, 10]` representing 49 time frames of 10 MFCC coefficients extracted from 1 second of 16kHz audio [2.4, 1.9].
3. **Output:** A classification probability vector of shape `[3]` (`[0: Silence/Noise, 1: Unknown Word, 2: "Vyom"]`) [1.7].
4. **Why Simpler Rules Fail:** Simple pitch or threshold rules cannot differentiate between "Vyom" and phonetically similar words ("Volume", "Vroom", "Home") or handle variable speaker accents, speech cadences, and background acoustic variations [INFERENCE].
5. **Data Required for Training:** ~1,000 positive custom keyword recordings + ~5,000 negative speech/noise samples [RESEARCHED].
6. **Model Topology & Size:** Depthwise Separable CNN (DS-CNN) with 38.6K parameters [3.3]. Size after INT8 post-training quantization: **42.5 KB Flash**, **~22 KB RAM Tensor Arena** [3.3, 3.5].
7. **Evaluation Metrics:**
   * Keyword Accuracy: >95%
   * False Activation Rate: <1 per 24 hours of background noise
   * Inference Latency: <15ms on ESP32-S3 @ 160MHz
8. **Failure Mode Handling:**
   * *False Positive:* Edge triggers streaming unnecessarily; server VAD/ASR detects no command or invalid keyword and silently closes the socket after 2 seconds [INFERENCE].
   * *False Negative:* User repeats wake-word; model sliding window catches second utterance [INFERENCE].
9. **Human Oversight:** Critical spacecraft control operations require secondary ASR text parsing and explicit user confirmation before executing commands [INFERENCE].

### Non-AI Components
* **Audio Capture & Framing:** Handled purely via deterministic C++ DMA interrupt routines [4.6].
* **Network Streaming & Packetization:** Handled via standard TCP/WebSocket state machine [4.2].

## 14. Data Architecture & Offline/Low-Network Design

### Memory Architecture & Schema
To adhere strictly to the **<256KB RAM budget** [PS], static memory allocation is enforced:

```c
// Static Memory Layout Allocation (Total MCU RAM Used: ~142 KB / 256 KB Limit)
#define TFLM_ARENA_SIZE      (24 * 1024)   // 24 KB Static Tensor Arena
#define PREROLL_BUFFER_SIZE  (16 * 1024)   // 16 KB Ring Buffer (~500ms 16kHz PCM)
#define DMA_PINGPONG_SIZE    (4 * 1024)    // 4 KB Double Buffer
#define MFCC_FEATURE_MATRIX  (49 * 10)     // 490 Bytes
#define WEBSOCKET_TX_BUFFER  (8 * 1024)    // 8 KB Network Frame Buffer
#define FREERTOS_STACKS      (40 * 1024)   // Task Stacks
#define SYSTEM_LWIP_WIFI     (45 * 1024)   // LwIP TCP/IP Stack & Wi-Fi Drivers
```

### Local Caching & Offline Handling
* **Offline Resilience:** If Wi-Fi connection drops, the edge device continues local KWS processing. Upon keyword detection, it attempts immediate socket reconnection [INFERENCE].
* **Ring Buffer Retry Strategy:** If network socket writing blocks temporarily due to Wi-Fi packet retransmission, audio frames buffer into a secondary 2-second SRAM queue [1.1, 1.15]. If the queue overflows, oldest audio is dropped to prevent system crashes [1.12].
* **Bandwidth Reduction:** Audio can optionally be encoded using 4-bit IMA ADPCM or lightweight Opus, reducing network bandwidth from 256 kbps down to 32–64 kbps [RESEARCHED].

## 15. Security, Privacy & Governance

* **Zero Privacy Invasion During Idle State:** The raw audio stream is captured exclusively in volatile MCU SRAM ring buffers [2.5, 1.9]. No audio is ever written to persistent flash memory or transmitted over the network until the local KWS model fires a high-confidence trigger [PS].
* **Transport Encryption:** All audio streaming between edge microcontrollers and the gateway server utilizes TLS-encrypted WebSockets (`wss://`) with mTLS (mutual TLS certificate authentication) to prevent eavesdropping or spoofing [4.10].
* **Access Control & Authorization:** Edge devices embed an HMAC-SHA256 device key in secure MCU hardware storage (e.g., ESP32 eFuse) [INFERENCE]. Each audio stream header contains a signed token to authenticate against the ASR gateway [INFERENCE].
* **Governance & Liability:** The prototype code provided for SIH is an experimental demonstration; operational deployment on spaceflight hardware requires formal ISRO software assurance validation and radiation-hardened hardware testing [INFERENCE].
