# 1. Executive Snapshot

### Summary
Autonomous Underwater Vehicles (AUVs) deployed by oceanographic agencies like the National Institute of Ocean Technology (NIOT) rely on side-scan sonar for benthic mapping and marine exploration [PS]. However, traditional fixed-frequency sonar pings underperform in dynamic underwater environments where water turbidity, salinity, depth, and temperature rapidly alter acoustic propagation [PS]. High-frequency pings (500 kHz) deliver millimeter-resolution imagery but scatter immediately in turbid or deep waters, whereas low-frequency pings (100 kHz) penetrate long distances through murky estuaries at the cost of image resolution [PS]. This dossier presents an actionable, low-power, physical Software-Defined Sonar (SDS) Transmitter Payload designed for a 4-6 student team. Built on an ARM Cortex-M7 (STM32H7) microcontroller platform coupled with Direct Memory Access (DMA), hardware timers, a high-speed Digital-to-Analog Converter (DAC), and an active Sallen-Key analog frontend, the module continuously ingests environmental sensor data and mathematically synthesizes optimized physical analog pulse waveforms—including Linear Frequency Modulated (LFM) chirps, geometric sweeps, and phase-coded pulses—in real time with zero CPU latency stalls [PS, INFERENCE].

# 5. Constraints & Environment Realities

### Field & Environmental Realities
1. **Acoustic Attenuation in Seawater:** Acoustic absorption in seawater is governed by the Francois-Garrison equation [RESEARCHED]. Attenuation rises dramatically with frequency: $\approx 0.03\,\text{dB/m}$ at $100\,\text{kHz}$ versus $\approx 0.16\,\text{dB/m}$ at $500\,\text{kHz}$ [RESEARCHED]. In turbid waters, suspended sediment particles cause volumetric Mie scattering, forcing the sonar to drop to lower frequencies ($100\,\text{kHz}-200\,\text{kHz}$) to maintain range [PS, INFERENCE].
2. **SWaP-C (Size, Weight, Power, and Cost):** AUVs (e.g., NIOT's 1.5m student AUVs or commercial vehicles like Bluefin-12) operate on fixed Li-ion or LiFePO4 battery packs [RESEARCHED]. Payload electronics logic must draw $<2\,\text{W}$ to avoid compromising vehicle endurance [PS, INFERENCE].
3. **Zero In-Mission RF Communication:** Electromagnetic waves do not propagate underwater [KNOWN]. The payload must operate completely autonomously without cloud API access, internet connectivity, or real-time human intervention during mission execution [PS, INFERENCE].
4. **Thermal Constraints in Enclosed Pods:** Sealed underwater pressure vessels have zero airflow [KNOWN]. Power dissipation in the analog amplifier stage must be minimized to prevent internal thermal throttling [INFERENCE].

# 10. Recommended Approach & Why

### Primary Recommendation: Hybrid STM32H7 ARM Cortex-M7 Architecture
The **STM32H743ZI / STM32H723ZG** platform is selected as the optimal architecture for a 4-6 student team [ASSUMPTION].

### Key Justifications
1. **Zero CPU Overhead via Hardware Timer + DMA:** The STM32H7 hardware architecture allows TIM6 to trigger DMA transfers directly from DTCM SRAM to the DAC holding register (`DAC_DHR12RD`). The CPU core remains 99.8% idle during active wave transmission, completely satisfying the strict low-power and CPU stall requirements [PS, INFERENCE].
2. **Dual Internal 12-bit DACs / SPI High-Speed DAC Interface:** Operating the internal DAC in fast mode yields sampling rates up to $1.0 - 2.0\,\text{MSPS}$, sufficient for generating fundamental sonar sweeps up to $400\,\text{kHz}$ [INFERENCE]. An external SPI/Parallel DAC (e.g., DAC8562 or AD9708) can optionally be driven via Quad-SPI/FMC for ultra-high sampling rates up to $10\,\text{MSPS}$ [INFERENCE].
3. **Rapid Development Ecosystem:** Accessible software libraries (STM32CubeHAL, CMSIS-DSP) enable fast implementation of windowing algorithms and ADC adaptation logic without low-level FPGA timing closure issues [INFERENCE].

### Why Alternatives Were Rejected
* **Pure FPGA Approach:** Rejected for the primary core due to the steep HDL hardware debugging curve, high risk of routing/timing failures during the hackathon, and requirement for custom multi-layer PCB design [INFERENCE].
* **TI DSP Approach:** Rejected due to proprietary hardware toolchains, higher power consumption, and lack of integrated high-speed DACs on accessible low-cost dev boards [INFERENCE].

### Data Flow Narrative
1. **Sensor Ingestion:** Physical potentiometers (or actual ocean sensors) present variable DC analog voltages ($0-3.3\,\text{V}$) to the MCU ADC channels. The ADC operates in DMA scan mode [PS, INFERENCE].
2. **Parametric Adaptation:** Upon ADC conversion complete, an interrupt calculates the desired waveform parameters based on environmental conditions:
   * **High Turbidity (Murky Water):** Target $f_c = 100\,\text{kHz}$, $\Delta f = 30\,\text{kHz}$, longer $T_p = 10\,\text{ms}$, maximum power $A = 100\%$ [PS, INFERENCE].
   * **Low Turbidity (Clear Shallow Reef):** Target $f_c = 450\,\text{kHz}$, $\Delta f = 100\,\text{kHz}$, short $T_p = 1\,\text{ms}$, reduced power $A = 40\%$ [PS, INFERENCE].
3. **DDS Buffer Synthesis:** The CPU writes the synthesized 12-bit waveform data into inactive Buffer B of the ping-pong DMA memory block [INFERENCE].
4. **Hardware DMA Streaming:** Hardware Timer TIM6 generates periodic TRGO trigger pulses at $f_s = 2.5\,\text{MSPS}$. DMA1 streams 12-bit digital words from DTCM RAM directly to `DAC1->DHR12RD` without CPU cycle consumption [PS, INFERENCE].
5. **Analog Reconstruction & Envelope Tapering:** The DAC output voltage passes through a high-slew-rate active Sallen-Key LPF ($f_c = 600\,\text{kHz}$) to eliminate aliasing stair-steps, followed by a driver stage to yield a smooth, windowed physical analog acoustic ping [PS, INFERENCE].

# 13. AI/ML Justification

### Core Synthesis Engine: Classical Signal Processing (NO AI/ML REQUIRED)
* **Question 1: What exact problem does AI solve?** None in the real-time wave synthesis path [INFERENCE].
* **Question 4: Why can a simpler rule/system not solve it?** Classical Direct Digital Synthesis (DDS), trigonometric equations, and empirical hydroacoustic propagation models (Francois-Garrison) solve waveform generation deterministically in $<1\,\mu\text{s}$ with zero prediction error or non-deterministic latency [INFERENCE].

# 14. Data Architecture & Offline/Low-Network Design

### Circular Ping-Pong DMA Memory Schema

```
  DTCM RAM MEMORY BUFFER LAYOUT
  +-------------------------------------------------------------+
  | BUFFER A (2048 Samples x 16-bit) -> Currently Streaming DAC |
  +-------------------------------------------------------------+
  | BUFFER B (2048 Samples x 16-bit) -> Updating via ADC Logic  |
  +-------------------------------------------------------------+
               │                                   ▲
               └────── DMA Half-Transfer ISR ──────┘
```

1. **Zero-Wait-State Memory Placement:** Sine wave lookup tables and active ping-pong buffers are mapped to the STM32H7 DTCM (Data Tightly-Coupled Memory) RAM located at address `0x20000000`, bypassing the main AXI bus matrix for zero-latency CPU and DMA access [INFERENCE].
2. **Ping-Pong Buffer Execution Flow:**
   * DMA Stream 0 transfers Buffer A to `DAC1->DHR12RD` triggered by TIM6 TRGO events [INFERENCE].
   * When Buffer A reaches half-transfer, DMA generates a `Transfer Half Complete` interrupt [INFERENCE].
   * The MCU core reads current ADC environmental values, computes new phase increment $\Delta \theta$, and populates Buffer B [INFERENCE].
   * Upon `Transfer Complete`, DMA automatically loops back to Buffer B while the CPU populates Buffer A [INFERENCE].
3. **Bandwidth & Latency Optimization:**
   * Processing latency per buffer update: $< 8.5\,\mu\text{s}$ at $480\,\text{MHz}$ [INFERENCE].
   * External network requirement: **0 KB/s** (100% offline edge execution) [PS, INFERENCE].
