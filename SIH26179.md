# Qualcomm Edge Retail Intelligence Dossier: SIH26179

---

## 1. Executive Snapshot

### Executive Summary
The Qualcomm-sponsored problem statement **SIH26179** demands an edge-native, privacy-preserving, AI-powered retail intelligence platform tailored for Indian retail environments—ranging from Kirana stores to multi-lane supermarkets [PS]. Modern retail operations in Tier-2 and Tier-3 Indian cities are severely hindered by frequent internet disruptions, stock-outs, inventory shrinkage, unmonitored shelf compliance, and long billing queues that degrade customer experience [PS, INFERENCE]. Cloud-only vision analytics solutions incur exorbitant bandwidth costs, latency spikes, recurring cloud GPU fees, and grave customer privacy concerns [KNOWN, INFERENCE]. The proposed solution, **OmniEdge Retail AI**, solves this by executing computer vision models—including anonymous shopper tracking, densely packed shelf inventory auditing, and queue congestion forecasting—directly on Qualcomm Snapdragon / Dragonwing edge hardware using the Qualcomm Neural Processing SDK and converted Deep Learning Container (`.dlc`) models [PS, RESEARCHED]. By decoupling real-time store analytics from cloud connectivity, OmniEdge processes RTSP video streams locally, scrubbing raw frames in-memory and outputting only lightweight, anonymized telemetry JSON [INFERENCE]. This delivers sub-100ms inference latency, zero cloud streaming costs, 100% offline resilience during network outages, and strict compliance with India's Digital Personal Data Protection (DPDP) Act 2023 [KNOWN, INFERENCE].

## 5. Constraints & Environment Realities

1.  **Network & Connectivity Constraints (Tier-2 / Tier-3 India):**
    *   *Reality:* Cellular 4G/5G and local broadband in non-metro Indian commercial districts suffer daily downtime, packet loss, and severe bandwidth throttling [KNOWN, INFERENCE].
    *   *Design Impact:* System MUST NOT stream live camera video to cloud servers [PS, INFERENCE]. All video decoding, AI inference, tracking, aggregation, local storage, and alert generation must happen entirely inside the store LAN [INFERENCE].
2.  **Power & Electrical Stability:**
    *   *Reality:* Unscheduled power outages and voltage spikes are routine; stores rely on basic inverter/UPS back-ups [KNOWN].
    *   *Design Impact:* Edge hardware must be low-power ($\le 15\text{W} - 30\text{W}$) and run on power-efficient ARM architectures (e.g., Qualcomm QCS6490 / RB5) [RESEARCHED, INFERENCE]. Database engines must use write-ahead logging (WAL) in SQLite/DuckDB to prevent corruption during sudden hard reboots [INFERENCE].
3.  **Lighting & Store Physical Conditions:**
    *   *Reality:* Kirana and Tier-2 supermarkets frequently mix flickering fluorescent tubes, natural sunlight glare, dim corner aisles, and crowded, narrow passages with hanging promotional flyers [KNOWN, INFERENCE].
    *   *Design Impact:* Vision models must be trained with heavy data augmentation (brightness/contrast jitter, occlusion, shadow synthesis) and robust multi-object tracking (ByteTRACK) resilient to temporary occlusions [INFERENCE].
4.  **Hardware & Mounting Limitations:**
    *   *Reality:* Retailers will not install expensive ceiling truss systems. Cameras will be mounted on existing walls, light poles, or directly onto shelf headers at angles ranging from $30^\circ$ to $70^\circ$ [INFERENCE].
    *   *Design Impact:* Camera calibration module must support wide-angle distortion correction and homography matrix transformation for accurate floorplan mapping [INFERENCE].
5.  **Regulatory & Privacy Laws (India DPDP Act 2023):**
    *   *Reality:* Storing identifiable personal video records without explicit user consent violates Indian data privacy laws and creates legal liability [KNOWN].
    *   *Design Impact:* Strict architecture rule: **Zero face recognition, zero persistent biological tracking**. Video frames must reside in volatile RAM only during inference pass and purged immediately [PS, INFERENCE].

## 10. Recommended Approach & Why

### Selection: Approach 3 (Qualcomm On-Device Edge AI Platform)

#### Why Alternatives Were Rejected:
1.  **Approach 1 (Cloud-Centric):** Directly violates explicit requirement 4a ("Run all computer vision models locally on edge hardware") and requirement 4b ("Operate even during internet disruptions") [PS]. It introduces unsustainable monthly cloud bills and violates privacy requirement 5c [PS, INFERENCE].
2.  **Approach 2 (Heavy x86 GPU Server):** Fails the economic and environmental constraints of Indian retail stores (high power consumption, active fan maintenance in dusty environments, high upfront cost) and fails to leverage Qualcomm hardware—the sponsoring organization [PS, RESEARCHED, INFERENCE].

#### Why Approach 3 Wins:
*   **100% Problem Alignment:** Built precisely around Qualcomm's edge AI stack (Qualcomm Neural Processing SDK, Deep Learning Container `.dlc` format, Hexagon DSP/NPU acceleration) [PS, RESEARCHED].

### Data Flow Narrative

1.  **Ingestion:** Multiple IP cameras stream H.264/H.265 RTSP feeds over the store's local Wi-Fi/Ethernet network to the Qualcomm Edge AI Node [INFERENCE].
2.  **Inference & Anonymization:** The edge node decodes video streams in RAM [INFERENCE]. The Qualcomm Neural Processing SDK passes frame tensors directly into converted `.dlc` neural network containers running on the Hexagon NPU [RESEARCHED, INFERENCE].
    *   *Entrance Camera:* YOLOv8n detects human bounding boxes; ByteTRACK assigns temporary IDs to calculate entry/exit line crossings [INFERENCE].
    *   *Aisle Cameras:* YOLOv8n tracks shopper centroids inside designated ROI polygons to compute zone dwell time [INFERENCE]. Coordinates are projected onto a 2D floorplan via homography matrix multiplication to generate movement heatmaps [INFERENCE].
    *   *Shelf Cameras:* Dense object detector inspects shelf bounding boxes against reference planogram masks to flag empty gaps (out-of-stock) [INFERENCE].
    *   *Queue Camera:* Person tracking inside queue ROI polygons calculates queue length, service duration, and forecasts congestion 10 minutes ahead [INFERENCE].
    *   *Frame Purging:* Video frames are instantly overwritten in volatile RAM after inference pass. Zero video is saved to disk [PS, INFERENCE].
3.  **Local Event Processing:** Inferred coordinates and detection events are published to the local Mosquitto MQTT broker (`events/entry`, `events/shelf_out_of_stock`, `events/queue_alert`) [INFERENCE].
4.  **Local Storage & Alerting:** The FastAPI edge service subscribes to MQTT topics, updates local SQLite tables, and pushes real-time WebSocket alerts to floor staff mobile apps and store manager dashboards [INFERENCE].
5.  **POS Integration:** When a cashier scans items at POS, the transaction total and SKU count are posted to the local edge REST API (`/api/v1/pos/transaction`), enabling immediate sales conversion calculation ($\frac{\text{POS Transactions}}{\text{Entrance Footfall}}$) [INFERENCE].
6.  **Cloud Sync:** When internet connectivity is online, a background daemon uploads compressed daily JSON metrics to the central cloud platform for multi-store benchmarking [INFERENCE].

## 13. AI/ML Justification

### 1. Anonymous Shopper Detection & Footfall Tracking
*   **Purpose:** Detect customers, count store entries/exits, track dwell time, and generate movement heatmaps [PS].
*   **Model Type:** YOLOv8-nano (Object Detection) + ByteTRACK (Heuristic Multi-Object Tracker) [RESEARCHED].
*   **Input:** 1080p RTSP camera frame (30 FPS, resized to $640 \times 640$).
*   **Output:** List of bounding boxes: `[class_id=0 (person), confidence, x1, y1, x2, y2]` + `track_id`.
*   **Data Required:** COCO dataset + VisDrone / MOT20 fine-tuning [RESEARCHED].
*   **Why AI is Necessary:** Traditional infrared break-beams cannot measure dwell time, movement vectors, or zone heatmaps [INFERENCE]. Rule-based blob detection fails under crowding [INFERENCE].
*   **Evaluation:** Mean Average Precision (mAP@50 $\ge 85\%$), Multiple Object Tracking Accuracy (MOTA $\ge 75\%$) [INFERENCE].
*   **Failure Mode:** Severe camera occlusion or extreme low light.
*   **Human Oversight:** None required for automated counting; aggregated metrics displayed on dashboard [INFERENCE].

### 2. Dense Shelf Inventory & Out-of-Stock Detector
*   **Purpose:** Identify empty shelf gaps, count product facings, and detect planogram compliance errors [PS].
*   **Model Type:** Custom YOLOv8 Medium/Nano trained on SKU-110K dataset [RESEARCHED].
*   **Input:** High-resolution shelf crop image ($1280 \times 1280$) taken every 60 seconds [INFERENCE].
*   **Output:** Grid array of detected SKU bounding boxes + Occupancy Ratio per shelf zone [INFERENCE].
*   **Data Required:** SKU-110K dataset (11,743 images, 1.7M bounding boxes) + store planogram target map [RESEARCHED].
*   **Why AI is Necessary:** Rule-based color/edge detection fails due to changing product packaging, shadows, and packaging updates [INFERENCE].
*   **Evaluation:** Precision/Recall on dense object bounding boxes (mAP@50 $\ge 80\%$) [INFERENCE].
*   **Failure Mode:** False positive out-of-stock alert if a shopper temporarily blocks the camera view.
*   **Human Oversight:** Alerts push a visual crop of the shelf zone to floor staff mobile app; staff physically verifies before restocking [INFERENCE].

### 3. Queue Length & Congestion Forecaster
*   **Purpose:** Count shoppers in queue zone and predict queue wait time 10 minutes ahead [PS].
*   **Model Type:** Hybrid AI-Heuristic Model: Person detection ROI count + Differential Inflow-Outflow Time-Series Equation [INFERENCE].
*   **Input:** Current queue count $N(t)$, entry footfall velocity $\frac{dE}{dt}$, historical average checkout rate $S$ (seconds per customer) [INFERENCE].
*   **Output:** Predicted queue length $N(t+10\text{min})$ and predicted wait time $T_{\text{wait}}$ [INFERENCE].
*   **Data Required:** Historical queue length logs and POS transaction time stamps [INFERENCE].
*   **Why AI is Necessary:** Simple static thresholding triggers alerts *after* the line is long; predictive modeling triggers alerts *before* congestion occurs [PS, INFERENCE].
*   **Evaluation:** Mean Absolute Error (MAE) $< 1.5$ persons on 10-minute horizon forecast [INFERENCE].
*   **Failure Mode:** Unexpected cashier shift change or terminal freeze causes forecast lag.
*   **Human Oversight:** Store manager receives "Open Counter 3" recommendation and makes final decision to deploy staff [PS, INFERENCE].

### Explicit Non-AI Directives:
*   **DO NOT USE AI FOR:**
    1.  *Counter Recommendation Logic:* Standard deterministic threshold rules (`if predicted_wait > 4 mins and closed_counters > 0 trigger alert`) [INFERENCE].
    2.  *POS Sales Conversion:* Pure arithmetic division ($\frac{\text{Sales Count}}{\text{Footfall Count}}$) [INFERENCE].
    3.  *Planogram Layout Storage:* Static JSON database mapping [INFERENCE].

### Local SQLite Database Schema

```sql
-- Store Configuration & Metadata
CREATE TABLE store_zones (
    zone_id INTEGER PRIMARY KEY AUTOINCREMENT,
    zone_name TEXT NOT NULL, -- e.g., 'Aisle 1 - Dairy', 'Entrance', 'Queue 1'
    camera_id TEXT NOT NULL,
    roi_polygon TEXT NOT NULL -- JSON array of polygon coordinates [[x1,y1], [x2,y2]...]
);

-- Real-Time Footfall Log (Anonymized)
CREATE TABLE footfall_events (
    event_id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    camera_id TEXT NOT NULL,
    direction TEXT CHECK(direction IN ('IN', 'OUT')),
    track_id INTEGER NOT NULL
);

-- Zone Dwell Analytics Log
CREATE TABLE zone_dwell_logs (
    log_id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    zone_id INTEGER FOREIGN KEY REFERENCES store_zones(zone_id),
    track_id INTEGER NOT NULL,
    dwell_duration_seconds REAL NOT NULL
);

-- Shelf Inventory & Out-of-Stock Status
CREATE TABLE shelf_status (
    shelf_id TEXT PRIMARY KEY, -- e.g., 'AISLE_02_SHELF_03'
    zone_id INTEGER FOREIGN KEY REFERENCES store_zones(zone_id),
    expected_facings INTEGER NOT NULL,
    detected_facings INTEGER NOT NULL,
    occupancy_percentage REAL NOT NULL,
    status TEXT CHECK(status IN ('NORMAL', 'LOW_STOCK', 'OUT_OF_STOCK')),
    last_inspected DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Queue Intelligence Log
CREATE TABLE queue_metrics (
    metric_id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    counter_id TEXT NOT NULL,
    current_queue_count INTEGER NOT NULL,
    predicted_wait_time_minutes REAL NOT NULL,
    active_counters INTEGER NOT NULL,
    recommended_counters INTEGER NOT NULL
);

-- Offline Telemetry Sync Queue
CREATE TABLE sync_queue (
    payload_id INTEGER PRIMARY KEY AUTOINCREMENT,
    payload_json TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    sync_status TEXT DEFAULT 'PENDING' CHECK(sync_status IN ('PENDING', 'SYNCED', 'FAILED'))
);
```

### Synchronization & Low-Network Strategy
*   **Local Caching:** All analytics events are written directly to the local SQLite database running in Write-Ahead Logging (WAL) mode, guaranteeing zero data loss during network outages [INFERENCE].
*   **Payload Compression:** Every hour, a background sync service aggregates atomic events into compressed JSON summaries (e.g., hourly footfall histogram, shelf out-of-stock events) [INFERENCE]. Payload size is typically $< 50\text{ KB}$ per store/day [INFERENCE].
*   **Retry & Backoff:** When internet connectivity is restored, the sync manager sends queued payloads to the cloud endpoint using an exponential backoff algorithm (`1s, 2s, 4s, 8s ... max 300s`) [INFERENCE].
*   **Conflict Handling:** The edge database is the **single source of truth** for real-time operational state and store metrics [INFERENCE]. Cloud serves purely as a read-only historical reporting portal [INFERENCE].
*   **Bandwidth Reduction:** Raw video is **never transmitted over the WAN** [PS]. Bandwidth consumption drops from gigabytes/hour to kilobytes/day [INFERENCE].
