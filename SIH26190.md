## 1. Executive Snapshot

This dossier presents a comprehensive technical blueprint and strategic roadmap for developing a **Secure Digital Document Management System (DMS) for Legal and Investigation Documents** [PS]. Tailored for the Ministry of Home Affairs (MHA), National Crime Records Bureau (NCRB) – Women Safety Division [PS], the system provides an end-to-end, tamper-proof, legally compliant digital platform for handling sensitive case files—including FIRs, charge sheets, witness statements, forensic reports, and court filings [PS]. By combining Role-Based / Attribute-Based Access Control (RBAC/ABAC), Public Key Infrastructure (PKI) digital signatures, automated AI-driven OCR and semantic search, and an immutable permissioned Blockchain audit ledger (Hyperledger Fabric), the proposed system eliminates paper-handling bottlenecks while ensuring non-repudiation and evidentiary admissibility under Section 63 of the Bharatiya Sakshya Adhiniyam (BSA), 2023 [RESEARCHED].

## 5. Constraints & Environment Realities

*   **Connectivity Realities:** Rural police stations in Tier-3 towns and remote districts frequently suffer from intermittent or low-bandwidth cellular/broadband connections (2G/3G speeds or frequent dropouts) [KNOWN]. The system *cannot* depend on continuous high-speed cloud connectivity for initial data capture.
*   **Hardware Realities:** Field officers rely on low-to-mid-range Android smartphones (2GB-4GB RAM) or aging desktop PCs in station offices running legacy web browsers [KNOWN]. The system must feature an ultra-lightweight frontend web/mobile client.
*   **Language & Literacy Realities:** Primary case entries (FIRs, witness statements) are recorded in local regional languages (e.g., Hindi, Marathi, Tamil, Bengali) [KNOWN]. The AI OCR and search engine must support multilingual extraction and Zero-FIR translation standards [RESEARCHED].
*   **Legal & Admissibility Constraints:** Under Indian evidence law (Bharatiya Sakshya Adhiniyam, 2023, Section 63), electronic records are admissible *only* if chain-of-custody, system integrity, hash verification, and dual-certification (Part A device controller + Part B technical expert) are satisfied [RESEARCHED]. A generic document management system lacking cryptographic chain-of-custody will fail in court.
*   **Deployment Architecture Mandate:** Government policy mandates that sensitive police/judicial systems reside on MeitY-empanelled cloud infrastructure (e.g., NIC MeghRaj Cloud) with strict data residency within Indian geographic boundaries [RESEARCHED].

## 10. Recommended Approach & Why

**Selected Approach:** **Approach 2 – Hybrid Architecture combining Microservices Storage, Permissioned Hyperledger Fabric Blockchain, AI-Driven OCR/Search, and PKI Digital Signature Certification.**

### Architectural Justification

1.  **Off-Chain Storage with On-Chain Cryptographic Integrity:** Heavy files (scanned multi-page PDF charge sheets, forensic videos, medical reports) are encrypted and stored in secure S3-compatible Object Storage (MinIO / AWS S3). Only the immutable cryptographic fingerprint (SHA-256 hash), document metadata, version history, and audit event logs are committed to the Hyperledger Fabric ledger [INFERENCE].
2.  **BSA 2023 Statutory Alignment:** This design directly satisfies Section 63 of the Bharatiya Sakshya Adhiniyam, 2023. When a document is produced in court, the system compares its current file hash against the ledger hash written at time of creation, auto-generating a certified Part A/B compliance slip [RESEARCHED].
3.  **Privacy Compliance:** Under India's Digital Personal Data Protection (DPDP) Act, 2023, personal data must be managed with strict access controls and auto-redaction capabilities [KNOWN]. Storing raw documents on a public blockchain (Approach 3) violates privacy laws, whereas off-chain storage allows automated PII masking while maintaining audit integrity on the private ledger [INFERENCE].

### Why Alternatives Were Rejected

*   **Approach 1 (Traditional SQL Cloud DMS):** Rejected because standard database logs can be manipulated by DB administrators, cloud hosting root users, or insider threats. It lacks true cryptographic non-repudiation required for high-stakes criminal trials [INFERENCE].
*   **Approach 3 (Public Blockchain + IPFS):** Rejected because public blockchains incur unpredictable gas fees, slow transaction finality, and violate Indian data sovereignty and data privacy mandates by broadcasting encrypted legal metadata to global nodes [INFERENCE].

### Detailed Step-by-Step Data Flow Narrative

1.  **Document Capture & Ingestion:**
    *   An Investigating Officer (IO) uploads a scanned charge sheet PDF or captures photos via the Mobile Field App.
    *   The client app calculates a local SHA-256 hash immediately upon capture.
2.  **Encryption & Off-Chain Storage:**
    *   The file payload is encrypted client-side or at gateway using AES-256 envelope encryption.
    *   The encrypted binary object is transferred via TLS 1.3 to MinIO / S3 Object Storage, returning a unique Content Identifier (CID/URI).
3.  **Blockchain Ledger Commit:**
    *   The Ingestion Service constructs a transaction block containing: `{ DocumentID, CaseID, SHA256_Hash, StorageURI, UploaderID, Timestamp, State: "SUBMITTED" }`.
    *   This transaction is submitted to the Hyperledger Fabric network. Endorsing peer nodes (Police HQ, FSL, Prosecution) execute smart contract validation and commit the block to the ledger.
4.  **AI OCR, Indexing & Redaction:**
    *   An asynchronous worker triggers PaddleOCR to extract text from scanned pages (supporting English & Hindi).
    *   The PII Redaction service identifies sensitive victim details using Named Entity Recognition (NER) and creates a sanitized view for unauthorized roles.
    *   Extracted text is indexed into Elasticsearch and vectorized into PostgreSQL `pgvector` for semantic search.
5.  **Multi-Agency Verification & Legal Certificate Output:**
    *   When the Prosecutor or Court Magistrate requests the file, the system fetches the encrypted file from Object Storage, computes its live SHA-256 hash, and compares it against the Hyperledger Fabric ledger record.
    *   If hashes match 100%, the document is rendered along with an auto-generated **BSA Section 63 Digital Certificate PDF** bearing the verified ledger timestamp and PKI digital signatures.

```sql
    is_confidential BOOLEAN DEFAULT FALSE,
    blockchain_tx_id VARCHAR(128),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- BSA Sec 63 Compliance Audit Log
CREATE TABLE bsa_certificates (
    cert_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID REFERENCES legal_documents(document_id),
    part_a_signer_id UUID NOT NULL,
    part_b_expert_id UUID,
    generated_hash CHAR(64) NOT NULL,
    verification_status VARCHAR(30) DEFAULT 'VERIFIED',
    issued_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Offline-First Mobile Synchronization Strategy

```
+-----------------------------------------------------------------------------------------------------------------+
|                                    OFFLINE MOBILITY & SYNC ARCHITECTURE                                         |
|                                                                                                                 |
|   +-----------------------------------------------------------------------------------------+                   |
|   | Mobile Device (Offline Police Station / Field Location)                                 |                   |
|   |  1. Capture Document -> Save to Local Encrypted SQLite Database                         |                   |
|   |  2. Compute Local SHA-256 Hash immediately upon photo creation                          |                   |
|   |  3. Store in Local Queue [Status: PENDING_SYNC]                                         |                   |
|   +-----------------------------------------------------------------------------------------+                   |
|                                                |                                                                |
|                                                v (Network Reconnected - Auto Background Sync)                   |
|   +-----------------------------------------------------------------------------------------+                   |
|   | Sync Gateway                                                                            |                   |
|   |  4. Upload encrypted payload via TLS 1.3 Resume-able Multipart Transfer                 |                   |
|   |  5. Compare client hash with gateway hash                                               |                   |
|   |  6. Commit to Hyperledger Fabric Ledger & update status to [SYNCED]                     |                   |
|   +-----------------------------------------------------------------------------------------+                   |
+-----------------------------------------------------------------------------------------------------------------+
```

*   **Conflict Resolution:** Last-Write-Wins (LWW) with Immutable Immutable Versioning. Modifying a document creates a new version record (`v1`, `v2`) on the ledger; previous versions are never overwritten [INFERENCE].
*   **Bandwidth Reduction:** Images/PDFs are compressed on-device using WebP / optimized PDF compression algorithms prior to transfer, saving up to 70% cellular data overhead [INFERENCE].
