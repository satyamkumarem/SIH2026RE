## 5. Constraints & Environment Realities

* **Geography & Field Conditions:** Heritage monuments, ASI (Archaeological Survey of India) sites, and rural cultural centers are frequently located in remote areas with thick stone masonry, creating cellular dead zones [KNOWN].
* **Connectivity:** Unreliable internet access (frequent packet loss, 2G/3G speeds, or total blackouts) [KNOWN]. System **must** run core narration and tactile responses completely offline [INFERENCE].
* **Power Supply:** Intermittent grid power at rural cultural venues [KNOWN]. Kiosk power design must support wide-input 12V DC power with an integrated Lithium-ion / LiFePO4 battery backup for 4+ hours of uninterrupted operation [ASSUMPTION].
* **Language & Diversity:** India has 22 officially recognized languages and hundreds of dialects [KNOWN]. Text-only or monolingual systems exclude over 70% of potential visitors [INFERENCE]. Audio-first, multi-lingual voice synthesis is mandatory [INFERENCE].
* **Hardware Procurement & Budget:** Student teams face budget limits (~₹10,000 – ₹20,000 per prototype) and component availability constraints in local Indian markets (e.g., Nehru Place, Lamington Road, SP Road) [KNOWN]. Components must be standard, commercially available modules [ASSUMPTION].
* **Physical Durability & Vandalism:** Public hardware units undergo heavy wear and tear. Enclosures must use thick acrylic, wood, or sheet metal with flush-mounted capacitive touch contacts rather than fragile mechanical buttons [INFERENCE].

### Detailed Data Flow Narrative

1. **User Interaction & Tactile Triggering:** A visitor touches a specific architectural section (e.g., the carved wheel of a 3D-milled Konark temple panel) or scans a physical artifact token on the NFC pad [INFERENCE].
2. **Embedded Signal Acquisition:** The MPR121 capacitive touch sensor IC detects a delta in capacitance (exceeding preset noise threshold) and generates an active-low interrupt signal on the ESP32-S3 microcontroller [KNOWN].
3. **Event Serialization:** The ESP32 formats the event into a JSON payload: `{"event": "touch", "zone_id": "wheel_section_03", "timestamp": 1725525750}` and transmits it over high-speed USB-UART (115200 baud) to the Raspberry Pi 5 [ASSUMPTION].
4. **Local Logic & Content Lookup:** The Raspberry Pi's Asyncio Python daemon captures the UART packet, queries the local SQLite database for `zone_id = "wheel_section_03"` in the selected language (e.g., Odia/Hindi), and retrieves the text script, visual media path, and lighting cues [INFERENCE].
5. **Multi-Lingual Audio Generation:**
   * *Online Mode:* If 4G/Wi-Fi is active, the system dispatches an HTTPS POST request to the **Bhashini API Pipeline** to convert script text into high-fidelity streaming WAV audio [RESEARCHED].
   * *Offline Mode:* If offline, the daemon routes the request to the onboard **Piper Local TTS Engine** running a lightweight ONNX model, generating clear audio in <200ms latency [INFERENCE].
6. **Synchronized Playback:** The audio pipeline streams speech to the hardware amplifier speaker, while the Express/React UI on the connected HDMI monitor updates simultaneously to show related 4K imagery, historical timelines, and sign language video overlay [INFERENCE].

### Detailed AI Component Analysis

#### Component 1: Multi-lingual Voice Synthesis (Bhashini Pipeline)
1. **Purpose:** Convert text scripts describing cultural heritage into natural-sounding speech across 22 scheduled Indian languages [RESEARCHED].
2. **Model Type:** Deep Neural Text-to-Speech (VITS / FastSpeech2 architecture hosted on Bhashini servers) [RESEARCHED].
3. **Input:** UTF-8 text string + target language code (e.g., `hi` for Hindi, `ta` for Tamil).
4. **Output:** 24kHz WAV/MP3 audio stream.
5. **Why AI is Preferable:** Pre-recording static human audio for millions of heritage descriptions across 22 languages requires thousands of studio hours and terabytes of storage. Neural TTS generates audio dynamically on demand [INFERENCE].
6. **Evaluation Metric:** Mean Opinion Score (MOS > 4.0 for voice naturalness and pronunciation accuracy).
7. **Failure Mode:** Internet latency spike or API downtime.
8. **Failure Mitigation:** Automatic fallback to pre-rendered local audio clips or onboard Piper TTS ONNX engine [INFERENCE].
9. **Human Oversight:** Curators verify text script accuracy in the CMS before sending to the TTS generator [INFERENCE].

#### WHERE AI SHOULD NOT BE USED
* **Physical Touch Event Detection:** Must remain strictly deterministic rule-based code reading raw capacitance register thresholds from the MPR121 sensor [INFERENCE]. Attempting to use ML models for touch detection introduces unnecessary latency, unexplainable false positives, and power overhead [INFERENCE].
* **System State Transitions:** UI page switches, RFID card reading, and audio volume adjustments must use explicit, deterministic state machines [INFERENCE].

