## 5. Constraints & Environment Realities

1. **Camera Network Degradation & Field Conditions**:
   - In Indian urban environments, CCTVs face dust accumulation, lens smudges, monsoon rain distortion, severe headlight glare at night, and extreme viewing angles [RESEARCHED]. Cameras deployed by BEL across cities like Chandigarh or Jammu often face maintenance outages (e.g., 8-10% offline rate) [RESEARCHED].
   - *Implication*: The OCR pipeline cannot rely on high-resolution, front-facing clear images; it must include preprocessing (contrast enhancement, perspective correction, sharpening) [INFERENCE].

2. **Network Bandwidth & Edge Constraints**:
   - Streaming full HD (1080p/4K) raw video from hundreds of junction cameras to a central cloud server consumes massive backhaul bandwidth (up to 4-8 Mbps per camera) [KNOWN].
   - *Implication*: The architecture must support hybrid edge-cloud deployment where edge processing units (e.g., NVIDIA Jetson / edge servers) perform detection and OCR locally, transmitting lightweight JSON metadata payloads (`{plate: "DL01AB1234", timestamp: "...", camera_id: "CAM_102"}`) over cellular/leased lines to the central server, while retaining compressed frame snapshots for verification [INFERENCE].

3. **Plate Heterogeneity & HSRP Compliance**:
   - Indian roads feature diverse vehicle classes (2-wheelers, 3-wheelers, cars, commercial trucks) with varying plate sizes, multi-line character layouts, regional scripts, modified/non-standard fonts, and official High Security Registration Plates (HSRP) conforming to AIS-159 / CMVR 1989 standards [RESEARCHED].
   - *Implication*: The OCR engine must handle double-line plates (common on two-wheelers and commercial vehicles) and recognize standard HSRP FE-Schrift fonts as well as custom fonts with equal robustness [INFERENCE].

4. **Hardware & Budget Realities for Hackathon Demonstration**:
   - University student teams do not possess city-wide live camera networks or expensive GPU clusters during the hackathon evaluation [KNOWN].
   - *Implication*: The MVP must simulate multi-camera RTSP video streams locally or via cloud instances, serving realistic pre-recorded traffic video feeds tied to simulated geographic coordinate nodes [ASSUMPTION].

## 9. Candidate Solution Approaches

### Approach 1: Edge-Heavy Monolithic Pipeline (Traditional OCR + Relational Spatial Queries)
- **Mechanism**: Edge devices perform plate detection using basic Haar cascade/YOLOv5 and execute Tesseract OCR locally. Extracted text and timestamps are sent via HTTP POST to a centralized monolithic relational database (PostgreSQL). Trajectories are calculated using standard SQL `GROUP BY plate_number ORDER BY timestamp`.
- **Pros**: Low cloud computing cost; simple architecture; easy to understand.
- **Cons**: Tesseract OCR struggles (<70% accuracy) on angled, blurred, or dirty plates [RESEARCHED]. Relational `GROUP BY` queries on millions of detection rows cause massive database latency during trajectory reconstruction. Lacks route anomaly detection and real-time streaming capability.
- **Feasibility**: High for simple demo, Low for meeting problem requirements (>90% accuracy, real-time analytics).

### Approach 2: Microservices Architecture with YOLOv11/PaddleOCR + Spatial-Temporal Graph Indexing (PostGIS + Uber H3 + TimescaleDB) [RECOMMENDED]
- **Mechanism**: Edge/Cloud ingestion workers process RTSP feeds using fine-tuned **YOLOv11** for plate localization and **PaddleOCR / Fast-Plate-OCR** fine-tuned on Indian HSRP dataset with pre-processing pipelines (CLAHE, unsharp masking). Detection events are streamed to **Apache Kafka**. **TimescaleDB + PostGIS** handles time-series spatial tracking, while **Uber H3** hexagonal indexing enables real-time spatial aggregation for macro heatmaps. Trajectory reconstruction uses road network map-matching (`pgRouting`). **Redis** handles sub-10ms blacklist matching.
- **Pros**: Exceeds >90% OCR accuracy; highly scalable time-series spatial database; sub-second heatmap rendering via H3 spatial indexing; highly modular microservices.
- **Cons**: Requires managing multi-container infrastructure (Kafka, PostGIS, Redis, Python microservices).
- **Feasibility**: Very High for 4-6 student team using Docker Compose during hackathon; fully enterprise-grade for production.

### Approach 3: Fully Decentralized Streaming Architecture (Kafka + Flink + Deep Visual Re-ID Embeddings + Graph DB)
- **Mechanism**: Ingests raw video streams into a central cluster. Uses a multi-modal AI pipeline that extracts license plate text *and* vehicle visual appearance feature vectors (ResNet-50 visual Re-ID). Streams events into **Apache Flink** for complex event processing (CEP), storing trajectories directly in a Graph Database (**Neo4j**).
- **Pros**: Handles missing or completely unreadable license plates via visual vehicle Re-ID (color, make, model, scratches).
- **Cons**: Extremely high computational cost (requires massive GPU clusters for continuous multi-camera visual embedding generation); extreme implementation complexity for a student team in a hackathon setting.
- **Feasibility**: Low for hackathon timeframe; high risk of non-functional demo.

### Detailed Data Flow Narrative

1. **Video Capture & Framing**: An RTSP camera feed at an urban junction broadcasts a multi-lane video stream. The Ingestion Engine captures frames at 15-25 FPS [INFERENCE].
2. **Detection & Cropping**: Frames enter the YOLOv11 Plate Detector. Bounding box coordinates for all visible license plates are extracted. Bounding boxes are cropped and passed through contrast enhancement (CLAHE) [INFERENCE].
3. **OCR Character Extraction**: The cropped plate image is passed to the fine-tuned PaddleOCR model. The raw text output (e.g., `"DL01CA1234"`) is assigned a confidence score [INFERENCE].
4. **Regex & Formatting Cleaning**: The plate string is validated against standard Indian vehicle registration patterns. If slight character confusion occurs (e.g., `'O'` vs `'0'`), regex rules correct positional characters [INFERENCE].
5. **Event Emission**: An event payload is constructed:
   ```json
   {
     "event_id": "evt_987654321",
     "camera_id": "CAM_DELHI_J12",
     "timestamp": "2026-09-05T10:15:30.500Z",
     "plate_number": "DL01CA1234",
     "confidence": 0.942,
     "location": {"lat": 28.6139, "lng": 77.2090},
     "speed_estimate_kmph": 48.5,
     "lane_id": 2
   }
   ```
6. **Hotlist & Anomaly Evaluation**: The event is pushed to Kafka. A consumer worker checks `plate_number` against Redis hotlists. Simultaneously, the anomaly worker fetches the vehicle's last recorded camera detection from Redis state. If the time elapsed between Camera A and Camera B implies an impossible travel speed (>150 km/h) or an illegal route sequence, a `Route Anomaly` alert is emitted over WebSockets [INFERENCE].
7. **Storage & Spatial Indexing**: The event is persisted into TimescaleDB. PostGIS updates the spatial point `ST_SetSRID(ST_MakePoint(lng, lat), 4326)`. Uber H3 maps the coordinates to a 64-bit spatial hexagon index [INFERENCE].
8. **Dashboard Visualization**: When an ICCC operator queries a specific plate (`DL01CA1234`), FastAPI executes a spatial-temporal query retrieving all chronological points. `pgRouting` fits the points to the OpenStreetMap road graph, drawing an animated trajectory line on MapLibre GL [INFERENCE].

## 13. AI/ML Justification

### 1. License Plate Detection Engine
- **Purpose**: Locate and extract bounding boxes of license plates from multi-lane video frames.
- **Model Type**: YOLOv11 Small / YOLOv8 Nano (Convolutional Neural Network).
- **Input**: Raw video frame (`1920x1080` RGB tensor).
- **Output**: Bounding box coordinates `[x_min, y_min, x_max, y_max]`, confidence score, vehicle class.
- **Data Required**: ~10,000 annotated Indian vehicle images with bounding box labels (DataCluster / Kaggle datasets) [RESEARCHED].
- **Why AI**: Fixed geometric algorithms (e.g., edge detection, Hough transforms) fail under varying lighting, shadows, dirt, and complex backgrounds [INFERENCE].
- **Evaluation**: Mean Average Precision at IoU 0.5 ($mAP_{50} > 0.95$).
- **Failure Mode & Oversight**: If plate detection fails (false negative), the frame is skipped; human operators can manually tag unrecognized vehicles from saved clips in high-priority security investigations [INFERENCE].

### 2. Optical Character Recognition (OCR) Engine
- **Purpose**: Convert cropped license plate sub-images into clean alphanumeric text strings.
- **Model Type**: Deep CRNN (Convolutional Recurrent Neural Network) / SVTR (Single Visual Model for Text Recognition) via PaddleOCR / Fast-Plate-OCR [RESEARCHED].
- **Input**: Cropped plate image tensor (`48x128` or `64x256` grayscaled/normalized).
- **Output**: Alphanumeric string (e.g., `"KA05MH1234"`), character-level confidence array.
- **Data Required**: ~15,000 cropped plate images labeled with character ground truth [RESEARCHED].
- **Why AI**: Traditional template matching fails when fonts, dirt, motion blur, angle, or plate damage alter character geometries [INFERENCE].
- **Evaluation**: Character Accuracy Rate ($CAR > 95\%$) and Word/Plate Accuracy Rate ($PAR > 90\%$).
- **Failure Mode**: Low-confidence OCR predictions (<0.70) are flagged with an `UNSURE_OCR` tag and routed to an operator verification queue [INFERENCE].

### Non-AI Components (Simpler Rule/System Choice)
- **Blacklist Hotlist Matching**: **DO NOT USE AI**. Use Levenshtein distance fuzzy matching and Redis hash lookups. Rule-based string comparison is 100% deterministic, instant (<1ms), and eliminates non-deterministic ML hallucination risks [INFERENCE].
- **Trajectory Interpolation**: **DO NOT USE AI**. Use PostGIS spatial functions (`ST_MakeLine`) combined with `pgRouting` shortest road graph matching. Graph algorithms provide exact physical road paths without AI hallucination [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### PostgreSQL / TimescaleDB Database Schema

```sql
-- Extension Setup
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS timescaledb;

-- Camera Metadata Table
CREATE TABLE camera_nodes (
    camera_id VARCHAR(50) PRIMARY KEY,
    junction_name VARCHAR(100) NOT NULL,
    location GEOMETRY(Point, 4326) NOT NULL,
    h3_index_r8 BIGINT NOT NULL,
    lane_count INT DEFAULT 2,
    status VARCHAR(20) DEFAULT 'ACTIVE'
);

-- ANPR Detection Time-Series Hypertable
CREATE TABLE vehicle_detections (
    detection_id UUID DEFAULT gen_random_uuid(),
    timestamp TIMESTAMPTZ NOT NULL,
    camera_id VARCHAR(50) REFERENCES camera_nodes(camera_id),
    plate_number VARCHAR(20) NOT NULL,
    confidence FLOAT NOT NULL,
    vehicle_type VARCHAR(30),
    speed_kmph FLOAT,
    h3_index_r8 BIGINT NOT NULL,
    location GEOMETRY(Point, 4326) NOT NULL
);

-- Convert to TimescaleDB Hypertable
SELECT create_hypertable('vehicle_detections', 'timestamp');

-- Indexes for Fast Trajectory Querying
CREATE INDEX idx_plate_time ON vehicle_detections (plate_number, timestamp DESC);
CREATE INDEX idx_spatial_h3 ON vehicle_detections (h3_index_r8, timestamp DESC);

-- Blacklist Registry
CREATE TABLE blacklist_registry (
    plate_number VARCHAR(20) PRIMARY KEY,
    reason VARCHAR(255) NOT NULL,
    added_by VARCHAR(100) NOT NULL,
    severity VARCHAR(20) CHECK (severity IN ('CRITICAL', 'HIGH', 'MEDIUM')),
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Local Storage & Edge Offline Synchronization Strategy
1. **Edge Store-and-Forward**: In the event of network disruption between edge camera nodes and the central server, edge nodes write detection JSON payloads to a local SQLite database or embedded RocksDB instance [INFERENCE].
2. **Buffer Capacity**: Local edge storage buffers up to 72 hours of metadata and low-resolution cropped plate thumbnails [INFERENCE].
3. **Synchronization & Conflict Resolution**: Upon network restoration, edge nodes sync buffered records via gRPC streaming batches. The server resolves duplicates using the unique tuple `(camera_id, timestamp, plate_number)` [INFERENCE].
4. **Bandwidth Optimization**: Edge nodes transmit full video frames *only* when a critical blacklist alert is triggered; for routine traffic, only 1KB JSON telemetry payloads are transmitted [INFERENCE].
