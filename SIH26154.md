# 1. Executive Snapshot

The **Gen AI Platform for Automated Content Transformation** is an enterprise-grade, multi-modal generative intelligence system designed for the **National Technical Research Organisation (NTRO)** [PS]. Organizations like NTRO frequently ingest high-value, complex information—such as threat intelligence reports, cyber advisories, technical research papers, news feeds, and raw incident logs—and must rapidly transform them into purpose-built communication deliverables [PS]. Currently, manually reading, distilling, re-contextualizing, and formatting these source materials into diverse media (e.g., video packages, executive briefings, structured advisories, visual infographics, slide decks, and social media posts) is time-consuming, labor-intensive, and prone to stylistic inconsistency [PS]. 

This solution introduces a multi-agent orchestration architecture paired with local, open-source multi-modal AI models and specialized document/media synthesis engines. Through a configurable dashboard, operators upload multi-modal source content (documents, text, images, video clips) and select target output formats with fine-grained parameter controls (audience level, tone, detail depth, language, and communication style) [PS]. The platform automatically extracts core semantics, plans domain-specific content structures, and generates production-grade artefacts across multiple selected media types simultaneously [PS]. Crucially, the platform is engineered to support air-gapped, on-premises deployment, ensuring zero data leakage for sensitive government and intelligence workloads [INFERENCE].

# 5. Constraints & Environment Realities

1. **Security & Air-Gapped Deployment:** As a technical intelligence organization under the National Security Adviser, NTRO cannot route classified or sensitive intelligence data through public cloud APIs (e.g., OpenAI, Claude, Midjourney) [RESEARCHED]. The system must be fully capable of running on local enterprise servers with self-hosted AI models [INFERENCE].
2. **Compute Realities during Hackathon:** For the SIH demonstration, hosting massive 70B parameter LLMs locally on standard student laptop GPUs (e.g., NVIDIA RTX 3060/4060 6GB-8GB VRAM) is impossible [KNOWN]. The system must utilize quantized 8B parameter models (Llama-3.2-3B/8B, Qwen2.5-7B quantized via Ollama/GGUF) and fast local TTS engines (Edge-TTS or Piper TTS) [ASSUMPTION].
3. **Execution Latency:** Multi-modal content generation (especially image synthesis and video compilation) is compute-heavy [KNOWN]. A synchronous Web request will time out. An asynchronous worker model (Celery + Redis) with real-time WebSocket progress updates is strictly necessary [INFERENCE].
4. **Input Diversity & Quality:** Source documents in real-world government setups vary from clean digital PDFs to scanned low-res memos or multi-speaker video briefings [KNOWN]. The ingestion engine must robustly handle messy OCR and noisy transcriptions without hallucinating missing context [INFERENCE].
5. **Language Support:** Primary input requirement specified is high-quality English [PS], but parameters allow selecting output target languages (e.g., Hindi, regional Indian languages) [PS]. Translation capabilities should be embedded [INFERENCE].

# 6. Research Questions

1. *How do we guarantee consistent scene-to-scene visual character and theme continuity when auto-generating storyboards and videos?*
   * *Investigation:* Use fixed seed parameters, consistent style prompt prefixes (e.g., "flat vector cyber illustration, dark navy palette"), or code-based fallback visual asset generators [INFERENCE].
2. *What is the most reliable method for generating native `.pptx` slides with valid speaker notes via python-pptx?*
   * *Investigation:* Direct LLM generation of raw XML or python-pptx code often produces syntax errors. The optimal pattern is demanding structured JSON output from LLMs adhering to a strict schema, then using a deterministic Python backend script to build the PowerPoint deck [INFERENCE].
3. *How to handle multi-output generation without exceeding LLM context windows or incurring massive redundant processing?*
   * *Investigation:* Implement a two-pass approach: Pass 1 parses the multi-modal source content into a unified "Semantic Source Graph" (SSG). Pass 2 feeds this single SSG into specialized lightweight prompt templates for each selected output format concurrently [INFERENCE].
4. *How to ensure full functionality in an air-gapped, offline environment for NTRO/NCIIPC deployment?*
   * *Investigation:* Deploy local Docker containers packaging Ollama (for Llama 3 / Qwen models), local Whisper models, Piper TTS, and local SVG rendering libraries [RESEARCHED].

# 9. Candidate Solution Approaches

### Approach 1: Monolithic Single-Prompt LLM Pipeline (Naïve Approach)
* **Mechanism:** Single massive prompt asking a LLM to output all requested formats (text, JSON for slides, script for video, advisory markdown) in a single response pass.
* **Problem Fit:** Poor. LLMs struggle to maintain output schema consistency across multiple massive outputs simultaneously [KNOWN].
* **Accuracy Potential:** Low (high hallucination and truncation risk due to token limit constraints) [KNOWN].
* **Complexity:** Low code complexity, high prompt engineering fragile complexity [INFERENCE].
* **Scale & Cost:** Inefficient token usage; easily hits token output limits [KNOWN].
* **Hackathon Feasibility:** High to build initially, but prone to frequent failures during live demo [ASSUMPTION].
* **Production Feasibility:** Unviable for enterprise deployment [INFERENCE].

### Approach 2: Fine-Tuned Local Open-Source Models Pipeline
* **Mechanism:** Fine-tuning specific small models (e.g., Llama-3-8B) on explicit dataset pairs for each format (Advisories, PPTX JSON, Social Posts).
* **Problem Fit:** Good domain specialization.
* **Accuracy Potential:** High for specific fine-tuned tasks.
* **Complexity:** Extremely High. Requires massive training datasets, GPU clusters for training, and maintaining multiple fine-tuned weights [KNOWN].
* **Hackathon Feasibility:** Unrealistic for a 4-6 student team within hackathon constraints due to data collection and fine-tuning time [ASSUMPTION].
* **Production Feasibility:** Moderate, but maintenance-heavy when requirements evolve [INFERENCE].

### Approach 3: Multi-Agent Dynamic Orchestration with Pluggable Multi-Modal Rendering Backends (RECOMMENDED)
* **Mechanism:** 
  1. **Ingestion Agent:** Extracts raw text from multi-modal inputs (PDF, video, images, text) into a unified Markdown representation.
  2. **Semantic Knowledge Graph (SKG) Extractor:** Distills the input into a structured core JSON representation containing key facts, technical metrics, timelines, entities, and primary objectives.
  3. **Parallel Task Dispatcher:** Passes the SKG and dashboard configuration parameters (tone, audience, style) to specialized generator agents running in parallel.
  4. **Dedicated Rendering Engines:**
     * *Video:* Script agent $\rightarrow$ Edge-TTS/Piper $\rightarrow$ Stable Diffusion/Pillow visual builder $\rightarrow$ FFmpeg compiler.
     * *Presentation:* Slide structured JSON agent $\rightarrow$ `python-pptx` builder.
     * *Advisory:* Structured markdown agent $\rightarrow$ WeasyPrint HTML/PDF builder.
     * *Infographic:* Data extraction agent $\rightarrow$ CairoSVG / HTML-Canvas renderer.
     * *Social Media:* Platform-constrained text agents (LinkedIn / Twitter thread slicer).
* **Problem Fit:** Perfect match for NTRO requirements [PS].
* **Accuracy Potential:** Very High. Deterministic rendering engines eliminate visual and schema syntax errors [INFERENCE].
* **Complexity:** Modular and manageable.
* **Scale & Cost:** Cost-effective (uses open-source models locally), highly scalable via worker queues [INFERENCE].
* **Hackathon Feasibility:** Excellent. Easily built using Python, LangChain/LangGraph, Celery, and standard open-source rendering libraries [ASSUMPTION].

# 10. Recommended Approach & Why

The **Multi-Agent Dynamic Orchestration with Pluggable Multi-Modal Rendering Backends (Approach 3)** is selected [ASSUMPTION].

### Why Alternatives Were Rejected
* **Approach 1 (Monolithic LLM Prompt)** was rejected because generative LLMs fail at simultaneously outputting reliable raw JSON for slides, precise character-counted tweets, and structured visual storyboards in a single output stream [KNOWN]. Truncation errors, invalid JSON syntax, and formatting drift make it unreliable for production [KNOWN].
* **Approach 2 (Fine-Tuned Specialized Models)** was rejected because fine-tuning 6 separate open-source models for 6 distinct formats requires high-end training hardware, weeks of dataset curation, and creates brittleness when dashboard parameters (e.g., changing tone or audience) are modified [INFERENCE].

### Why Approach 3 Wins
Approach 3 strictly decouples **Semantic Intelligence (LLM Reasoning)** from **Artefact Rendering (Deterministic Code)** [INFERENCE]:
1. LLMs are used exclusively where they excel: understanding context, extracting key entities, altering tone, summarizing, and structuring text into typed JSON schemas [INFERENCE].
2. Code libraries (`python-pptx`, WeasyPrint, CairoSVG, FFmpeg) are used where LLMs fail: pixel-perfect positioning, native presentation slide generation, binary PDF creation, and multi-track video assembly [INFERENCE].
3. The multi-agent parallel structure allows instant scalability. Adding a new output format (e.g., Audio Podcast or RSS Feed) simply requires adding a new worker task without modifying core ingestion logic [INFERENCE].

### Detailed Data Flow Narrative

1. **Submission Phase:** The operator accesses the web dashboard, uploads one or more source content items (e.g., a 10-page PDF threat report + an MP4 briefing video), and configures parameters: Target Audience = "Executive Leadership", Tone = "Formal Urgent", Language = "English", Detail = "Concise Briefing" [PS]. The operator selects three output deliverables: **Video Package**, **Presentation Deck**, and **Structured Advisory** [PS].
2. **Ingestion & Normalization:** FastAPI receives the request and stores raw files in local MinIO storage. Ingestion workers process the inputs: PyMuPDF extracts text from the PDF, while Whisper transcribes the MP4 video audio track [INFERENCE]. All parsed textual streams are merged into a unified, clean Markdown document [INFERENCE].
3. **Semantic Fact Extraction (SKG Building):** The Semantic Extraction Agent calls the core local LLM (e.g., Llama-3.2-8B via Ollama) with a structured JSON output schema. The LLM distills the normalized text into a **Semantic Knowledge Graph (SKG)** JSON object containing: core summary, key threat actors, technical vulnerabilities, severity scores, recommended mitigations, key statistical metrics, and temporal timelines [INFERENCE].
4. **Parallel Task Dispatching:** The Task Dispatcher creates three isolated Celery tasks, passing the SKG JSON and user configuration parameters to each format-specific generation agent concurrently [INFERENCE].
5. **Format-Specific Execution:**
   * *Task A (Video Package):* The Video Agent uses the LLM to write a 6-scene script with visual visual descriptions, narrator text, and storyboard layouts. It sends narrator text to Edge-TTS/Piper to generate MP3 audio clips and SRT subtitles. Visual descriptions are converted into scene images via Stable Diffusion/Pillow templates. Finally, FFmpeg stitches audio, images, and subtitles into a finished `.mp4` preview video [INFERENCE].
   * *Task B (Presentation Deck):* The Presentation Agent uses the LLM to format the SKG into a slide-by-slide JSON payload containing slide titles, bullet points, visual layout types, and speaker notes. The `python-pptx` builder script parses this JSON and constructs a native `.pptx` file [INFERENCE].
   * *Task C (Structured Advisory):* The Advisory Agent maps the threat data into a standardized Security Advisory JSON structure. Jinja2 renders this data into an HTML template styled according to NCIIPC guidelines, and WeasyPrint compiles it into a downloadable PDF [RESEARCHED].
6. **Delivery & Notification:** As each background worker finishes, it updates PostgreSQL and emits a WebSocket signal to the frontend UI. The operator's dashboard updates in real-time, enabling live side-by-side previews and direct download links for all rendered artefacts [INFERENCE].

# 13. AI/ML Justification

### Component 1: Ingestion Speech-to-Text (Whisper)
* **Purpose:** Transcribe incoming video or audio source files into accurate plain text [INFERENCE].
* **Model Type:** OpenAI Whisper (`small.en` / `base.en` weights running locally) [KNOWN].
* **Input:** MP4 / MP3 audio stream [INFERENCE].
* **Output:** Timestamped plain text transcript [INFERENCE].
* **Data Required:** Audio buffer from uploaded media [INFERENCE].
* **Why AI is Preferable:** Classical acoustic rule models fail on noisy environment recordings, variable accents, and technical terminology [KNOWN].
* **Evaluation:** Word Error Rate (WER) on defense/technical speech samples [KNOWN].
* **Failure Mode:** Low clarity or background noise causes missed words. *Fallback:* Allow user to edit raw transcript in UI before proceeding [INFERENCE].
* **Human Oversight:** Operator can review and edit transcript text on the dashboard before generation [INFERENCE].

### Component 2: Core Semantic Extractor & Format Agents (LLM)
* **Purpose:** Analyze raw text, extract structured JSON knowledge graph, adapt tone/style, generate slide bullets, and write video scripts [INFERENCE].
* **Model Type:** Llama-3.2-8B-Instruct or Qwen2.5-7B-Instruct via Ollama [RESEARCHED].
* **Input:** Normalized Markdown text + system prompt parameters (Audience, Tone, Language, Format Requirements) [PS].
* **Output:** Validated Pydantic JSON objects (Slide JSON, Script JSON, Advisory JSON, Social Posts) [INFERENCE].
* **Data Required:** Source content Markdown [INFERENCE].
* **Why AI is Preferable:** Rule-based regex or template tools cannot understand context, perform abstractive summarization, or adjust writing tone dynamically [KNOWN].
* **Evaluation:** JSON Schema compliance rate, BLEU/ROUGE summarization scores, hallucination rate [KNOWN].
* **Failure Mode:** JSON schema validation error or key omission. *Fallback:* Automated Pydantic retry loop re-prompting LLM with validation error log [INFERENCE].
* **Human Oversight:** Operator can review and edit generated text in the interactive preview canvas before downloading final files [INFERENCE].

### Component 3: Text-to-Speech Narration Engine (Piper/Edge-TTS)
* **Purpose:** Convert generated video script narration text into clear, natural voiceover audio [INFERENCE].
* **Model Type:** Neural Tacotron2 / VITS model (Piper / Edge-TTS) [KNOWN].
* **Input:** Script narration plain text string [INFERENCE].
* **Output:** WAV / MP3 audio file + timestamp alignments [INFERENCE].
* **Data Required:** Clean script text [INFERENCE].
* **Why AI is Preferable:** Formant/concatenative legacy synthesizers sound robotic and unengaging [KNOWN].
* **Evaluation:** Mean Opinion Score (MOS) for speech naturalness [KNOWN].
* **Failure Mode:** Mispronunciation of rare acronyms (e.g., "NCIIPC"). *Fallback:* Pre-processing phoneme mapping dictionary for defense/security acronyms [INFERENCE].
* **Human Oversight:** Audio playback control in UI allows operator to regenerate narration with alternative voice presets [INFERENCE].

### Explicit Identification of Non-AI Components (Where AI MUST NOT Be Used)
1. **PPTX File Building:** Must be handled by deterministic Python code (`python-pptx`) [INFERENCE]. Using an LLM to output raw PPTX binary or XML causes corruption [KNOWN].
2. **PDF Advisory Formatting:** Must be compiled via HTML/CSS templates (`WeasyPrint`) [INFERENCE]. LLMs cannot guarantee strict pixel alignment or print-ready pagination [2.6].
3. **Character Limit Slicing (Twitter/LinkedIn):** Twitter 280-character boundary checks must be enforced by deterministic Python string length validation, not LLM token estimations [INFERENCE].
4. **Infographic Graphic Layout:** Chart axes, SVG vector paths, and box alignments must be rendered by CairoSVG/matplotlib to prevent garbled text [2.14].

# 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL)

```sql
-- Operators Table
CREATE TABLE operators (
    operator_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(100) UNIQUE NOT NULL,
    role VARCHAR(50) NOT NULL, -- e.g., 'Analyst', 'Admin'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Transformation Jobs Table
CREATE TABLE transformation_jobs (
    job_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    operator_id UUID REFERENCES operators(operator_id),
    status VARCHAR(30) NOT NULL, -- 'PENDING', 'PROCESSING', 'COMPLETED', 'FAILED'
    target_audience VARCHAR(50),
    tone VARCHAR(50),
    target_language VARCHAR(30),
    level_of_detail VARCHAR(50),
    communication_style VARCHAR(50),
    selected_outputs JSONB NOT NULL, -- e.g., ["video", "presentation", "advisory"]
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP WITH TIME ZONE
);

-- Source Inputs Table
CREATE TABLE source_inputs (
    input_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    job_id UUID REFERENCES transformation_jobs(job_id) ON DELETE CASCADE,
    file_type VARCHAR(20) NOT NULL, -- 'pdf', 'docx', 'video', 'image', 'text'
    file_path VARCHAR(255) NOT NULL,
    extracted_markdown TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Generated Artefacts Table
CREATE TABLE generated_artefacts (
    artefact_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    job_id UUID REFERENCES transformation_jobs(job_id) ON DELETE CASCADE,
    output_type VARCHAR(30) NOT NULL, -- 'video', 'presentation', 'advisory', 'infographic', 'linkedin', 'twitter', 'exec_summary'
    file_path VARCHAR(255), -- Path to .mp4, .pptx, .pdf, .svg
    content_payload JSONB, -- Raw text / JSON representation
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Offline & Low-Network Operations Strategy
1. **Local Model Caching:** All model weights (Ollama GGUF models, Whisper models, Piper voice models) are pre-loaded into local container volumes during system setup [RESEARCHED]. No internet access is required during operational transformations [INFERENCE].
2. **Local Static Assets:** SVG icons, CSS frameworks, and font files (e.g., Inter, Roboto) are self-hosted within the Next.js static asset directory, eliminating external CDN dependencies [INFERENCE].
3. **Queue Resilience & Retry Policy:** Redis queues store intermediate task payloads. If an AI worker crashes due to VRAM spike, Celery automatically retries the task with a fallback quantized model setting [INFERENCE].
4. **Bandwidth Optimization:** For remote field deployment over low-bandwidth tactical networks, generated video packages default to lightweight MP4 (720p H.264), and presentation files are compressed natively [INFERENCE].
