# AI-Driven Standardization and Harmonization of Material Codes Across CPSEs

---

## 1. Executive Snapshot

Central Public Sector Enterprises (CPSEs) under the Ministry of Petroleum & Natural Gas (MoPNG) and related ministries—such as Chennai Petroleum Corporation Limited (CPCL), IOCL, ONGC, GAIL, NTPC, SAIL, and BHEL—procure and maintain millions of functionally identical or equivalent materials [PS]. However, because each CPSE maintains an isolated Enterprise Resource Planning (ERP) system (primarily SAP MM or Oracle) with customized material master schemas, free-text descriptions, local unit abbreviations, and disparate numbering systems, the same physical item (e.g., a "2-inch SS316 Ball Valve Class 150 Flanged") is cataloged under thousands of distinct material codes [INFERENCE]. This results in massive master data duplication, inflated safety stock levels, fragmented vendor spend, lack of inter-CPSE inventory visibility during emergency shutdowns, and missed bulk procurement savings [INFERENCE]. 

This dossier proposes **"SAMNVAYA" (Smart Automated Material Network for Verification, Alignment & Analytics)**—an AI-driven National Unified Material Master Framework that normalizes unstructured material descriptions, extracts technical attributes using fine-tuned Named Entity Recognition (NER), clusters duplicates/near-duplicates using multi-stage semantic vector search, generates a standardized **Common National Material Code (CNMC)** aligned with global standards (UNSPSC / ISO 8000), provides a dual-level human-in-the-loop governance workflow, and synchronizes seamless bidirectional updates with legacy CPSE SAP/ERP systems via RESTful microservices and IDoc/BAPI interfaces [INFERENCE].

## 5. Constraints & Environment Realities

1.  **ERP Heterogeneity & Legacy Schema Rigidness:**  
    Participating CPSEs run different ERP platforms (SAP ECC 6.0, SAP S/4HANA, Oracle E-Business Suite, custom web portals) [KNOWN]. Local SAP material numbers (`MATNR`) are heavily linked to historical purchase orders, goods receipts, and plant maintenance records [KNOWN]. Direct modification or replacement of local material numbers in CPSE ERPs is unacceptable to plant operations [INFERENCE].  
    *Design Choice:* The Common National Material Code (CNMC) must be stored as an *external mapping reference* or *Classification Characteristic (Class Type 001)* in SAP MM, leaving local `MATNR` intact [RESEARCHED].

2.  **Unstructured, Noise-Heavy Text Data:**  
    Material master short texts in CPSEs are severely truncated (34-40 characters in SAP) and heavily abbreviated (e.g., `"VLV BL 2 IN CS A105 #300 SW"`, `"VALVE BALL 50MM CS CLASS 300 SOCKET WELD"`) [KNOWN]. Spellings, units (inches vs. mm), and order of words vary wildly across CPSEs [INFERENCE].  
    *Design Choice:* Must implement a custom domain-specific text normalizer and dictionary specifically built for Indian industrial MRO (Maintenance, Repair, and Operations) terminologies [INFERENCE].

3.  **Data Privacy & Inter-CPSE Security:**  
    While CPSEs are under government oversight, operational inventory levels and strategic supplier contract prices are commercially sensitive [INFERENCE]. Raw ERP transactional data cannot be directly exposed to other CPSEs without role-based access controls [INFERENCE].  
    *Design Choice:* Implemented multi-tenant data governance: central harmonization engine processes sanitized technical attributes, while enterprise-specific financial/inventory balances are restricted via Role-Based Access Control (RBAC) [INFERENCE].

4.  **Hardware & Compute Limits for Hackathon:**  
    Running 70B parameter Large Language Models (LLMs) locally during an SIH demonstration is infeasible due to GPU costs and latency constraints [INFERENCE].  
    *Design Choice:* Use lightweight, high-performance ONNX-quantized Transformer embeddings (`bge-small-en-v1.5` or `all-MiniLM-L6-v2`) and small fine-tuned classification models capable of CPU/GPU inference in <50ms per item [INFERENCE].

## 6. Research Questions

1.  *What global and national material taxonomy standards are most suitable for CPSE industrial procurement?*  
    *Finding:* **UNSPSC** (United Nations Standard Products and Services Code) and **eCl@ss** are global gold standards [RESEARCHED]. In India, the **Government e-Marketplace (GeM)** uses a taxonomy derived from UNSPSC with "Golden Parameters" for technical attributes [RESEARCHED]. **ISO 8000** specifies master data quality and portability standards [RESEARCHED].  
    *Decision:* Align the 12-digit CNMC hierarchy directly with UNSPSC / GeM taxonomy classes [INFERENCE].

2.  *How are material master updates injected into SAP MM without custom ABAP modifications?*  
    *Finding:* Standard SAP provides Function Module `BAPI_MATERIAL_SAVEDATA` and IDoc `MATMAS.MATMAS05` [RESEARCHED]. UNSPSC / External codes are populated in SAP MM via Class Type `001` using Characteristics (created via Transaction `CT04`) assigned to Material Classes (created via Transaction `CL01`) [RESEARCHED].  
    *Decision:* Build the integration interface to output data structured for `BAPI_MATERIAL_SAVEDATA` and `MATMAS05` XML payloads [RESEARCHED].

3.  *What NLP approach yields highest precision for short engineering descriptions?*  
    *Finding:* Pure generative LLMs often hallucinate technical specifications or generate non-deterministic codes [RESEARCHED]. Encoders (BERT/RoBERTa) combined with Regex/Spacy NER extract entities with >90% precision, while dense vector models (`bge-small`) excel at semantic candidate retrieval [RESEARCHED].  
    *Decision:* Deploy a 3-stage pipeline: (1) Rule/NER Extractor -> (2) Dense Vector Retriever -> (3) Deterministic Code Generator [INFERENCE].

### Approach 1: Traditional Rule-Based & String Distance (Baseline)
*   *Mechanism:* Preprocess descriptions with regex, perform Levenshtein / Jaro-Winkler string similarity comparisons, and map keywords against a static dictionary [INFERENCE].
*   *Evaluation:* Highly deterministic and cheap, but fails completely when word order changes or abbreviations differ (e.g., `"VALVE BALL 2IN"` vs `"2 INCH BALL VALVE"` have low string edit similarity despite being identical) [INFERENCE]. Rejected as primary engine [INFERENCE].

### Approach 2: Pure Generative LLM (LLM-Only)
*   *Mechanism:* Feed raw truncated text directly into a Large Language Model (e.g., Llama-3-70B or GPT-4o) via API prompts to output standardized JSON and code [INFERENCE].
*   *Evaluation:* High contextual understanding, but non-deterministic (may return different codes for the same item), highly vulnerable to domain hallucinations, expensive at enterprise scale (millions of records), and slow (>1-2 seconds per record) [INFERENCE]. Rejected as primary engine [INFERENCE].

### Approach 3: Multi-Stage Hybrid Modular AI Pipeline (RECOMMENDED)
*   *Mechanism:* 
    1.  *Rule-Based Preprocessing:* Regex-based abbreviation expansion and unit normalization [INFERENCE].
    2.  *Named Entity Recognition (NER):* Fine-tuned transformer (`RoBERTa-NER`) extracts explicit technical parameters (Noun, Modifier, Material Grade, Pressure Rating, Dimensions) [INFERENCE].
    3.  *Dense Vector Candidate Retrieval:* Embed text into vector space using specialized domain sentence-transformers (`bge-small-en-v1.5`) indexed in Qdrant / Pgvector for sub-10ms O(N log N) retrieval [INFERENCE].
    4.  *Attribute Tolerance & Re-Ranking:* Cross-Encoder scoring + strict numerical parameter tolerance matching (e.g., `50mm == 2 inch`) [INFERENCE].
    5.  *Deterministic Code Generation:* Generate 12-digit CNMC from taxonomy hierarchy + normalized attribute hash [INFERENCE].
*   *Evaluation:* Combines the semantic strength of AI with the zero-hallucination reliability of deterministic logic. Fast, scalable, highly explainable, and cost-effective [INFERENCE].

## 10. Recommended Approach & Why

The **Multi-Stage Hybrid Modular AI Pipeline (Approach 3)** is selected [INFERENCE].

### Justification
1.  **Zero Hallucination Guarantee for Codes:** Generative AI is NEVER allowed to invent material codes [INFERENCE]. The CNMC is generated deterministically from verified taxonomy buckets and extracted attribute hashes [INFERENCE].
2.  **Explainability for Data Stewards:** When the system flags two materials as duplicates, it explicitly highlights *why*: matching Noun (`BALL VALVE`), matching Material (`SS316`), and matching Rating (`150#`), alongside a numerical confidence score (e.g., `96.4% Match`) [INFERENCE].
3.  **High Throughput & Low Cost:** Vector similarity via HNSW indexing allows comparing 100,000 material records in milliseconds on standard CPU hardware without paying external API token costs [KNOWN][INFERENCE].
4.  **Graceful Degradation:** If the neural NER model encounters an unseen string, the system falls back to rule-based token parsing and flags the item for human review rather than outputting garbage data [INFERENCE].

### Data Flow Narrative

1.  **Ingestion Phase:** Raw material records (containing CPSE Code, Description, Plant, UOM) are uploaded via batch CSV or REST API from participating CPSE ERPs [INFERENCE].
2.  **Normalization Phase:** The raw text (e.g., `"VLV BL 2IN SS316 #150"`) passes through the Text Normalizer, expanding abbreviations (`"VLV"` -> `"VALVE"`, `"BL"` -> `"BALL"`), converting units to standard SI/Imperial representations (`"2IN"` -> `"2 INCH"`), and stripping illegal noise characters [INFERENCE].
3.  **Entity Extraction (NER) Phase:** The cleaned text is fed into the Transformer NER model, extracting a structured dictionary: `{Noun: "VALVE", Modifier: "BALL", Material: "STAINLESS STEEL 316", Rating: "150 LB", Size: "2 INCH"}` [INFERENCE].
4.  **Vector Candidate Search Phase:** The normalized text is converted into a 384-dimensional dense vector using `bge-small-en-v1.5`. The vector index in Qdrant executes a fast K-Nearest Neighbor (KNN) search to pull the top 10 candidate standardized items [INFERENCE].
5.  **Re-Ranking & Tolerance Matching Phase:** Candidate items are scored by combining vector similarity with exact key-value parameter matching. If extracted attributes match exactly (or within defined numerical tolerances), a final confidence score (0-100%) is assigned [INFERENCE].
6.  **CNMC Assignment / Generation Phase:** 
    *   If confidence > 90% against an existing standardized material, the item is linked to that existing CNMC [INFERENCE].
    *   If confidence < 90% but the category is clear, a new unique CNMC is generated following the UNSPSC taxonomy structure [INFERENCE].
7.  **Governance & Approval Phase:** High-confidence matches (>95%) are staged for auto-approval; lower-confidence matches (70-95%) are flagged in the Data Steward Verification UI for one-click human review [INFERENCE].
8.  **ERP Synchronization Phase:** Once approved, the system generates an export payload (or triggers the simulated SAP BAPI/IDoc adapter) to update the CPSE's local ERP system [INFERENCE].

## 13. AI/ML Justification

### 1. Technical Attribute Extraction Engine (NER)
*   **Purpose:** Extract structured key-value parameters from unstructured material short texts [INFERENCE].
*   **Model Type:** Fine-tuned `RoBERTa-base` / `DeBERTa-v3` Token Classifier [RESEARCHED].
*   **Input:** Raw material short text (e.g., `"PIPE CS SEAMLESS 4IN SCH 40 ASTM A106 GR B"`).
*   **Output:** Entity tags: `[Noun: PIPE], [Material: CS], [Type: SEAMLESS], [Size: 4 IN], [Schedule: SCH 40], [Standard: ASTM A106 GR B]`.
*   **Why AI Over Rules:** Rule-based regex fails when word order changes or non-standard punctuation is used [INFERENCE].
*   **Evaluation:** Entity extraction Token-level F1-Score (>90%) [RESEARCHED].
*   **Failure Mode & Oversight:** Unrecognized attributes are captured in an `Unclassified_Attributes` string and flagged for human steward review [INFERENCE].

### 2. Semantic Similarity & Candidate Retrieval (Vector Embedder)
*   **Purpose:** Perform high-speed semantic matching across hundreds of thousands of material records [INFERENCE].
*   **Model Type:** `bge-small-en-v1.5` Sentence-Transformer (384 dimensions) [RESEARCHED].
*   **Input:** Normalized description string.
*   **Output:** 384-dimensional floating-point dense vector embedding.
*   **Why AI Over Rules:** Keyword search fails when different synonyms are used (e.g., `"TUBING"` vs `"PIPE"`, `"GASKET"` vs `"SEALING RING"`) [INFERENCE].
*   **Evaluation:** Top-K Recall@10 (>95%) [INFERENCE].
*   **Failure Mode & Oversight:** If top candidate vector similarity is <0.65, the system categorizes the item as a "Potential New Material" and routes it to manual classification [INFERENCE].

### Explicit Non-AI Exclusions
*   **CNMC Generation:** AI is **NOT** used to generate the 12-digit code digits. Code generation is 100% rule-based and deterministic based on taxonomy mappings to ensure zero code corruption [INFERENCE].
*   **Audit Logging:** No AI is used in audit trails or approval tracking [INFERENCE].
