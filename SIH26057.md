## 1. Executive Snapshot

### Summary
The Ministry of Earth Sciences (MoES) and the National Institute of Ocean Technology (NIOT) require an automated, AI-driven software system to analyze Side-Scan Sonar (SSS) imagery for detecting anthropogenic marine debris (such as ghost nets, pipes, cylinders, and shipwrecks) and underwater anomalies [PS]. Manual analysis of thousands of kilometers of acoustic logs is slow, tedious, and prone to human error due to complex seabed geology, speckle noise, varying pixel resolutions, acoustic shadows, and vehicle motion artifacts [PS]. 

This project proposes **OceanScan-AI**: a modular, edge-deployable deep learning and geospatial analytics software pipeline. It ingests raw SSS binary logs (e.g., eXtended Triton Format - `.xtf`) [RESEARCHED], executes slant-range correction and speckle noise reduction [KNOWN], performs multi-class object detection and semantic segmentation using YOLOv11 and U-Net [RESEARCHED], filters false positives using an acoustic shadow verification engine [INFERENCE], and outputs structured, geo-tagged anomaly reports (JSON/CSV) alongside an interactive, offline-capable dashboard interface [PS].

## 5. Constraints & Environment Realities

### Field & Operational Constraints

1. **Acoustic Environment Limitations**:
   * *Speckle Noise*: Acoustic backscatter inherently contains granular noise caused by constructive and destructive interference of coherent acoustic waves [KNOWN].
   * *Acoustic Shadows*: Objects block sound waves, leaving a dark "shadow" zone behind them. Natural geological ridges create similar shadow patterns [PS].
   * *Non-Uniform Illumination*: Sonar intensity decays exponentially with slant range distance ($\text{Gain Loss} = 20\log_{10}(R) + 2\alpha R$), causing outer edges to appear dark while the water column center is bright [KNOWN].

2. **Vehicle & Sensor Dynamics**:
   * *Towed vs. AUV Platforms*: Towed fish suffer from surface wave heave, pitch, and roll, introducing crinkling and horizontal line dropouts into sonar imagery [PS].
   * *Variable Resolution*: Cross-track resolution depends on acoustic pulse length, whereas along-track resolution depends on vessel speed and ping rate, creating anisotropic pixel scaling [KNOWN].

3. **Compute & Connectivity Environment**:
   * *Zero Ocean Connectivity*: AUVs and offshore survey vessels operate in environments without 4G/5G or high-speed internet [INFERENCE]. All pre-processing, inference, geo-referencing, and report rendering must occur entirely offline [PS].
   * *Hardware Power Constraints*: Onboard AUV processing units operate on strict power budgets (typically 10W - 25W on platforms like NVIDIA Jetson) [RESEARCHED]. Heavy cloud AI frameworks cannot be used directly onboard [PS].

### Approach 1: Classical Heuristic Image Processing Pipeline
* **Mechanism**: Adaptive thresholding (Otsu), Canny edge detection, morphologic closing, and geometric contour filtering (aspect ratio, perimeter).
* **Pros**: Ultra-lightweight, zero GPU required, deterministic execution.
* **Cons**: Fails completely in complex geological seabed terrain (rock ridges, sand ripples) [PS]; high false positive rate.

### Approach 2: Direct End-to-End Deep Learning Object Detection
* **Mechanism**: Feed raw uncorrected sonar image tiles directly into a standard RGB YOLOv8/v11 model.
* **Pros**: Fast to implement using off-the-shelf transfer learning models.
* **Cons**: Ignores acoustic physics; fails on slant-range geometric distortions; confuses natural rock shadows with target shadows; cannot compute real-world lat/long without parsing ping headers [INFERENCE].

### Approach 3: Hybrid Dual-Stage Modular Pipeline (RECOMMENDED)
* **Mechanism**:
  1. *Ingestion & Geometry*: Parse `.xtf` binary pings via `pyxtf` [2.4]; execute slant-range correction and Speckle Lee Filtering [KNOWN].
  2. *Detection*: YOLOv11-OBB (Oriented Bounding Boxes) trained specifically on SSS acoustic imagery [4.4].
  3. *Physics Validation*: Acoustic shadow verification module checks for a bright acoustic return followed immediately by an acoustic shadow along the acoustic wave propagation axis [INFERENCE].
  4. *Geo-Engine*: Calculate target GPS coordinates from ping navigation headers [PS].
  5. *UI/Dashboard*: Lightweight WebGL/Leaflet dashboard displaying real-time geotagged hazard maps [PS].

### Data Flow Narrative

1. **Upload & Parsing**: User uploads a raw `.xtf` file via the React UI [PS]. The FastAPI backend receives the binary file stream and passes it to the `pyxtf` parser [RESEARCHED].
2. **Metadata Extraction**: Latitude, longitude, vessel heading, towfish altitude, range, and speed are extracted from `XTFHeaderType.sonar` packets [2.4].
3. **Pre-Processing Pipeline**:
   * *Slant Range Correction*: Converts acoustic slant range $R$ to true horizontal range $x = \sqrt{R^2 - h^2}$ where $h$ is towfish altitude above seafloor [KNOWN].
   * *Speckle Filtering*: Applies an adaptive spatial Lee Filter to suppress speckle noise while preserving sharp object boundary edges [KNOWN].
4. **AI Inference**: Corrected 2D sonar waterfall image tiles are passed through the INT8-quantized YOLOv11-OBB model to extract candidate bounding boxes with class labels (`shipwreck`, `pipe`, `cylinder`, `ghost_net`) [PS].
5. **Acoustic Shadow Verification**: For each candidate box, the post-processing engine analyzes pixel intensities along the sonar beam direction (away from nadir). If a high-intensity return (highlight) is NOT followed by a low-intensity drop (shadow) proportional to target height, the confidence score is penalized to suppress rock cluster false positives [INFERENCE].
6. **Geotagging & Dimension Estimation**: Using towfish offset formulas and ping timestamp matching, pixel coordinates $(x,y)$ inside the bounding box are mapped to exact GPS coordinates (latitude, longitude). Physical width and length are calculated using pixel resolution ratios [PS].
7. **Visualization & Export**: Findings are stored in an internal GeoJSON store, pushed live via WebSockets to the Leaflet map overlay, and made available for immediate download as structured JSON/CSV reports [PS].

## 13. AI/ML Justification

```
+--------------------------------------------------------------------------------------------------+
|                                      AI/ML Decision Framework                                   |
+-----------------------------------+----------------------------------+---------------------------+
| Module Name                       | Primary Objective                | Selected Architecture     |
+-----------------------------------+----------------------------------+---------------------------+
| 1. Sonar Target Detector          | Identify & locate debris targets | YOLOv11-OBB (INT8)        |
| 2. Pixel Hazard Masker            | Segment fine ghost net boundaries| Lightweight U-Net         |
| 3. False Positive Filter          | Verify acoustic shadow physics   | Non-AI Heuristic Algorithm|
+-----------------------------------+----------------------------------+---------------------------+
```

### 1. Object Detection Engine (YOLOv11-OBB)
* **Exact Problem Solved**: Detects and localizes rotated man-made objects against complex seabed backgrounds [PS].
* **Input**: Pre-processed, speckle-filtered side-scan sonar image tile ($640 \times 640$ pixels, single-channel acoustic intensity).
* **Output**: Oriented Bounding Box coordinates $(x_c, y_c, w, h, \theta)$, class label (`ghost_net`, `shipwreck`, `pipe`, `cylinder`), and raw class probability [PS].
* **Why AI is Necessary**: Manual rule-based shape detection fails on irregular, partially buried ghost nets and complex shipwrecks [PS].
* **Evaluation Metric**: Mean Average Precision at IoU 0.5 ($\text{mAP}@0.5$) and F1-score [1.1, 1.8].
* **Failure Mode & Human Oversight**: Low-confidence detections ($30\% - 60\%$) are flagged with a "Yellow Review" tag in the UI dashboard, requiring human operator confirmation [INFERENCE].

### 2. Semantic Segmentation Engine (U-Net)
* **Exact Problem Solved**: Provides fine pixel-level mask boundaries for complex, non-rectangular hazards like entangled ghost nets [PS].
* **Input**: Cropped sonar target tile from candidate detection box.
* **Output**: Binary pixel mask ($1 = \text{debris}, 0 = \text{background}$).
* **Why AI is Necessary**: Ghost nets lack rigid geometric bounds; pixel-level mask is critical to estimate net surface area for dive cleanup operations [PS].
* **Evaluation Metric**: Mean Intersection over Union (mIoU) and Dice Coefficient [1.4, 1.7].

### Explicit Non-AI Component Recommendation
* **Acoustic Shadow Verification**: Do **NOT** use deep learning to verify acoustic shadows. Use a deterministic signal analysis script: measure pixel brightness in a 20-pixel strip directly behind the bounding box along the acoustic beam propagation vector [INFERENCE]. If average intensity does not drop by at least 40% relative to background seafloor, downgrade detection confidence score [REQ-4.1]. This approach is faster, deterministic, and fully explainable [INFERENCE].
