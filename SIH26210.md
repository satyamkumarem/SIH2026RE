## 1. Executive Snapshot

### Executive Summary
India loses an estimated ₹92,651 crore ($11.2 billion) to ₹1.53 trillion ($18.5 billion) annually in agricultural post-harvest losses [RESEARCHED], with fruits and vegetables experiencing wastage rates between 4.87% and 15.88% due to inadequate sorting, grading, storage, and processing infrastructure at the farm-gate [RESEARCHED]. Problem statement SIH26210, sponsored by AICTE / MIC-Student Innovation under the **Hardware** category and **Agriculture, FoodTech & Rural Development** theme, calls for a student-led hardware innovation to enhance agricultural productivity and manage/process agricultural produce [PS]. 

To solve this, we propose **"AgriSort-Process Edge"**—a solar-hybrid, portable hardware ecosystem combining an automated optical sorting and grading module with a decentralized solar-assisted micro-dehydration unit. Driven by edge-AI computer vision running on a low-power microcontroller/single-board computer, the system non-destructively grades produce according to AGMARK/eNAM standards at the farm-gate [INFERENCE] while redirecting B/C-grade produce to the integrated micro-dehydrator for value addition (making dried slices, powders, or preserves) [INFERENCE]. Operating completely offline with store-and-forward telemetry [INFERENCE], this dual-action hardware bridges the gap between raw harvest management and decentralized processing for Indian smallholder farmers and Farmer Producer Organizations (FPOs) [INFERENCE].

* **Dust & Field Contaminants:** Farm-gate environments contain heavy particulate matter, dirt, and moisture from fresh produce [KNOWN]. The camera enclosure must use sealed IP65 clear acrylic windows with anti-dust blower ports [INFERENCE].
* **Human Factors & Digital Literacy:** Smallholders may have limited formal literacy [KNOWN]. The UI must prioritize iconographic displays, color-coded LED indicators (Green = Grade A, Yellow = Grade B, Red = Processing), and regional audio prompts [INFERENCE].
* **Cost Constraints:** Smallholders and small FPOs cannot afford industrial sorters costing ₹10–25 Lakhs ($12,000–$30,000) [RESEARCHED]. Target hardware system BOM for a rural FPO cluster must remain under ₹35,000–₹50,000 for the MVP prototype [ASSUMPTION].

## 10. Recommended Approach & Why

### Selection: Approach 2 (Edge-AI Optical Sorter + Solar-Hybrid Micro-Dehydrator + IoT Telemetry)
Approach 2 is selected because it directly fulfills both core imperatives of SIH26210: **managing** produce (via objective non-destructive AI sorting) and **processing** produce (via integrated solar-hybrid value-addition dehydration) [PS, INFERENCE]. Unlike static sieves, it detects rot, disease, and surface defects [INFERENCE]. Unlike capital-intensive industrial sorters, it is compact, low-cost, and engineered specifically for rural off-grid environments [INFERENCE].

### Justification for Rejecting Alternatives
* **Approach 1 (Static Mechanical Sieve & Passive Dryer) Rejected:** Fails to address non-destructive defect detection (fungal rot, pest damage, skin burns) [INFERENCE]. Mechanical sieves frequently bruise delicate produce like ripe tomatoes [INFERENCE]. Passive solar dryers lack temperature control, causing product caramelization or mold growth during cloudy weather [INFERENCE].
* **Approach 3 (Industrial Pneumatic Sorter) Rejected:** Requires high-voltage 3-phase grid electricity and compressed air infrastructure that does not exist at rural farm-gates [INFERENCE]. Prototype cost and physical footprint make it impossible for a student team to build and demonstrate within SIH constraints [INFERENCE].

### Detailed Data Flow Narrative
1. **Produce Ingestion:** Harvested produce (e.g., tomatoes) is loaded into the hopper. A 12V DC motorized roller belt aligns items into a single file to enter the enclosed vision box.
2. **Image Capture & Weight Trigger:** An IR proximity sensor detects an incoming item, triggering the USB/CSI camera under uniform CRI 95+ LED lighting. Concurrently, the item passes over a load plate instrumented with an HX711 load cell.
3. **Edge AI Assaying:** The Raspberry Pi 4 / Jetson Orin Nano executes the TFLite MobileNetV3 model in <80ms, extracting:
   * **Diameter/Volume:** Pixel contour bounding box mapped to physical mm [INFERENCE].
   * **Color Maturity:** HSV color histogram mapping [INFERENCE].
   * **Defect Surface Area %:** Segmentation of black spots, rot, or cracks [INFERENCE].
4. **Classification & Actuation:** The edge model maps extracted metrics against AGMARK rules:
   * *Grade A (Fresh Premium):* Servo gate directs item to Box 1 (Mandi / Export).
   * *Grade B (Slight Cosmetic Blemish):* Servo gate directs item to Box 2 (Local Sale / Immediate Consumption).
   * *Grade C / Processing Grade (High Rot/Deformity):* Servo gate directs item to Box 3 (Processing Chute leading to Solar Dehydrator).
5. **Micro-Processing Phase:** Grade C produce is manually or gravity-fed into the slicing unit and placed on mesh trays inside the solar-hybrid dehydrator. The ESP32 monitors chamber temperature (DS18B20) and humidity (DHT22), driving a PWM exhaust fan and auxiliary PTC heating element to maintain optimal drying curves (55°C–60°C) [INFERENCE].
6. **Local Logging & Store-Forward Sync:** Every transaction (Batch Weight, Grade Distribution %, Dryer Runtime) is stored in SQLite on local storage. When GSM/4G signal is acquired, the device publishes JSON payloads to the central cloud MQTT broker.

## 13. AI/ML Justification

### Component 1: Non-Destructive Crop Assaying & Defect Segmentation
1. **What exact problem does AI solve?** Detects non-uniform surface defects (rot, fungal marks, skin cracks, sunburn) and complex shape deformities that traditional color sensors or mechanical screens cannot detect [INFERENCE].
2. **What is the input?** 1080p RGB image crop of individual fruit/vegetable passing through the illuminated box [INFERENCE].
3. **What is the output?** Grade Class (`Grade_A`, `Grade_B`, `Grade_C_Processing`), Bounding Box, Defect Area Percentage (%), Estimated Diameter (mm) [INFERENCE].
4. **Why can a simpler rule/system not solve it?** Fixed visual thresholds fail under natural crop variation (e.g., natural speckles vs rot lesions) [INFERENCE].
5. **What data is required?** ~1,500 labeled images per crop variety capturing healthy, bruised, deformed, and diseased states [ASSUMPTION].
6. **How will it be evaluated?** Mean Average Precision (mAP@0.5) > 88% and Classification Accuracy > 90% against expert human assayers [ASSUMPTION].
7. **What happens when it is wrong?** Misclassified items drop into adjacent bins. A manual supervisory bin check allows human correction [INFERENCE].
8. **Does it require training?** Yes, pre-trained on ImageNet and fine-tuned on custom crop dataset [INFERENCE].
9. **Does it require fine-tuning?** Yes, crop-specific fine-tuning is required [INFERENCE].
10. **Does it require RAG?** No [INFERENCE].
11. **Does it require computer vision?** Yes, fundamental requirement [INFERENCE].
12. **Does it require speech processing?** Optional (Text-to-Speech output for rural HMI) [INFERENCE].
13. **Does it require forecasting?** No [INFERENCE].
14. **Is human oversight required?** Yes, spot-checks by FPO operator [INFERENCE].

### Component 2: Dehydration Completion & Shelf-Life Estimation
1. **What exact problem does AI solve?** Predicts remaining drying time and final shelf-life based on real-time chamber temperature, ambient humidity, and initial crop moisture content [INFERENCE].
2. **What is the input?** Time-series array: Drying Chamber Temp (°C), Humidity (%), Crop Type, Weight Loss Rate (g/min) [INFERENCE].
3. **What is the output?** Estimated Time to Completion (mins), Moisture Content %, Predicted Shelf Life (days) [INFERENCE].
4. **Why can a simpler rule/system not solve it?** Nonlinear thermodynamic drying behavior varies dynamically with ambient weather changes [INFERENCE].
5. **What data is required?** Empirical drying curves across crop types under varying thermal profiles [RESEARCHED].
6. **How will it be evaluated?** Mean Absolute Error (MAE) < 5 minutes on predicted drying time [ASSUMPTION].
7. **What happens when it is wrong?** Product may be slightly under/over-dried; backup manual moisture meter check mitigates risk [INFERENCE].
8. **Does it require training?** Yes, regression model trained on lab dehydration runs [INFERENCE].
9. **Does it require fine-tuning?** No, lightweight decision tree regression [INFERENCE].
10. **Does it require RAG?** No [INFERENCE].
11. **Does it require computer vision?** No [INFERENCE].
12. **Does it require speech processing?** No [INFERENCE].
13. **Does it require forecasting?** Yes, time-series regression forecasting [INFERENCE].

### Where AI Should NOT Be Used
* **Weight Measurement:** Load cells using HX711 ADCs require straightforward linear strain-gauge calibration equations ($y = mx + c$), not machine learning [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Local SQLite Schema (Edge Device)

```sql
-- Batch Table
CREATE TABLE IF NOT EXISTS produce_batches (
    batch_id VARCHAR(36) PRIMARY KEY,
    farmer_id VARCHAR(50) NOT NULL,
    crop_type VARCHAR(30) NOT NULL,
    start_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    end_time DATETIME,
    total_weight_kg REAL DEFAULT 0.0,
    grade_a_weight_kg REAL DEFAULT 0.0,
    grade_b_weight_kg REAL DEFAULT 0.0,
    grade_c_weight_kg REAL DEFAULT 0.0,
    sync_status INTEGER DEFAULT 0 -- 0 = Unsynced, 1 = Synced
);

-- Item Assaying Table
CREATE TABLE IF NOT EXISTS item_inspections (
    item_id VARCHAR(36) PRIMARY KEY,
    batch_id VARCHAR(36) REFERENCES produce_batches(batch_id),
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    assigned_grade CHAR(1) CHECK(assigned_grade IN ('A', 'B', 'C')),
    confidence_score REAL,
    defect_percentage REAL,
    item_weight_g REAL,
    image_path TEXT
);

-- Processing Session Table
CREATE TABLE IF NOT EXISTS dehydration_sessions (
    session_id VARCHAR(36) PRIMARY KEY,
    batch_id VARCHAR(36) REFERENCES produce_batches(batch_id),
    initial_weight_kg REAL,
    final_weight_kg REAL,
    target_moisture_pct REAL,
    duration_minutes INTEGER,
    energy_source VARCHAR(20) -- 'SOLAR', 'HYBRID', 'GRID'
);
```

### Offline Synchronization & Conflict Handling
* **Store-and-Forward Daemon:** A background Python daemon periodically checks for internet connectivity (pings `8.8.8.8` or MQTT broker). Unsynced records (`sync_status = 0`) are queried, compressed into gzip JSON arrays, and published via MQTT with QoS Level 1 [INFERENCE].
* **Conflict Resolution:** Every record uses UUID v4 as primary key (`batch_id`). Because data generation is strictly local-first and immutable per edge unit, server-side primary key collisions are mathematically impossible [INFERENCE]. If batch updates occur on both mobile app and edge box, the edge box timestamp takes authority for physical weights [INFERENCE].
* **Bandwidth Optimization:** Raw crop images are retained locally on the SD card for 7 days and purged. Only metadata (grade, weight, defect %) and thumbnail images (128x128 compressed JPEG) are transmitted over low-bandwidth cellular connections [INFERENCE].
