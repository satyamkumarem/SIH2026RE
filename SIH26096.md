## 1. Executive Snapshot

This dossier presents a complete technical blueprint and strategic roadmap for **SIH26096**, commissioned by the **Ministry of Social Justice and Empowerment (MoSJE)**. The project addresses the historical fragmentation and accessibility barriers of Dr. B. R. Ambedkar’s writings, speeches, rare manuscripts, and Constituent Assembly debates [PS]. The proposed solution is a **Centralized Hardware-Software Integrated Digital Archive Platform** designed for deployment at institutions like the **Dr. Ambedkar International Centre (DAIC), New Delhi** [PS, KNOWN]. The platform combines interactive touch-screen kiosks, smart displays, a high-performance centralized archival server, and a specialized AI suite featuring OCR document processing, multilingual speech and translation via Bhashini APIs, vector-based semantic search, and an AI Research Assistant for constitutional Q&A [PS, INFERENCE]. This document provides a 4-6 student team with the exact architectural choices, dataset strategies, hardware configurations, and demonstration plan necessary to win Smart India Hackathon 2026.

## 2. Problem Deconstruction

The problem statement provided by MoSJE outlines nine explicit core requirements. To ensure full compliance without omitting or weakening any requirement, they are mapped below:

1. **REQ-1: AI-Powered Semantic Search & Knowledge Mapping**
   * *Source Text:* "AI-powered semantic search and intelligent knowledge mapping." [PS]
   * *Interpretation:* Keyword search is insufficient; the platform must understand conceptual relations (e.g., linking "Annihilation of Caste" to constitutional Article 17) using vector embeddings and knowledge graphs [INFERENCE].
   * *Implementation Implication:* Vector database (Qdrant / PostgreSQL with `pgvector`) + Graph database (Neo4j / NetworkX) for entity mapping [INFERENCE].

2. **REQ-2: Full-Text & Summarized Access**
   * *Source Text:* "Full-Text and summarized access to writings and speeches." [PS]
   * *Interpretation:* Users must be able to read full raw transcripts/books (e.g., BAWS 22 volumes) or generate concise, context-aware summaries for quick learning [PS, INFERENCE].
   * *Implementation Implication:* High-speed document reader UI + pre-computed/on-demand LLM summarization pipeline with page-accurate citation tracking [INFERENCE].

3. **REQ-3: OCR Digitization of Manuscripts**
   * *Source Text:* "OCR-based digitization of old documents and manuscripts." [PS]
   * *Interpretation:* Ingest low-quality, yellowed, or handwritten historical scans, remove noise, extract text, and preserve layout metadata [PS, INFERENCE].
   * *Implementation Implication:* Image preprocessing (OpenCV) + Indic OCR models (Tesseract 5 / PaddleOCR / Bhashini OCR API) [RESEARCHED, INFERENCE].

4. **REQ-4: Multilingual Translation & Audio Narration**
   * *Source Text:* "Multilingual translation and audio narration features." [PS]
   * *Interpretation:* Break language barriers across 22 scheduled Indian languages, enabling audio playback (text-to-speech) for visually impaired or non-English literate visitors [PS, RESEARCHED].
   * *Implementation Implication:* Integration with Digital India Bhashini NMT (Neural Machine Translation) and TTS (Text-to-Speech) APIs [RESEARCHED].

5. **REQ-5: Audio-Video Archival System**
   * *Source Text:* "Audio-video archival system for lectures, documentaries, and interviews." [PS]
   * *Interpretation:* Host, index, stream, and timestamp historical audio recordings, documentaries, and academic lectures with synchronized transcript playback [PS, INFERENCE].
   * *Implementation Implication:* HLS (HTTP Live Streaming) media server + Automated Speech Recognition (ASR) whisper/Bhashini pipeline for timestamped subtitle generation [INFERENCE].

6. **REQ-6: Interactive Timeline & Memorial Storytelling**
   * *Source Text:* "Interactive timeline and memorial story telling modules." [PS]
   * *Interpretation:* Visually map key milestones in Dr. Ambedkar's life (Mahad Satyagraha, Poona Pact, Drafting Committee, Conversion to Buddhism) connected to relevant documents, speeches, and photo galleries [PS, KNOWN].
   * *Implementation Implication:* Rich interactive UI component (React / D3.js / Vis.js) connected to chronological event schemas [INFERENCE].

7. **REQ-7: AI Research Assistant**
   * *Source Text:* "AI Research Assistant for answering queries related to Dr. Ambedkar's works and constitutional ideas." [PS]
   * *Interpretation:* A conversational interface that answers academic and public queries strictly based on verified historical sources without hallucinations [PS, INFERENCE].
   * *Implementation Implication:* Retrieval-Augmented Generation (RAG) architecture using Llama-3 / Mixtral / Claude with strict source attribution and guardrails [INFERENCE].

8. **REQ-8: Hardware-Software Integrated Kiosk System**
   * *Source Text:* "centralized hardware-software integrated digital archive system should be developed for institutions such as Dr. Ambedkar International Centre. The solution should include interactive kiosks and smart displays..." [PS]
   * *Interpretation:* The solution cannot be purely a web URL; it must include physical hardware kiosk integration (touchscreen interface, lockdown browser mode, edge caching, proximity sensors/accessibility options) [PS, INFERENCE].
   * *Implementation Implication:* Dual-mode architecture: Edge Kiosk Client (Electron / React Kiosk Shell running on Raspberry Pi 5 or Mini PC with touch display) connected to a Centralized On-Premise/Cloud Archival Server [INFERENCE].

9. **REQ-9: Secure Digital Preservation & Metadata Tagging**
   * *Source Text:* "The platform should also support secure digital preservation, metadata tagging, and institutional archival management." [PS]
   * *Interpretation:* Admin dashboard for archivists to upload documents, apply Dublin Core metadata standards, manage role-based access control (RBAC), and maintain archival audit logs [PS, INFERENCE].
   * *Implementation Implication:* Institutional admin backend with Dublin Core schema, S3/MinIO secure object storage, and checksum validation [INFERENCE].

## 5. Constraints & Environment Realities

1. **Hardware & Physical Kiosk Realities:**
   * Kiosks deployed at high-footfall institutions like DAIC face heavy public physical interaction [PS, KNOWN]. Touches must be responsive (<200ms feedback), screens must be vandal-resistant, and the OS must run in **Kiosk Lockdown Mode** (preventing users from exiting to the desktop or accessing system settings) [INFERENCE].
   * Physical sound management: High ambient museum noise requires directed audio (directional speakers or dual headphone jacks) for speech listening [INFERENCE].

2. **Network & Connectivity Constraints:**
   * Institutional Wi-Fi/LAN can experience intermittent outages. High-resolution manuscript scans and video streaming must not crash during connectivity loss. The kiosk client must maintain a **Local Edge Cache** (SQLite/IndexedDB) with core offline capabilities (pre-buffered timeline, cached core documents, and UI assets) [INFERENCE].

3. **Multilingual & Digital Literacy Constraints:**
   * Visitors span diverse socio-economic backgrounds, age groups, and literacy levels [PS, INFERENCE]. The UI must avoid complex menu hierarchies, feature large touch targets, provide voice search (Speech-to-Text), and support primary regional scripts (Hindi, Marathi, English, Tamil, Telugu, Bengali, Gujarati) [PS, RESEARCHED].

4. **Archival & Document Condition Constraints:**
   * Many historical manuscripts from 1920–1950 suffer from paper yellowing, ink bleeding, torn edges, and low contrast [RESEARCHED]. Standard OCR fails on uncleaned images. Image pre-processing (binarization, deskewing, noise reduction) is mandatory prior to OCR execution [INFERENCE].

## 9. Candidate Solution Approaches

### Approach 1: Basic Web Archive Portal (Pure Software / Keyword Search)
* *Mechanism:* Traditional monolithic web application (Django + PostgreSQL) with standard SQL `LIKE` or Full-Text Search (FTS) indexing on parsed PDF texts.
* *Complexity:* Low.
* *Cost:* Very Low.
* *Evaluation:*
  * *Pros:* Simple to build within 48 hours; minimal infrastructure cost.
  * *Cons:* Fails REQ-1 (no semantic concept mapping), REQ-7 (no AI assistant), REQ-8 (no kiosk hardware layer), and REQ-4 (no real-time speech/translation). Completely fails the hardware category expectation of SIH [INFERENCE].

### Approach 2: Heavy Cloud-Native AI Architecture (Microservices + Commercial LLMs)
* *Mechanism:* Microservices on AWS/GCP using OpenAI GPT-4, Pinecone vector database, AWS Transcribe, and AWS Polly.
* *Complexity:* High.
* *Cost:* High (recurring API token costs and cloud hosting).
* *Evaluation:*
  * *Pros:* High NLP accuracy out of the box; fast rapid prototyping.
  * *Cons:* Severe vulnerability to internet downtime in physical museum settings; high recurring costs for public kiosks; poor performance on low-resource Indian languages compared to specialized Indic models [INFERENCE].

### Approach 3: Integrated Hardware-Software Architecture with Edge Kiosk Caching & Bhashini / Indic AI Stack (RECOMMENDED)
* *Mechanism:* Dedicated Edge Touch-Kiosk Client (Electron/React Kiosk Shell) backed by an On-Premise/Cloud Hybrid Server (FastAPI + PostgreSQL `pgvector` + Qdrant). Integrates Government of India’s **Bhashini API** for voice/translation, **Tesseract 5/PaddleOCR** for document ingestion, and a localized RAG pipeline for constitutional Q&A [RESEARCHED, INFERENCE].
* *Complexity:* Moderate - High.
* *Cost:* Low (uses open-source tools and free tier government Bhashini APIs).
* *Evaluation:*
  * *Pros:* Meets 100% of problem requirements [PS]; satisfies the Hardware category requirement [PS]; robust against network drops via edge caching; zero recurring commercial LLM costs [INFERENCE].
  * *Cons:* Requires hardware setup and careful API pipeline integration [INFERENCE].

### Detailed Data-Flow Narrative

1. **Visitor Kiosk Session Initiated:**
   A visitor approaches the touch kiosk at DAIC. The proximity sensor detects the visitor, waking up the screen from saver mode. The Electron touch shell presents a multilingual home screen (Hindi, English, Marathi, etc.) [INFERENCE].

2. **Query / Voice Input & Processing:**
   * *Text Input:* The user types "What were Ambedkar's views on Article 370?" into the semantic search bar.
   * *Voice Input:* The user presses the microphone icon and speaks in Hindi: "डॉ. आंबेडकर के शिक्षा पर क्या विचार थे?". The edge client streams audio to the backend via WebSocket. The backend routes audio to **Bhashini Speech-to-Text (ASR)**, returning text in Hindi [RESEARCHED, INFERENCE].

3. **Semantic Vector Search & RAG Generation:**
   The text query is passed to the **Embedding Model** (bge-m3 / IndicBERT) to generate a dense vector [RESEARCHED]. The vector database (`pgvector` / Qdrant) performs similarity search across chunked BAWS volumes and Constituent Assembly Debates.
   The top-k relevant text chunks (with exact volume and page citations) are injected into the context window of the **RAG Engine**.
   The LLM generates a clear summary. If the visitor selected Hindi, the output is translated via **Bhashini NMT** and spoken aloud using **Bhashini TTS** [RESEARCHED, INFERENCE].

4. **Archival Upload & Processing Flow (Admin Side):**
   An archivist uploads a scanned handwritten manuscript PDF via the Admin Portal. The file is saved in MinIO Object Storage. An async Celery background task runs OpenCV binarization, executes **Tesseract 5 OCR**, extracts text, generates vector embeddings, creates Dublin Core metadata tags, and updates the vector index [INFERENCE].

## 13. AI/ML Justification

### 1. Vector Embeddings & Semantic Search Engine
* **Exact Purpose:** Enable conceptual search (e.g., matching "social democracy" to speeches on fraternity and equality) beyond rigid keywords [PS, INFERENCE].
* **Model Type:** `bge-m3` or `IndicBERT` embeddings [RESEARCHED].
* **Input:** Raw text user query.
* **Output:** Ranked array of document chunk IDs, BAWS volume numbers, and exact page references.
* **Data Required:** Pre-tokenized chunks of BAWS 22 volumes and Constituent Assembly Debates [PS, RESEARCHED].
* **Why AI:** Rule-based keyword matching misses synonyms, indirect references, and conceptual links across historical texts [INFERENCE].
* **Evaluation:** Mean Reciprocal Rank (MRR@10) and Normalized Discounted Cumulative Gain (NDCG) on a gold-standard query dataset [INFERENCE].
* **Failure Mode & Oversight:** If similarity scores fall below threshold (<0.65), fall back to exact keyword match and display: *"No exact semantic match found. Showing keyword results."* [INFERENCE]

### 2. Document OCR & Layout Processing Engine
* **Exact Purpose:** Convert scanned manuscript PDFs into searchable UTF-8 text while preserving document structure [PS].
* **Model Type:** OpenCV preprocessing + Tesseract 5 / PaddleOCR [RESEARCHED].
* **Input:** Raw manuscript image (PNG/TIFF/PDF).
* **Output:** Cleaned plain text, layout bounding boxes, and extracted metadata.
* **Data Required:** Historical document sample scans for OCR fine-tuning [INFERENCE].
* **Why AI:** Handwritten and aged printed manuscripts have non-standard fonts, uneven alignment, and paper noise that rule-based extractors cannot handle [INFERENCE].
* **Evaluation:** Character Error Rate (CER) and Word Error Rate (WER) against ground-truth manual transcriptions [INFERENCE].
* **Failure Mode & Oversight:** Flag low-confidence text outputs (CER > 15%) in the Admin Portal for manual human-in-the-loop archivist review [INFERENCE].

### 3. RAG AI Research Assistant ("Babasaheb AI")
* **Exact Purpose:** Provide natural language answers to user queries regarding Dr. Ambedkar's works and constitutional ideas [PS].
* **Model Type:** Quantized Llama-3-8B-Instruct / Mixtral with RAG prompt guardrails [INFERENCE].
* **Input:** User question + Top-5 retrieved BAWS text chunks.
* **Output:** Synthesized answer with inline BAWS volume/page citations.
* **Data Required:** Chunked vector index of official writings and speeches [PS, RESEARCHED].
* **Why AI:** Enables conversational exploration for non-expert visitors and synthesizes information spread across multiple volumes [INFERENCE].
* **Evaluation:** Answer faithfulness (Ragas framework), citation accuracy, and hallucination rate [INFERENCE].
* **Failure Mode & Oversight:** Strict system prompt instruction: *"Answer strictly using the provided context. If the answer is not present in the historical context, state 'Information not found in available archives.'"* [INFERENCE]

### Where AI Should NOT Be Used:
* **Historical Fact Alteration / Document Rendering:** Raw historical PDFs and original manuscript scans must be served **unaltered**. AI must never "correct" or rephrase historical original documents [INFERENCE].
* **User Authentication & Access Control:** Admin permissions and kiosk lockdown security must be governed by strict deterministic RBAC, never AI decisions [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### PostgreSQL Core Database Schema

```sql
-- Core Archives Table
CREATE TABLE archival_assets (
    asset_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    asset_type VARCHAR(50) CHECK (asset_type IN ('manuscript', 'speech', 'writing', 'photo', 'audio', 'video')),
    baws_volume INT,
    page_number INT,
    author VARCHAR(100) DEFAULT 'Dr. B. R. Ambedkar',
    language VARCHAR(30) DEFAULT 'English',
    publication_date DATE,
    dublin_core_metadata JSONB NOT NULL,
    file_path VARCHAR(500) NOT NULL,
    checksum_sha256 VARCHAR(64) UNIQUE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Document Chunks for Vector Search & RAG
CREATE TABLE document_chunks (
    chunk_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_id UUID REFERENCES archival_assets(asset_id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,
    raw_text TEXT NOT NULL,
    token_count INT NOT NULL,
    embedding vector(1024), -- pgvector extension column
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_chunks_embedding ON document_chunks USING hnsw (embedding vector_cosine_ops);
```

### Local Caching & Offline Synchronization Flow

```
+-----------------------------------------------------------------------------------+

                                       |

            |                                                     |
  [ONLINE: WAN Active]                                  [OFFLINE: WAN Down]

```

1. **Bandwidth Reduction Strategy:** Images served to kiosks are automatically compressed and delivered in WebP format; audio is streamed via AAC/Ogg; video uses adaptive HLS chunks (480p/720p/1080p based on local LAN speeds) [INFERENCE].
2. **Conflict Handling:** Kiosks are read-only consumers. Analytical logs and feedback are queued locally with ISO timestamps and synced asynchronously using an idempotent append-only API endpoint [INFERENCE].

## 15. Security, Privacy & Governance

1. **Personal & Visitor Data Protection:** The public kiosk system operates in **Anonymous Guest Mode**. No personal identifiable information (PII) like name, phone number, or email is collected during visitor interactions [INFERENCE].
2. **Kiosk Enclosure & OS Security:** Kiosks run a locked-down Linux environment (e.g., Ubuntu Core / Kiosk OS) with disabled USB mass storage, blocked shell shortcuts (Ctrl+Alt+Del, Alt+Tab), auto-launching Electron shell, and automated nightly reboot cycles [INFERENCE].
3. **Role-Based Access Control (RBAC):** Admin portal access is strictly controlled via JWT authentication with multi-factor authentication (MFA) for archivists [INFERENCE]:
   * *Role 1 (Viewer/Public):* Read-only access to published assets.
   * *Role 2 (Archivist):* Upload, OCR run, edit metadata tags, draft assets.
   * *Role 3 (Super Admin/DAIC Head):* Publish assets, manage users, view analytics.
4. **Historical Data Integrity & Provenance:** Every uploaded file generates a unique SHA-256 checksum upon ingestion to detect any file tampering or corruption over time [INFERENCE].
5. **AI Guardrails & Governance:** RAG outputs are constrained by strict system prompts to prevent political bias, hallucinations, or off-topic conversational drift. All generated AI answers contain explicit volume and page citations for user verification [INFERENCE].
