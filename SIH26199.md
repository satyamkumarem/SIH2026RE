## 1. Executive Snapshot

This project presents a cross-sector digital ecosystem platform designed for Smart India Hackathon (SIH) candidate problem statement **SIH26199** under the AICTE MIC-Student Innovation track [PS]. Rather than building isolated vertical apps, the system—titled **OmniServe TertiaryMesh**—creates an interoperable digital infrastructure unifying Hospitality, Financial Services, Entertainment, and Retail [INFERENCE]. By leveraging India's Digital Public Infrastructure (DPI) including the Open Network for Digital Commerce (ONDC Beckn Protocol) [RESEARCHED], RBI's Account Aggregator (AA) framework [RESEARCHED], and Unified Payments Interface (UPI) / CBDC rails [KNOWN], OmniServe TertiaryMesh enables hyper-local experiential discovery, zero-commission retail and hospitality bookings, event ticketing, and real-time consent-based micro-financing for tier-2/3 MSMEs and micro-vendors [INFERENCE].

## 5. Constraints & Environment Realities

*   **Connectivity Realities:** Variable 3G/4G bandwidth in Tier-3 locations and heritage travel spots [KNOWN]. App must operate as a Progressive Web App (PWA) under 3MB initial payload with offline listing storage using IndexedDB [INFERENCE].
*   **Hardware Realities:** Merchants use entry-level Android smartphones (2GB–4GB RAM, MediaTek chips) [KNOWN]. Heavy client-side JS frameworks or local ML models will crash client devices; all heavy ML inference must occur server-side [INFERENCE].
*   **Digital Literacy & Language Constraints:** Over 60% of small kirana and homestay owners in Tier-2/3 regions prefer local spoken dialects over complex English dashboards [KNOWN]. Voice input/output and simple WhatsApp/SMS notification fallbacks are mandatory [INFERENCE].
*   **Financial & Regulatory Constraints:**
    *   *RBI Guidelines:* Financial data retrieval must strictly adhere to the RBI Master Direction for NBFC-Account Aggregators [RESEARCHED]. No credential scraping or PDF parsing permitted [RESEARCHED].
    *   *Data Ownership:* DPDP Act 2023 mandates strict consent management, explicit purpose limits, and user-initiated data erasure options [KNOWN].

## 6. Research Questions

1.  *How do ONDC Beckn API v2.0 schemas represent multi-domain search results across heterogeneous inventory (e.g., hotel rooms vs. physical retail SKUs vs. event time-slots)?*
    *   *Finding:* Beckn v2.0 uses domain-specific context tags (`context.domain`) with generic `item`, `fulfillment`, and `offer` primitives [RESEARCHED].
2.  *What is the exact REST flow for initiating and fetching financial data via RBI's Account Aggregator framework?*
    *   *Finding:* ReBIT specification defines: `POST /aa/v2/consent` (creates consent handle) $\rightarrow$ User approves on AA App $\rightarrow$ `POST /aa/v2/fi/request` $\rightarrow$ `POST /aa/v2/fi/fetch` (fetches encrypted payload) [RESEARCHED].
3.  *What is the live adoption and scale of Ministry of Tourism's NIDHI+ portal for verifying legitimate hospitality providers?*
    *   *Finding:* As of 2026, over 27,000 hotels and 8,000 homestays are registered on NIDHI+ [RESEARCHED]. NIDHI ID can serve as a primary verification attribute [INFERENCE].
4.  *Are public GSTN API sandboxes accessible for student hackathons without paying expensive GST Suvidha Provider (GSP) fees?*
    *   *Finding:* Official GSTN developer sandbox (`developer.gst.gov.in`) and open platforms like Sandbox.co.in offer free UAT sandbox keys for GSTIN verification [RESEARCHED].

## 10. Recommended Approach & Why

**Selected Approach:** **Approach 3: DPI-Native Cross-Sector Mesh Platform ("OmniServe TertiaryMesh")** [INFERENCE].

### Why Alternatives Were Rejected:
1.  **Rejection of Approach 1 (Monolithic Multi-Portal):** Building four separate siloed forms (Hotel booking form, Kirana shopping cart, Event ticket seller, Loan application form) is an outdated design pattern. It fails to demonstrate national innovation and ignores India's open network transformations (ONDC, Account Aggregator) [RESEARCHED] [INFERENCE].
2.  **Rejection of Approach 2 (Pure LLM Agent System):** Relying entirely on an LLM agent to execute financial bookings and credit checks introduces catastrophic failure modes—hallucinated room rates, invalid transaction payloads, non-deterministic API execution, and latency over 5 seconds per request, which breaks live hackathon evaluation [INFERENCE].

### Why Approach 3 Wins:
*   **National Alignment:** Natively integrates ONDC Beckn protocol for open retail/hospitality commerce and RBI Account Aggregator for cash-flow-based financial lending [RESEARCHED].
*   **Engineering Robustness:** Combines deterministic core payment/booking flows with targeted AI enhancements (Whisper voice processing and XGBoost credit underwriting) [INFERENCE].
*   **Feasibility:** Allows student developers to build standard REST microservices backed by simulated DPI sandboxes during the SIH finale [INFERENCE].

### Detailed Data Flow Narrative:
1.  **Discovery & Natural Language Input:**
    *   A consumer speaks into the PWA: *"Show me a heritage stay in Udaipur under ₹3,000 with local handloom shopping and traditional music ticket for tonight."*
    *   Web Audio API captures raw WAV audio blob and streams it to the AI Service via HTTPS POST [INFERENCE].
    *   Whisper AI converts speech to text. Llama-3-8B parses entities: `{ location: "Udaipur", max_stay_price: 3000, categories: ["hospitality", "retail_handloom", "entertainment_music"], time: "tonight" }` [INFERENCE].
2.  **Open Network Broadcasting (Beckn Engine):**
    *   The Beckn Adapter creates a standardized Beckn `/search` JSON request context and multicasts it to simulated ONDC seller providers (BPPs) across Retail, Hospitality, and Entertainment [RESEARCHED] [INFERENCE].
    *   BPP adapters respond asynchronously with matching inventory items [RESEARCHED].
3.  **Cross-Sector Bundle Generation:**
    *   The Dynamic Bundle Engine calculates a bundled offer (e.g., Hotel Room + Handicraft Store Coupon + Concert Pass) offering a 10% combined discount funded by reduced platform commissions [INFERENCE].
4.  **Checkout & Multi-Party UPI Settlement:**
    *   The consumer confirms the bundle. The Payment Service generates an NPCI-compliant UPI link with split payment metadata [KNOWN]. Upon callback verification, escrow funds are immediately allocated to the three respective merchant accounts [INFERENCE].
5.  **Merchant Micro-Financing via Account Aggregator:**
    *   The handicraft merchant applies for a ₹25,000 working capital loan directly inside their merchant portal [INFERENCE].
    *   The AA FIU Service initiates `POST /aa/v2/consent` to the merchant's AA app (e.g., Setu/Sahamati Sandbox) [RESEARCHED].
    *   Once approved, `POST /aa/v2/fi/fetch` retrieves encrypted 6-month transaction data [RESEARCHED].
    *   The XGBoost scoring model evaluates cash flow volatility, average monthly balance, and ONDC order volume, issuing an automated credit rating and loan approval recommendation in under 15 seconds [RESEARCHED] [INFERENCE].

```sql
    merchant_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(user_id),
    business_name VARCHAR(150) NOT NULL,
    sector VARCHAR(30) CHECK (sector IN ('HOSPITALITY', 'RETAIL', 'ENTERTAINMENT')),
    gstin VARCHAR(15),
    nidhi_id VARCHAR(50), -- Ministry of Tourism NIDHI verification ID
    ondc_bpp_id VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Consolidated Items / Inventory Table (Beckn Standardized)
CREATE TABLE inventory_items (
    item_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    merchant_id UUID REFERENCES merchants(merchant_id),
    title VARCHAR(200) NOT NULL,
    description TEXT,
    category VARCHAR(50) NOT NULL, -- e.g., 'ROOM', 'HANDICRAFT', 'EVENT_TICKET'
    price DECIMAL(10,2) NOT NULL,
    available_stock INT DEFAULT 1,
    location_point GEOGRAPHY(POINT, 4326),
    embedding vector(384) -- pgvector embedding for AI search
);

-- Account Aggregator Consent Records
CREATE TABLE aa_consents (
    consent_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    merchant_id UUID REFERENCES merchants(merchant_id),
    consent_handle VARCHAR(100) UNIQUE NOT NULL,
    status VARCHAR(20) CHECK (status IN ('PENDING', 'APPROVED', 'REVOKED', 'EXPIRED')),
    purpose_code VARCHAR(20) DEFAULT '101', -- Cash Flow Credit Assessment
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Offline & Low-Network Synchronization Flow:
1.  **Local Caching (IndexedDB via Dexie.js):**
    *   Merchant inventory edits, offline QR ticket generations, and order fulfillment updates are stored locally in IndexedDB when network connection drops [INFERENCE].
2.  **Background Sync Engine:**
    *   A Service Worker registers a `sync` event (`sync-merchant-orders`). Once internet connectivity (2G/3G/4G) is re-established, the queue flushes pending transactions to the backend via a single batch sync API (`POST /api/v1/sync/batch`) [INFERENCE].
3.  **Conflict Handling:**
    *   *Strategy:* Server-wins for inventory availability; Client-timestamp log for merchant updates [INFERENCE]. If a room or ticket was sold online while the merchant was offline, the system triggers an automated customer refund flow and alerts the merchant via SMS fallback [INFERENCE].
