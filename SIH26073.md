## 1. Executive Snapshot

SkyGuard AI is an edge-cloud hybrid intelligent anomaly detection, explainability, and data imputation framework engineered specifically for the India Meteorological Department's (IMD) Automatic Weather Station (AWS) network [INFERENCE]. Designed to process streaming meteorological observations constrained strictly to **Air Temperature (°C)**, **Atmospheric Pressure (hPa)**, and **Relative Humidity (%)** [PS], the system deploys a two-tier architecture: an ultra-low-power TinyML Autoencoder running directly on ESP32 microcontroller edge nodes for sub-second localized detection [PS], paired with a cloud-based multivariate spatial-temporal ensemble (XGBoost + Isolation Forest + Spatial Kriging) [INFERENCE]. SkyGuard AI eliminates false alarms by cross-referencing temporal rate-of-change with neighbor-station consistency—distinguishing genuine extreme meteorological events (e.g., severe convective storms or sudden microbursts) from hardware faults, sensor freeze, calibration drift, and transmission corruption [PS]. Built-in SHAP (SHapley Additive exPlanations) provides human-interpretable physical reasoning and confidence scoring for every alert, while an automated imputation module restores missing or corrupted data streams [PS].

## 5. Constraints & Environment Realities

### Deployment Environment Analysis (India AWS Network)

1. **Connectivity Realities:**
   * IMD AWS units transmit data via dual modes: GPRS (cellular) and satellite telemetry (INSAT-3D / Kalpana-1 PRBS burst sequence) [RESEARCHED].
   * In rural, high-altitude (Himalayas), coastal, or desert regions, cellular connectivity suffers frequent dropouts [RESEARCHED]. Satellite uplink bursts occur typically once every 15 to 60 minutes [RESEARCHED].
   * *System Impact:* Edge node must run fully autonomous anomaly detection locally and store logs in SPIFFS/Flash memory during offline periods [INFERENCE].

2. **Power & Hardware Limitations:**
   * AWS stations operate off 12V 40Ah/100Ah solar-charged batteries [RESEARCHED].
   * The edge processing MCU (ESP32-S3 or standard ESP32) has strict energy budgets (<1W continuous draw, 240MHz dual-core CPU, 520KB SRAM, 4MB Flash) [RESEARCHED].
   * *System Impact:* Deep neural networks cannot run unquantized on the edge node. Edge models must use INT8 quantization and execution via TensorFlow Lite Micro [RESEARCHED].

3. **Sensor Degradation & Harsh Environmental Factors:**
   * Temperature RTDs/Thermistors suffer radiation shield debris accumulation or solar heating bias when unventilated [RESEARCHED].
   * Capacitive humidity sensors experience degradation due to dust, saline air in coastal belts (e.g., Odisha, Gujarat), and saturation hysteresis during prolonged fog/monsoon [RESEARCHED].
   * Piezoresistive pressure sensors suffer temperature thermal drift if internal temperature compensation fails [RESEARCHED].
   * *System Impact:* System must detect subtle multi-week calibration drift without confusing seasonal atmospheric transitions [INFERENCE].

4. **Strict Input Constraint (No Auxiliary Sensors):**
   * Problem constraints limit input parameters strictly to $T$, $P$, and $RH$ [PS].
   * Conventional weather anomaly detectors use wind speed or rain gauge data to cross-check pressure drops. SkyGuard AI cannot rely on wind/rain parameters [INFERENCE].
   * *System Impact:* System must rely heavily on psychrometric relationships (e.g., relative humidity physical ceiling relative to air temperature) and spatial inter-station correlations [INFERENCE].

## 9. Candidate Solution Approaches

### Approach A: Rule-Based & Statistical Thresholding System (Pure Baseline)
* **Mechanism:** A pipeline executing WMO-No. 8 physical limits, moving Z-score calculations, and Exponentially Weighted Moving Average (EWMA) step checks [RESEARCHED].
* **Data Requirements:** Stream of $T, P, RH$.
* **Architecture:** C++ firmware executing on ESP32 or basic Python script.
* **Complexity:** Extremely Low.
* **Explainability:** 100% Rule-Based (e.g., "Value $> 55^\circ\text{C}$ exceeds physical maximum").
* **Hackathon Feasibility:** 100% (Can be coded in 2 hours).
* **Limitations:** Fails evaluation criteria on Innovation (25%) and Accuracy (20%); cannot detect hidden multivariate drift or distinguish real microbursts from sensor glitches [INFERENCE].

### Approach B: Pure Cloud Deep Learning (LSTM Autoencoder + Cloud SHAP)
* **Mechanism:** All raw AWS data is continuously streamed over GPRS/MQTT to a centralized PyTorch LSTM-Autoencoder. Anomalies are flagged based on reconstruction error thresholds ($\text{MSE} > \tau$), and SHAP explanations are computed in the cloud [RESEARCHED].
* **Data Requirements:** Continuous high-frequency stream of $T, P, RH$ to cloud.
* **Architecture:** Heavy Cloud Backend (FastAPI + PyTorch + Celery).
* **Complexity:** High.
* **Explainability:** High (via SHAP KernelExplainer).
* **Hackathon Feasibility:** Moderate (Requires cloud setup and continuous connectivity).
* **Limitations:** Violates Edge AI requirement (ESP32) [PS]; fragile during network outages; high cellular data bandwidth costs across 700+ remote stations [INFERENCE].

### Approach C: Hierarchical Edge-Cloud AI with SHAP & Spatial Kriging (Proposed Winner)
* **Mechanism:** 
  * **Tier 1 (Edge Node - ESP32):** Runs an INT8 quantized 1D-Convolutional Autoencoder in C++ via TensorFlow Lite Micro. Filters gross spikes, frozen values, and local noise in $<20\text{ms}$ while computing a local Anomaly Score ($S_{\text{edge}}$) [INFERENCE].
  * **Tier 2 (Cloud Core - Python FastAPI):** Receives data packets. If $S_{\text{edge}} > \text{threshold}$, triggers a multivariate ensemble (XGBoost + Isolation Forest) enriched with spatial neighbor correlation (Spatial Kriging) [INFERENCE].
  * **Tier 3 (XAI & Self-Healing Layer):** Computes exact SHAP feature attributions, classifies root-cause (Fault vs. Weather Event), generates imputed replacement values, and updates sensor health score [INFERENCE].
* **Data Requirements:** $T, P, RH$ time series + Neighbor station GeoJSON metadata.
* **Architecture:** ESP32 C++ Firmware + FastAPI Backend + TimescaleDB + Next.js Dashboard.
* **Complexity:** High (Balanced modular design).
* **Explainability:** High (Exact SHAP tree values & human-language translation).
* **Hackathon Feasibility:** 100% achievable for a 4–6 student team with proper task separation.
* **Strengths:** Fully satisfies ALL PS requirements including Edge AI on ESP32, Explainability (SHAP), Spatial consistency, and Energy efficiency [PS].

### Detailed Data Flow Narrative

1. **Perception & Sampling:** The AWS sensors measure Air Temperature, Atmospheric Pressure, and Relative Humidity at 1-minute intervals [RESEARCHED].
2. **Edge Filtering & Inference (ESP32):**
   * The ESP32 MCU reads raw values, checks basic physical limits (e.g., $T \in [-50, 60]^\circ\text{C}$), and updates a sliding buffer of 12 timesteps [INFERENCE].
   * The quantized TFLite Micro 1D-CNN Autoencoder evaluates the buffer. If Mean Squared Error ($\text{MSE}$) exceeds the edge threshold, an anomaly bit is set in the MQTT telemetry payload [INFERENCE].
3. **Transmission:** Payload is serialized in JSON/Protocol Buffers and published to `imd/aws/{station_id}/telemetry` over TLS-encrypted MQTT [INFERENCE].
4. **Cloud Processing & Spatial Cross-Check:**
   * FastAPI ingests the message. If flagged by the Edge or exceeding cloud temporal thresholds, the Spatial Consistency Checker fetches readings from surrounding stations within a $50\text{km}$ radius [INFERENCE].
   * If neighboring stations exhibit parallel trends (e.g., rapid pressure drop across 4 stations), the anomaly flag is overridden and labeled **Genuine Meteorological Event** [INFERENCE].
   * If isolated to a single station, the Root-Cause Classifier categorizes it into **Spike**, **Frozen Value**, **Calibration Drift**, **Power Fluctuation**, or **Sensor Malfunction** [INFERENCE].
5. **SHAP Explanation & Imputation:**
   * TreeSHAP calculates feature contributions (e.g., $\Delta P = +0.42, \Delta T = -0.15$), generating an plain-English explanation [INFERENCE].
   * If flagged as a sensor anomaly, the Data Imputer generates an estimated replacement value ($\hat{T}, \hat{P}, \hat{RH}$) using spatial inverse distance weighting and temporal interpolation [INFERENCE].
6. **Storage & Visualization:** The raw value, anomaly status, confidence score, SHAP attributions, and imputed values are committed to TimescaleDB and streamed to the Next.js dashboard via WebSockets [INFERENCE].

### Deep Dive: Individual AI Components

#### Component 1: Edge TinyML 1D-CNN Autoencoder
* **Exact Problem Solved:** Local, real-time identification of sensor hardware spikes, zero-variance freezes, and communication noise directly at the AWS station [INFERENCE].
* **Input:** Matrix of shape $(12, 3)$ representing the last 12 minutes of Temperature, Pressure, and Relative Humidity [INFERENCE].
* **Output:** Scalar Reconstruction Error ($\text{MSE}$) and binary trigger flag ($0$ or $1$) [INFERENCE].
* **Why Simpler Rules Fail:** Static thresholds cannot detect a frozen sensor whose value is within normal broad ranges (e.g., $T = 28.5^\circ\text{C}$ constant for 8 hours during mid-day when diurnal variation should occur) [INFERENCE].
* **Data Required:** 30 days of uncorrupted 1-minute historical AWS readings [INFERENCE].
* **Evaluation Metric:** Mean Squared Error ($\text{MSE}$) on clean test set; target latency $< 20\text{ms}$ on ESP32 [INFERENCE].
* **Failure Mode:** False alarm during sudden microburst; mitigated by passing flagged events to Cloud Tier 2 spatial verification [INFERENCE].
* **Training/Fine-tuning:** Offline training in PyTorch $\rightarrow$ Quantization to INT8 via TFLite Converter $\rightarrow$ Export to C++ byte array header (`model_data.h`) [RESEARCHED].

#### Component 2: Cloud Multivariate Root-Cause Classifier (XGBoost Ensemble)
* **Exact Problem Solved:** Multi-class classification of detected anomalies into specific failure modes or legitimate weather phenomena [INFERENCE].
* **Input:** $T, P, RH$, rolling mean/std (5m, 15m, 1h), rate of change ($\Delta T/\Delta t, \Delta P/\Delta t, \Delta RH/\Delta t$), psychrometric dew point departure, and spatial neighbor mean differences [INFERENCE].
* **Output:** Class Probabilities across 6 categories: `Normal`, `Sensor_Spike`, `Sensor_Freeze`, `Calibration_Drift`, `Power_Communication_Noise`, `Extreme_Weather_Event` [INFERENCE].
* **Why Simpler Rules Fail:** Multi-parameter physical correlations (e.g., $P$ dropping rapidly while $RH$ rises to 98% and $T$ drops $4^\circ\text{C}$) represent complex non-linear decision boundaries that rule sets miss or misclassify [INFERENCE].
* **Data Required:** Historical weather data enriched with synthetic anomaly injections and labeled operational logs [INFERENCE].
* **Evaluation Metric:** Multi-class F1-Score (Target $> 0.92$), False Alarm Rate (Target $< 2\%$) [INFERENCE].
* **Failure Mode:** Overfitting to specific regional climates; mitigated by training on diverse geographic nodes (Himalayan, Coastal, Desert, Inland Plains) [INFERENCE].

#### Component 3: Explainable AI Engine (TreeSHAP)
* **Exact Problem Solved:** Translating high-dimensional tree model decisions into human-interpretable physical explanations for IMD forecasters [PS].
* **Input:** Labeled anomaly instance + Trained XGBoost model object [INFERENCE].
* **Output:** Vector of Shapley values for each feature ($\phi_T, \phi_P, \phi_{RH}, \phi_{\text{spatial\_diff}}$) and auto-generated explanation string [INFERENCE].
* **Why Simpler Rules Fail:** Black-box models provide no visibility into why a sample was flagged. SHAP provides exact additive feature importance guarantees grounded in game theory [RESEARCHED].
* **Evaluation Metric:** Human sanity check agreement with meteorological physical principles [INFERENCE].

#### Component 4: Spatio-Temporal Data Imputer (Spatial Kriging + Bi-LSTM)
* **Exact Problem Solved:** Imputing missing or corrupt data values to maintain continuous data feeds for numerical weather prediction models [PS].
* **Input:** Corrupted observation timestamp, station coordinates, clean values from $K$-nearest neighbor AWS nodes ($K=3..5$), and past 12-hour local historical trajectory [INFERENCE].
* **Output:** Estimated replacement values ($\hat{T}, \hat{P}, \hat{RH}$) with confidence interval [INFERENCE].
* **Why Simpler Rules Fail:** Simple linear interpolation fails during rapid non-linear weather transitions (e.g., sudden temperature drops during convective rain) [INFERENCE].

### WHERE NOT TO USE AI (Rule-Based Safety Net)

AI models MUST NOT be used for absolute physical bound enforcement [INFERENCE]. Deterministic, hardcoded rule filters must run prior to any ML inference:
1. **Absolute Physical Range Limits:**
   * Air Temperature: Flag if $T < -50^\circ\text{C}$ or $T > +60^\circ\text{C}$ [RESEARCHED].
   * Relative Humidity: Flag if $RH < 0\%$ or $RH > 100\%$ [RESEARCHED].
   * Atmospheric Pressure: Flag if $P < 500\text{ hPa}$ or $P > 1080\text{ hPa}$ [RESEARCHED].
2. **Hard Power Supply Failure:** If battery voltage $V_{\text{batt}} < 9.5\text{V}$, instantly flag "Power Failure Anomaly" without executing ML models [INFERENCE].

### Offline & Low-Network Resiliency Strategy

```
+-----------------------------------------------------------------------------------+
|                        ESP32 EDGE OFFLINE SYNC STATE MACHINE                      |
+-----------------------------------------------------------------------------------+
|  [Sensors Read] ---> Store in 12-sample Ring Buffer                               |
|                           |                                                       |
|                           v                                                       |
|                     [Run TFLite] ---> Flag Anomaly?                               |
|                           |                                                       |
|              +------------+------------+                                          |
|              |                         |                                          |
|     (Network Available)       (Network Offline)                                   |
|              |                         |                                          |
|              v                         v                                          |
|      Send MQTT Stream         Append to SPIFFS / SD Log                          |
|                                        |                                          |
|                                        v                                          |
|                               Check Network Link Loop                             |
|                                        |                                          |
|                                        v (Link Restored)                          |
|                               Burst Sync with Backoff Delay                       |
+-----------------------------------------------------------------------------------+
```

1. **Local Ring-Buffer & SPIFFS Flash Logging:** The ESP32 firmware maintains a circular memory buffer in SRAM for instant inference and writes compressed records to internal SPIFFS Flash memory (or microSD module) during network dropouts [INFERENCE].
2. **Store-and-Forward Retry Protocol:** When GPRS/satellite connectivity fails, the device enters `OFFLINE_LOGGING` mode. Upon reconnection, it executes an exponential backoff burst transmission protocol to push stored logs without overloading the cloud broker [INFERENCE].
3. **Data Bandwidth Reduction:** During normal operations, normal observations can be aggregated into 5-minute averages, whereas detected anomalies trigger immediate high-frequency 1-minute alert frames [INFERENCE].
