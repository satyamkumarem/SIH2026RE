# Smart India Hackathon (SIH) Solution Dossier
## Problem Statement SIH26208: Student Innovation - Conceptualize and Develop Unique Toys and Games Based on Our Civilization, History, and Culture

---

## 1. Executive Snapshot

### Executive Summary
This dossier presents a comprehensive technical architecture and implementation strategy for **"Samskriti Heritage Quest & Digital Toy Studio"** (code-named **BHARAT-QUEST**), an interactive multi-platform software ecosystem designed for Smart India Hackathon (SIH) 2026 under problem statement `SIH26208` [PS]. Conceived under the AICTE / MIC-Student Innovation track [PS], the system addresses the critical national objective of integrating Indian Knowledge Systems (IKS) and toy-based pedagogy into school and higher education curricula as mandated by the National Education Policy (NEP) 2020 [RESEARCHED]. The solution combines lightweight WebGL/WebXR 3D historical quest environments, an offline-first Progressive Web Application (PWA) engine, an AI-powered multi-lingual procedural storytelling and assessment pipeline, and a printable DIY cardboard smart toy generator. Designed explicitly for low-bandwidth, budget-hardware operating environments in Tier-2/3 Indian schools [INFERENCE], the system bridges ancient civilizational history (from Harappan urban planning to Chola maritime navigation) with 21st-century digital interactive play.

## 5. Constraints & Environment Realities

*   **Geography & Rural Infrastructure:** Primary deployment targets include PM SHRI schools, Jawahar Navodaya Vidyalayas, and rural state board schools across diverse geographical regions [RESEARCHED].
*   **Connectivity Realities:** Tier-2/3/4 locations frequently experience high-latency 2G/3G connections, sporadic 4G with packet drops, or complete offline states during school hours [KNOWN]. The client application must not fail when network connection drops [INFERENCE].
*   **Hardware Limitations:** Schools predominantly operate low-cost desktop PCs (Intel Core i3 4th Gen or Celeron, 4GB RAM, integrated graphics) or low-cost Android tablets ($80–$120 price point, Mali/Adreno entry GPUs) [KNOWN]. Uncompressed 3D assets or heavy game engines (Unreal Engine 5) will fail to render [INFERENCE].
*   **Power Supply:** Semi-urban and rural feeders experience unannounced load shedding [KNOWN]. Local state persistent autosave is non-negotiable [INFERENCE].
*   **Language & Literacy:** Medium of instruction varies widely across Indian states [KNOWN]. UI and game text must support multi-lingual toggling (Hindi, Tamil, Telugu, Marathi, Bengali, English) [INFERENCE].
*   **Digital Personal Data Protection (DPDP) Act 2023 Compliance:** Strict statutory prohibitions apply to tracking, behavioral profiling, or collecting biometric/personal data of children under 18 years of age in India (Section 9, DPDP Act 2023) [RESEARCHED].
*   **Field Operating Conditions:** Classroom environments require high durability, simple touch/mouse interfaces, and zero requirement for expensive external VR headsets or high-end sensors [INFERENCE].

## 10. Recommended Approach & Why

### Selected Strategy: Hybrid WebGL/WebXR + PWA + Procedural IKS Engine (Approach 3)

#### Justification for Selection
1.  **Zero Installation & Universal Access:** WebGL/PWA allows instant execution in any modern browser on Windows, Linux, Android, or iOS without requiring app store installation or admin privileges on school PCs [INFERENCE].
2.  **Low-Spec Optimization:** Uses procedural low-poly Three.js rendering with baked lighting shaders, allowing smooth execution (`30–60 FPS`) on integrated Intel HD Graphics and $80 Android tablets [INFERENCE].
3.  **Digital-Physical Bridge (DIY Smart Toys):** Includes a module that generates printable PDF target cards (e.g., Harappan granary or Chola ship pieces). When scanned with a web camera, WebXR renders 3D interactive models on top of the physical paper craft [INFERENCE].
4.  **Offline Resiliency:** Progressive Web App capabilities via Service Workers allow the complete game to be cached locally on a school PC once, operating 100% offline indefinitely [INFERENCE].

#### Rejection Analysis for Alternatives
*   **Approach 1 (Unreal/Unity Native) Rejected Because:** High bundle size (`> 500 MB`), failure on integrated Intel graphics chips common in government schools, and complex native installation barriers [INFERENCE].
*   **Approach 2 (Pure 2D Quiz Web App) Rejected Because:** Fails the "unique toys and games" core mandate of problem statement SIH26208, appearing as merely an e-learning platform rather than an engaging game [INFERENCE].

### Detailed Data-Flow Narrative
1.  **Initial Load & Caching:** The user navigates to the PWA URL. The Service Worker intercepts the request, downloads the minimal core bundle (`< 5MB`), and caches static 3D models (GLTF format), texture maps, and audio files into IndexedDB [INFERENCE].
2.  **Authentication / Offline Mode:** The client checks network status. If online, it authenticates via lightweight JWT. If offline, it logs into a local anonymous profile stored in IndexedDB [INFERENCE].
3.  **Game World Initialization:** The student selects an IKS Quest Module (e.g., *Sarasvati-Sindhu Civilizational Architecture*). Three.js initializes the 3D scene canvas, loads compressed DRACO-encoded GLTF assets, and starts the render loop [INFERENCE].
4.  **Interactive Gameplay Loop:**
    *   The player navigates 3D urban layouts, solving engineering and historical puzzles (e.g., aligning ancient water drainage pipes according to Indus Valley ratios) [INFERENCE].
    *   When an artifact is discovered, an interactive inspection dialog opens.
    *   If the student scans a physical DIY target card using their device camera, MindAR.js overlays a 3D interactive model onto the paper piece [INFERENCE].
5.  **Assessment & State Sync:**
    *   Upon puzzle completion, the client evaluates decision logic locally.
    *   Quest state, time taken, and competency metrics are logged to IndexedDB.
    *   When network connectivity is detected, a background sync worker pushes encrypted JSON telemetry to the Node.js backend to update the student's progress and issue verifiable digital badges [INFERENCE].

## 13. AI/ML Justification

### AI Component 1: Multi-Lingual IKS Quest Generator & Quiz Adaptor

*   **1. What exact problem does AI solve?** Dynamically translates and adapts historical quest dialogs and assessment questions into regional Indian languages while maintaining pedagogical intent [INFERENCE].
*   **2. What is the input?** English master JSON quest template + target language code (e.g., `hi`, `ta`, `te`).
*   **3. What is the output?** Contextually accurate, culturally appropriate translated story dialogs and adaptive multiple-choice questions [INFERENCE].
*   **4. Why can a simpler rule/system not solve it?** Static translation rule-sets fail on cultural context and nuanced regional historical terms [INFERENCE].
*   **5. What data is required?** Parallel corpus of educational content and IKS glossary terms.
*   **6. How will it be evaluated?** BLEU/ROUGE translation scores verified by human regional language reviewers [INFERENCE].
*   **7. What happens when it is wrong?** Fallback to pre-validated human-curated static language strings [INFERENCE].
*   **8. Does it require training?** No.
*   **9. Does it require fine-tuning?** No.
*   **10. Does it require RAG?** Yes. RAG pipeline querying verified IKS text corpus to prevent factual hallucinations [INFERENCE].
*   **11. Computer Vision?** No.
*   **12. Speech processing?** Optional TTS integration via Web Speech API / Bhashini API [RESEARCHED].
*   **13. Forecasting?** No.
*   **14. Human oversight required?** Yes. All AI-generated curriculum quiz templates must be pre-sanitized by educators before live deployment [INFERENCE].

### AI Component 2: Camera-based Physical Target Recognition (MindAR ML Engine)

*   **1. What exact problem does AI solve?** Detects 2D printable papercraft target markers from device camera feed in real time [INFERENCE].
*   **2. What is the input?** Live video frames from device camera.
*   **3. What is the output?** 6-DOF (Degree of Freedom) target pose matrix (position, rotation, scale) [INFERENCE].
*   **4. Why can a simpler rule/system not solve it?** Object tracking across variable lighting, camera angles, and partial occlusions requires feature extraction ML models [INFERENCE].
*   **5. What data is required?** Pre-compiled target feature anchor patterns extracted from vector PDFs.
*   **6. How will it be evaluated?** Detection latency (`< 100ms`) and tracking stability (low jitter) [INFERENCE].
*   **7. What happens when it is wrong?** Target model fails to render; visual prompt asks user to align card in frame [INFERENCE].
*   **8–13. Specifics:** Uses pre-trained WebAssembly ML compiled model embedded inside MindAR.js [KNOWN].
*   **14. Human oversight required?** No. Automated computer vision pipeline.

### Explicit Non-AI Rule
**AI must NOT be used for grading core historical facts or computing final academic scores.** Scoring algorithms must remain deterministic, rule-based mathematical functions to ensure fairness, transparency, and compliance with educational evaluation standards [INFERENCE].

model UserBadge {
  id          String   @id @default(uuid())
  userId      String
  badgeCode   String   // e.g., "HARAPPAN_ENGINEER_L1"

### Local Storage & Caching Strategy
*   **Service Worker Cache (Workbox):**
    *   `CacheFirst` policy for static assets (`.gltf`, `.glb`, `.jpg`, `.mp3`, `.wasm`).
    *   `NetworkFirst` with offline fallback for user profile and leaderboard REST endpoints.
*   **IndexedDB Local Schema:**
    *   `assets_store`: Holds blob buffers of downloaded 3D models.
    *   `telemetry_queue`: Queues completed quest records while offline.

### Synchronization & Conflict Handling
*   **Queue-Based Background Sync:** Completed quest payloads are assigned a unique local UUID and timestamp. When `navigator.onLine` fires, the queue processor flushes records sequentially to `/api/v1/sync`.
*   **Conflict Resolution:** Server evaluates records using `Max(scoreAchieved)` and `Min(timeSpentSec)`. Late-arriving offline records never overwrite higher online scores [INFERENCE].
