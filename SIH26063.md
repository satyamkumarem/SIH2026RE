## 1. Executive Snapshot

### Executive Summary
The National Centre for Polar and Ocean Research (NCPOR) [PS], an autonomous institute under the Ministry of Earth Sciences (MoES) [PS], conducts cutting-edge research across Earth's polar and oceanic frontiers, including Antarctica (Maitri, Bharati stations) [RESEARCHED], the Arctic (Himadri station) [RESEARCHED], the Himalayas [RESEARCHED], and the Southern Ocean [RESEARCHED]. Despite generating vast troves of scientific datasets, expedition reports, research papers, and multimedia, these assets remain fragmented across legacy systems like the National Polar Data Center (NPDC) [RESEARCHED] and physical library archives [RESEARCHED]. 

To bridge this gap, **PolarIS (Polar Information & Synergy Portal)** is proposed—an integrated, web-native platform that functions simultaneously as a FAIR-compliant (Findable, Accessible, Interoperable, Reusable) digital knowledge repository [INFERENCE], an automated media dissemination engine [PS], and an immersive public outreach portal [PS]. PolarIS leverages a decoupled microservices architecture [INFERENCE] featuring an automated AI Content Studio [INFERENCE] that converts dense scientific reports into multi-channel public communications (press releases, infographics text, social media snippets for X/Twitter, LinkedIn, and Instagram) [INFERENCE], alongside an offline-first mobile/field sync client designed specifically for bandwidth-constrained satellite environments at polar bases [INFERENCE].

## 5. Constraints & Environment Realities

*   **Geographic & Operating Environment:** NCPOR manages operations across extreme remote geographies: Antarctica (Bharati station at 69°S in Larsemann Hills; Maitri station at 70°S in Schirmacher Oasis) [RESEARCHED], Arctic (Himadri station at 78°N in Ny-Ålesund, Svalbard) [RESEARCHED], Himalayas (Sutri Dhaka base) [RESEARCHED], and oceanographic vessels (ORV Sagar Kanya, Sagar Nidhi) [RESEARCHED].
*   **Satellite Connectivity Realities:** Maitri station relies on restricted SATCOM bandwidth (~4 MHz satellite link) [RESEARCHED]. Bharati has dedicated C-band satellite links connected via NRSC Hyderabad [RESEARCHED], but high latency (>600 ms) and severe blizzard-induced outages remain common [INFERENCE]. Uploading 1 GB video files directly over SATCOM is infeasible [INFERENCE].
*   **Field Device Realities:** Expedition scientists use ruggedized laptops and personal cameras under extreme ambient temperatures (-40°C to +5°C) [RESEARCHED]. Storage drives are filled locally during field traverses [INFERENCE].
*   **Language & Accessibility:** Public outreach in India requires bilingual support (Hindi and English) [KNOWN] to comply with Union official language guidelines and achieve nationwide reach across rural and urban schools [INFERENCE]. WCAG 2.1 AAA accessibility (high contrast, screen reader compatibility) is mandatory for government portals [KNOWN].

## 9. Candidate Solution Approaches

### Approach 1: Monolithic Web CMS with Manual Social Media Publishing
*   **Mechanism:** Standard WordPress / Drupal platform extended with custom plugin modules for document upload and social media embeds.
*   **Pros:** Low initial development complexity; quick template setup during hackathon.
*   **Cons:** Extremely poor handling of large scientific datasets, no native spatial search (GIS), high security vulnerability profile, no automated AI content generation, unsuited for low-bandwidth satellite sync.
*   **Feasibility Score:** Hackathon: 80/100 | Production: 30/100.

### Approach 2: Microservices FAIR Repository + Manual REST API Dissemination
*   **Mechanism:** React frontend connected to Django/FastAPI microservices, PostgreSQL with PostGIS for spatial metadata, and Elasticsearch for document search. Social media posts created manually by admins.
*   **Pros:** Clean architecture, high stability, excellent FAIR data standard compliance.
*   **Cons:** Misses the central problem statement requirement for automated social media/website content generation; high manual workload on outreach staff remains.
*   **Feasibility Score:** Hackathon: 70/100 | Production: 65/100.

### Approach 3: Decoupled FAIR Knowledge Repository + Multimodal AI Content Studio + Low-Bandwidth Field Sync (RECOMMENDED)
*   **Mechanism:** Next.js single-page frontend (pwa-enabled), FastAPI backend, PostgreSQL + `pgvector` + PostGIS database, MinIO object storage, FFmpeg video processing pipeline, and an LLM-powered Multimodal AI Studio that ingests papers/media to auto-generate multi-platform content (press releases, X threads, LinkedIn posts, website news snippets). Includes an offline-first service worker for field scientists.
*   **Pros:** Directly addresses all explicit requirements (archival + content generation + outreach) [PS], optimized for low-bandwidth SATCOM, highly scalable, state-of-the-art UI/UX.
*   **Cons:** Higher architectural complexity requiring strict AI guardrails.
*   **Feasibility Score:** Hackathon: 92/100 | Production: 95/100.

## 10. Recommended Approach & Why

**Approach 3 (Decoupled FAIR Knowledge Repository + Multimodal AI Content Studio)** is chosen as the winning architecture.

### Why Alternatives Were Rejected:
*   *Approach 1 (Monolithic CMS)* was rejected because it fails to support scientific dataset schemas (ISO 19115), lacks spatial GIS query capabilities, and cannot handle offline SATCOM synchronization required at Maitri/Bharati [INFERENCE].
*   *Approach 2 (Traditional Microservices without AI)* was rejected because it ignores the explicit mandate: *"while generating content for websites and social media"* [PS]. Forcing NCPOR outreach staff to manually write posts for hundreds of papers creates an unscalable bottleneck [INFERENCE].

Approach 3 uniquely balances robust scientific archival standards with modern AI-driven public engagement [INFERENCE].

### Data-Flow Narrative

1.  **Ingestion & Archival Path:**
    *   An expeditioner at Bharati or an administrator in Goa uploads a document (Expedition Report PDF, Research Paper, or Dataset CSV) via the web or offline PWA client.
    *   The file is sent to FastAPI backend; media files (photos/videos) pass through FFmpeg for thumbnail extraction, web-optimization (WebP/MP4), and EXIF spatial/temporal parsing [INFERENCE].
    *   Text documents are processed via PyMuPDF/Tesseract OCR [KNOWN] to extract raw text, which is chunked and stored in `PostgreSQL` alongside vector embeddings generated via `sentence-transformers` in `pgvector` [INFERENCE].
    *   Dataset metadata is assigned an ISO 19115 / Schema.org JSON-LD tag and indexed in PostGIS with spatial coordinates [INFERENCE].

2.  **AI Dissemination Path:**
    *   When a new scientific publication or report is archived, the **AI Content Studio** triggers a job queue task in Redis/Celery [INFERENCE].
    *   An LLM processes the abstract and executive summary using a strict prompt template to generate:
        *   A 3-tweet summary thread with relevant hashtags (#Antarctica #ClimateChange #MoES) [INFERENCE].
        *   A professional LinkedIn press post highlighting key findings [INFERENCE].
        *   A concise bilingual web news release (English & Hindi) [INFERENCE].
    *   The generated draft enters the **Human-in-the-Loop Review Dashboard**, where an NCPOR Media Officer approves or edits the content before one-click publishing via social media APIs or RSS [INFERENCE].

## 13. AI/ML Justification

### 1. AI Component: Automated Media & PR Synthesizer
*   **Purpose:** Summarize complex scientific papers/expedition reports into accessible public communications (X threads, LinkedIn posts, bilingual press releases) [PS].
*   **Model Type:** Fine-tuned Multimodal LLM (e.g., Llama-3-70B-Instruct or GPT-4o-mini API) [INFERENCE].
*   **Input:** Research paper abstract, PDF text chunks, key figure captions [INFERENCE].
*   **Output:** Structured JSON containing: `tweet_thread`, `linkedin_post`, `press_release_en`, `press_release_hi`, `suggested_hashtags` [INFERENCE].
*   **Data Required:** 200+ historical MoES press releases and polar science abstracts for fine-tuning/few-shot prompts [INFERENCE].
*   **Why AI is Preferable:** Writing 5 distinct media formats for dozens of monthly papers manually takes outreach staff ~4 hours per paper. AI completes initial drafts in 5 seconds [INFERENCE].
*   **Evaluation Metric:** ROUGE score against human PR summaries; factual precision check [INFERENCE].
*   **Failure Mode:** Hallucinated scientific figures or misattributed findings.
*   **Human Oversight:** **Mandatory.** Posts CANNOT auto-publish; they remain in "Pending Review" queue until approved by an NCPOR admin [INFERENCE].

### 2. AI Component: Auto-Tagging & Visual Search for Polar Media
*   **Purpose:** Automatically categorize uploaded expedition photos and videos (e.g., "Bharati Station", "Penguins", "Glacier Calving", "ORV Sagar Kanya") [INFERENCE].
*   **Model Type:** CLIP (Contrastive Language-Image Pre-training) / Vision Transformer [INFERENCE].
*   **Input:** High-resolution field photos/video frames [INFERENCE].
*   **Output:** Auto-generated descriptive tags and vector embeddings for semantic visual search ("Find photos of ice coring at Maitri") [INFERENCE].
*   **Data Required:** Pre-trained CLIP model zero-shot inference [INFERENCE].
*   **Why AI is Preferable:** Scientists upload thousands of field photos without adding manual tags [INFERENCE].
*   **Failure Mode:** Misidentifying glacier types or animal species.
*   **Human Oversight:** Admins can edit or remove tags in the DAM portal.

### Explicit Non-AI Rule
**AI MUST NOT be used for:**
1.  Direct alteration of scientific dataset numerical values or raw expedition log records [INFERENCE].
2.  Determining dataset licensing or access permissions [INFERENCE].
3.  Generating authoritative scientific conclusions without peer-reviewed source backing [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Core Database Schema (Entity Relationship Outline)

```sql
-- Core Table: Digital Assets (Reports, Papers, Media, Datasets)
CREATE TABLE assets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(500) NOT NULL,
    asset_type VARCHAR(50) CHECK (asset_type IN ('EXPEDITION_REPORT', 'DATASET', 'PUBLICATION', 'PHOTO', 'VIDEO', 'EVENT')),
    description TEXT,
    publication_date DATE,
    expedition_name VARCHAR(100), -- e.g., '43rd ISEA', 'Arctic 2023'
    location_name VARCHAR(100),   -- e.g., 'Maitri', 'Bharati', 'Himadri'
    spatial_coverage GEOMETRY(Polygon, 4326), -- PostGIS Spatial Bounding Box
    author_details JSONB,         -- Array of authors, affiliations, ORCIDs
    doi VARCHAR(100),
    file_path VARCHAR(1000) NOT NULL,
    file_size_bytes BIGINT,
    metadata_jsonld JSONB,       -- Schema.org / ISO 19115 compliant JSON
    is_public BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- AI Generated Social Media Content Queue
CREATE TABLE ai_generated_content (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_id UUID REFERENCES assets(id) ON DELETE CASCADE,
    platform VARCHAR(50) CHECK (platform IN ('X_TWITTER', 'LINKEDIN', 'WEBSITE_NEWS', 'PRESS_RELEASE')),
    language VARCHAR(10) DEFAULT 'en',
    generated_text TEXT NOT NULL,
    status VARCHAR(30) DEFAULT 'PENDING_APPROVAL', -- 'PENDING_APPROVAL', 'APPROVED', 'PUBLISHED', 'REJECTED'
    reviewer_comments TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Low-Bandwidth & Offline Field Synchronization Architecture

To solve the constraint of ~4 MHz SATCOM satellite links at Maitri base [RESEARCHED]:

1.  **Client-Side Heavy Compression:** Before upload, the PWA web app uses WebAssembly (Wasm) [KNOWN] modules to compress images to AVIF format (70% smaller than JPEG) and transcode high-res video down to 720p H.265/AV1 streams locally on the scientist's laptop [INFERENCE].
2.  **Resumable Chunked Uploads:** Files are split into 1 MB chunks using `tus.io` protocol [KNOWN]. If a blizzard disrupts the satellite link, the upload pauses seamlessly and resumes from the exact byte offset when connectivity returns [INFERENCE].
3.  **Local IndexedDB Caching:** Expedition logs written offline are stored in browser `IndexedDB` [KNOWN]. A Background Sync Service Worker detects network availability and pushes batched metadata JSON payload first (few kilobytes) while deferring binary file transfers to off-peak satellite windows [INFERENCE].
