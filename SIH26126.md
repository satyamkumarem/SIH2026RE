# Autonomous Vision-Based Navigation Dossier for Unmanned Ground Vehicles (UGVs) in GPS-Denied Outdoor Environments

---

## 1. Executive Snapshot

### Summary
Outdoor Unmanned Ground Vehicles (UGVs) operating in military, search-and-rescue, agricultural, or tactical reconnaissance domains face extreme environmental unpredictability, including high-frequency terrain changes, dynamic ambient lighting, and complete GPS degradation or spoofing [PS]. To achieve reliable autonomy without reliance on external satellite signals or active radio emissions (which can be jammed or intercepted) [INFERENCE], the UGV must depend entirely on onboard passive computer vision and visual-inertial state estimation [PS]. 

This technical dossier details the end-to-end design, algorithm selection, data strategy, and implementation roadmap for a **Vision-Based Autonomous Navigation System** designed for Bharat Electronics Limited (BEL) [PS]. The proposed solution integrates real-time semantic terrain segmentation (distinguishing drivable paths from hazards like rocks, ditches, and trees), stereo visual-inertial odometry (VIO) / SLAM for GPS-denied position tracking, and a dynamic local path planner integrated with ROS 2 Navigation2 (Nav2) [RESEARCHED]. The system is tailored for a 4–6 student hackathon team, utilizing simulated outdoor environments (Gazebo/Webots) and prerecorded off-road rosbag datasets (RUGD, RELLIS-3D) for validation [RESEARCHED], while maintaining an architecturally sound path toward embedded edge deployment (NVIDIA Jetson) for physical UGV field trials [ASSUMPTION].

### Atomic Requirements Extraction

* **Requirement 1: Operational Environment & Constraints**
  * *Source Text:* "Outdoor Unmanned Ground Vehicles (UGVs) face unpredictable terrain, changing light, and unreliable GPS signals." [PS]
  * *Interpretation:* The vehicle cannot rely on global navigation satellite systems (GNSS) or static road markings. Light variations (lens flare, shadow transitions) and natural terrain variations must not cause localization loss or trajectory instability [INFERENCE].
  * *Implementation Implication:* Must use passive sensor modalities (stereo vision + IMU) and robust illumination-invariant perception techniques [INFERENCE].

* **Requirement 2: Primary Sensing Modality**
  * *Source Text:* "...operating in a GPS-denied outdoor environment using camera feeds as the primary sensor." [PS]
  * *Interpretation:* Vision (cameras) is the mandatory primary perception sensor. Active sensors like LiDAR or radar can only be supplementary or simulated if used, but the primary software pipeline must operate on vision [INFERENCE].
  * *Implementation Implication:* System pipeline must rely on monocular/stereo RGB depth estimation and visual features [INFERENCE].

* **Requirement 3: Challenge 1 – Path Detection**
  * *Source Text:* "1. Path Detection: Real-time identification of safe, traversable paths vs. hazards (e.g., rocks, ditches, trees)." [PS]
  * *Interpretation:* Pixel-wise or region-based semantic classification distinguishing drivable ground (grass, dirt road, gravel) from non-drivable obstacles/hazards (rocks, ditches, trees, drop-offs) [INFERENCE].
  * *Implementation Implication:* Deployment of lightweight semantic segmentation models fine-tuned on off-road datasets (e.g., DDRNet-23-slim or FastSCNN) operating at $\ge 15\text{ FPS}$ [RESEARCHED].

* **Requirement 4: Challenge 2 – Visual Localization**
  * *Source Text:* "2. Visual Localization: Estimating the UGV’s position and orientation without GPS using visual data." [PS]
  * *Interpretation:* Continuous 6-DOF pose estimation (x, y, z, roll, pitch, yaw) relative to an initial starting pose without external beacon assistance [INFERENCE].
  * *Implementation Implication:* Feature-based or direct Visual-Inertial Odometry / SLAM pipeline (e.g., ORB-SLAM3 stereo-IMU mode or OpenVINS) [RESEARCHED].

* **Requirement 5: Challenge 3 – Collision Avoidance**
  * *Source Text:* "3. Collision Avoidance: Dynamically routing the vehicle around sudden obstacles toward a destination." [PS]
  * *Interpretation:* Local real-time replanning based on transient or unmapped obstacles blocking the UGV's global path [INFERENCE].
  * *Implementation Implication:* A local motion planner (e.g., Time Elastic Band (TEB) or Model Predictive Path Integral (MPPI)) executing on an updated local occupancy grid/costmap [RESEARCHED].

* **Requirement 6: Module Component 1 – Perception AI**
  * *Source Text:* "Perception AI: A lightweight model for obstacle and path detection." [PS]
  * *Implementation Implication:* Neural network model optimized via TensorRT/ONNX Runtime running on edge compute (e.g., Jetson/x86 GPU) [RESEARCHED].

* **Requirement 7: Module Component 2 – Visual SLAM/Odometry**
  * *Source Text:* "Visual SLAM/Odometry: A pipeline to track vehicle movement." [PS]
  * *Implementation Implication:* C++ node producing ROS 2 transformation trees (`tf2`) from `camera_link` to `odom`/`map` [RESEARCHED].

* **Requirement 8: Module Component 3 – Path Planner**
  * *Source Text:* "Path Planner: An algorithm to translate visual data into wheel/motor commands." [PS]
  * *Implementation Implication:* ROS 2 Navigation2 stack node publishing `geometry_msgs/msg/Twist` velocity commands to motor controllers/drive hardware [RESEARCHED].

* **Requirement 9: Overall Success Criteria**
  * *Source Text:* "Success Criteria: Successful, collision-free navigation from Point A to Point B across outdoor scenarios" [PS]
  * *Implementation Implication:* Complete end-to-end mission loop: Goal coordinates $(X_{target}, Y_{target})$ provided relative to origin $\to$ path planned $\to$ visual tracking maintained $\to$ obstacles avoided $\to$ destination reached within tolerance threshold [INFERENCE].

1. **Connectivity Realities:** Total absence of cell tower, satellite, or cloud connectivity [PS]. All compute (visual perception, SLAM, path planning, control loops) must run 100% locally on onboard UGV compute [INFERENCE].
2. **Lighting Variations:** Unstructured outdoor scenes feature high dynamic range (HDR) lighting—sudden shadows cast by trees, direct lens flare from low-angle sunlight, and over-saturation [KNOWN]. Monocular visual odometry frequently fails due to sudden photometric gain adjustments; stereo vision coupled with IMU fusion is essential to bridge low-texture or overexposed frames [RESEARCHED].
3. **Terrain Unstructuredness:** Unlike urban driving where road boundaries are crisp, outdoor environments feature non-rigid vegetation, tall grass hiding rocks, mud, and uneven ditch gradients [KNOWN]. Standard geometric obstacle detectors fail on tall grass; semantic visual AI is strictly necessary to categorize ground traversability [INFERENCE].
4. **Mechanical & Power Constraints:** Field UGVs operate under strict power envelopes (e.g., 12V–24V DC supply) [KNOWN]. Embedded edge accelerators like NVIDIA Jetson Orin Nano / AGX Orin represent the realistic deployment limit, capping inference power to under 30 Watts [RESEARCHED].
5. **Real-time Latency Limits:** Control loops for differential or Ackermann drive UGVs require velocity updates at minimum $10\text{ Hz}$ to prevent dynamic overshoot or collisions [KNOWN]. The entire vision-to-actuation processing latency must remain under $100\text{ ms}$ [INFERENCE].

## 6. Research Questions

To build an optimal solution, the team must systematically resolve six core engineering questions [INFERENCE]:

1. **Camera Topology:** Should the system rely on Monocular, Stereo, or RGB-D sensors for outdoor environments?
   * *Finding:* RGB-D cameras (e.g., Intel RealSense D435) rely on active infrared structured light/stereo, which fails in bright outdoor sunlight beyond 3–5 meters due to IR saturation from solar radiation [KNOWN]. Passive Stereo RGB vision (with configurable baseline $\ge 12\text{ cm}$) is required for outdoor perception beyond 10 meters [RESEARCHED].
2. **Visual SLAM Drift Management:** How to prevent visual odometry drift over hundreds of meters without GPS?
   * *Finding:* Tightly coupled Visual-Inertial Fusion (Stereo + IMU) constrains metric scale and maintains pose estimates during aggressive UGV pitching or momentary visual feature loss [RESEARCHED].
3. **Semantic Perception Architecture:** Which deep learning architecture provides the optimal trade-off between mean Intersection over Union (mIoU) and inference frame rate on embedded GPUs?
   * *Finding:* Architectures like DDRNet-23-slim or FastSCNN achieve $> 75\%\text{ mIoU}$ on off-road datasets while exceeding $30\text{ FPS}$ on TensorRT-optimized edge hardware [RESEARCHED].
4. **Semantic-to-Costmap Projection:** How can pixel-level semantic classifications be projected into 3D metric space for ROS 2 navigation costmaps?
   * *Finding:* Stereo depth estimation (or camera projection matrices combined with ground-plane assumption / stereo point clouds) projects semantic label classes into 3D camera coordinates $(X, Y, Z)$, which are ray-casted onto a 2D grid map [RESEARCHED].
5. **Ditch and Negative Obstacle Detection:** How can negative obstacles (ditches, drop-offs) be detected via visual feeds?
   * *Finding:* Negative obstacles lack direct surface reflections. Perception must rely on semantic segmentation (training models on ditch/hole classes) combined with geometric surface variance analysis from dense stereo disparity [RESEARCHED].
6. **Local Path Planner Selection:** Which ROS 2 planner handles complex outdoor non-holonomic constraints best?
   * *Finding:* Model Predictive Path Integral (MPPI) or Time Elastic Band (TEB) planners handle costmap gradients and vehicle kinematics far superior to traditional Dynamic Window Approach (DWA) in unstructured terrain [RESEARCHED].

### Approach 1: Classical Vision + Monocular Visual Odometry + Rule-Based Grid
* **Mechanism:** Uses traditional color thresholding (HSV ground color segmentation), Canny edge detection for hazard boundaries, and optical flow / Monocular Visual Odometry for movement tracking [KNOWN].
* **Perception AI:** Rule-based color/texture filtering [KNOWN].
* **Localization:** Monocular OpenCV Feature Tracking / FOVIS [RESEARCHED].
* **Complexity:** Low; runs on basic CPU [KNOWN].
* **Strengths:** Minimal compute requirements, easy implementation [KNOWN].
* **Weaknesses:** Highly brittle under lighting shifts, shadows, or varying grass/dirt colors; scale ambiguity prevents accurate distance measurements; severe drift [INFERENCE].
* **Hackathon Feasibility:** 95/100 | **Production Feasibility:** 15/100 [INFERENCE].

### Approach 2: Deep Semantic Perception + Stereo Visual-Inertial SLAM + ROS 2 Nav2 (RECOMMENDED)
* **Mechanism:** Integrates a lightweight deep semantic segmentation network (DDRNet-23-slim) trained on off-road datasets [RESEARCHED], stereo camera depth processing, ORB-SLAM3 Stereo-IMU visual localization [RESEARCHED], and ROS 2 Nav2 local planning (MPPI/TEB) [RESEARCHED].
* **Perception AI:** DDRNet-23-slim / FastSCNN fine-tuned on RUGD/RELLIS-3D datasets [RESEARCHED].
* **Localization:** ORB-SLAM3 (Stereo + IMU) providing metric 6-DOF odometry [RESEARCHED].
* **Complexity:** Moderate-High; requires GPU acceleration (TensorRT) and ROS 2 setup [INFERENCE].
* **Strengths:** Robust to extreme lighting and texture changes; explicit metric scale; probabilistic obstacle mapping; modular ROS 2 architecture [INFERENCE].
* **Weaknesses:** Higher compute footprint; requires stereo camera calibration [INFERENCE].
* **Hackathon Feasibility:** 88/100 | **Production Feasibility:** 90/100 [INFERENCE].

### Approach 3: End-to-End Deep Reinforcement Learning (Vision-to-Control)
* **Mechanism:** Trains a deep neural network (e.g., PPO or SAC) taking raw camera frames as input and directly outputting wheel linear and angular velocity commands (`v`, `w`) [KNOWN].
* **Perception & Control:** Integrated end-to-end policy network [KNOWN].
* **Complexity:** Extremely High; requires massive simulation training episodes [INFERENCE].
* **Strengths:** Eliminates hand-crafted costmaps and explicitly unified pipeline [KNOWN].
* **Weaknesses:** Complete black box; non-explainable decision making (critical failure risk for defense/BEL); prone to catastrophic domain shift when moving from sim to real outdoor terrain [INFERENCE].
* **Hackathon Feasibility:** 30/100 | **Production Feasibility:** 20/100 [INFERENCE].

## 10. Recommended Approach & Why

### Selection: Approach 2 (Deep Semantic Perception + Stereo Visual-Inertial SLAM + ROS 2 Nav2)

```
   ┌──────────────────────────────────────────────────────────────────┐
   │                   WHY APPROACH 2 IS SELECTED                     │
   ├──────────────────────────────────────────────────────────────────┤
   │ 1. Direct Alignment with BEL Requirements: Meets all three PS      │
   │    challenges (Path Detection, Localization, Obstacle Avoidance). │
   │ 2. Metric Scale Accuracy: Stereo+IMU eliminates monocular scale   │
   │    drift, providing precise motor displacement commands.          │
   │ 3. Deterministic Safety Layer: Costmap representation allows      │
   │    safety bounds, recovery behaviors, and full explainability.    │
   │ 4. Modular Development: 4-6 students can work in parallel       │
   │    (Perception, SLAM, Nav2 Planning, Simulation/Hardware).        │
   └──────────────────────────────────────────────────────────────────┘
```

### Justification & Rejection of Alternatives
* **Approach 1 Rejection:** Classical computer vision techniques (color thresholding, edge detection) fail unpredictably in outdoor environments due to ambient light fluctuation, shifting clouds, tree shadows, and mud/grass color overlap [KNOWN]. It cannot reliably detect hazardous ditches or distinguish grass from weeds [INFERENCE].
* **Approach 3 Rejection:** End-to-end reinforcement learning lacks safety guarantees and explainability [KNOWN]. In defense applications managed by BEL, a "black box" model that cannot explain *why* a vehicle turned into a specific path is unacceptable [INFERENCE]. Furthermore, training end-to-end policies for complex outdoor visual terrain within a hackathon timeline presents extreme convergence risks [INFERENCE].
* **Approach 2 Selection:** Approach 2 decouples perception (what is safe/unsafe), localization (where am I), and planning (how do I move safely). This modularity allows independent testing, fine-tuning, and robust safety overrides [RESEARCHED].

### Detailed Data-Flow Narrative

1. **Data Ingestion:** The UGV hardware/simulator captures time-synchronized stereo RGB frames (Left/Right) at $30\text{ FPS}$ alongside high-frequency ($200\text{ Hz}$) 6-axis IMU raw telemetry [RESEARCHED].
2. **Visual Localization Processing:** The raw stereo frames and IMU measurements are ingested by the `ORB-SLAM3` node [RESEARCHED]. Features (ORB keypoints) are extracted, matched across stereo pairs, and integrated with double-integrated IMU pre-integration values [RESEARCHED]. This outputs real-time 6-DOF UGV pose tracking and continuously broadcasts coordinate frame transformations: `map` $\to$ `odom` $\to$ `base_link` $\to$ `camera_link` [RESEARCHED].
3. **Semantic Perception Processing:** Concurrently, the Left RGB frame is fed into the ONNX/TensorRT-optimized `DDRNet-23-slim` inference engine [RESEARCHED]. The model outputs a pixel-level semantic mask categorizing terrain into four distinct traversal classes: `Safe Path`, `Low Hazard (Grass/Dirt)`, `High Hazard (Rocks/Bushes)`, and `Lethal Hazard (Trees/Ditches/Obstacles)` [RESEARCHED].
4. **Semantic Costmap Generation:** The `Semantic Costmap Converter` node combines stereo depth disparity maps with the semantic mask [RESEARCHED]. Using the stereo baseline intrinsic matrix, 2D semantic pixels are reprojected into 3D metric point clouds $(X, Y, Z)$ [RESEARCHED]. Points are mapped onto a 2D grid map where traversability probabilities are converted into costmap values ($0$ for clear, $254$ for lethal obstacles) [RESEARCHED].
5. **Global & Local Path Planning:** 
   - When a goal pose $(X_{goal}, Y_{goal})$ is received, the Nav2 `Smac Planner` computes a coarse global path over the mapped environment using cost-aware A* [RESEARCHED].
   - The Nav2 `MPPI Controller` continuously evaluates local candidate trajectory rollouts against the dynamic local costmap at $20\text{ Hz}$ [RESEARCHED].
6. **Actuation Command Output:** The local controller selects the optimal trajectory that maximizes velocity towards the goal while minimizing costmap collision risks, publishing linear and angular velocity vectors (`/cmd_vel`) to the UGV motor driver interface [RESEARCHED].

## 13. AI/ML Justification

```
   ┌──────────────────────────────────────────────────────────────────┐
   │                  AI/ML DEPLOYMENT DECISION MAP                   │
   ├───────────────────────────────┬──────────────────────────────────┤
   │ AI Component                  │ Non-AI (Algorithmic) Component   │
   ├───────────────────────────────┼──────────────────────────────────┤
   │ Real-time Terrain             │ 3D Geometric Depth Reprojection  │
   │ Classification                │                                  │
   │ Differentiating Safe Path vs. │ Visual Feature Matching & Bundle │
   │ Rocks, Ditches, Trees         │ Adjustment (ORB-SLAM3 Engine)    │
   │                               │ Trajectory Optimization (MPPI)   │
   └───────────────────────────────┴──────────────────────────────────┘
```

### Perception AI Engine Breakdown
1. **Exact Problem AI Solves:** Classifying visual pixels into semantic terrain categories (Safe Path, Dirt, Grass, Rock, Ditches, Vegetation, Trees) where low-level geometric depth alone cannot distinguish traversability (e.g., distinguishing drivable tall grass from non-drivable dense thorn bushes or flat rock surfaces) [RESEARCHED].
2. **Input:** Single rectified RGB image frame $(1280 \times 720 \times 3)$ from the left stereo camera [ASSUMPTION].
3. **Output:** 2D class segmentation mask $(1280 \times 720 \times 1)$ where each pixel value maps to a class index ($0$ to $N$) [RESEARCHED].
4. **Why Simpler Rules Fail:** Color thresholding or edge detection fails during cloud shadows, direct sunlight glare, wet terrain, or seasonal vegetation shifts [KNOWN].
5. **Data Required:** Pixel-annotated off-road images (RELLIS-3D and RUGD datasets containing $> 20,000$ labeled outdoor frames) [RESEARCHED].
6. **Evaluation Metrics:** Mean Intersection over Union ($\text{mIoU} \ge 75\%$) and Per-Class IoU for high-risk categories (Ditches, Rocks) [RESEARCHED].
7. **Failure Mitigation Strategy:** If confidence for a region is low ($< 0.60$), the region is assigned a medium-high cost in the ROS 2 costmap, forcing the UGV to slow down and route around it [INFERENCE].
8. **Training Requirements:** Pre-trained weights on Cityscapes/ImageNet fine-tuned for $50$ epochs on merged RUGD + RELLIS-3D datasets [RESEARCHED].
9. **Fine-Tuning / RAG / Vision Needs:** Standard fine-tuning required; zero RAG or LLM required [INFERENCE].

### Where AI Should NOT Be Used
* **Kinematic Control & Motor Commands:** Motor velocity planning must remain deterministic and physics-based (using MPPI/TEB algorithms) to enforce physical velocity, acceleration, and dynamic stability limits [INFERENCE].
* **Visual Odometry Feature Tracking:** ORB feature extraction and bundle adjustment use proved classical geometric SLAM routines, providing mathematical guarantees of spatial consistency [RESEARCHED].

## 14. Data Architecture & Offline/Low-Network Design

```
┌────────────────────────────────────────────────────────────────────────┐
│                   OFFLINE DATA FLOW & LOCAL PIPELINE                   │
├────────────────────────────────────────────────────────────────────────┤
│ Stereo Cameras ──> Memory Shared IPC ──> TensorRT Engine (Zero-Copy)   │
│                                                │                       │
│ IMU Sensor ──────> Ring Buffer Memory ──> ORB-SLAM3 Engine             │
│                                                │                       │
│ Local Costmap <── Reprojection Node <──────────┘                       │
│      │                                                                 │
│      └──> ROS 2 Nav2 BT Local Planner ──> Motor Serial Bus             │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Zero-Network Architecture:** The pipeline executes completely on onboard local memory and hardware busses (PCIe, USB 3.0, CAN bus/UART for serial motor commands) [INFERENCE]. Zero external HTTP, cloud, or offboard network calls are executed [PS].
2. **Local Storage & Caching:**
   - Map points and keyframes from ORB-SLAM3 are maintained in a local C++ ring buffer in RAM [RESEARCHED].
   - Dynamic costmap layers (2D sliding grid of size $50\text{m} \times 50\text{m}$ at $0.05\text{m}$ resolution) are allocated in RAM, automatically clearing stale observations behind the UGV moving window [RESEARCHED].
3. **Frame Synchronization:** High-frequency IMU messages ($200\text{ Hz}$) are buffered in a synchronized queue. Camera frames ($30\text{ Hz}$) are timestamped using hardware sync or ROS 2 system time header matching to guarantee sub-millisecond visual-inertial alignment [RESEARCHED].
4. **Bandwidth Reduction & Zero-Copy IPC:** Nodes within the ROS 2 workspace utilize intra-process communication (`rclcpp::NodeOptions().use_intra_process_comms(true)`) to pass shared pointers to image frames across perception and SLAM nodes without memory copying [RESEARCHED].
5. **Sensor Degradation Fallback:**
   - *Visual Tracking Loss (e.g., sudden blindness from dirt/glare):* System automatically drops back to pure IMU pre-integration dead reckoning for up to 3 seconds while commanding the UGV speed to drop by 50% [INFERENCE].
   - *Persistent Tracking Loss:* UGV executes a ROS 2 Recovery Behavior (stops completely, performs a slow $360^\circ$ rotation to re-localize against mapped visual keyframes) [RESEARCHED].

1. **Passive Operations (Tactical Advantage):** By relying entirely on visual optical camera feeds and passive IMUs (rather than active LiDAR, Radar, or RF/GPS), the UGV emits zero electromagnetic signatures, making it undetectable to RF direction-finding tools [INFERENCE].
2. **Access Control & Code Execution:** Secure boot enabled on the edge hardware (NVIDIA Jetson) to prevent unauthorized firmware modifications [INFERENCE]. ROS 2 node communication can be locked down using SROS 2 (DDS-Security) with encrypted node authentication [RESEARCHED].
3. **Data Retention & Privacy:** Raw video feeds captured during operations are retained in an encrypted local storage partition (LUKS encryption) and purged upon mission completion to protect operational privacy [INFERENCE].
4. **False Positive / Negative Safety Protocols:**
   - *False Positive (Ghost Obstacle):* Local costmap inflation decay clears false transient obstacles after $1.5\text{ seconds}$ if re-observed as clear ground [RESEARCHED].
   - *False Negative (Missed Ditch):* Geometric stereo point-cloud depth filtering acts as an independent safety override layer to catch raw depth drop-offs even if the neural net fails to classify a ditch [INFERENCE].
5. **System Governance Disclaimer:** Prototype code developed during SIH represents a proof-of-concept software module [PS]. Full military deployment requires independent hardware-in-the-loop (HITL) testing and MIL-STD environmental qualification by BEL [INFERENCE].
