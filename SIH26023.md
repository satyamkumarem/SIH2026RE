## 5. Constraints & Environment Realities

1. **Legacy Document Quality (Field Conditions):** Mining archives in CMPDI Regional Institutes (RIs in Ranchi, Dhanbad, Bilaspur, Nagpur, Asansol, Singrauli, Bhubaneswar) contain physical reports dating back to the 1970s–1990s [KNOWN]. These files suffer from carbon-copy fading, handwritten annotations, low-dpi scans (100–150 DPI), skewing, and oil/water stains [INFERENCE].
2. **Network & Offline Realities:** While CIL HQ and CMPDI HQ (Ranchi) have fiber connectivity, remote exploration camps and open-cast mine sites in interior coalfields often face erratic broadband and low network bandwidth [KNOWN]. System must support local client caching and asynchronous background synchronization [INFERENCE].
3. **Data Security & Air-Gapped Hosting:** Ministry of Coal regulations strictly prohibit sending confidential geological reserve estimates, coal seam grades, or unreleased commercial block data to public third-party APIs (e.g., OpenAI, Anthropic cloud endpoints) [INFERENCE]. System MUST run entirely on self-hosted, air-gapped infrastructure [ASSUMPTION].
4. **Domain Terminology & Acronym Density:** Mining documents are saturated with domain-specific Indian coal terminology (e.g., *UNFC 331/332/333*, *GCV Grade G1–G17*, *OBR (Overburden Removal)*, *PRC (Peak Rated Capacity)*, *MDO*, *Borehole/BH*, *Seam IV Top*, *Jhama*, *Coking/Non-Coking*) [KNOWN]. Standard off-the-shelf NLP models fail without custom dictionary / domain adaptation [INFERENCE].
5. **Hardware Availability for Hackathon:** Student team operates on standard laptop/cloud free-tier GPU resources (e.g., NVIDIA T4 / RTX 3090/4090 on Colab or AWS instance) [ASSUMPTION]. AI architecture must be optimized for parameter efficiency (e.g., 7B/8B quantized LLMs, lightweight OCR) [INFERENCE].

## 9. Candidate Solution Approaches

### Approach 1: Heuristic & Traditional OCR Pipeline (Rule-Based + Tesseract + SQL)
- **Mechanism:** Standard Tesseract OCR extracts raw text. Custom Regex and Python heuristics extract table structures and store them in a relational SQLite/PostgreSQL database. SQL queries generate reports, and basic keyword searching (BM25/TF-IDF) handles queries.
- **Data Requirements:** Raw PDFs and pre-defined regex rules.
- **Complexity:** Low.
- **Explainability:** 100% deterministic.
- **Cost:** Near zero (runs on basic CPU).
- **Scalability:** Low (breaks whenever document layout varies slightly).
- **Hackathon Feasibility:** High (easy to build).
- **Production Feasibility:** Poor (fails on non-standard, scanned, or complex multi-page geological reports).
- **Risks:** High brittleness to document layout variations; inability to answer complex semantic parliamentary queries.

### Approach 2: Native Multimodal LLM End-to-End Pipeline (Cloud Vision LLM)
- **Mechanism:** Direct processing of document images through commercial Multimodal LLMs (e.g., GPT-4o / Claude 3.5 Sonnet) for vision extraction, topic modeling, and report drafting via long-context prompts.
- **Data Requirements:** Document page images fed directly into API prompts.
- **Complexity:** Medium (simple codebase, heavy reliance on external API).
- **Explainability:** Low (black-box model inference).
- **Cost:** Extremely High (token/image API costs scale exponentially with thousands of multi-page reports).
- **Scalability:** High computationally, but blocked by air-gap enterprise governance.
- **Hackathon Feasibility:** High for small demos, but violates air-gapped security rules.
- **Production Feasibility:** Infeasible (violates Ministry of Coal air-gap/data security mandates, high operational cost).
- **Risks:** Severe privacy/security non-compliance; hallucination of numeric coal figures; vendor lock-in.

### Approach 3: Enterprise Hybrid Pipeline (Layout-Aware Doc AI + Hybrid RAG + Deterministic Validation + Template NLG) — **RECOMMENDED**
- **Mechanism:** 
  1. *Ingestion:* Preprocessing (denoising/deskewing) + DocTR/PaddleOCR + LayoutLMv3 for layout-aware region detection (text vs table vs map image).
  2. *Structured Data Processing:* TableNet/TATR extracts tables into structured JSON. A deterministic python validation engine verifies mathematical relationships (depth totals, seam percentages).
  3. *Semantic Engine:* Chunking aware of document hierarchy; indexed in Hybrid Qdrant/PgVector (Dense embeddings via `bge-m3` + Sparse BM25 keywords).
  4. *Topic Engine:* BERTopic + TF-IDF with D3.js interactive Word Cloud visualization.
  5. *Generation Engine:* Jinja2 templates + fine-tuned/quantized Llama-3.1-8B-Instruct (or Mistral-7B) for narrative report generation and citation-backed parliamentary query responses.
- **Data Requirements:** Historical scanned PDFs, spreadsheets, parliamentary archives, domain dictionary.
- **Complexity:** Medium-High.
- **Explainability:** High (strict source page bounding box highlighting + deterministic numeric check).
- **Cost:** Low (runs on self-hosted local GPUs; zero external API fees).
- **Scalability:** High (horizontal scaling via containerized microservices).
- **Hackathon Feasibility:** High (can be containerized and run on local GPU/Colab).
- **Production Feasibility:** Excellent (meets air-gap security, zero hallucination on numbers, scalable).
- **Risks:** OCR errors on extremely degraded 1970s scans (mitigated by human-in-the-loop verification UI).

## 10. Recommended Approach & Why

### Selection
**Approach 3: Enterprise Hybrid Pipeline (Layout-Aware Doc AI + Hybrid RAG + Deterministic Validation + Template NLG)** is selected as the winning architecture.

### Why Alternatives Were Rejected
- **Approach 1 (Traditional OCR + Regex):** Rejected because legacy mining documents from CMPDI contain dozens of different table formats, hand-drawn annotations, and complex text arrangements. Heuristic regex rules break whenever a new subsidiary format is introduced [INFERENCE].
- **Approach 2 (Pure Multimodal Cloud LLM):** Rejected because sending confidential geological reports and un-auctioned coal block data to public third-party APIs violates Ministry of Coal data governance mandates [INFERENCE]. Furthermore, pure LLMs frequently hallucinate precise numeric drill depths or production metrics, which is unacceptable for parliamentary submissions [INFERENCE].

### Why Approach 3 Wins
1. **Zero-Hallucination Guarantees for Numbers:** Tabular data (bore logs, GCV values, production MT) bypasses LLM generative text and is parsed directly into structured JSON, validated deterministically with mathematical rules, and stored in relational tables [INFERENCE].
2. **Complete Traceability:** Every extracted claim in an auto-generated report or parliamentary answer links directly to a bounding-box coordinate on the original scanned page [INFERENCE].
3. **Air-Gap Ready:** The entire stack uses open-source models (DocTR, BGE-M3, Llama-3.1-8B-Instruct) capable of running completely offline on CIL/CMPDI enterprise hardware [INFERENCE].

### Detailed Data Flow Narrative

1. **Ingestion & Preprocessing:** A user uploads a multi-page PDF/scanned TIFF (e.g., a 1985 Geological Report for Korba Coalfield). OpenCV automatically corrects image rotation, deskews, and enhances contrast [INFERENCE].
2. **Layout & OCR Extraction:** DocTR / LayoutLMv3 segments each page into structural blocks: text headers, narrative paragraphs, tabular drill logs, and geological map images [INFERENCE].
3. **Table Parsing & Deterministic Validation:** Tabular regions are processed by Table Transformer (TATR). The extracted rows (e.g., *Borehole ID, Seam Name, Depth From, Depth To, Thickness, Ash %, GCV*) are output as structured JSON. A Python rule validator verifies that `Depth To - Depth From = Thickness` [INFERENCE]. If a discrepancy occurs, the row is flagged for human review [INFERENCE].
4. **Indexing & Embedding:** Narrative text chunks (preserving page and paragraph metadata) are vectorized using `bge-m3` and indexed into Qdrant alongside BM25 sparse lexical tokens [INFERENCE].
5. **Topic Mining & Word Cloud:** BERTopic processes all ingested narrative text across selected document collections, generating topic clusters, key terms, and word frequency vectors for the D3.js Word Cloud visualization [INFERENCE].
6. **Query & Parliamentary Response:** When an official submits a query (e.g., *"What is the proved coal reserve in seam IV of Mugoli block and what was the 2023 production?"*), the hybrid retriever pulls top candidate chunks. BGE-Reranker scores relevance. Llama-3.1-8B-Instruct formats a concise draft response, explicitly linking every statement to `[Doc #12, Page 4, Table 2]` [INFERENCE].
7. **Interactive Audit & Export:** The UI displays the response alongside a PDF viewer that highlights the exact bounding boxes on the original scanned document for instant verification. The report or answer can be exported as PDF/DOCX [INFERENCE].

## 13. AI/ML Justification

### Detailed AI Component Breakdown

#### 1. Layout-Aware Document OCR & Region Parser (DocTR + LayoutLMv3)
- **Purpose:** Segment complex geological report pages into narrative text, structured tables, and map image blocks [INFERENCE].
- **Model Type:** Object Detection & Layout Vision Transformer [INFERENCE].
- **Input:** High-resolution page image (PNG/TIFF) [INFERENCE].
- **Output:** Bounding box coordinates with layout classification tags (`table`, `text`, `header`, `figure`) [INFERENCE].
- **Data Required:** PubLayNet + synthetic fine-tuning on 100 CMPDI report pages [ASSUMPTION].
- **Why AI is Preferable:** Rule-based heuristics fail because legacy geological reports have variable column layouts, inline headers, and floating tables [INFERENCE].
- **Evaluation:** Mean Average Precision (mAP @ IoU 0.5) for layout segmentation [INFERENCE].
- **Failure Mode:** Misidentifying a small multi-column table as regular text [INFERENCE].
- **Human Oversight:** UI visual bounding box overlay allows users to re-tag unparsed table regions with a drag-and-drop tool [INFERENCE].

#### 2. Table Structure Recognition Engine (TATR / Table Transformer)
- **Purpose:** Parse row and column grid boundaries inside extracted table regions to produce structured JSON/CSV [INFERENCE].
- **Model Type:** Deep Learning Vision Transformer for Table Structure Recognition [INFERENCE].
- **Input:** Cropped image of a table region [INFERENCE].
- **Output:** Row/Column indices, cell bounding boxes, merged cell flags [INFERENCE].
- **Data Required:** Finetuned on ICDAR/PubTabNet + 50 scanned borehole log tables [ASSUMPTION].
- **Why AI is Preferable:** Fixed grid lines are frequently missing, faded, or broken in scanned 1980s drill logs [INFERENCE].
- **Evaluation:** Cell-level F1-Score & Tree-Edit-Distance-Based Similarity (TEDS) [INFERENCE].
- **Failure Mode:** Multi-line header misalignment [INFERENCE].
- **Human Oversight:** Tabular grid editor in UI for manual cell split/merge correction before saving to DB [INFERENCE].

#### 3. Hybrid Semantic Search & RAG Engine (BGE-M3 + BGE-Reranker + Llama-3.1-8B)
- **Purpose:** Retrieve relevant historical blocks and answer complex policy/technical questions with precise page citations [INFERENCE].
- **Model Type:** Dense/Sparse Bi-Encoder Embedder + Cross-Encoder Reranker + Causal LLM Generator [INFERENCE].
- **Input:** Natural language user query + Top-K retrieved document chunks [INFERENCE].
- **Output:** Formatted answer with inline metadata citations `[Document, Page, Paragraph]` [INFERENCE].
- **Data Required:** Chunked geological text, parliamentary QA archives, domain glossary [INFERENCE].
- **Why AI is Preferable:** Keyword search misses conceptual queries like *"What structural disturbances affect seam IV in Singrauli?"* where exact terms vary [INFERENCE].
- **Evaluation:** Context Recall, Context Precision, Faithfulness (Ragas Framework) [INFERENCE].
- **Failure Mode:** Retrieving plausible but outdated block figures [INFERENCE].
- **Human Oversight:** Every response includes direct click-to-view links to source pages; user feedback thumbs up/down logs instances [INFERENCE].

#### 4. Word Cloud & Topic Identification Module (BERTopic)
- **Purpose:** Extract key themes, operational bottlenecks, and geological terms across large document archives [INFERENCE].
- **Model Type:** Contextual Transformer Embeddings + HDBSCAN Clustering + Class-based TF-IDF [INFERENCE].
- **Input:** Array of document text chunks [INFERENCE].
- **Output:** Topic clusters, term frequency weights, topic hierarchy trees [INFERENCE].
- **Data Required:** Narrative text extracted from ingested reports [INFERENCE].
- **Why AI is Preferable:** Simple keyword frequency ignores synonyms and context (e.g., grouping "faulting", "folding", "tectonic disturbance" under "Geological Complexity") [INFERENCE].
- **Evaluation:** Topic Coherence (c_v score) [INFERENCE].
- **Failure Mode:** Creating duplicate or overly granular topic categories [INFERENCE].
- **Human Oversight:** Administrators can merge or rename topic categories in the dashboard [INFERENCE].

### Where AI Should NOT Be Used
- **Mathematical Aggregations & Reserve Totals:** Total coal reserves, average seam thickness, and sum of monthly production figures MUST NOT be calculated by LLMs [INFERENCE]. These must be computed via SQL `SUM()`, `AVG()` functions on validated database tables [INFERENCE].
- **User Authentication & Authorization:** Permission checks for sensitive mining block data must rely strictly on standard RBAC code, never LLM decisions [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema Design (PostgreSQL)

```sql
-- Main Document Metadata Table
CREATE TABLE documents (
    document_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    subsidiary VARCHAR(50) NOT NULL, -- ECL, BCCL, CCL, NCL, WCL, SECL, MCL, CMPDI
    report_type VARCHAR(50) NOT NULL, -- Geological_Report, Project_Report, Monthly_Production, Parliamentary_QA
    publication_year INT,
    file_path VARCHAR(512) NOT NULL,
    ocr_status VARCHAR(20) DEFAULT 'PENDING', -- PENDING, COMPLETED, FAILED
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Extracted Borehole Tabular Data Table (Deterministic Storage)
CREATE TABLE borehole_logs (
    log_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID REFERENCES documents(document_id),
    borehole_number VARCHAR(50) NOT NULL,
    coalfield VARCHAR(100) NOT NULL,
    block_name VARCHAR(100) NOT NULL,
    seam_name VARCHAR(50) NOT NULL,
    depth_from NUMERIC(8,2) NOT NULL,
    depth_to NUMERIC(8,2) NOT NULL,
    thickness NUMERIC(6,2) NOT NULL,
    ash_percentage NUMERIC(5,2),
    moisture_percentage NUMERIC(5,2),
    gcv_kcal_kg NUMERIC(7,2),
    unfc_code VARCHAR(10), -- 331 (Proved), 332 (Indicated), 333 (Inferred)
    source_page_num INT NOT NULL,
    bounding_box JSONB, -- Coordinates on page image [x, y, w, h]
    validation_status VARCHAR(20) DEFAULT 'VALID' -- VALID, ANOMALY_FLAGGED
);

-- Document Chunks for Vector Search & Citation
CREATE TABLE document_chunks (
    chunk_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID REFERENCES documents(document_id),
    page_number INT NOT NULL,
    paragraph_number INT NOT NULL,
    content TEXT NOT NULL,
    qdrant_point_id UUID NOT NULL
);
```

### Offline & Low-Network Edge Strategy
1. **Local IndexedDB Caching (Progressive Web App):** The React frontend uses Service Workers and IndexedDB to cache recent search results, report templates, and draft parliamentary responses locally [INFERENCE]. Users can draft responses offline in field camps [INFERENCE].
2. **Asynchronous Background Synchronization:** When connectivity is restored, an automated queue syncs locally drafted reports and pending OCR batch uploads with the central server via chunked HTTP POST requests [INFERENCE].
3. **Bandwidth Reduction Optimization:** PDF previewing uses client-side rendering with SVG bounding box overlays [INFERENCE]. Only the specific page image requested by the user is downloaded on-demand, rather than re-downloading 300MB full report PDFs over cellular networks [INFERENCE].

4. **AI Hallucination Liability Mitigation:** All AI-generated parliamentary answers and report summaries contain mandatory legal disclaimer footers [INFERENCE]. The UI enforces human-in-the-loop validation: generated answers MUST be reviewed and approved by an authorized official before export [INFERENCE].
