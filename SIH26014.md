# Solution Research Dossier: Integrated GIS-based Digital Public Infrastructure for Land Governance (Land Stack)

---

## 1. Executive Snapshot

The **Land Stack** project is a flagship Digital Public Infrastructure (DPI) initiative led by the Department of Land Resources (DoLR), Ministry of Rural Development, Government of India [PS]. Its core objective is to dismantle the siloed, state-specific land administration databases that currently result in fragmented records, transaction delays, and rampant land disputes [PS]. By building an interoperable, parcel-centric spatial framework anchored by the 14-digit Unique Land Parcel Identification Number (ULPIN / Bhu-Aadhaar) [RESEARCHED], Land Stack unifies base cadastral maps with essential governance records (Record of Rights, registration, zoning, encumbrance) and additional service layers (utilities, taxation, valuation) across rural and urban domains [PS]. This dossier presents a complete technical, spatial, and strategic architectural blueprint for a 4–6 student hackathon team to build a scalable, federated prototype and a comprehensive Standard Technical Document compliant with national e-governance guidelines [PS].

## 5. Constraints & Environment Realities

1. **State Subject & Legal Heterogeneity [PS]:** Under Schedule 7 (List II, Entry 18 & 45) of the Constitution of India, land is a State subject [KNOWN]. Each State/UT possesses distinct land revenue codes (e.g., UP Zamindari Abolition Act vs Tamil Nadu Land Encroachment Act) [KNOWN]. System architecture must federate rather than centralized-replace state databases [INFERENCE].
2. **Language & Terminology Spectrum [RESEARCHED]:** Revenue terms vary drastically: land identification is called *Khasra* in MP/UP, *Dag* in Assam, *Survey Number* in TN/Maharashtra, and *Gut Number* in regional belts [RESEARCHED]. Terminology must be dynamically normalized using DoLR’s *Glossary of Revenue Terms (GoRT)* [RESEARCHED].
3. **Connectivity Realities in Rural Belts [KNOWN]:** Village-level Patwaris and field inspectors frequently operate in low-bandwidth or offline environments [KNOWN]. PWA with local vector tile storage and offline field verification sync is mandatory [INFERENCE].
4. **Urban vs Rural Spatial Disparities [PS]:** Rural areas rely on 2D vector cadastral maps (scale 1:4000) [KNOWN], whereas urban areas require high-resolution drone imagery (NAKSHA initiative) and 3D building/apartment unit representations [RESEARCHED].
5. **Hardware Constraints at Sub-Registrar / Tehsil Level [KNOWN]:** Legacy desktop browsers (Chrome 80+, Edge) with limited RAM (4GB-8GB) [ASSUMPTION]. Frontend spatial rendering must rely on GPU-accelerated WebGL vector tiling (MapLibre GL) to ensure smooth performance [INFERENCE].

## 6. Research Questions

1. **ULPIN Calculation Mechanics:** How is the 14-digit ULPIN deterministically generated from polygon vertex coordinates adhering to ECCMA and OGC standards? [RESEARCHED]
2. **Data Model Federation:** How can disparate SQL schemas (PostgreSQL, Oracle, MSSQL) from state land portals (e.g., Dharani, Bhoomi, MP Bhulekh) be dynamically mapped to a unified Land Stack OGC-compliant schema without data loss? [RESEARCHED]
3. **Change Detection Models:** What satellite imagery resolution (Sentinel-2 10m vs PlanetScope 3m) and computer vision architectures (U-Net vs Segment Anything Model - SAM) are feasible for detecting unauthorized construction or land-use conversion during a hackathon build? [RESEARCHED]
4. **Interoperability & Lock Protocols:** How can the platform maintain transactional lock integrity when a parcel undergoes simultaneous mutation in the Revenue Court and mortgage recording in a commercial bank? [INFERENCE]

## 10. Recommended Approach & Why

**Selected Approach: Approach 3 — Cloud-Native DPI Federated Spatial Architecture.**

### Strategic Justification
1. **WebGL Client-Side Vector Tiling:** Utilizing dynamic MVT (Mapbox Vector Tiles) generated directly from PostGIS via lightweight tile servers (`pg_tileserv` or `Martin`) enables smooth 60fps rendering of thousands of parcel polygons with interactive hover details, outperforming heavy raster WMS servers [INFERENCE].
2. **Schema-Agnostic Adapter Pattern:** Solves the core challenge of State Subject diversity [PS] by placing a Schema Mapping Layer (utilizing DoLR’s Glossary of Revenue Terms - GoRT) between state-specific DB instances and the unified Land Stack core [INFERENCE].
3. **Event-Driven Interoperability:** Uses asynchronous webhooks and Kafka/RabbitMQ events to trigger automatic cross-departmental updates (e.g., Deed registration in SRO automatically pushes an "Auto-Mutation Pending" notification to Revenue Court) [INFERENCE].

### Why Alternatives Were Rejected
* **Approach 1 (Monolithic Web-GIS):** Rejected due to performance bottlenecks under concurrent national load, heavy server-side raster tile generation costs, and rigid inability to map state schema variations dynamically [INFERENCE].
* **Approach 2 (GeoServer Microservices):** Rejected because traditional GeoServer instances introduce unnecessary Java runtime memory overhead for simple MVT tile serving during rapid hackathon prototyping [INFERENCE].

### Detailed Data-Flow Narrative

1. **Parcel Query Step:** Citizen enters a 14-digit ULPIN or uses GPS location on the Map Interface [INFERENCE].
2. **API Resolution:** API Gateway validates JWT authentication and forwards request to `Parcel Governance Engine` [INFERENCE].
3. **Spatial Vector Retrieval:** `pg_tileserv` streams Mapbox Vector Tiles (MVT) directly from PostGIS spatial indexes (GIST index on geometry), rendering parcel boundaries on MapLibre GL [INFERENCE].
4. **Multi-Layer Federation:** The client requests activated overlays (e.g., Cadastral + Master Plan Zoning + Sub-Registrar Encumbrance). The `Layer Stacking GIS Service` joins records on `parcel_ulpin` [INFERENCE].
5. **Terminology Translation:** State-specific attributes (e.g., *Khasra No 412, Area in Bigha*) pass through the `GoRT Adapter Engine` and render as normalized standardized fields alongside local vernacular terms [INFERENCE].
6. **Audit Trail Logging:** Every query, transaction request, or mutation trigger writes an entry with a SHA-256 hash hash-chained to the prior record in the `Audit Ledger` table [INFERENCE].

### Core Relational Spatial Schema (PostGIS)

```sql
-- Base Parcel Table
CREATE TABLE land_parcels (
    ulpin VARCHAR(14) PRIMARY KEY, -- 14-Digit ULPIN Bhu-Aadhaar
    state_code VARCHAR(10) NOT NULL,
    district_code VARCHAR(10) NOT NULL,
    tehsil_code VARCHAR(10) NOT NULL,
    village_code VARCHAR(10) NOT NULL,
    local_parcel_id VARCHAR(50) NOT NULL, -- Khasra / Survey No
    area_sq_m NUMERIC(12, 2) NOT NULL,
    land_use_category VARCHAR(50) NOT NULL, -- Agri, Res, Comm, Govt
    geom GEOMETRY(Polygon, 4326) NOT NULL, -- WGS84 Spatial Polygon
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_parcels_geom ON land_parcels USING GIST(geom);
CREATE INDEX idx_parcels_ulpin ON land_parcels(ulpin);

-- Essential Layer: Record of Rights (RoR)
CREATE TABLE ror_records (
    ror_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ulpin VARCHAR(14) REFERENCES land_parcels(ulpin),
    owner_name VARCHAR(255) NOT NULL,
    owner_masked_aadhaar VARCHAR(12),
    ownership_type VARCHAR(50), -- Sole, Joint, Leasehold
    share_fraction VARCHAR(20),
    encumbrance_status BOOLEAN DEFAULT FALSE,
    last_updated TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Additional Layer: Municipal Tax & Utilities
CREATE TABLE municipal_utilities (
    utility_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ulpin VARCHAR(14) REFERENCES land_parcels(ulpin),
    tax_property_id VARCHAR(50),
    water_connection_status VARCHAR(20),
    electricity_consumer_no VARCHAR(50),
    annual_property_tax NUMERIC(10, 2),
    tax_due_amount NUMERIC(10, 2) DEFAULT 0.00
);
```

## 15. Security, Privacy & Governance

1. **Personal Data Protection (DPDP Act 2023 Compliance):** Citizen identity numbers (Aadhaar) are strictly masked (`XXXX-XXXX-1234`) in public API endpoints [KNOWN]. Ownership lookup requires OTP authentication via citizen mobile [INFERENCE].
2. **Role-Based Access Control (RBAC):**
   * *Public/Citizen:* Read-only spatial viewing, masked RoR verification, tax payment interface [PS].
   * *Patwari/Tehsildar:* Field verification submit, mutation initiation, local map edit draft [PS].
   * *Sub-Registrar (SRO):* Deed registration lock/unlock on parcel ULPIN [PS].
   * *System Admin:* Configuration of state adapters and API access tokens [PS].
3. **Cryptographic Tamper-Evident Audit Ledger:** Every state change (e.g., mutation approved, lien created) writes an audit log entry:
   $$\text{Hash}_n = \text{SHA256}(\text{Hash}_{n-1} \parallel \text{Timestamp} \parallel \text{ULPIN} \parallel \text{ActorID} \parallel \text{Payload})$$
   This guarantees immutable historical lineage and deters fraudulent manipulation [INFERENCE].
