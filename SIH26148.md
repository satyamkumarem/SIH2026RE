## 1. Executive Snapshot

The National Technical Research Organisation (NTRO) requires a stealthy, non-disruptive digital forensic acquisition and telemetry framework named **'JOCKY'**. Modern Endpoint Detection and Response (EDR) and antivirus (AV) solutions heavily restrict proprietary forensic utilities by detecting behavioral heuristics, static signatures, standard MSVC/GCC compiler artifacts, known API call sequences, and kernel telemetry callbacks [PS]. When investigating a compromised or high-security host, standard forensic tools (e.g., FTK Imager, Velociraptor, OSQuery) can alert active adversaries or trigger security software that kills the process or blocks acquisition [PS, RESEARCHED]. To overcome these limitations, JOCKY combines a Domain-Specific Language (DSL) transpiler/compiler with custom LLVM Intermediate Representation (IR) obfuscation passes, an automated polymorphic CI/CD build engine, in-memory living-off-the-land execution primitives, driver-level physical memory access (BYOVD interaction), and CDN/Cloud API domain-fronted telemetry channels [PS]. This dossier outlines a comprehensive technical architecture, trade-off evaluation, and implementation roadmap designed for a 4-6 student team to build and demonstrate a functional prototype at the Smart India Hackathon 2026.

## 2. Problem Deconstruction

The problem statement provided by NTRO decomposes into five core explicit and functional requirements [PS]:

*   **Requirement 1: Independent Programming Language / LLVM IR Frontend** [PS]
    *   *Source Text:* "1. Independent programming Language - Programming language or custom Language-independent intermediate representation (LLVM) frontend alters basic control-flow graphs, token generation, and binary structures, rendering signature-based detection ineffective."
    *   *Interpretation:* JOCKY must feature a custom Domain-Specific Language (DSL) or compiler frontend targeting LLVM IR. The compilation stage must alter control-flow graphs (CFG), substitute instructions, inject opaque predicates, and randomize token generation to strip standard compiler signatures (MSVC/GCC) [INFERENCE].
    *   *Implementation Implication:* Implement a JOCKY DSL parser that emits valid C/LLVM IR code, which is then transformed using custom or customized LLVM obfuscation passes (e.g., Obfuscator-LLVM architecture) before emitting machine code [INFERENCE].
    *   *Confidence Tag:* [PS]

*   **Requirement 2: Polymorphic CI/CD Build Engine** [PS]
    *   *Source Text:* "2. Polymorphism in scripts/function generated - Rather than manually packing a binary, the scripts/function in framework uses a continuous delivery pipeline. Every iteration automatically passes through integrated obfuscators, variable-encryption routines, and polymorphic engines. This ensures that every deployment instance possesses unique hashes, modified entry points, and altered import tables, neutralizing traditional file-reputation databases."
    *   *Interpretation:* Every time a forensic script is compiled and deployed, an automated pipeline must dynamically mutate the output binary, generating a unique cryptographic file hash (SHA-256), randomized entry points, dynamic import tables, and encrypted variable strings [INFERENCE].
    *   *Implementation Implication:* Create an automated build wrapper (CI/CD pipeline runner) that injects randomized decryption keys, junk code routines, and dynamic PE/ELF header modifiers prior to agent deployment [INFERENCE].
    *   *Confidence Tag:* [PS]

*   **Requirement 3A: Living-off-the-Land & In-Memory Execution** [PS]
    *   *Source Text:* "3. Living-off-the-Land & BYOVD Execution ... A. In-Memory Execution: Utilizing multiple distinct file-less techniques (e.g., process hollowing, reflective DLL injection, API unhooking, direct system calls, or thread execution hijacking) to run secondary script entirely within the memory space of trusted processes."
    *   *Interpretation:* Forensic collection modules must execute entirely filelessly in RAM to avoid dropping temporary `.exe` or `.so` files to disk. The agent must bypass user-mode EDR hooks by restoring clean API headers or issuing indirect system calls (`syscall` / `sysenter`) [INFERENCE].
    *   *Implementation Implication:* Build an in-memory execution payload utilizing indirect syscalls (SysWhispers pattern on Windows) and `memfd_create` / reflective loading on Linux to execute secondary triage modules inside trusted process memory [INFERENCE].
    *   *Confidence Tag:* [PS]

*   **Requirement 3B: Kernel-Level Subversion & Driver Abstraction (BYOVD)** [PS]
    *   *Source Text:* "B. Kernel-Level Subversion: Detection of legitimate or vulnerable third-party drivers (BYOVD) to disable EDR callbacks or manipulate kernel structures directly, blinding security agents running in user or kernel space."
    *   *Interpretation:* The framework must possess driver-level capabilities to inspect kernel memory structures (`EPROCESS`, callback routines) or leverage existing signed drivers to extract physical RAM and system artifacts without triggering EDR kernel callbacks (`PspCreateProcessNotifyRoutine`, `ObRegisterCallbacks`) [INFERENCE].

    *   *Confidence Tag:* [PS]

*   **Requirement 4: Central Management Interface & Domain-Fronted CDN Transport** [PS]
    *   *Source Text:* "Framework also able to handle multiple system analysis simultaneously using central management interface. The traffic b/w management interface and client should be routed through trusted cloud infrastructure or content delivery networks (CDNs) using domain fronting or legitimate cloud APIs."
    *   *Interpretation:* A central web interface must orchestrate concurrent forensic jobs across multiple endpoints. C2 command-and-telemetry traffic must blend in with legitimate enterprise HTTPS traffic by utilizing CDN edge proxies, Cloudflare Workers/Fastly, or cloud storage APIs (Azure Blob/AWS S3) with host-header obfuscation [INFERENCE].
    *   *Implementation Implication:* Build a Go/React web console with WebSockets, integrated with a serverless edge proxy (e.g., Cloudflare Workers / Nginx proxy) acting as a domain-fronting redirector [INFERENCE].
    *   *Confidence Tag:* [PS]

*   **Requirement 5: Cross-Platform Compiler (Windows & Ubuntu)** [PS]
    *   *Source Text:* "...using cross-platform compiler (windows & ubuntu) which enables systematic creation of scripts..."
    *   *Interpretation:* The toolchain and compiled forensic agents must natively target both Windows 10/11 (x86_64 PE) and Ubuntu Linux 20.04/22.04/24.04 (x86_64 ELF) [INFERENCE].

## 10. Recommended Approach & Why

The recommended solution is **Approach 3 (JOCKY Transpiler to C/C++ + LLVM IR Obfuscation Pass + Polymorphic Engine + In-Memory Evasion Loader + CDN Domain-Fronted C2)** [INFERENCE].

**Why Alternatives Were Rejected:**
*   *Approach 1 (Full LLVM IR Frontend from scratch):* Rejected due to extreme implementation risk during a hackathon. Writing a custom AST-to-LLVM-IR emitter consumes excessive development time that must be dedicated to core evasion, BYOVD abstraction, and C2 telemetry features [INFERENCE].
*   *Approach 2 (Embedded Interpreter):* Strictly rejected because it violates explicit Requirement #1 (LLVM IR control-flow graph mutation) and fails against modern EDR memory scanning heuristics [PS, INFERENCE].

**Why Approach 3 Wins:**
Transpiling the JOCKY DSL to clean C/C++ source code allows the system to seamlessly tap into the full, production-grade LLVM compiler suite (`clang`, `llvm-opt`, OLLVM passes). It achieves authentic Control-Flow Graph (CFG) flattening, token alteration, and binary structure randomization at the intermediate representation level while ensuring the student team can realistically build, test, and demonstrate the entire system [INFERENCE].

### Detailed Data-Flow Narrative

1.  **Script Authoring & Compilation Trigger:** An incident responder logs into the Central Management Interface and authors or selects a JOCKY script (`memory_triage.jocky`). The operator selects target hosts (Windows and Ubuntu) and clicks "Deploy Mission" [INFERENCE].
2.  **Transpilation & LLVM Mutation:** The C2 backend invokes the JOCKY Transpiler, converting DSL code into modular C functions. A dynamic seed generator produces fresh cryptographic keys and junk code parameters. The C code is passed into the Clang/OLLVM compiler, which executes control-flow flattening, instruction substitution, and string encryption at the LLVM IR stage [INFERENCE].
3.  **Polymorphic Artifact Emission:** The compiler outputs uniquely hashed cross-platform binaries (PE for Windows, ELF for Ubuntu) with randomized entry points, modified import tables, and unique SHA-256 hashes [INFERENCE].
4.  **CDN Domain-Fronted Transmission:** The compiled payload is dispatched through the C2 transport layer. The connection utilizes TLS SNI headers matching a highly trusted domain (e.g., `cdn.cloudflare.com`) while internal HTTP Host headers direct the request through edge serverless workers to the target agent [RESEARCHED, INFERENCE].
5.  **In-Memory Endpoint Execution:** On the target host, the agent receives the payload. On Windows, it performs API unhooking by reading a clean copy of `ntdll.dll` from disk to strip user-mode EDR hooks, then executes the triage payload filelessly in memory using indirect syscalls [RESEARCHED, INFERENCE]. On Ubuntu, it utilizes `memfd_create` to execute the payload directly from anonymous RAM [INFERENCE].
6.  **Kernel & Memory Artifact Extraction:** The payload executes forensic collection: reading process memory structures, parsing loaded modules, enumerating handles, and interfacing with authorized memory drivers [INFERENCE].
7.  **Encrypted Telemetry Exfiltration:** Gathered forensic artifacts are compressed using Zstandard, encrypted with AES-256-GCM, and sent back through the domain-fronted CDN proxy to the Central C2 server for analyst visualization [INFERENCE].
