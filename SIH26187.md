## 1. Executive Snapshot

The proposed project, **IBVAP (Intelligent Border Video Analytics Platform)**, addresses a critical operational gap facing the Sashastra Seema Bal (SSB) along India's open borders with Nepal and Bhutan [PS, RESEARCHED]. Border security forces currently rely on legacy IP CCTV networks deployed across Border Out Posts (BOPs), check posts, and border roads [PS]. However, these conventional systems require continuous human monitoring and lack automated threat intelligence [PS]. Upgrading to hardware-dependent AI cameras or specialized proprietary video processing hardware across thousands of remote locations is economically prohibitive and operationally complex [PS, INFERENCE]. IBVAP delivers a software-defined, edge-hybrid video analytics layer that ingests standard RTSP streams from existing CCTV cameras, performing multi-stream real-time AI analytics (human tracking, vehicle classification, face recognition, ANPR, virtual fence intrusion, suspicious behavior, and night-time motion detection) directly on localized edge nodes with full store-and-forward offline resilience [PS, ASSUMPTION].

## 5. Constraints & Environment Realities

1. **Geographic & Physical Environment:** SSB guards the 1,751 km Indo-Nepal and 699 km Indo-Bhutan borders, spanning dense Terai forests, riverine plains, and high-altitude Himalayan terrain [RESEARCHED]. BOPs are situated in harsh physical conditions with extreme temperature ranges, dust, heavy monsoon rain, and winter fog [KNOWN].
2. **Connectivity Limitations:** Remote BOPs frequently rely on low-bandwidth satellite (VSAT), cellular 2G/3G/4G with high latency, or unreliable line-of-sight wireless links [KNOWN]. Continuous streaming of raw 1080p video (requiring 2–4 Mbps per camera) to a centralized cloud is technically infeasible [INFERENCE].
3. **Power Grid Instability:** Remote border outposts experience frequent power outages, relying on diesel generators and solar battery backups [KNOWN]. Edge compute hardware must be power-efficient (e.g., low-TDP edge servers or industrial NVIDIA Jetson Orin modules operating under 60W) [ASSUMPTION].
4. **Existing Hardware Heterogeneity:** Legacy CCTV infrastructure comprises various brands (CP Plus, Dahua, Hikvision, Bosch) with differing resolutions (720p, 1080p, 4K), frame rates (10–30 FPS), codecs (H.264, H.265), and infrared illuminator ranges [KNOWN].
5. **Human Factors & Operator Literacy:** Field personnel at BOPs may have limited technical IT expertise [KNOWN]. The user interface must be clutter-free, highly visual, localized, and require minimal manual setup [ASSUMPTION].

## 9. Candidate Solution Approaches

### Approach 1: Centralized Cloud / Sector HQ Processing
* **Mechanism:** All remote BOP CCTV streams are compressed and streamed continuously over WAN/VSAT to a centralized cloud/datacenter server running heavy GPU clusters for AI inference.
* **Required Data:** High-bandwidth live RTSP video feeds from all cameras simultaneously.
* **Architecture:** Edge RTSP Streamer $\rightarrow$ WAN / Satellite Network $\rightarrow$ Central GPU Inference Server (Triton/DeepStream) $\rightarrow$ Web Dashboard.
* **Pros & Cons:** High centralized model accuracy and simple edge hardware management. *Critical Flaw:* Requires continuous 2–4 Mbps per camera WAN bandwidth. In remote border areas with unstable connectivity, the pipeline completely collapses during outages [INFERENCE].
* **Hackathon / Production Feasibility:** High for hackathon demo; Completely unviable for production border deployment [INFERENCE].

### Approach 2: Proprietary Edge AI Smart Camera Replacement
* **Mechanism:** Replace all legacy CCTV cameras with modern edge AI smart cameras featuring built-in NPU chips for on-camera inference.
* **Required Data:** On-camera video streams; edge configuration updates.
* **Architecture:** AI Camera (Built-in NPU) $\rightarrow$ Local Alert Gateway $\rightarrow$ Central C2.
* **Pros & Cons:** Extremely low latency; minimal edge server footprint. *Critical Flaw:* Directly violates the core requirement of the problem statement (*"without requiring dedicated FRS, ANPR, or smart-camera hardware"* [PS]) and requires massive capital expenditure.
* **Hackathon / Production Feasibility:** Disqualified by problem constraints [PS].

### Approach 3: Hybrid Software-Defined Edge-Gateway Architecture (Recommended)
* **Mechanism:** Deploy a localized software-defined **IBVAP Edge Gateway** (e.g., an industrial x86 server or NVIDIA Jetson Orin box) at each BOP. The gateway ingests local legacy camera RTSP streams, executes lightweight quantized AI models (YOLO, ByteTrack, RetinaFace, ANPR OCR) on-site, generates immediate local audio-visual alerts, caches incident clips, and syncs lightweight JSON telemetry (+ compressed snapshot) over low-bandwidth links to the **IBVAP Central C2 Platform**.
* **Required Data:** Local RTSP streams; local edge SQLite/PostgreSQL store; remote MQTT telemetry link.
* **Architecture:** Legacy IP Cameras $\rightarrow$ Local LAN $\rightarrow$ IBVAP Edge Gateway (DeepStream/GStreamer + TensorRT) $\rightarrow$ Local BOP UI & Audio Alarm $\rightarrow$ Low-Bandwidth MQTT Store-and-Forward $\rightarrow$ IBVAP Central C2 Master Dashboard.
* **Pros & Cons:** Zero modification to existing cameras [PS]; operates 100% autonomously during WAN network blackouts; uses <10 KB/s WAN bandwidth per alert [INFERENCE]; highly scalable across hundreds of BOPs.

## 10. Recommended Approach & Why

The **Hybrid Software-Defined Edge-Gateway Architecture (Approach 3)** is selected.

### Justification & Rejection of Alternatives

1. **Compliance with PS Constraints:** Approach 3 strictly fulfills the explicit requirement to leverage *existing CCTV infrastructure without hardware modifications to cameras* [PS]. Approach 2 was explicitly rejected as it violates this primary constraint.
2. **Bandwidth Realities at Remote Border Outposts:** Approach 1 was rejected because streaming continuous raw video feeds over remote border satellite/cellular links is practically impossible and cost-prohibitive [INFERENCE]. Approach 3 processes video locally at the BOP, converting heavy video streams into ultra-lightweight metadata JSON strings and compressed event snapshots for transmission [INFERENCE].
3. **Operational Autonomy:** Border outposts frequently experience network cut-offs due to weather or terrain [KNOWN]. Approach 3 guarantees that local BOP guards receive sub-second intrusion alarms and live video overlays even if the external network connection is completely severed [INFERENCE].

### Step-by-Step Data Flow Narrative

1. **Stream Ingestion & Decoding:** Legacy IP cameras push RTSP H.264/H.265 video feeds over local BOP Ethernet/Wi-Fi to the IBVAP Edge Gateway [PS, ASSUMPTION]. The ingestion engine decodes video frames using hardware acceleration (NVDEC/VAAPI) and maintains reconnect buffers to ensure stream persistence [ASSUMPTION].
2. **Night & Contrast Pre-processing:** Low-light or night IR feeds undergo dynamic contrast enhancement (CLAHE filter) to amplify edge details before inference [ASSUMPTION].
3. **Primary Object Detection & Tracking:** Frames are passed to a TensorRT-optimized YOLOv11 detector, generating bounding boxes for `person` and `vehicle` classes [ASSUMPTION]. Bounding boxes are tracked across frames by ByteTrack to assign consistent track IDs and calculate speed/direction vectors [ASSUMPTION].
4. **Specialized Parallel Analytics:**
   - *ANPR Pipeline:* Vehicle bounding boxes trigger plate region extraction, which is passed to PaddleOCR to extract text strings [RESEARCHED, ASSUMPTION].
   - *Facial Biometrics Pipeline:* Person bounding boxes containing faces trigger SCRFD face detection and ArcFace feature extraction (512-d vector) [RESEARCHED, ASSUMPTION]. Vectors are matched locally against the cached watchlist using Cosine Similarity [ASSUMPTION].
   - *Spatial & Behavioral Analytics:* Person/vehicle footprint coordinates are checked against user-defined GeoJSON polygon coordinates (Virtual Fence) using Shapely spatial intersection math [ASSUMPTION]. Dwell times are computed to flag loitering or illegal border crossing [INFERENCE].
5. **Local Alerting & Caching:** If an intrusion, watchlist match, or suspicious activity rule triggers, the Edge Core instantly generates a local alert on the BOP Duty Officer's console, playing an audible alarm and displaying a WebRTC video overlay with bounding boxes [INFERENCE]. The event metadata, crop image snapshot, and 10-second video buffer are logged into local SQLite storage [ASSUMPTION].
6. **Low-Bandwidth Store-and-Forward Synchronization:** The Edge Gateway packages the alert into a compact JSON payload (<5 KB) with an optional compressed snapshot (<50 KB) and pushes it via MQTT over TLS to Sector HQ [ASSUMPTION]. If the network connection is down, MQTT queues messages locally on disk and auto-flushes them once connectivity is restored [INFERENCE].
7. **Central C2 Visualization & External Integration:** Sector HQ receives telemetry events, updating the live MapLibre GIS map with threat markers and logging incidents into PostGIS [ASSUMPTION]. The C2 Integration Gateway exposes REST endpoints and Cursor-on-Target (CoT) XML feeds to forward alerts to legacy MHA command systems [PS, ASSUMPTION].

## 13. AI/ML Justification

### Detailed AI Component Matrix

#### 1. Human & Vehicle Detection & Tracking
* **Purpose:** Detect and assign persistent IDs to persons and vehicles across camera frames [PS].
* **Model Type:** YOLOv11 object detector + ByteTrack tracker [ASSUMPTION].
* **Input:** Decoded RGB video frame (1080p/720p at 15–25 FPS) [INFERENCE].
* **Output:** Bounding box coordinates `[x1, y1, x2, y2]`, class ID (`person`, `car`, `truck`, `bus`, `two-wheeler`), track ID, confidence score [INFERENCE].
* **Data Required:** Open-source surveillance datasets (COCO, VisDrone) fine-tuned on custom Indian border terrain images [ASSUMPTION].
* **Why AI:** Rule-based background subtraction fails completely due to swaying vegetation, lighting shifts, shadows, and weather changes [INFERENCE].
* **Evaluation Metric:** Mean Average Precision (mAP@0.5 > 88%), Higher Order Tracking Accuracy (HOTA > 65%) [ASSUMPTION].
* **Failure Mode:** False positives caused by animals (e.g., cattle, dogs) or false negatives during extreme heavy fog [INFERENCE].
* **Human Oversight:** Officer verifies alert thumbnail on BOP console before dispatching QRT [ASSUMPTION].

#### 2. Automatic Number Plate Recognition (ANPR)
* **Purpose:** Identify vehicle license plate text for blacklist matching [PS].
* **Model Type:** Custom License Plate Bounding Box Localizer + PaddleOCR text recognition [RESEARCHED, ASSUMPTION].
* **Input:** Cropped vehicle image region [INFERENCE].
* **Output:** Alphanumeric license plate string (e.g., `UK07AB1234`), plate confidence score [INFERENCE].
* **Data Required:** Dataset of Indian license plates including High Security Registration Plates (HSRP) and standard formats under diverse angles/lighting [RESEARCHED, ASSUMPTION].
* **Why AI:** Traditional pattern matching cannot handle non-standard fonts, dirt, reflection, angled perspectives, and varied state formats [RESEARCHED, INFERENCE].
* **Evaluation Metric:** Character Recognition Accuracy (>92%), Plate Localization Recall (>95%) [ASSUMPTION].
* **Failure Mode:** Mismatched characters due to muddy plates or customized "fancy" illegible fonts [RESEARCHED, INFERENCE].
* **Human Oversight:** OCR output string displayed alongside raw cropped plate snapshot for instant human visual confirmation [ASSUMPTION].

#### 3. Facial Biometric Identification (FRS)
* **Purpose:** Detect faces and identify individuals against a POI watchlist [PS].
* **Model Type:** SCRFD face detector + ArcFace feature embedder (ResNet50 / MobileFaceNet backbone) [RESEARCHED, ASSUMPTION].
* **Input:** Cropped human face region (>60x60 pixels resolution) [INFERENCE].
* **Output:** 512-dimensional floating-point vector embedding; matched Person ID + similarity score [INFERENCE].
* **Data Required:** Normalized face datasets (LFW, MS1MV2) fine-tuned for low-resolution surveillance crops [RESEARCHED, ASSUMPTION].
* **Why AI:** Biometric facial identification is mathematically impossible using traditional deterministic algorithms [INFERENCE].
* **Evaluation Metric:** True Accept Rate (TAR) > 95% at False Accept Rate (FAR) = 0.001% [ASSUMPTION].
* **Failure Mode:** False dismissal due to severe facial angle (>45 degrees), heavy physical disguise, or extreme darkness [INFERENCE].
* **Human Oversight:** High-severity alert triggered only above 0.75 Cosine Similarity; officer visually compares side-by-side face images [ASSUMPTION].

#### 4. Behavioral & Loitering Analytics
* **Purpose:** Flag suspicious loitering, sudden running, or movement in restricted directions [PS].
* **Model Type:** Heuristic Spatio-Temporal Trajectory Analyzer operating on ByteTrack track histories [ASSUMPTION].
* **Input:** Sequence of tracked object centroid coordinates `(x, y, t)` over time [INFERENCE].
* **Output:** Behavioral flag (`loitering_detected`, `rapid_approach`, `reverse_flow`) + anomaly confidence [INFERENCE].
* **Data Required:** Trajectory vector logs [INFERENCE].
* **Why AI/Algorithmic Fusion:** Tracks spatial-temporal movement patterns across time windows that human operators cannot manually track across 20 feeds simultaneously [INFERENCE].
* **Evaluation Metric:** False Alarm Rate < 2 per camera/day [ASSUMPTION].
* **Failure Mode:** Nuisance alerts caused by guards on routine patrol standing near boundary lines [INFERENCE].
* **Human Oversight:** Configurable dwell-time thresholds (e.g., >30 seconds in zone) set by duty officers [ASSUMPTION].

### Where AI Should NOT Be Used

* **Virtual Fence Intersection Math:** Determining if an object has crossed a virtual fence boundary must be executed using deterministic computational geometry algorithms (e.g., **Ray-Casting Polygon Intersection / Shapely spatial math**) on object base coordinates, NOT generative or probabilistic AI models [INFERENCE].
* **User Authentication & Role Management:** System access control and audit logging must strictly rely on deterministic cryptographic RBAC mechanisms [INFERENCE].
* **Alert Storage & Sync Rules:** Network transmission queuing and store-and-forward retries must rely on deterministic state machines (MQTT QoS 1) [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Data Schema (Relational & JSON Layout)

```sql
-- Local Edge & Central PostGIS Incident Table
CREATE TABLE incident_alerts (
    alert_id UUID PRIMARY KEY,
    bop_id VARCHAR(50) NOT NULL,
    camera_id VARCHAR(50) NOT NULL,
    timestamp TIMESTAMPTZ NOT NULL,
    alert_type VARCHAR(30) CHECK (alert_type IN ('INTRUSION', 'ANPR_MATCH', 'FACE_MATCH', 'LOITERING', 'NIGHT_MOVEMENT')),
    severity VARCHAR(10) CHECK (severity IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL')),
    object_class VARCHAR(20),
    track_id INT,
    bounding_box JSONB, -- [x1, y1, x2, y2]
    metadata JSONB,     -- e.g., {"plate_number": "UK07AB1234", "confidence": 0.94}
    snapshot_path VARCHAR(255),
    sync_status VARCHAR(15) DEFAULT 'PENDING' CHECK (sync_status IN ('PENDING', 'SYNCED', 'FAILED')),
    location GEOMETRY(Point, 4323) -- GeoJSON Camera GPS location
);

-- Central Master Watchlist Table
CREATE TABLE face_watchlist (
    person_id UUID PRIMARY KEY,
    full_name VARCHAR(100),
    alias VARCHAR(50),
    threat_category VARCHAR(30),
    face_embedding VECTOR(512), -- Milvus / PGVector extension
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

### Local Storage & Offline Store-and-Forward Strategy

* **Local Storage Footprint:** Each IBVAP Edge Gateway maintains a local circular buffer storage on an industrial NVMe/SSD drive [ASSUMPTION]. Event crop snapshots (50 KB) and 10-second video clips (2 MB) are retained locally for 30 days [ASSUMPTION].
* **Store-and-Forward Queue:**
  1. When an alert occurs, the Edge Core writes the alert record to local SQLite storage marked as `sync_status = 'PENDING'` [ASSUMPTION].
  2. An background MQTT worker attempts to publish the lightweight JSON payload over `sih/bop/{bop_id}/alerts` with **QoS 1 (At Least Once)** [ASSUMPTION].
  3. If the external WAN link is disconnected, the payload remains queued in local persistent storage [INFERENCE].
  4. Upon network reconnection, the broker automatically drains the pending queue, transmitting historical alerts chronologically to Central HQ without data loss [INFERENCE].
* **Bandwidth Reduction:** Continuous video streaming requires ~3 Mbps per camera. IBVAP's edge telemetry sync requires only ~5 KB per alert JSON metadata, representing a **>99.8% bandwidth reduction** over satellite/cellular networks [INFERENCE].
