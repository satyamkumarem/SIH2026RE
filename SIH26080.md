# Regime-Aware AI Post-Processing of Monsoon Rainfall Forecasts

## 1. Executive Snapshot

### Summary
Numerical Weather Prediction (NWP) models operated by the National Centre for Medium Range Weather Forecasting (NCMRWF) and India Meteorological Department (IMD) frequently exhibit systematic, non-linear rainfall biases across the Indian subcontinent [KNOWN]. Standard static statistical post-processing (e.g., unconditioned Model Output Statistics or spatial quantile mapping) fails because physical error structures vary drastically under different synoptic weather regimes—such as Active Monsoon, Break Monsoon, Monsoon Depressions/Lows, Orographic precipitation over the Western Ghats, Coastal convection, and Western Disturbances [PS, KNOWN]. This proposed solution introduces a **Two-Stage Physics-Informed AI Post-Processing Framework**. Stage 1 utilizes a synoptic atmospheric feature-embedding classifier (trained on 850 hPa wind fields, Mean Sea Level Pressure, Precipitable Water, and Outgoing Longwave Radiation) to identify prevailing weather regimes [RESEARCHED]. Stage 2 applies a **Gated Residual Learning (GRL) & Regime-Conditioned Ensemble Network** to correct raw NWP grid precipitation and output calibrated heavy rainfall probabilities (>64.5 mm, >115.5 mm, >204.5 mm) [RESEARCHED]. The pipeline automatically maps output to district administrative boundaries and generates automated spatial verification reports featuring Fractions Skill Score (FSS), Equitable Threat Score (ETS), Critical Success Index (CSI), POD, FAR, and RMSE [PS, RESEARCHED].

## 2. Problem Deconstruction

### Atomic Requirement Extraction

1. **Weather Regime Classifier [PS]**
   - *Source Text*: "Weather regime classifier - Classification of active, break, depression, coastal/orographic rainfall regimes"
   - *Interpretation*: Build an ML/DL classification engine that analyzes large-scale synoptic meteorological fields (e.g., 850 hPa wind vector anomalies, MSLP, moisture flux) and labels regional grids into distinct weather regimes [PS, RESEARCHED].
   - *Implementation Implication*: Requires multi-variable atmospheric predictors extracted from NWP analysis/reanalysis data (e.g., ERA5 or NCUM analysis) rather than surface rainfall alone [INFERENCE].

2. **Bias-Corrected Rainfall Forecast [PS]**
   - *Source Text*: "Bias-corrected rainfall forecast - Improved rainfall forecast compared to raw NWP output"
   - *Interpretation*: Correct systematic spatial, magnitude, and displacement errors present in raw NWP quantitative precipitation forecasts (QPF) [PS, RESEARCHED].
   - *Implementation Implication*: Post-processing model must produce continuous physical rainfall values ($\text{mm/day}$ or $\text{mm/3-hr}$) that preserve mass conservation and handle spatial double-penalty errors [INFERENCE].

3. **Heavy Rainfall Probability [PS]**
   - *Source Text*: "Heavy rainfall probability - Probability of rainfall exceeding operational thresholds"
   - *Interpretation*: Calculate calibrated probabilistic exceedance forecasts for IMD operational thresholds: Heavy ($\ge 64.5\text{ mm}$), Very Heavy ($\ge 115.5\text{ mm}$), and Extremely Heavy ($\ge 204.5\text{ mm}$) [PS, RESEARCHED].
   - *Implementation Implication*: Must output a spatial probability map ($0.0$ to $1.0$) per threshold using logistic Sigmoid outputs or ensemble distribution fitting [INFERENCE].

4. **District-Level Rainfall Product [PS]**
   - *Source Text*: "District-level rainfall product - User-friendly rainfall forecast table/map"
   - *Interpretation*: Aggregate high-resolution gridded post-processed forecasts to India's $700+$ administrative district boundaries and present interactive visual maps and tabular downloads [PS, RESEARCHED].
   - *Implementation Implication*: Requires spatial zonal statistics (area-weighted average and maximum grid value) integrated with GIS vector geometries (GeoJSON/Shapefiles) [INFERENCE].

5. **Verification Report [PS]**
   - *Source Text*: "Verification report - Skill comparison using RMSE, ETS, CSI, POD, FAR and FSS"
   - *Interpretation*: Automatically evaluate raw vs. post-processed forecasts against ground-truth gridded rain-gauge observations (IMD $0.25^\circ \times 0.25^\circ$) using six mandatory statistical and spatial verification metrics [PS, RESEARCHED].
   - *Implementation Implication*: System must implement exact mathematical formulations for Root Mean Square Error (RMSE), Equitable Threat Score (ETS), Critical Success Index (CSI), Probability of Detection (POD), False Alarm Ratio (FAR), and Fractions Skill Score (FSS) [PS, RESEARCHED].

## 5. Constraints & Environment Realities

- **Atmospheric & Spatial Dynamics**: Monsoon precipitation features strong non-linear spatial variability, fine-scale convective bursts, and complex terrain interactions (Western Ghats and Himalayas) [KNOWN]. Standard pixel-wise evaluation suffers from the "double-penalty" effect where small spatial shifts severely penalize good forecasts [RESEARCHED].
- **High-Performance Computing (HPC) & File Formats**: Operational weather data resides in multidimensional binary formats (`GRIB2`, `NetCDF4`) on MoES HPC clusters (e.g., *Arunika* supercomputer at NCMRWF) [RESEARCHED]. Post-processing workflows must efficiently process multi-gigabyte GRIB2 files within strict medium-range forecast windows (00 and 12 UTC cycles) [INFERENCE].
- **Observational Ground-Truth Latency**: High-resolution IMD gridded daily rainfall data ($0.25^\circ \times 0.25^\circ$) is compiled using $\sim 6,900$ rain gauges and satellite merges, typically updated with a 24-hour latency [RESEARCHED]. Real-time operational post-processing must rely on NWP forecast lead times (Day 1 to Day 5) while using historical gridded data for training and offline validation [INFERENCE].
- **Administrative Mapping Realities**: District boundaries frequently change in India. Spatial joins must dynamically use standardized official administrative GeoJSON layers from Survey of India / Local Government Directory (LGD) codes [INFERENCE].

## 6. Research Questions

1. *How can synoptic weather regimes over India be mathematically defined for automated machine learning classification?*
   - **Answer**: By extracting domain-averaged indices and spatial feature fields over the core monsoon zone ($18^\circ\text{N} - 28^\circ\text{N}, 65^\circ\text{E} - 88^\circ\text{E}$), specifically 850 hPa zonal wind anomalies, Mean Sea Level Pressure (MSLP) gradients, and Outgoing Longwave Radiation (OLR) [RESEARCHED].
2. *Why do traditional static bias-correction methods fail during monsoon regime transitions?*
   - **Answer**: Global quantile mapping assumes a stationary bias distribution. During an Active-to-Break transition or low-pressure system (monsoon depression) landfall, model thermodynamics shift dramatically, causing static methods to either severely underestimate extreme convective rainfall or over-correct light stratiform rain [RESEARCHED].
3. *What spatial verification metric best addresses spatial displacement in high-resolution rainfall forecasts?*
   - **Answer**: The Fractions Skill Score (FSS), which evaluates fractional coverage of rainfall exceeding specific thresholds over varying spatial neighborhood sizes, avoiding the double-penalty effect of point-to-point metrics [RESEARCHED].

## 10. Recommended Approach & Why

The recommended solution is **Approach C: Hybrid Physics-Informed Synoptic Embedding + Gated Residual Learning Ensemble**.

### Justification
1. **Why Approach A was rejected**: Hard rule-based regime thresholds create sharp artificial discontinuities at spatial and temporal regime boundaries. When an atmospheric state lies on the margin between "Active" and "Monsoon Low", switching abruptly between independent XGBoost models causes unphysical forecast jumps [INFERENCE].
2. **Why Approach B was rejected**: End-to-end deep learning models (like black-box U-Nets) act as pure spatial smoothers. In monsoon forecasting, this results in the severe underestimation of heavy localized convective rainfall peaks ($>115.5\text{ mm/day}$) and fails to provide forecasters with interpretable physical regime diagnostic metrics [RESEARCHED].
3. **Why Approach C Wins**: Approach C splits the problem into two physically grounded stages [RESEARCHED]:
   - **Stage 1 (Synoptic Regime Classifier)** uses dimensionality reduction (PCA/Autoencoder) followed by soft Gaussian Mixture Model (GMM) clustering on 850 hPa wind vector anomalies, MSLP, and precipitable water to yield continuous soft-regime probability distributions $P(\text{Regime}_k)$ [RESEARCHED].
   - **Stage 2 (Gated Residual Learning)** applies a non-linear gated neural network where the raw NWP forecast passes through a identity skip connection while a gated residual branch (conditioned on $P(\text{Regime}_k)$) predicts the additive spatial bias map [RESEARCHED]. This ensures physical mass conservation, prevents over-smoothing, and provides 100% interpretable feature attribution via SHAP/LIME [RESEARCHED].

### Detailed Data-Flow Narrative

1. **Ingestion & Standardized Regridding**: The automated background worker fetches raw NWP forecast datasets (e.g., NCUM 12 km or GFS 0.25°) in GRIB2/NetCDF formats [RESEARCHED]. Using `xarray` and `rasterio`, the system crops the geographic domain to India ($6^\circ\text{N}-38^\circ\text{N}, 68^\circ\text{E}-98^\circ\text{E}$) and regrids rainfall and atmospheric variables onto a uniform $0.25^\circ \times 0.25^\circ$ grid [RESEARCHED].
2. **Synoptic Feature Extraction**: Atmospheric variables—850 hPa zonal ($u$) and meridional ($v$) wind speeds, Mean Sea Level Pressure (MSLP), Precipitable Water (PW), and Outgoing Longwave Radiation (OLR)—are processed to compute spatial anomalies relative to seasonal climatology [RESEARCHED].
3. **Stage 1 Regime Inference**: The synoptic feature vector is passed to the trained Stage 1 Classifier. The model calculates continuous soft-membership probabilities across 6 defined regimes: Active Monsoon, Break Monsoon, Monsoon Low/Depression, Orographic Rain (Western Ghats/Himalayas), Coastal Convective Rain, and Western Disturbance [PS, RESEARCHED].
4. **Stage 2 Bias Correction & Exceedance Calculation**: The soft-regime probability vector and raw NWP rainfall grid enter the Gated Residual Neural Network [RESEARCHED]. The network predicts a spatial residual matrix $\Delta R(x,y)$, which is added to the raw forecast $R_{\text{raw}}(x,y)$ to produce the final bias-corrected physical precipitation grid $R_{\text{corrected}}(x,y)$ [RESEARCHED]. Concurrently, a binary classification head applies sigmoid activations conditioned on the latent embeddings to calculate grid-level probabilities ($0\% - 100\%$) of exceeding $64.5\text{ mm}$ (Heavy), $115.5\text{ mm}$ (Very Heavy), and $204.5\text{ mm}$ (Extremely Heavy) [PS, RESEARCHED].
5. **GIS Zonal Aggregation & District Product Generation**: Spatial vector boundaries of 700+ Indian districts are overlaid onto the $0.25^\circ$ corrected grid using `geopandas` [RESEARCHED]. Zonal statistics calculate the district area-weighted mean rainfall, peak grid rainfall, and maximum heavy rainfall probability, assigning an operational alert status (Green, Yellow, Orange, Red) [RESEARCHED].
6. **Automated Skill Verification Engine**: When corresponding IMD gridded observation files ($0.25^\circ$) become available for the forecast date, the verification module computes pixel-wise RMSE, categorical scores (ETS, CSI, POD, FAR) across thresholds, and neighborhood spatial skill via Fractions Skill Score (FSS) at $1\times 1$, $3\times 3$, and $5\times 5$ window sizes [PS, RESEARCHED].
7. **Interactive Visual Dashboard**: The Next.js frontend fetches GeoJSON layers and tabular statistics via FastAPI endpoints, rendering interactive choropleth maps, district forecast tables, side-by-side raw vs. corrected visual comparisons, and dynamic verification charts [INFERENCE].

## 13. AI/ML Justification

### AI Component 1: Synoptic Weather Regime Classifier

- **Exact Problem Solved**: Categorizes complex, continuous 3D synoptic atmospheric states into soft weather regime probabilities [PS, RESEARCHED].
- **Model Type**: Gaussian Mixture Model (GMM) soft-clustering coupled with an XGBoost multi-class classifier [RESEARCHED].
- **Input**: Spatial grid anomalies of 850 hPa wind vector ($u, v$), MSLP, Precipitable Water, and OLR over India ($18^\circ-28^\circ\text{N}, 65^\circ-88^\circ\text{E}$) [RESEARCHED].
- **Output**: 6-element probability vector $\vec{P} = [P_{\text{active}}, P_{\text{break}}, P_{\text{depression}}, P_{\text{orographic}}, P_{\text{coastal}}, P_{\text{WD}}]$ summing to $1.0$ [PS, RESEARCHED].
- **Data Required**: Historical ERA5 / NCUM reanalysis fields matched with standard IMD active/break monsoon catalog dates ($1990-2023$) [RESEARCHED].
- **Why AI is Preferable**: Atmospheric regimes do not have sharp physical boundaries. AI soft-clustering captures subtle multi-variable non-linear synoptic interactions better than manual index thresholding [RESEARCHED].
- **Evaluation**: Classification Accuracy, Adjusted Rand Index (ARI), and Log-Loss against verified IMD historical regime catalogs [RESEARCHED].
- **Failure Mode**: During transitional periods, probabilities may distribute evenly ($\approx 0.16$ each).
- **Human Oversight**: Operational forecasters can manually override regime flags in the dashboard UI if an official synoptic bulletin is issued by IMD [INFERENCE].

### AI Component 2: Gated Residual Bias-Correction Post-Processor

- **Exact Problem Solved**: Corrects spatial, amplitude, and displacement biases in raw NWP rainfall grids [PS, RESEARCHED].
- **Model Type**: Gated Residual Network (GRN) with Convolutional Residual Blocks [RESEARCHED].
- **Input**: Raw NWP precipitation grid $R_{\text{raw}}(x,y)$ + soft regime vector $\vec{P}$ + terrain DEM elevation grid + land-sea mask [RESEARCHED].
- **Output**: Bias-corrected continuous precipitation grid $R_{\text{corrected}}(x,y)$ ($\text{mm/day}$) [PS].
- **Data Required**: Historical paired raw NWP forecasts (NCUM/GFS) and IMD gridded observed rainfall ($0.25^\circ$) over 10+ monsoon seasons [RESEARCHED].
- **Why AI is Preferable**: The relationship between raw NWP error, synoptic regime, and terrain is highly non-linear. Linear regression or standard quantile mapping cannot adapt dynamically across spatial domains [RESEARCHED].
- **Evaluation**: Continuous metrics (RMSE, MAE) and spatial skill (FSS) against IMD ground truth [PS, RESEARCHED].
- **Failure Mode**: Network predicting negative rain values (handled by ReLU/Softplus output clipping at $0.0\text{ mm}$) [INFERENCE].
- **Human Oversight**: Model output bounded by physical maximum limits (e.g., maximum historical daily record $+20\%$) to prevent unphysical AI hallucinated extremes [INFERENCE].

### AI Component 3: Heavy Rainfall Exceedance Probabilistic Model

- **Exact Problem Solved**: Converts deterministic forecast guidance into calibrated exceedance probabilities for operational alert thresholds [PS, RESEARCHED].
- **Model Type**: Convolutional Sigmoid Classification Heads trained on Binary Cross-Entropy (BCE) Loss [RESEARCHED].
- **Input**: Latent embeddings from Stage 2 Post-Processor [RESEARCHED].
- **Output**: 3 spatial probability grids ($0.0 - 1.0$) for thresholds: $\ge 64.5\text{ mm}$, $\ge 115.5\text{ mm}$, and $\ge 204.5\text{ mm}$ [PS, RESEARCHED].
- **Data Required**: Historical binary ground truth masks constructed from IMD gridded observations [RESEARCHED].
- **Why AI is Preferable**: Deterministic NWP outputs cannot provide reliable sub-grid uncertainty without running computationally expensive 50-member ensembles [RESEARCHED].
- **Evaluation**: Brier Score, Reliability Diagrams, and Area Under ROC Curve (AUC-ROC) [RESEARCHED].
- **Failure Mode**: Over-confidence in rare extreme events (mitigated by Focal Loss during training) [RESEARCHED].
- **Human Oversight**: Alert thresholds mapped directly to standard IMD Color Codes (Green, Yellow, Orange, Red) for forecaster validation [INFERENCE].

### Where AI Should NOT Be Used
- **GIS District Zonal Aggregation**: Must use deterministic area-weighted polygon clipping and exact mathematical averaging (`geopandas` / `rasterstats`) [INFERENCE].
- **Verification Score Engine**: Must strictly compute exact deterministic formulas for RMSE, ETS, CSI, POD, FAR, and FSS [PS, RESEARCHED].

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema (PostgreSQL / PostGIS)

```sql
-- 1. District Metadata Table
CREATE TABLE districts (
    district_id VARCHAR(10) PRIMARY KEY, -- LGD Code
    district_name VARCHAR(100) NOT NULL,
    state_name VARCHAR(100) NOT NULL,
    geom GEOMETRY(MultiPolygon, 4326) NOT NULL
);

-- 2. Forecast Runs Table
CREATE TABLE forecast_runs (
    run_id SERIAL PRIMARY KEY,
    model_name VARCHAR(50) NOT NULL, -- e.g., 'NCUM_12km', 'GFS_0.25'
    forecast_init_time TIMESTAMP WITH TIME ZONE NOT NULL,
    forecast_valid_time TIMESTAMP WITH TIME ZONE NOT NULL,
    lead_day INT NOT NULL, -- Day 1 to Day 5
    primary_regime VARCHAR(50) NOT NULL,
    regime_confidence FLOAT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 3. District-Level Post-Processed Results
CREATE TABLE district_forecast_results (
    result_id BIGSERIAL PRIMARY KEY,
    run_id INT REFERENCES forecast_runs(run_id),
    district_id VARCHAR(10) REFERENCES districts(district_id),
    raw_mean_rain_mm FLOAT NOT NULL,
    corrected_mean_rain_mm FLOAT NOT NULL,
    corrected_max_rain_mm FLOAT NOT NULL,
    prob_heavy_gt_64_5 FLOAT NOT NULL,
    prob_very_heavy_gt_115_5 FLOAT NOT NULL,
    prob_extreme_gt_204_5 FLOAT NOT NULL,
    alert_level VARCHAR(10) NOT NULL -- 'GREEN', 'YELLOW', 'ORANGE', 'RED'
);

-- 4. Operational Verification Reports
CREATE TABLE verification_reports (
    report_id SERIAL PRIMARY KEY,
    forecast_date DATE NOT NULL,
    lead_day INT NOT NULL,
    regime_name VARCHAR(50) NOT NULL,
    rmse_raw FLOAT NOT NULL,
    rmse_corrected FLOAT NOT NULL,
    ets_heavy_raw FLOAT NOT NULL,
    ets_heavy_corrected FLOAT NOT NULL,
    fss_heavy_corrected FLOAT NOT NULL,
    csi_heavy_corrected FLOAT NOT NULL,
    pod_heavy_corrected FLOAT NOT NULL,
    far_heavy_corrected FLOAT NOT NULL
);
```

- **Automated Fallback Synchronization**: If live API streaming fails, the system serves the latest cached forecast cycle accompanied by an explicit timestamp warning flag (`STALE_DATA_WARNING`) [INFERENCE].
