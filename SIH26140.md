## 1. Executive Snapshot

### Executive Summary
Quantum computing represents a paradigm shift in computational science, but India’s higher education ecosystem faces an acute shortage of quantum-literate talent [KNOWN]. Primary bottlenecks include abstract theoretical frameworks (superposition, entanglement, phase estimation), static non-interactive learning materials, lack of affordable access to physical Quantum Processing Units (QPUs), and fragmented Software Development Kits (SDKs) [PS]. To bridge this gap under India's National Quantum Mission (NQM) [RESEARCHED], this document presents the architecture for **QuantaLearn AI**: an integrated, interactive, web-based quantum education platform. QuantaLearn AI merges a drag-and-drop circuit composer, a Monaco-based code editor supporting OpenQASM 3.0 / Qiskit / Cirq / PennyLane, a multi-backend execution engine (Qiskit Aer, PennyLane, Cirq, and qBraid transpilation graph), client-side WebAssembly (Pyodide) simulation for low-latency offline execution, dynamic state visualizers (Bloch spheres, statevector bars, probability density plots), and a domain-fine-tuned AI Quantum Mentor for real-time circuit debugging, code optimization, and personalized learning pathways.

## 5. Constraints & Environment Realities

### Field & Environmental Factors in Indian Higher Education
1. **Academic Infrastructure Variance:** Tier-1 institutes (IITs, IISc) possess high-speed internet and modern hardware, whereas tier-2/3 regional colleges frequently experience low internet bandwidth (<2 Mbps) and legacy hardware (dual-core CPUs, 4GB RAM) `[KNOWN]`.
2. **Local Simulation Compute Bottlenecks:** Simulating quantum circuits on classical CPUs incurs exponential time and memory complexity ($O(2^N)$ complex numbers for $N$ qubits) `[KNOWN]`. A 20-qubit statevector requires $2^{20} \times 16 \text{ bytes} = 16 \text{ MB}$, but a 30-qubit circuit requires $16 \text{ GB}$ of uncompressed RAM `[KNOWN]`.
3. **Absence of Hardware Execution Credentials:** Direct QPU execution on physical hardware (e.g., IBM Quantum, IonQ) requires commercial tokens or long queue delays (hours to days) `[RESEARCHED]`.
4. **Data Sovereignty & Privacy:** Compliance with India's Digital Personal Data Protection (DPDP) Act 2023 mandates that student personal data and educational records remain hosted within Indian sovereign cloud regions `[KNOWN]`.
5. **Language Diversity:** Non-metro university students benefit significantly from vernacular explanations (Hindi, Tamil, Telugu, Marathi) alongside English technical terms `[INFERENCE]`.

## 6. Research Questions

### Primary Research Findings

1. **How can real-time visual drag-and-drop be converted to code bidirectionally?**
   * *Finding:* Using OpenQASM 3.0 as an intermediate representation (IR). Visual canvas interactions modify a Abstract Syntax Tree (AST). The AST stringifies into OpenQASM 3.0, which can then be transpiled via Python parsers into native Qiskit, Cirq, or PennyLane code `[RESEARCHED]`.
2. **Can quantum circuit simulation run inside the user's browser without server backend calls?**
   * *Finding:* Yes. Through Pyodide (Python compiled to WebAssembly) and lightweight C++/JS statevector simulators (like `qiskit-aer` WebAssembly builds or micro-simulators), circuits up to 12–14 qubits can execute client-side in under 100ms with zero server cost `[RESEARCHED]`.
3. **What is the accuracy and failure rate of quantum cross-framework transpilers?**
   * *Finding:* Peer-reviewed research shows `qBraid-SDK` utilizes a graph-based hub-and-spoke architecture centered around OpenQASM and Cirq, achieving high transpilation fidelity across Qiskit, Cirq, Amazon Braket, and PennyLane `[RESEARCHED]`.
4. **How to prevent AI LLM hallucinations when explaining complex quantum math?**
   * *Finding:* Generic LLMs fail on exact quantum matrix math and statevector derivations `[KNOWN]`. Mitigate by passing the deterministic simulation output (exact numerical statevector, density matrix, probabilities) directly into the LLM prompt context alongside RAG context from verified quantum texts `[INFERENCE]`.

## 9. Candidate Solution Approaches

### Approach 1: Pure Serverless Cloud-Backend Execution + External LLM API
* **Mechanism:** All circuit simulations and visual code execution requests are transmitted via HTTP REST to a serverless backend (AWS Lambda / Google Cloud Functions running Python with Qiskit/Cirq). AI queries invoke OpenAI GPT-4 API directly `[INFERENCE]`.
* **Complexity:** Low initial development complexity `[INFERENCE]`.
* **Cost:** High recurring operational costs per simulation run and per AI token `[INFERENCE]`.
* **Latency:** High execution latency (300ms–2000ms round-trip) even for simple 2-qubit circuits `[INFERENCE]`.
* **Hackathon Feasibility:** High (Fast to build) `[INFERENCE]`.
* **Production Feasibility:** Low (Scalability cost bottlenecks and heavy server load) `[INFERENCE]`.

### Approach 2: Pure Client-Side WebAssembly (Pyodide) Execution + Rule-Based Tutor
* **Mechanism:** Entire Python quantum environment runs inside the user browser using Pyodide and WebAssembly. AI tutoring relies on static rule-based templates and local regular expressions `[INFERENCE]`.
* **Complexity:** Moderate frontend development complexity `[INFERENCE]`.
* **Cost:** Near zero server infrastructure cost `[INFERENCE]`.
* **Limitations:** Browser memory restricts simulations to $\le 12$ qubits; rule-based AI lacks natural language comprehension for open-ended student queries `[INFERENCE]`.
* **Hackathon Feasibility:** Moderate `[INFERENCE]`.
* **Production Feasibility:** Moderate (Fails for advanced high-qubit circuits and natural AI conversation) `[INFERENCE]`.

### Approach 3: Hybrid Edge-Cloud Architecture with Domain-Fine-Tuned SLM / RAG (RECOMMENDED)
* **Mechanism:** Dual-tier execution:
  1. *Client-Side Tier (0–12 Qubits):* Instant client-side simulation using Pyodide/WebAssembly for zero-latency interactive visual feedback `[INFERENCE]`.
  2. *Cloud Microservice Tier (>12 Qubits & Multi-SDK):* FastAPI microservice cluster executing full Qiskit Aer, Cirq, PennyLane, and qBraid transpilation `[INFERENCE]`.
  3. *AI Engine:* Local RAG vector pipeline paired with a fast Small Language Model (e.g., Qwen-2.5-Coder / DeepSeek-R1 distilled) fed with exact numerical simulation outputs to ensure zero hallucinations `[INFERENCE]`.
* **Explainability:** High (Exact matrix math combined with contextual AI explanation) `[INFERENCE]`.
* **Scalability:** High (80% of beginner execution offloaded to client browser) `[INFERENCE]`.
* **Hackathon Feasibility:** Very High (Core hybrid model buildable in hackathon timeframe) `[INFERENCE]`.

### Detailed Data Flow Narrative

1. **Circuit Creation Phase:**
   * User drags a Hadamard ($H$) gate onto Qubit 0 in the Visual Canvas [INFERENCE].
   * The visual engine updates the canvas state JSON and immediately triggers the client-side OpenQASM 3.0 AST Generator [INFERENCE].
   * The AST emits `qreg q[2]; creg c[2]; h q[0];` into the Monaco Code Editor, keeping code and canvas in instant lockstep [INFERENCE].

2. **Simulation & Visualization Phase:**
   * If Qubit Count $\le 12$, client-side Pyodide executes the gate operations locally [INFERENCE].
   * The resulting statevector $\frac{1}{\sqrt{2}}|00\rangle + \frac{1}{\sqrt{2}}|10\rangle$ is passed directly to the WebGL Visualizer, animating the Bloch vector of Qubit 0 to point along the X-axis ($\theta = \pi/2, \phi = 0$) [INFERENCE].
   * If Qubit Count $> 12$ or PennyLane QML execution is requested, the OpenQASM string is posted via WebSocket to the Cloud Simulation Gateway [INFERENCE]. The job executes on Dockerized Qiskit Aer / PennyLane workers, returning shot distributions and statevector matrices back to the browser [INFERENCE].

3. **AI Assistance & Debugging Phase:**
   * The user adds an invalid gate sequence or experiences unexpected measurement outcomes (e.g., phase kickback error) and clicks "Explain Error" [INFERENCE].
   * The frontend bundle sends: (a) Code snippet, (b) AST structure, and (c) Statevector output to the AI Engine [INFERENCE].
   * The AI Engine queries the ChromaDB Vector Store for relevant theoretical concepts, feeds exact statevector numbers to the LLM context, and streams back step-by-step guidance without hallucinating math [INFERENCE].

## 13. AI/ML Justification

### Detailed AI Component Breakdown

#### 1. Context-Aware Quantum Concept Tutor
* **Exact Problem Solved:** Translates abstract mathematical concepts (e.g., superposition, phase kickback, quantum teleportation) into intuitive conversational explanations [PS].
* **Input:** User query string + current module topic + active circuit OpenQASM string [INFERENCE].
* **Output:** Markdown response with LaTeX equation rendering and step-by-step theoretical breakdown [INFERENCE].
* **Why AI is Necessary:** Rule-based systems cannot handle arbitrary student queries or contextualize explanations based on the student's specific circuit design [INFERENCE].

## 14. Data Architecture & Offline/Low-Network Design

### Database Schema (Entity-Relationship Overview)

```sql
-- Users & Roles
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    role VARCHAR(50) CHECK (role IN ('student', 'instructor', 'admin')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Quantum Curricula & Modules
CREATE TABLE modules (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    slug VARCHAR(255) UNIQUE NOT NULL,
    description TEXT,
    difficulty_level VARCHAR(50),
    order_index INT NOT NULL
);

-- Coding Challenges & Assignments
CREATE TABLE challenges (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    module_id UUID REFERENCES modules(id),
    title VARCHAR(255) NOT NULL,
    problem_statement TEXT NOT NULL,
    initial_qasm TEXT,
    target_statevector JSONB NOT NULL, -- Deterministic test case
    max_qubits INT DEFAULT 5
);

-- User Submissions & Progress
CREATE TABLE user_progress (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    challenge_id UUID REFERENCES challenges(id),
    saved_qasm TEXT NOT NULL,
    is_completed BOOLEAN DEFAULT FALSE,
    execution_metrics JSONB, -- Shot counts, fidelity, gate depth
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Low-Network & Offline-First Strategy
1. **IndexedDB Local Caching:** All learning module text, static media, and WebAssembly Python binaries are cached client-side using Service Workers (PWA model) `[INFERENCE]`.
2. **Local Offline Execution:** Circuits under 12 qubits execute entirely offline using Pyodide in the user browser `[INFERENCE]`.
3. **Delta Synchronization Engine:** When internet connectivity is restored, offline assignment submissions and progress telemetry are automatically synced back to PostgreSQL via queue background workers `[INFERENCE]`.
4. **Bandwidth Reduction:** Instead of sending bulky UI states, only compact OpenQASM 3.0 strings (<2 KB) are transmitted across the network `[INFERENCE]`.
