## 1. Executive Snapshot

### Summary
This project delivers a software prototype for proactive cybersecurity that moves beyond static, single-flow intrusion detection. Commissioned by the National Technical Research Organisation (NTRO) `[PS]`, the system leverages **World Models**—AI architectures designed to learn causal state-transition dynamics $P(S_{t+1} \mid S_t)$ over time `[PS]`. By ingesting dual-level telemetry (flow-level NetFlow/IPFIX and packet-level PCAP features) `[PS]`, the platform constructs a time-evolving network state representation `[INFERENCE]`. It performs $K$-step forward simulations to forecast the probability and progression of multi-stage cyber attacks (e.g., reconnaissance leading to lateral movement and exfiltration) before system compromise is finalized `[PS]`. The architecture maps predicted trajectories directly to the MITRE ATT&CK framework `[PS]` and provides interpretable feature attribution via SHAP/attention mechanisms `[PS]`. The entire system is engineered for zero-cloud dependency, supporting air-gapped Critical Information Infrastructure (CII) environments `[INFERENCE]`.

## 2. Problem Deconstruction

### Explicit Problem Requirements

1. **Dual-Level Telemetry Feature Extraction Pipeline** `[PS]`
   - **Source Text:** *"In-gest network traffic... work with both flow-level and packet-level features drawn from open-source network traffic datasets... Flow-level features (NetFlow / IPFIX format): source/destination IP/port, TCP flag bitmask, protocol, bytes/packets per flow, duration, IAT statistics, bidirectional ratios. Packet-level features (PCAP-derived): TTL values/variance, TCP window size, IP fragment flags, payload size distribution, port scan signatures, retransmission counts."*
   - **Interpretation:** The pipeline must parse raw PCAP files (via Scapy/PyShark) and CSV flow records (e.g., CIC-IDS-2018/CTU-13) `[PS]`, synchronizing aggregate statistical flow behavior with fine-grained micro-packet timing patterns into a unified timestamped feature matrix `[INFERENCE]`.
   - **Implementation Implication:** Flow extractors alone miss slow scans; packet parsers alone choke on high throughput `[PS]`. The engine must construct time-binned composite state vectors combining both aggregate flow stats and per-packet structural attributes `[INFERENCE]`.
   - **Confidence Tag:** `[PS]`

2. **World Model State-Transition Dynamics Learning Architecture** `[PS]`
   - **Source Text:** *"Represent network state using feature vectors or graphs... Learn state-transition dynamics P(S_t+1 | S_t) using sequence models (LSTM, Transformer), Graph Neural Networks, latent state models... Trained on labelled open-source datasets using supervised dynamics learning... Generalise to unseen attack patterns."*
   - **Interpretation:** The AI must model how the overall network environment state $S_t$ shifts to $S_{t+1}$ across consecutive time windows `[PS]`. It must be trained using sequence or spatial-temporal models on annotated dataset timelines, learning generalizable network operational physics rather than static signature classification `[INFERENCE]`.
   - **Implementation Implication:** Models must not take single flows as independent samples `[PS]`. Traffic must be converted into chronological sequence windows or spatial-temporal graphs where target labels represent future state transitions `[INFERENCE]`.
   - **Confidence Tag:** `[PS]`

3. **Infiltration Prediction & Forward Simulation Engine ($K$-Step Rollout)** `[PS]`
   - **Source Text:** *"Perform K-step forward simulation from a current traffic snapshot and output: infiltration probability score (time-series), predicted MITRE ATT&CK stage (Reconnaissance, Initial Access, Lateral Movement, C2, Exfiltration)..."*
   - **Interpretation:** The engine must auto-regressively predict network states $K$ time windows ahead ($\hat{S}_{t+1}, \dots, \hat{S}_{t+K}$) and compute an escalating threat score, identifying if current activity will converge to compromise `[PS]`.
   - **Implementation Implication:** $K$ must be configurable (e.g., $K=3, 5, 10$ steps ahead, corresponding to 15s–5min real time depending on windowing) `[ASSUMPTION]`. The state vectors must map to tactical attack stages defined in MITRE ATT&CK `[PS]`.
   - **Confidence Tag:** `[PS]`

4. **Interpretable Explainability Engine** `[PS]`
   - **Source Text:** *"Provide explainability using attention mechanisms, feature attribution (SHAP values) or equivalent techniques... identifying which flags, ports, or flow statistics are driving the prediction. Black-box outputs without interpretability are not acceptable."*
   - **Interpretation:** Every forecast score and stage assignment must be accompanied by explicit feature contributions indicating why the model expects an escalation `[PS]`.
   - **Implementation Implication:** Integrate SHAP (SHapley Additive exPlanations) or attention-weight extraction directly into the inference loop to highlight top-5 causal network features `[INFERENCE]`.
   - **Confidence Tag:** `[PS]`

5. **Offline Demonstration Application & Benchmark** `[PS]`
   - **Source Text:** *"Working demonstration interface (Streamlit, Flask web app, or CLI) that accepts a PCAP or CSV file... displays infiltration probability timeline, flagged flows, attack stage annotations... run fully offline without cloud API dependencies. Benchmark results comparing model performance (F1, precision, recall, FPR) against a logistic regression baseline."*
   - **Interpretation:** The submission must contain an offline interactive UI/CLI, a full benchmark validation report comparing temporal dynamics against static Logistic Regression `[PS]`, and complete evaluation deliverables `[PS]`.
   - **Confidence Tag:** `[PS]`

## 5. Constraints & Environment Realities

1. **Air-Gapped Operational Infrastructure:** National security and CII environments (e.g., nuclear, power grids, defense networks overseen by NTRO/NCIIPC) enforce strict air-gap policies `[KNOWN]`. No external LLM APIs (OpenAI, Anthropic), public cloud analytics, or external domain name lookups are permitted during inference `[PS]`.
2. **High Throughput vs. Compute Overhead:** Real-world enterprise networks process multi-Gbps traffic `[KNOWN]`. While a hackathon prototype operates on offline PCAPs, feature extraction and deep sequence inference must not introduce massive computational lag `[INFERENCE]`.
3. **Data Anonymization & Noise:** Open-source datasets (e.g., CSE-CIC-IDS2018) contain missing values, infinite float values in inter-arrival times, and highly imbalanced attack-to-benign ratios `[RESEARCHED]`. Clean handling of raw telemetry artifacts is critical.
4. **Hardware Constraints:** Hackathon evaluation relies on standard laptop GPUs (e.g., NVIDIA RTX 3060/4060 or CPU-only containers) `[ASSUMPTION]`. Model parameter size must be optimized for real-time offline execution without requiring multi-GPU server clusters `[INFERENCE]`.

## 6. Research Questions

1. **State Vector Representation:** How can continuous packet streams and discrete flow records be binned into a fixed-dimension latent state vector $S_t$ without losing fine-grained timing signatures?
2. **Ground-Truth Dynamics Formulation:** How do we convert static sample labels in datasets like CSE-CIC-IDS2018 and CTU-13 into temporal state sequences $S_0, S_1, \dots, S_T$ representing evolving attack kill chains?
3. **Multi-Step Rollout Error Accumulation:** How do we prevent auto-regressive error propagation during $K$-step forward simulations ($S_t \to \hat{S}_{t+1} \to \hat{S}_{t+2} \dots \to \hat{S}_{t+K}$)?
4. **Offline Explainability Speed:** Can SHAP values or Transformer attention weights be computed fast enough during live PCAP playback without degrading demo interactivity?

### 1. Traditional Signature & Rule-Based IDSs (Snort, Suricata, Zeek)
* **Description:** Inspects packet payloads and flow signatures against static rules `[KNOWN]`.
* **Strengths:** High speed, deterministic, low false-positive rate for known signature matches `[KNOWN]`.
* **Weaknesses:** Cannot detect zero-day attacks; completely blind to multi-stage temporal patterns where individual flows appear benign `[KNOWN]`.
* **Gap:** Fails to forecast future states or learn temporal network behavior dynamics `[PS]`.

### 2. Static Machine Learning Classifiers (CICFlowMeter + XGBoost / Random Forest)
* **Description:** Extracts flow statistics over an entire session and outputs a binary label (`Benign` vs. `Malicious`) `[RESEARCHED]`.
* **Strengths:** Easy to train; achieves high isolated metric scores on static tabular datasets `[RESEARCHED]`.
* **Weaknesses:** Evaluates each flow in complete isolation; discards inter-flow arrival timing, order, and causal kill-chain progression `[PS]`.
* **Gap:** Provides post-facto classification rather than early predictive forecasting `[PS]`.

### 3. Deep Learning Anomaly Detectors (LSTM Autoencoders)
* **Description:** Reconstructs normal flow sequences and flags deviations exceeding an error threshold `[RESEARCHED]`.
* **Strengths:** Detects novel anomalies without pre-defined attack signatures `[RESEARCHED]`.
* **Weaknesses:** High false-positive rates; lacks forward simulation capabilities; does not predict *what* specific attack stage is approaching `[INFERENCE]`.
* **Gap:** Reconstructs current inputs rather than predicting future $S_{t+1}$ environment states or mapping to MITRE ATT&CK stages `[PS]`.

## 10. Recommended Approach & Why

### Primary Recommendation
We select **Candidate 3: A Hybrid Temporal Transformer Latent Dynamics World Model** paired with a dual-level feature extraction pipeline `[INFERENCE]`.

```
                         OUR RECOMMENDED HYBRID ARCHITECTURE
                         
  PCAP / CSV Stream ---> [Dual Parser Engine] ---> [Time-Binned State Encoder]
                                                               |
  [Explainability] <--- [Forward Simulator] <--- [Temporal Transformer]
   (SHAP/Attention)      (K-Step Rollout)         (Learns P(S_{t+1}|S_t))
           |                     |                         |
           v                     v                         v
   Top Feature Drivers   Infiltration Score      MITRE ATT&CK Progression
```

### Why Alternatives Were Rejected
1. **Rejection of Static Classifiers / Logistic Regression:** Static classifiers treat flows independently `[PS]`. They cannot perform forward simulation $K$ steps ahead because they possess no internal state memory or concept of temporal succession `[PS]`.
2. **Rejection of Pure ST-GNN (Candidate 2):** While GNNs excel at topological lateral movement, open-source datasets (CSE-CIC-IDS2018/CTU-13) frequently mask or randomize subnets, making full network graph reconstruction unstable within a 36-hour hackathon build window `[INFERENCE]`.
3. **Rejection of Pure LSTM (Candidate 1):** LSTMs suffer from gradient vanishing across long time windows and lack the explicit, multi-head temporal attention mechanisms required for fine-grained explainability `[INFERENCE]`.

### Data-Flow Narrative

1. **Telemetry Ingestion:** The user uploads a `.pcap` or `.csv` file via the offline Streamlit interface `[PS]`. The backend parsing pipeline processes packet headers and flow summaries in memory using PyShark/Polars `[INFERENCE]`.
2. **Feature Fusion:** For each time window $\Delta t = 5\text{s}$, the system aggregates flow-level attributes (e.g., flow duration, bidirectional byte ratio) with packet-level attributes (e.g., TTL variance, TCP window size entropy) into a state vector $S_t \in \mathbb{R}^D$ `[PS]`.
3. **World Model Forward Pass:** The sequence of historical state vectors $(S_{t-W}, \dots, S_t)$ is passed to the trained Temporal Transformer `[INFERENCE]`. The model predicts the probability distribution over the next state $P(\hat{S}_{t+1} \mid S_t)$ `[PS]`.
4. **$K$-Step Forward Simulation:** The forward simulator recursively feeds predicted latent states back into the model for $K$ iterations, deriving a trajectory $(\hat{S}_{t+1}, \hat{S}_{t+2}, \dots, \hat{S}_{t+K})$ `[PS]`.
5. **Infiltration & Stage Evaluation:** A classifier head evaluates the trajectory, generating an escalation probability score and assigning the state to a MITRE ATT&CK phase (e.g., `T1046 Network Service Discovery` $\to$ `T1021 Remote Services`) `[PS]`.
6. **Explainability Extraction:** SHAP values and cross-attention weights are extracted from the Transformer layer, mapping score surges directly to input attributes (e.g., elevated TCP SYN bitmask ratio and decreasing TTL variance) `[PS]`.
7. **Visualization:** The Streamlit UI plots the forecast timeline, displays active threats, and highlights driving attributes for security team review `[PS]`.

### Component 1: State Transition Dynamics Model $P(S_{t+1} \mid S_t)$

1. **Exact Problem Solved:** Models temporal evolution of network traffic across time windows, forecasting future state vectors before actual packet arrival `[PS]`.
2. **Input:** Chronological sequence of $W$ past network state vectors $(S_{t-W}, \dots, S_t) \in \mathbb{R}^{W \times D}$ `[INFERENCE]`.
3. **Output:** Predicted future network state vector $\hat{S}_{t+1} \in \mathbb{R}^D$ and probability distribution over latent state transitions `[PS]`.
4. **Why Simpler Rules Fail:** Static rules cannot capture non-linear, multi-variable temporal progressions (e.g., a subtle increase in port scan entropy followed 30 seconds later by a drop in TTL variance and a surge in ACK flags) `[PS]`.
5. **Required Data:** Chronologically ordered flow and packet sequences from CSE-CIC-IDS2018 and CTU-13 `[PS]`.
6. **Evaluation Metrics:** Mean Squared Error (MSE) on continuous state feature predictions; Cosine Similarity on predicted state vectors `[INFERENCE]`.
7. **Failure Mitigation:** If transition prediction variance is excessively high, the model falls back to a conservative single-step anomaly alert `[INFERENCE]`.
8. **Training Setup:** Trained supervised on time-indexed sequence windows derived from labeled datasets `[PS]`.
9. **Fine-Tuning:** Pre-trained on synthetic benign baseline traffic, fine-tuned on attack timelines `[INFERENCE]`.
10. **RAG:** Not required `[INFERENCE]`.
11. **Computer Vision:** Not required `[INFERENCE]`.
12. **Speech Processing:** Not required `[INFERENCE]`.
13. **Forecasting:** Core requirement; performs $K$-step auto-regressive forward rollout `[PS]`.
14. **Human Oversight:** High; output feeds directly into SOC analyst dashboard for manual verification `[PS]`.

### Component 2: Infiltration Classifier & MITRE Stage Mapper

1. **Exact Problem Solved:** Maps projected trajectory states $(\hat{S}_{t+1}, \dots, \hat{S}_{t+K})$ to an overall infiltration probability score and MITRE ATT&CK phase `[PS]`.
2. **Input:** Projected $K$-step future trajectory vector array `[INFERENCE]`.
3. **Output:** Continuous probability score $[0.0, 1.0]$ and discrete attack stage label (Reconnaissance, Initial Access, Lateral Movement, C2, Exfiltration) `[PS]`.
4. **Why Simpler Rules Fail:** Static thresholds fire on isolated events, generating high false positives. Multi-step trajectory classification filters out benign burst traffic `[INFERENCE]`.
5. **Evaluation Metrics:** Macro F1 Score, Precision, Recall, False Positive Rate (FPR) compared against Logistic Regression baseline `[PS]`.
6. **Failure Mitigation:** Outputs confidence interval; low-confidence forecasts are flagged as "Uncertain Escalation - Triage Required" `[INFERENCE]`.

### Where AI Should NOT Be Used
* **Packet Ingestion & Header Unpacking:** Raw packet parsing, IP address parsing, and TCP flag extraction must use deterministic, C-optimized parsers (PyShark/Scapy) `[INFERENCE]`.
* **Static IP/Port Blacklisting:** Known malicious IP lookup must use simple $O(1)$ hash table filtering rather than AI models `[INFERENCE]`.

### Feature Matrix Schema

| Column Name | Data Type | Source Level | Operational Description |
| :--- | :--- | :--- | :--- |

| `flow_count` | `UInt32` | Flow | Total active flows during the time window. |
| `tcp_syn_ratio` | `Float32` | Flow | Ratio of SYN flags set across active flows. |
| `tcp_ack_ratio` | `Float32` | Flow | Ratio of ACK flags set across active flows. |

* **Local Storage:** Raw telemetry feature matrices are converted to column-oriented Apache Parquet files or stored in an embedded DuckDB instance `[INFERENCE]`.

* **Zero Cloud Dependency:** Model weights (`world_model.pt`, ~15MB) are loaded directly from local storage, eliminating external API calls or telemetry leaks `[PS]`.
