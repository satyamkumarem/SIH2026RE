## 1. Executive Snapshot

### Executive Summary
The proposed solution is an enterprise-grade, multi-agent AI assistant engineered for the Department of Consumer Affairs (DoCA) to democratize access to Indian Standards and Bureau of Indian Standards (BIS) services [PS]. Built on a **Hierarchical Hybrid Retrieval-Augmented Generation (RAG)** architecture with **Clause-Aware Semantic Chunking** and a **Graph Knowledge Base**, the system bridges the gap between complex regulatory documentation and natural-language queries from MSMEs, startups, consumers, and laboratories [INFERENCE]. Users can ask questions in plain text or voice in 12 Indian languages, receive exact product-to-standard recommendations (e.g., mapping product specs to IS 10500 or IS 694), navigate certification schemes (ISI Mark, CRS, FMCS, Hallmarking), locate recognized testing labs via dynamic geographical filtering, and verify HUID/licence numbers—with every single technical claim linked directly to official BIS document clauses [PS, INFERENCE].

## 5. Constraints & Environment Realities

1.  **Low Network Bandwidth in Industrial Clusters:** MSMEs operating in semi-urban or rural industrial belts often face unstable 2G/3G/4G connectivity [KNOWN]. *Mitigation:* Progressive Web App (PWA) architecture with offline caching for core flowcharts and compressed JSON payloads [INFERENCE].
2.  **Multilingual Literacy & Technical Jargon Barrier:** Small business owners may know their product only in vernacular terms (e.g., "पानी की बोतल" or "बिजली की तार") rather than formal terms like "Polyvinyl Chloride Insulated Cables" [INFERENCE]. *Mitigation:* Colloquial-to-Technical dictionary mapping layer and voice-first interaction [INFERENCE].
3.  **PDF Structure & Copyright Constraints:** Official Indian Standards PDFs contain complex tables, chemical formulas, structural diagrams, and scanned Bengali/Hindi text [RESEARCHED]. Furthermore, full IS text downloading requires payment/access control on Manakonline [RESEARCHED]. *Mitigation:* Index publicly available abstracts, gazette notifications, Quality Control Orders (QCOs), and Schemes of Inspection and Testing (SITs) available via "Know Your Standard" portal [RESEARCHED].
4.  **Device Fragmentation:** Field inspectors, factory managers, and consumers use low-cost Android devices with constrained memory and processing power [KNOWN]. *Mitigation:* Offload all heavy embeddings, graph traversals, and LLM inference to cloud endpoints; keep frontend JS bundle < 1.5 MB [INFERENCE].

## 9. Candidate Solution Approaches

### Approach 1: Fine-Tuned Domain LLM (Direct Fine-Tuning)
*   **Mechanism:** Supervised Fine-Tuning (SFT) of a open model (e.g., Llama-3-8B) on a synthetic dataset of BIS PDFs, standards, and FAQs.
*   **Problem Fit:** Poor. LLMs parameterize knowledge, leading to unpredictable hallucinations on precise numerical thresholds (e.g., lead content limits in ppm).
*   **Accuracy Potential:** Low-Medium (65-75% accuracy on exact clause numbers).
*   **Data Requirements:** High (100,000+ QA pairs required for fine-tuning).
*   **Complexity:** Medium.
*   **Explainability:** Very Low (Cannot provide exact verifiable links to document clauses).
*   **Cost:** High GPU training cost.
*   **Scalability:** Low (Re-training required every time a QCO or standard is amended).
*   **Hackathon Feasibility:** Low (Time-consuming training pipeline).
*   **Production Feasibility:** Low.
*   **Risks:** Legal liability due to hallucinated safety standards.

### Approach 2: Standard Naive RAG (Vector Search + LLM Prompt)
*   **Mechanism:** Convert IS PDFs into fixed-size chunks (512 tokens), store in a vector database (e.g., ChromaDB), retrieve top-K chunks via cosine similarity, pass to LLM.
*   **Problem Fit:** Moderate. Good for plain text, but fails on structured tables, cross-clause references, and product classification taxonomies [RESEARCHED].
*   **Accuracy Potential:** Moderate (75-85%). "Lost in the middle" phenomenon and chunk fragmentation split crucial clause context [RESEARCHED].
*   **Data Requirements:** Medium.
*   **Complexity:** Low.
*   **Explainability:** Medium (Cites chunk ID, but often misses original clause numbers).
*   **Cost:** Low.
*   **Scalability:** High.
*   **Hackathon Feasibility:** High.
*   **Production Feasibility:** Moderate.
*   **Risks:** Sentence fragmentation breaking tabular test thresholds.

### Approach 3: Hierarchical Multi-Agent Graph-RAG with Clause-Level Vector Store & Routing (Recommended)
*   **Mechanism:** Multi-agent pipeline using:
    1.  *Document Processor:* Structural parsing of PDFs into JSON objects retaining exact clause numbers, tables, and parent-child document hierarchies [RESEARCHED].
    2.  *Knowledge Graph:* Neo4j graph linking `Product Category -> Indian Standard -> Mandatory QCO -> Certification Scheme -> Testing Lab` [INFERENCE].
    3.  *Hybrid Retrieval:* Combined BM25 keyword matching (for exact IS numbers/HUIDs) + BGE-M3 Dense Semantic Vector Search + Graph Traversal [RESEARCHED].
    4.  *Agentic Router:* Router agent directing queries to specialized sub-agents (Standard Recommendation Agent, Process Wizard Agent, Lab Locator Agent, Consumer Rights Agent) [INFERENCE].
*   **Problem Fit:** Exceptional. Directly addresses every explicit requirement [PS].
*   **Accuracy Potential:** Extremely High (95%+ with zero-hallucination guardrails).
*   **Data Requirements:** Structured indexing of scraped BIS knowledge corpus.
*   **Complexity:** High (Requires clean agent orchestration).
*   **Explainability:** Exceptional (Returns response with exact document title, year, clause number, and deep-link reference) [PS].
*   **Cost:** Moderate (Optimized cloud API usage).
*   **Scalability:** Outstanding (Incremental updates to Graph DB without model re-training).
*   **Hackathon Feasibility:** High (Achievable in build window using LangGraph / FastAPI / Qdrant) [INFERENCE].
*   **Production Feasibility:** Enterprise-grade.
*   **Risks:** Latency if agent chains are unoptimized (Mitigated via asynchronous tool execution).

## 10. Recommended Approach & Why

### Selection
**Approach 3: Multi-Agent Graph-Augmented Hybrid RAG System.**

### Justification & Rejection Analysis
*   *Why Approach 1 was Rejected:* Fine-tuning an LLM creates a "black box" where technical numbers and regulatory clauses are stored probabilistically [INFERENCE]. When a business relies on an answer regarding pressure vessel thickness or chemical toxicity limits, a 5% hallucination rate is unacceptable. Furthermore, BIS standards and Quality Control Orders (QCOs) are frequently updated; retraining an LLM continuously is economically and operationally infeasible [INFERENCE].
*   *Why Approach 2 was Rejected:* Naive fixed-token chunking destroys the structural integrity of technical standards [RESEARCHED]. An Indian Standard is structured hierarchically: *Clause 4 -> Sub-clause 4.1 -> Table 2*. Standard chunking splits Table 2 from Sub-clause 4.1, causing the LLM to misinterpret which test limit applies to which grade of material [RESEARCHED].
*   *Why Approach 3 Wins:* Approach 3 treats technical standards as **structured knowledge trees** [RESEARCHED]. By combining structural chunking (preserving Clause IDs) with a Knowledge Graph linking products to schemes and laboratories, the system guarantees 100% traceably cited answers [PS, INFERENCE]. It isolates deterministic logic (e.g., fee calculators, lab distance) into traditional code tools while leveraging LLMs solely for natural language understanding, semantic search re-ranking, and friendly synthesis [INFERENCE].

### Detailed Data Flow Narrative
1.  **User Query Input:** A user enters a query via text or voice (e.g., "मशीन से बने पीने के पानी की बोतल बेचने के लिए कौन सा BIS प्रमाण पत्र चाहिए?" or "What standard applies to 9W LED bulbs?").
2.  **Speech & Language Normalization:** If input is audio, Bhashini Speech-to-Text converts voice to text [RESEARCHED]. The Multilingual Middleware detects the language (Hindi) and translates it to English for internal vector search while storing the user's original language context for the final output translation [INFERENCE].
3.  **Intent Classification & Entity Extraction:** The Gateway routes the query to the **LangGraph Orchestrator**. The orchestrator extracts entities: `Product: drinking water bottle`, `Intent: certification_requirement`.
4.  **Multi-Agent Routing & Retrieval:**
    *   The **Product Matcher Agent** queries the **Neo4j Knowledge Graph** and **Qdrant Vector DB** using hybrid search (BM25 + BGE-M3 dense embedding).
    *   It identifies standard **IS 14543:2016** (*Packaged Drinking Water*) and notes that it falls under **Mandatory Scheme-I (ISI Mark)** due to a DoCA Quality Control Order [RESEARCHED].
    *   The **Lab Locator Agent** executes a spatial PostGIS query to find the nearest BIS-recognized labs accredited for IS 14543 testing based on the user's IP or stated city (e.g., Noida/Delhi NCR) [RESEARCHED].
5.  **Context Assembly & LLM Synthesis:** The retrieved context (Clause 4.1 specifications, Scheme-I licensing steps, fee breakdown, lab list) is packaged into a structured prompt with strict guardrails: *"You are an official BIS Assistant. Answer using ONLY the context provided. Cite exact IS numbers and clause numbers."* [INFERENCE]
6.  **Response Generation & Attribution:** The LLM synthesizes a concise response in the user's target language, adding markdown citation badges (e.g., `[Source: IS 14543:2016, Clause 3.2]`).
7.  **Client Delivery & Caching:** The response is cached in Redis for identical queries and rendered on the client UI with voice synthesis (Text-to-Speech via Bhashini) [RESEARCHED].

## 13. AI/ML Justification

### Detailed AI Component Analysis

#### 1. Intent Classifier & Named Entity Recognition (NER)
*   **Purpose:** Extract user intent (Standard Inquiry, Scheme Process, Lab Search, HUID Verification) and entities (Product Name, IS Code, Location).
*   **Model Type:** Lightweight Transformer / Fine-tuned DistilBERT or LLM Structured Output (`Pydantic`).
*   **Input:** Raw user text query.
*   **Output:** Structured JSON: `{"intent": "lab_search", "is_code": "IS 10500", "location": "Jaipur"}`.
*   **Data Required:** 500 annotated query examples.
*   **Why AI:** Plain text queries contain infinite syntactic variations that regex/rules cannot handle.
*   **Evaluation:** F1-score on entity extraction (>0.90 target).
*   **Failure Mode:** Misclassifies intent -> Fallback to general conversational assistant with clarification prompt.
*   **Human Oversight:** None required for query parsing.

#### 2. Hybrid Dense-Sparse Vector Retriever
*   **Purpose:** Retrieve top-K relevant standard clauses and scheme documentation.
*   **Model Type:** BGE-M3 Embedding Model + BM25 Sparse Keyword Matcher.
*   **Input:** Normalized search query.
*   **Output:** Array of text chunks with metadata (`is_no`, `clause_no`, `score`).
*   **Data Required:** Indexed BIS document corpus.
*   **Why AI:** Traditional keyword search fails when users ask for "water bottle safety" instead of "Packaged Drinking Water Specification".
*   **Evaluation:** Recall@5 and Mean Reciprocal Rank (MRR).
*   **Failure Mode:** Low similarity score (<0.65) -> Triggers fallback prompt: *"I could not find an exact Indian Standard matching your description. Did you mean...?"*

#### 3. Contextual Answer Generator
*   **Purpose:** Synthesize precise natural language answer conditioned strictly on retrieved context.
*   **Model Type:** Gemini 1.5 Flash / Llama-3-70B-Instruct.
*   **Input:** System prompt + Retrieved Document Chunks + User Query.
*   **Output:** Source-attributed natural language response with markdown citations.
*   **Data Required:** In-context retrieved snippets.
*   **Why AI:** Conversational synthesis, multilingual output formatting, and context integration.
*   **Evaluation:** Faithfulness & Answer Relevance using RAGAS evaluation framework.
*   **Failure Mode:** Hallucination detection guardrail checks if generated citations exist in context. If absent, response is rejected and replaced with direct context snippet.
*   **Human Oversight:** Automated guardrail validation.

#### 4. Multilingual Speech & Translation Pipeline
*   **Purpose:** Convert regional voice input to English text and synthesize regional voice response.
*   **Model Type:** Bhashini Speech-to-Text (STT) & Text-to-Speech (TTS) / IndicTrans2.
*   **Input:** Audio stream or regional text.
*   **Output:** Transcribed/translated text or speech audio buffer.
*   **Data Required:** Pre-trained Bhashini models.
*   **Why AI:** Essential for voice-based interaction across non-English speaking MSME owners and rural consumers.
*   **Evaluation:** Word Error Rate (WER) and BLEU score.
*   **Failure Mode:** STT failure -> Displays transcribed text to user for one-click manual editing.

### Where AI Should NOT Be Used
*   **HUID & Licence Format Validation:** Must use **Regex patterns** (e.g., 6-character alphanumeric for HUID [RESEARCHED]) and exact SQL database lookups. AI must never "guess" if a licence is valid.
*   **Distance & Lab Filtering:** Must use **PostGIS spatial distance formulas** (`ST_DistanceSphere`). AI must not estimate geographic distances.
*   **Fee Calculations:** Must use **Deterministic Python functions** multiplying marking fee rates by production volume as specified in official BIS fee schedules [RESEARCHED].

CREATE TABLE testing_laboratories (
    lab_id SERIAL PRIMARY KEY,

### Offline & Synchronization Architecture for PWA
1.  **Local PWA Cache (IndexedDB):** The PWA stores a compressed SQLite/IndexedDB database containing:
    *   Top 500 most frequently searched product-to-IS mappings.
    *   Offline step-by-step guidance flowcharts for ISI Mark, CRS, FMCS, and Hallmarking.
    *   Directory of BIS regional offices and emergency helpline contacts.
2.  **Bandwidth Optimization:**
    *   Responses are compressed using Gzip/Brotli JSON payloads.

3.  **Synchronization Protocol:**
    *   When connection drops, user queries are saved in ServiceWorker queue.
    *   Upon re-establishing connectivity, pending queries are synced in background via `BackgroundSync API`.
