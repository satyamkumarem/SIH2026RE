## 1. Executive Snapshot

Free Space Optical Communication (FSOC) provides high-bandwidth, license-free, and jam-resistant point-to-point wireless connectivity for satellite-to-satellite, satellite-to-ground, and airborne (UAV/HAPS) terminals `[KNOWN]`. However, establishing and maintaining an optical link requires ultra-precise Pointing, Acquisition, and Tracking (PAT) due to narrow optical beam divergence `[RESEARCHED]` ([MDPI Aerospace](https://www.mdpi.com/2304-6732/12/10/1001)). Developing PAT algorithms directly on physical hardware requires expensive optical benches, fast steering mirrors, pan-tilt gimbals, and high-speed sensors `[PS]`. 

This proposal presents **OptiTrack-SIM**, an end-to-end AI-assisted virtual camera tracking software application for FSOC coarse alignment. It provides a configurable 2D/3D synthetic optical scene, real-time disturbance injection (atmospheric turbulence, platform vibrations, sensor noise), closed-loop virtual pan-tilt camera control, multi-algorithm target detection/tracking (YOLOv8-Nano, SiamRPN, Lucas-Kanade + EKF), and an automated performance evaluation dashboard `[INFERENCE]`.

## 2. Problem Deconstruction

The explicit problem description provided by ISRO requires breaking down the coarse alignment process into software-based simulation modules `[PS]`.

### Explicit Requirements
1. **Configurable Virtual Environment Generation:** The software must render a virtual scene with customizable parameters (resolution, frame rate, background lighting, field of view) `[PS]`.
2. **Moving Target Generation:** The software must simulate one or more moving optical targets/beacons traversing predictable or dynamic 3D paths `[PS]`.
3. **Movable Virtual Camera Interface:** The application must implement a virtual pan-tilt camera viewport whose orientation (azimuth/yaw and elevation/pitch) can be adjusted dynamically `[PS]`.
4. **Automatic Target Beacon Detection:** The system must automatically identify and localize the optical target/beacon within the active camera field-of-view (FOV) `[PS]`.
5. **Continuous Target Tracking:** Computer vision / AI techniques must continuously track the localized beacon frame-by-frame `[PS]`.
6. **Closed-Loop Camera Repositioning:** The target position error relative to the camera viewport center must drive real-time angular control commands to reposition the virtual camera `[PS]`.
7. **Disturbance Generation & Injection:** The software must simulate atmospheric turbulence (scintillation, beam wander), platform vibrations, camera motion jitter, and optical noise directly into the camera feed `[PS]`.
8. **Real-Time Performance UI & Analytics:** The application must display real-time tracking performance graphics and display statistics during runtime `[PS]`.
9. **Mandatory Deliverables:**
   - Standalone Executable Application `[PS]`
   - Fully Documented, Modular Source Code `[PS]`
   - Technical Report (10–15 pages) `[PS]`
   - User Manual with Installation and Operational Guides (+ optional 3-5 min video) `[PS]`
   - Performance Log Exporter capturing simulation duration, FPS, acquisition time, average and maximum tracking error, lock retention rate, and processing latency `[PS]`

### Inferred & Derived Requirements `[INFERENCE]`
- **Coordinate Transformation Engine:** Mathematical conversion between 3D world space coordinates, 2D image pixel coordinates, and camera frame body-fixed angles `[INFERENCE]`.
- **Physics-Informed Disturbance Models:** Implementation of standard optical turbulence distributions (e.g., Gamma-Gamma irradiance distribution or modified von Kármán phase screens) and band-limited Gaussian vibration profiles `[RESEARCHED]` ([Optica Publishing Group](https://opg.optica.org/abstract.cfm?uri=oe-31-18-28859)).
- **Dual-Mode Controller:** Support for classical PID control and AI/predictive state estimation (Extended Kalman Filter) to allow objective side-by-side benchmarking `[INFERENCE]`.
- **Offline / Standalone Architecture:** The desktop application must operate entirely offline without reliance on paid cloud GPU services or external web servers during evaluation `[INFERENCE]`.

## 5. Constraints & Environment Realities

1. **Software-Only Execution Environment:** The evaluation is strictly software-based without access to physical gimbals, optical sensors, or lasers `[PS]`. The entire system must run on standard consumer workstation hardware (Windows/Linux PC with standard CPU/GPU) `[INFERENCE]`.
2. **Real-Time Processing Constraint:** Computer vision detection, state estimation, control output calculation, and frame rendering must execute within 16.6 ms to 33.3 ms per frame to maintain 30–60 FPS runtime `[INFERENCE]`.
3. **Mathematical Fidelity vs Computation:** Full wave-optics wave-propagation phase screens (e.g., split-step Fourier transforms) are computationally heavy for real-time 60 FPS rendering `[RESEARCHED]` ([SPIE Digital Library](https://www.spiedigitallibrary.org/conference-proceedings-of-spie/13617/136170K/Deep-reinforcement-learning-for-beam-pointing-control-in-ground-to/10.1117/12.3063817.full)). The system must adopt optimized, physically verified analytical approximations (Gamma-Gamma intensity fading and Gaussian beam wander) `[RESEARCHED]`.
4. **Offline Operational Security:** As an ISRO software submission, the application must not send telemetry or target trajectory data to external cloud servers `[INFERENCE]`.

## 9. Candidate Solution Approaches

### Approach 1: Classical Computer Vision + PID Controller
- **Mechanism:** Uses adaptive color thresholding / Hough circle detection to isolate the beacon optical centroid. Computes pixel offset $(e_x, e_y)$ from camera center and applies a Proportional-Integral-Derivative (PID) control loop to update camera azimuth/pitch angles.
- **Complexity:** Low.
- **Accuracy:** Moderate under static high-contrast conditions; poor under low-SNR, clouds, or solar glare.
- **Hackathon Feasibility:** High (1-2 days build).
- **Limitations:** Fails during total optical fading/scintillation events as it lacks target state memory `[INFERENCE]`.

### Approach 2: Deep Learning Object Detection (YOLOv8-Nano / SiamRPN) + Extended Kalman Filter (EKF) + Feed-Forward PID Controller (Hybrid Approach)
- **Mechanism:** Uses a lightweight YOLOv8-Nano / SiamRPN visual tracker to detect and bound the optical target in each frame. The detected target position is fed into an Extended Kalman Filter (EKF) that maintains target position, velocity, and acceleration vectors. The EKF state prediction feeds a feed-forward PID controller that drives the virtual camera pan-tilt viewport.
- **Complexity:** Moderate-High.
- **Accuracy:** High. Retains tracking during severe turbulence fading and target occlusion using EKF motion extrapolation `[RESEARCHED]`.
- **Hackathon Feasibility:** Very High (Realistic for 4-6 student team within available timeframe).
- **Scalability:** High. Easy to package as a standalone PyInstaller / C++ application.

### Approach 3: Deep Reinforcement Learning (DRL - PPO / Soft Actor-Critic)
- **Mechanism:** Trains an end-to-end Deep RL agent (PPO/SAC) where the input is the raw camera image or feature vector and the output is direct continuous pan-tilt motor torque/voltage signals `[RESEARCHED]` ([SPIE Digital Library](https://www.spiedigitallibrary.org/conference-proceedings-of-spie/13617/136170K/Deep-reinforcement-learning-for-beam-pointing-control-in-ground-to/10.1117/12.3063817.full)).
- **Complexity:** Very High. Requires offline policy training over millions of simulation steps.
- **Accuracy:** High in narrow trained regimes; unpredictable in unseen out-of-distribution turbulence scenarios.
- **Explainability:** Low ("black box" control loop).
- **Hackathon Feasibility:** Low-Moderate (High risk of convergence failure or unstable live presentation).

## 10. Recommended Approach & Why

**Selected Strategy:** **Approach 2 — Hybrid AI Visual Perception (YOLOv8-Nano / SiamRPN) + Extended Kalman Filter (EKF) State Estimation + Predictive Pan-Tilt Controller.**

### Justification
1. **Robustness to Disturbance:** Pure classical vision fails when atmospheric scintillation causes the optical beacon intensity to dip below dark thresholds `[RESEARCHED]`. Deep neural networks (YOLOv8-Nano) retain feature representations under severe blurring/scintillation, while the EKF provides motion prediction during momentary blackout frames `[INFERENCE]`.
2. **Determinism and Control Stability:** Pure DRL agents can behave unpredictably during edge-case disturbances `[INFERENCE]`. Combining AI perception with a deterministic EKF + PID controller guarantees stable kinematic convergence and predictable camera repositioning.
3. **Execution Efficiency:** YOLOv8-Nano achieves >100 FPS on modern desktop GPUs and ~30-40 FPS on standard CPUs `[KNOWN]`, ensuring smooth real-time execution alongside the simulation physics renderer.

### Why Alternatives Were Rejected
- *Approach 1 (Pure Classical)* was rejected because standard thresholding cannot distinguish between an optical beacon fading due to turbulence and background reflections or clouds `[INFERENCE]`.
- *Approach 3 (Pure DRL)* was rejected due to high training instability, long convergence times, lack of explainable safety margins for ISRO evaluation, and high demonstration risk during a live hackathon final `[INFERENCE]`.

### Detailed Data Flow Narrative
1. **Scene Initialization & Target Spawning:** The user configures initial parameters (camera FOV, target velocity, trajectory type, turbulence level $C_n^2$, vibration amplitude). The **3D Kinematic Engine** calculates target coordinates in 3D world space $\vec{P}_{target}(t) = [X, Y, Z]^T$.
2. **Virtual Camera Transformation:** The target 3D vector is transformed into the virtual camera's body frame using the current camera orientation angles $(\theta_{az}, \theta_{el})$ and projected onto 2D viewport coordinates $(u_{true}, v_{true})$.
3. **Disturbance Injection:** 
   - *Beam Wander / Jitter:* Random offsets $\Delta u_{jitter}, \Delta v_{jitter}$ sampled from low-pass filtered Gaussian noise are added to target pixel coordinates.
   - *Scintillation:* Target pixel brightness is multiplied by an intensity fading factor $I_{fade}$ sampled from a Gamma-Gamma distribution.
   - *Optical Noise:* Gaussian additive noise and atmospheric blur filters are applied to the final image matrix.
4. **AI Detection & Centroid Extraction:** The noisy image frame is passed to the **YOLOv8-Nano / SiamRPN Engine**, which outputs target bounding box $[\hat{u}, \hat{v}, w, h]$ and confidence score.
5. **EKF State Update & Prediction:** The extracted pixel coordinates are processed by the **Extended Kalman Filter**, smoothing out high-frequency frame noise and predicting target velocity vectors.
6. **Closed-Loop Control Execution:** The offset between the estimated target position and the viewport optical center $(u_0, v_0)$ represents the angular pointing error $e_{az}, e_{el}$. The **PID Controller** calculates necessary pan/tilt angular velocity commands $(\omega_{az}, \omega_{el})$ and updates camera orientation $(\theta_{az}^{new}, \theta_{el}^{new})$.
7. **KPI Metric Computation:** The **Analytics Engine** updates real-time tracking error graphs, calculates cumulative lock retention rate (percentage of frames target remains within camera FOV), checks acquisition time, and displays all metrics live on the **PySide6 Dashboard**.

## 13. AI/ML Justification

### AI Component Breakdown

#### 1. Target Detection Module (YOLOv8-Nano / SiamRPN)
- **Purpose:** Automatically detect and bound optical target beacons in noisy video streams under low SNR `[PS]`.
- **Model Type:** Lightweight Convolutional Neural Network (YOLOv8-Nano fine-tuned on synthetic beacon frames) or SiamRPN visual tracker `[RESEARCHED]`.
- **Input:** Single video frame matrix (e.g., $640 \times 480 \times 3$ BGR array).
- **Output:** Bounding box coordinates $[u, v, w, h]$ and confidence score $C \in [0, 1]$.
- **Data Required:** 2,000 synthetically generated images of optical beacons under varying glare, cloud cover, background intensity, and blur levels `[INFERENCE]`.
- **Why AI is Preferable:** Classical fixed color/brightness thresholding fails when atmospheric scintillation causes target dimming or solar glare creates false positives `[RESEARCHED]`.
- **Evaluation:** Mean Average Precision (mAP@50), Inference Latency (ms), Precision-Recall curves under different $C_n^2$ levels `[INFERENCE]`.
- **Failure Mode:** False negative during total beam fade; false positive on solar reflections.
- **Human Oversight:** Automatic fallback to EKF motion extrapolation when confidence $C < 0.35$ `[INFERENCE]`.

#### 2. Extended Kalman Filter (EKF) State Estimator
- **Purpose:** Smooth target position measurements and predict target motion vectors during temporary loss of sight (fade events) `[INFERENCE]`.
- **Model Type:** Mathematical State-Space Estimator (Non-AI mathematical filter).
- **Input:** Noisy target image coordinates $(u_k, v_k)$.
- **Output:** Smoothed state vector $[x, y, v_x, v_y, a_x, a_y]^T$ and predicted position $(\hat{x}_{k+1}, \hat{y}_{k+1})$.
- **Why AI Should NOT Be Used Here:** Linear/non-linear kinematics are perfectly modeled by deterministic physical differential equations; neural network prediction introduces non-deterministic lag and unpredictable behavior `[INFERENCE]`.

### Answering Required AI Questions
1. *What exact problem does AI solve?* Target beacon recognition under heavy atmospheric noise and background solar/cloud interference `[INFERENCE]`.
2. *Inputs:* Raw synthetic camera frames `[PS]`.
3. *Outputs:* Target bounding box centroid $(u, v)$ `[INFERENCE]`.
4. *Why non-AI is insufficient:* Thresholding fails when beacon brightness drops below background cloud luminescence `[RESEARCHED]`.
5. *Training required?* Yes, fine-tuning YOLOv8-Nano on synthetically generated dataset `[INFERENCE]`.
6. *Fine-tuning/RAG/Speech/Vision:* Visual object detection model; NO RAG, NO speech processing required `[INFERENCE]`.
7. *Human oversight:* Fully autonomous runtime execution with automated confidence threshold fallbacks `[INFERENCE]`.
