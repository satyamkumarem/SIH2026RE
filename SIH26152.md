## 2. Problem Deconstruction

The problem description provided by NTRO is broken down into five core atomic components [PS]. Every explicit requirement is preserved without omission or alteration:

### Component A: Continuous Data Collection & Timeline Management
* **Explicit Requirement A.1 [PS]:** Design a multi-platform data ingestion pipeline capable of pulling live data, posts, user interactions, and comments.
* **Explicit Requirement A.2 [PS]:** Support a structured, time-stamped historical database to map out the exact chronology of conversations.
* **Explicit Requirement A.3 [PS]:** Multi-platform tier structure:
  * *Essentials (Must-Have):* X (formerly Twitter) & Telegram [PS].
  * *Desirable (Good-to-Have):* Instagram & Facebook [PS].
  * *Appreciable Additions:* Reddit or YouTube (for extracting text-based context from video comments) [PS].
* **Interpretation & Implementation Implication [INFERENCE]:** The pipeline must handle disparate API architectures (REST endpoints, WebSocket feeds, Telegram MTProto userbots/bots) [KNOWN]. Historical mapping requires time-series indexing (e.g., PostgreSQL with TimescaleDB extension or Elasticsearch) to ensure sub-second temporal range queries for replay analysis [ASSUMPTION].

### Component B: Multi-Dimensional Sentiment Inference
* **Explicit Requirement B.1 [PS]:** Use Natural Language Processing (NLP) to detect nuanced emotions (e.g., sarcasm, anxiety, excitement, supportive, against, etc.) within user posts and comment threads.
* **Explicit Requirement B.2 [PS]:** Map how these sentiments fluctuate along the established data timeline.
* **Interpretation & Implementation Implication [INFERENCE]:** Binary or ternary sentiment (positive/negative/neutral) is insufficient [INFERENCE]. The system requires fine-grained multi-label emotion classification models (such as RoBERTa or IndicBERT fine-tuned on GoEmotions/multilingual datasets) capable of context-aware sarcasm and stance detection [RESEARCHED] ([GoEmotions Paper / ACL Anthology](https://aclanthology.org/2020.acl-main.401/)). Sentiments must be aggregated into temporal windows (e.g., hourly/daily bins) to plot fluctuation curves [ASSUMPTION].

### Component C: Automated Demographic Profiling
* **Explicit Requirement C.1 [PS]:** Develop models to infer aggregate, anonymized follower demographics (such as age brackets, geographic distribution, language, and professional interests).
* **Explicit Requirement C.2 [PS]:** Base demographic profiling on public profile indicators, bio text, behavioral patterns, etc.
* **Interpretation & Implementation Implication [INFERENCE]:** Direct PII collection is prohibited and technically unfeasible via public APIs [KNOWN]. Inference must rely on multimodal deep learning (e.g., M3Inference framework) processing bio text, usernames, profile imagery, and interaction metadata [RESEARCHED] ([M3Inference GitHub](https://github.com/euagendas/m3inference)). Outputs must be aggregated to group levels (e.g., "Age 18-24: 35%") to guarantee user anonymity [PS].

### Component D: Real-Time Trend & Topic Detection
* **Explicit Requirement D.1 [PS]:** Automatically identify, rank, and predict rising trends, viral keywords, and shifting discussions as they emerge chronologically in the dataset.
* **Interpretation & Implementation Implication [INFERENCE]:** Keyword frequency counts fail to group semantically similar phrasing or detect sub-narratives [INFERENCE]. The solution requires Dynamic Topic Modeling (DTM) or transformer-based clustering (such as BERTopic with temporal class-TF-IDF) alongside time-series velocity algorithms (e.g., Z-score spike detection on topic volume) to forecast rising viral narratives before peak saturation [RESEARCHED] ([BERTopic Documentation](https://maartengr.github.io/BERTopic/getting_started/topicsovertime/topicsovertime.html)).

### Component E: Link Analysis & Network Topology
* **Explicit Requirement E.1 [PS]:** Map the relationships among followers.
* **Explicit Requirement E.2 [PS]:** Identify 'nodes of high influence' (key opinion leaders - KOLs).
* **Explicit Requirement E.3 [PS]:** Visualize how a trend or sentiment spreads from one user segment to another over time.
* **Interpretation & Implementation Implication [INFERENCE]:** Requires a Graph Data Store or Graph Engine (e.g., NetworkX, igraph, or Neo4j) [KNOWN]. Centrality metrics (PageRank, Betweenness, Eigenvector) are needed to quantify influence [KNOWN]. Community detection algorithms (Louvain or Leiden) isolate user clusters, while time-sliced graph snapshots model sentiment and narrative propagation across cluster boundaries [RESEARCHED] ([NetworkX Community Docs](https://networkx.org/documentation/stable/reference/algorithms/community.html)).

* **Mechanism:** Uses VADER/TextBlob for sentiment, TF-IDF + N-gram frequency for trend detection, rule-based Regex heuristics for bio demographics, and standard NetworkX for graph metrics [INFERENCE].

* **Cons:** Requires managing multiple specialized Python libraries and microservice orchestration [INFERENCE].

## 10. Recommended Approach & Why

The **Hybrid Microservices & Dynamic Transformer Graph Architecture (Approach 3)** is selected [ASSUMPTION].

### Why Alternatives Were Rejected:
1. **Approach 1 (Rule-Based)** was rejected because simple lexicons (VADER) cannot detect sarcasm, anxiety, or implicit political stance [INFERENCE]. It produces high false-positive rates on complex social discourse, rendering it useless for NTRO intelligence requirements [INFERENCE].
2. **Approach 2 (End-to-End GNN/LLM)** was rejected because training heterogeneous GNNs and serving large LLMs in real time requires massive GPU infrastructure that exceeds hackathon hardware limits and introduces high operational latency [INFERENCE].

### Why Approach 3 Wins:
* **Requirement Alignment:** Directly satisfies all five NTRO components (A through E) using proven, open-source AI frameworks [PS][RESEARCHED].
* **Modularity:** Each component (Data Ingestion, Sentiment Transformer, BERTopic, M3Inference, Graph Engine) operates as an independent service, allowing 4-6 students to divide and build features concurrently [INFERENCE].
* **Resource Efficiency:** Fine-tuned transformer models (e.g., `cardiffnlp/twitter-roBERTa-base-emotion` or `l3cube-pune/hindi-bert`) and BERTopic run efficiently on a single modest workstation GPU (e.g., NVIDIA RTX 3090 / T4) [RESEARCHED].

### Detailed Data-Flow Narrative
1. **Ingestion:** Scraper/API workers connect to Telegram (via Telethon), X (via API/Mock feed), Reddit, and YouTube [RESEARCHED]. Data payloads are standardized into a unified schema containing `post_id`, `user_id`, `text`, `created_at`, `reply_to_id`, `retweet_count`, and `user_metadata` [ASSUMPTION].
2. **Buffering & Storage:** Raw records are pushed to Redis queues and stored in PostgreSQL/TimescaleDB with hyper-table time partitioning [ASSUMPTION].
3. **AI Enrichment Pipeline:**
   * **Sentiment/Emotion:** Text is fed to the fine-tuned RoBERTa model to output probability scores for 6 emotional dimensions plus sarcasm logits [RESEARCHED].
   * **Topic Extraction:** Text batches are passed to BERTopic to extract semantic clusters and assign topic IDs [RESEARCHED].
   * **Demographic Profiling:** User metadata (bio, handle, avatar) is passed to M3Inference to produce aggregate age/gender/account-type estimates [RESEARCHED].
4. **Graph Network Assembly:** Mention, retweet, and reply pairs are ingested into the Graph Engine (NetworkX/Neo4j) to compute PageRank scores, isolate communities (Louvain/Leiden), and map sentiment values onto graph nodes [RESEARCHED].
5. **Analytics & Frontend Delivery:** FastAPI serves consolidated JSON payloads via REST endpoints and pushes real-time stream updates over WebSockets to the React frontend [ASSUMPTION].

## 13. AI/ML Justification

### 1. Fine-Grained Sentiment & Emotion Classification
* **Purpose:** Detect nuanced emotional states (Sarcasm, Anxiety, Excitement, Support, Opposition) beyond basic polarity [PS].
* **Model Type:** Fine-tuned Transformer (`cardiffnlp/twitter-roBERTa-base-emotion` or `xlm-roberta-base` for Indic text) [RESEARCHED].
* **Input:** Post/Comment raw text string [PS].
* **Output:** Softmax probability vector across 6 emotion classes + Sarcasm flag (0 or 1) [INFERENCE].
* **Data Required:** GoEmotions dataset / Twitter Sarcasm corpus [RESEARCHED].
* **Why AI is Necessary:** Rule-based lexicons fail to comprehend context, double negatives, sarcasm, and evolving internet slang [INFERENCE].
* **Evaluation Metric:** Macro F1-score (Target: >0.80) [ASSUMPTION].
* **Failure Mode:** False positive sarcasm tagging on sarcastic-sounding factual statements [INFERENCE].
* **Human Oversight:** High-confidence alerts flagged for analyst review when emotion shifts exceed 3 standard deviations [INFERENCE].

### 2. Demographic Inference
* **Purpose:** Infer aggregate age brackets, gender distribution, and account types without PII violations [PS].
* **Model Type:** Multimodal Neural Network (M3Inference) [RESEARCHED].
* **Input:** Screen name, display name, user bio text, and profile avatar image URL [RESEARCHED].
* **Output:** Categorical probabilities: Gender (Male/Female), Age Group (≤18, 19-29, 30-39, ≥40), Account Type (Individual/Organization) [RESEARCHED].
* **Data Required:** Public user profile metadata [PS].
* **Why AI is Necessary:** Bio text is unstructured and sparse; profile pictures require computer vision feature extraction [RESEARCHED].
* **Evaluation Metric:** Accuracy / Micro F1 (Target: >0.78) [RESEARCHED].
* **Failure Mode:** Misclassifying corporate brand accounts with human profile pictures as individual users [INFERENCE].
* **Human Oversight:** Outputs are presented exclusively as aggregated percentages across communities [PS].

### 3. Dynamic Topic Modeling
* **Purpose:** Group semantically related posts into rising topics over time [PS].
* **Model Type:** Transformer Embeddings (`all-MiniLM-L6-v2`) + UMAP + HDBSCAN + Class-TF-IDF (BERTopic) [RESEARCHED].
* **Input:** Collection of time-stamped text documents [PS].
* **Output:** Topic clusters, top keyphrases per topic, and temporal volume distribution [RESEARCHED].
* **Why AI is Necessary:** Manual keyword lists fail to capture unexpected emerging narratives or shifting vocabulary [INFERENCE].
* **Evaluation Metric:** Topic Coherence Score (c_v > 0.65) [RESEARCHED].
* **Failure Mode:** Generating fragmented sub-topics under noisy input streams [INFERENCE].
* **Human Oversight:** Analysts can manually merge or rename detected topic clusters in the UI [INFERENCE].

### Where AI Should NOT Be Used:
* **Link Analysis & Network Centrality:** **Do NOT use Neural Network / GNN models for simple PageRank or community detection during the hackathon!** Deterministic graph algorithms (PageRank, Betweenness Centrality, Louvain/Leiden) run significantly faster, guarantee 100% mathematical reproducibility, and provide immediate explainability for intelligence analysts [INFERENCE].

### Offline & Low-Network Resiliency Architecture
* **Local Ingestion Buffering:** Ingestion workers store scraped raw data locally in SQLite files if backend DB connectivity drops [ASSUMPTION].
* **Bandwidth Reduction:** Images and profile media are not downloaded to raw storage; only lightweight feature embeddings or direct public CDN URLs are referenced [ASSUMPTION].
* **Cached Graph Snapshots:** Graph centrality metrics and Louvain community assignments are calculated in background batch jobs every 15 minutes and cached in Redis, preventing expensive real-time graph re-computations on frontend page reloads [ASSUMPTION].
* **Field Export Mode:** The frontend supports exporting interactive standalone HTML/JS reports containing pre-rendered Vis.js graphs and topic charts for air-gapped field offline evaluation [ASSUMPTION].
