## 1. Executive Snapshot

### Summary
Electronic Warfare (EW) operations rely heavily on Electronic Support (ES) receivers to search, intercept, and identify hostile radar and communication signals across vast electromagnetic spectrums [PS]. Traditional open-loop scanning strategies sweep frequency bands sequentially or rely on static pre-mission Electronic Order of Battle (EOB) intelligence [PS]. In modern multi-domain battlefields where emitters are frequency-agile, spatially scanning, or operate without prior intelligence, open-loop strategies fail by wasting dwell time on inactive/non-threatening spectrum while missing transient, high-value threat emitters [PS, INFERENCE]. This project defines a closed-loop, Reinforcement Learning (RL)-driven Smart Scan Scheduler for Electronic Support receivers [PS]. The system models the RF spectrum as a two-dimensional decision-making space (frequency vs. time slot) [PS] and trains a cognitive agent on real-time feedback ("hits" and "misses") [PS] to dynamically adapt frequency sweeps, minimize intercept time, and maximize interception ratios without relying on prior intelligence [PS].

### Fundamental System Objective
Develop a real-time, closed-loop machine learning software scheduler for Electronic Support (ES) receivers that dynamically tunes narrow instantaneous bandwidth receiver windows across broad RF spectrum bands to minimize intercept time and maximize interception probability against non-cooperative, frequency-agile, and spatially scanning threat emitters [PS, INFERENCE].

## 2. Problem Deconstruction

### PS Requirement Breakdown

#### Requirement (a): Spectrum Surveillance with Narrow Instantaneous Bandwidth
- **Source Text**: *"Detection of hostile communication or radar signals starts with search / scan of a wide frequency spectrum... Sensors with typically high sensitivity but with at least an order lower instantaneous bandwidth compared to overall bandwidth of the system are used... This requires a receiver / receivers to sweep over frequency bands."* [PS]
- **Interpretation**: The total RF spectrum to monitor (e.g., 2 GHz to 18 GHz) exceeds the receiver's instantaneous bandwidth (IBW) (e.g., 500 MHz) by a factor of 10 or more [INFERENCE]. The receiver front-end must sequentially or stochastically jump across discrete RF sub-bands to cover the spectrum [INFERENCE].
- **Implementation Implication**: The software must model the receiver as a discrete-time, multi-band tuner where selecting a frequency band at time step $t$ listens only to that sub-band's instantaneous window [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (b): Closed-Loop Smart Scan vs. Open-Loop Limitations
- **Source Text**: *"Hitherto strategies based on pre mission data / prior data (Open loop) are used... Open loop strategies focus only on this requirement and may lose time to nonthreatening emitters by not giving time to new or threatening ones. This problem statement focusses on development of Smart Scan Strategy for Electronic Warfare."* [PS]
- **Interpretation**: Open-loop sweep routines (e.g., raster sweeping) fail in dynamic or intelligence-starved environments [INFERENCE]. The system must implement closed-loop feedback based on signal detection events to modify future scan sequences in real time [INFERENCE].
- **Implementation Implication**: The scheduler must maintain a dynamic belief state / spectrum probability map updated instantaneously upon receiving detection outputs [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (c): Two-Dimensional Search Space & Figures of Merit
- **Source Text**: *"Interception of signals is a two dimensional search problem since it involves adjusting receiver’s frequency at correct time. This includes building up figures of merit for interception performance such as probability of detection, probability of false alarm, sensitivity, Avg intercept rate, Avg Reward / cost function, percentage of correct predictions and average intercept time error."* [PS]
- **Interpretation**: Interception requires matching both receiver frequency band $f$ and time slot $t$ with active emitter transmissions [INFERENCE]. The software must output a quantitative evaluation suite tracking all 7 specified figures of merit [PS].
- **Implementation Implication**: Build an automated bench-testing matrix calculating:
  1. $P_d = \frac{\text{Detected True Signals}}{\text{Total Emitter Transmissions}}$ [INFERENCE]
  2. $P_{fa} = \frac{\text{False Alarms}}{\text{Total Noise Observations}}$ [INFERENCE]
  3. Sensitivity ($\text{dBm}$ threshold detection limit) [INFERENCE]
  4. Average Intercept Rate ($\text{intercepts/second}$) [INFERENCE]
  5. Average Reward / Cost Function trajectory [INFERENCE]
  6. Percentage of Correct Predictions ($\%$) [INFERENCE]
  7. Average Intercept Time Error ($\Delta t$ between transmission start and interception) [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (d): Simulated RF Environment & System Model
- **Source Text**: *"A system model for the receiver needs to be developed with measurements obtained from a simulated RF environment which has truth information on status of emitters in each band and at each time slot. The frequency spectrum for own receiver consists of many bands. The status of environment for each frequency band at each time step can be recorded as a transmission or a non-transmission."* [PS]
- **Interpretation**: The solution must include a discrete event/time RF environment simulator that generates ground-truth binary or power-level matrices $E(f, t) \in \{0, 1\}$ or $\mathbb{R}^+$ representing active threat transmissions across all frequency bands $f \in \{1, \dots, N\}$ and time slots $t \in \{1, \dots, T\}$ [PS, INFERENCE].
- **Implementation Implication**: Implement a modular RF Environment Generator in Python/C++ capable of spawning customizable threat scenarios with ground-truth logging [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (e): Predictive Emitter Modeling (Spatial & Frequency-Agile)
- **Source Text**: *"The model should enable prediction of intercept time and interception ratio of a scanning receiver against spatially scanning and frequency agile emitters."* [PS]
- **Interpretation**: Emitters vary in behavior: spatially scanning radars (mainlobe illumination cycles), frequency-agile radars (hopping frequency per pulse/burst), and periodic emitters [PS, INFERENCE]. The scheduler must learn these underlying temporal patterns to predict when a band will become active [INFERENCE].
- **Implementation Implication**: Incorporate time-series pattern recognition (e.g., recurrent state estimators or Lomb-Scargle periodograms) within the RL state vector [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (f): ML-Based Scheduler & Hits/Misses Training Loop
- **Source Text**: *"Development of a robust scheduler using machine learning to minimize intercept time and ensure a high interception rate is the primary objective of the strategy. The model should then be trained based on hits and misses."* [PS]
- **Interpretation**: The core algorithmic core must be an RL agent receiving reward $+R$ on a "hit" (intercepting an active band) and penalty $-C$ on a "miss" (tuning to an idle band) [PS, INFERENCE].
- **Implementation Implication**: Formulate as a Partially Observable Markov Decision Process (POMDP) / Restless Multi-Armed Bandit (RMAB) trained via Deep Q-Networks (DQN) or Proximal Policy Optimization (PPO) [INFERENCE].
- **Confidence Tag**: [PS]

#### Requirement (g): Optimal Interception of Periodic Scan Receivers
- **Source Text**: *"Further, approaches to intercept a periodic scan receiver optimally should be outlined. Algorithms and techniques for the same need to be developed."* [PS]
- **Interpretation**: Specialized algorithms must be developed to synchronize own receiver sweeps with periodic radar/communication scan intervals to maximize probability of interception while minimizing dwell overhead [PS, INFERENCE].
- **Implementation Implication**: Develop a Phase-Locked Spectral Scheduler algorithm to estimate period $T_{scan}$ and phase $\phi$ of periodic emitters [INFERENCE].
- **Confidence Tag**: [PS]

## 5. Constraints & Environment Realities

```
+-----------------------------------------------------------------------------------+
|                        TACTICAL EW OPERATIONAL CONSTRAINTS                        |
+-----------------------------------------------------------------------------------+
| 1. HARDWARE BANDWIDTH GAP: Total Spectrum B_total (e.g. 18 GHz) >> IBW (500 MHz)  |
| 2. REAL-TIME LATENCY: Action selection per time slot must take < 100 microseconds |
| 3. NO CLOUD / AIR-GAPPED: System must run locally on embedded C++ / GPU hardware   |
| 4. UNKNOWN RF THREATS: Zero prior Electronic Order of Battle (EOB) intelligence   |
| 5. HIGH SNR VARIATION: Signals fluctuate with propagation distance & multipath    |
+-----------------------------------------------------------------------------------+
```

- **Hardware Bandwidth Limitation**: Instantaneous Bandwidth (IBW) is restricted by ADC sampling rates and RF front-end filters [KNOWN]. Monitoring an 18 GHz band with a 500 MHz IBW receiver requires partitioning the spectrum into at least 36 discrete sub-bands [INFERENCE].
- **Strict Real-Time Latency**: RF pulse durations are on the order of microseconds to milliseconds [KNOWN]. The ML scheduler must execute inference and send tuning commands to the synthesizer in $< 100\ \mu\text{s}$ per time slot [INFERENCE]. High-latency Python models will bottleneck real hardware [INFERENCE].
- **Zero Cloud / Air-Gapped Operation**: Tactical EW systems operate in strict electromagnetic and physical isolation [KNOWN]. All training, inference, and data storage must occur locally without external network dependencies [INFERENCE].
- **Zero-Shot / Cold-Start Environment**: The system cannot assume prior knowledge of emitter carrier frequencies, pulse repetition frequencies (PRF), or scan schedules [PS].
- **RF Clutter and Thermal Noise**: Signal detection is limited by thermal noise power $N = k T B F$ [KNOWN]. Low Signal-to-Noise Ratio (SNR) leads to non-zero Probability of False Alarm ($P_{fa}$), producing false "hits" in the feedback loop [INFERENCE].

### 1. Sequential / Raster Scanning (Traditional Open-Loop)
- **Description**: Receiver continuously sweeps from frequency $F_{min}$ to $F_{max}$ at a fixed tuning rate $\frac{df}{dt}$ [KNOWN].
- **Strengths**: Deterministic hardware implementation; simple control logic [KNOWN].
- **Weaknesses**: Dwells equally on empty/dead spectrum as active spectrum; extremely high intercept time for low-duty-cycle or agile emitters [PS].
- **Relevance**: Standard baseline required for comparison [PS].
- **Gap**: Completely unsuited for agile, non-cooperative threat environments [PS].
- **Source**: [Standard EW Receiver Design Literature / ResearchGate [1.6]]
- **Confidence Tag**: [KNOWN]

### 2. Pre-Mission Intel / Priority Open-Loop Scanning
- **Description**: Receiver scan sequence is pre-programmed based on prior Electronic Order of Battle (EOB) intelligence [PS].
- **Strengths**: High intercept probability for known, static threat radars [PS].
- **Weaknesses**: Fails completely when prior intelligence is missing, incomplete, or intentionally spoofed [PS]. Wastes scan cycles on non-threatening or inactive emitters [PS].
- **Relevance**: The explicit problem statement targets replacing this approach [PS].
- **Gap**: Zero adaptability to emergent or frequency-agile threats [PS].
- **Source**: [SIH Problem Description / ResearchGate [1.11]]
- **Confidence Tag**: [PS]

### 3. Multi-Armed Bandit (MAB) / UCB1 Spectrum Sensing
- **Description**: Spectrum channels are treated as arms in a Multi-Armed Bandit framework, using Upper Confidence Bound (UCB1) or EXP3 algorithms to balance exploration and exploitation [1.1].
- **Strengths**: Provable sublinear regret bounds; fast mathematical updates without deep neural network overhead [1.2].
- **Weaknesses**: Assumes static or independent probability distributions per channel; struggles with complex temporal patterns (e.g., periodic spatial sweeps or frequency-hopping sequences) [4.1].
- **Relevance**: Strong benchmark algorithm for cognitive spectrum access [1.1].
- **Gap**: Lacks sequence memory to predict exact arrival time of periodic or agile pulses [INFERENCE].
- **Source**: [IEEE Transactions on Aerospace and Electronic Systems [1.1]]
- **Confidence Tag**: [RESEARCHED]

## 9. Candidate Solution Approaches

```
+---------------------------------------------------------------------------------------+
|                             CANDIDATE ARCHITECTURE COMPARISON                         |
+---------------------------------------------------------------------------------------+
| Approach 1: Heuristic / Upper Confidence Bound (UCB1 / EXP3) Bandit                    |
| Approach 2: Flat Deep Q-Network (DQN) with Frame Stacking                              |
| Approach 3: Hierarchical RL (PPO) + Phase-Locked Periodic Pattern Estimator (Hybrid)  |
+---------------------------------------------------------------------------------------+
```

### Approach 1: Heuristic / Upper Confidence Bound (UCB1 / EXP3) Multi-Armed Bandit
- **Mechanism**: Treat each frequency sub-band as an arm. Update reward mean $\bar{\mu}_i$ and visit count $N_i$. Action choice: $a_t = \arg\max_i \left( \bar{\mu}_i + c \sqrt{\frac{\ln t}{N_i}} \right)$ [1.1].
- **Required Data**: Online hit/miss stream only [INFERENCE].
- **Architecture**: Lightweight C++ lookup table [INFERENCE].
- **Complexity**: $O(N)$ operations per time step [INFERENCE].
- **Cost**: Zero GPU compute needed [INFERENCE].
- **Explainability**: High (closed-form statistical formula) [INFERENCE].
- **Scalability**: High across thousands of sub-bands [INFERENCE].
- **Hackathon Feasibility**: Extremely high (can be built in 2 days) [INFERENCE].
- **Production Feasibility**: Moderate (lacks predictive capability for complex agile emitters) [INFERENCE].
- **Risks**: Gets stuck in suboptimal exploration loops when emitter hopping policies change [INFERENCE].

### Approach 2: Flat Deep Q-Network (DQN) with Frame Stacking
- **Mechanism**: Model state as a 2D matrix of historical observations across $N$ bands over the last $K$ time steps. Deep Neural Network predicts Q-values for tuning to each band [4.8].
- **Required Data**: Simulated RF environment matrix with hit/miss histories [INFERENCE].
- **Architecture**: CNN/MLP Q-Network receiving $(K \times N)$ state image, outputting $N$ Q-values [INFERENCE].
- **Complexity**: $O(|W|)$ neural net forward pass per time slot [INFERENCE].
- **Cost**: Requires local PyTorch/TensorRT pipeline [INFERENCE].
- **Explainability**: Low (black-box neural network) [INFERENCE].
- **Scalability**: Moderate (state dimension grows with spectrum resolution) [INFERENCE].
- **Hackathon Feasibility**: High (standard PyTorch/Stable-Baselines3 implementation) [INFERENCE].
- **Production Feasibility**: High (if exported to C++ ONNX runtime) [INFERENCE].
- **Risks**: May struggle to capture long-period periodic emitters without excessively large frame stacking $K$ [INFERENCE].

### Approach 3: Hierarchical RL (PPO) + Phase-Locked Periodic Pattern Estimator (Recommended Hybrid)
- **Mechanism**: A two-tier architecture:
  1. **Tier 1 (Periodic Pattern & Agility Estimator)**: Signal processing module (Lomb-Scargle Periodogram + Kalman Filter) tracking time-series periodicity and frequency-hopping transition matrices [4.7].
  2. **Tier 2 (Cognitive RL Scheduler)**: Actor-Critic (PPO) model taking spectrum belief state, uncertainty map, and Tier-1 periodicity predictions to select optimal sub-band tuning [4.3].
- **Required Data**: RF Simulator matrix + TSRD pulse train datasets [2.1, PS].
- **Architecture**: C++ / PyTorch hybrid pipeline with ONNX execution runtime [INFERENCE].
- **Complexity**: Moderate ($O(N \log N)$ FFT + lightweight neural net inference) [INFERENCE].
- **Cost**: Low (runs efficiently on modern multi-core CPU / Jetson GPU) [INFERENCE].
- **Explainability**: High (periodicity predictions are visible to operator; policy acts on deterministic belief vectors) [INFERENCE].
- **Scalability**: High (hierarchical design decouples signal feature extraction from policy decisions) [INFERENCE].
- **Hackathon Feasibility**: High for a 4-6 student team [INFERENCE].
- **Production Feasibility**: Defense-grade (matches cognitive radar/EW literature standards) [4.3].
- **Risks**: Tier-1 periodicity estimator requires sufficient hit observations before locking phase [INFERENCE].

## 10. Recommended Approach & Why

### Selection
**Approach 3: Hierarchical Reinforcement Learning (PPO) with Phase-Locked Periodic Pattern Estimator** is selected as the optimal architecture.

```
+-----------------------------------------------------------------------------------------+
|                               WHY APPROACH 3 WINS                                       |
+-----------------------------------------------------------------------------------------+
|  Component 1: Lomb-Scargle Periodogram --> Extracts periodic scan rate T_scan           |
|  Component 2: Dynamic Belief State       --> Tracks spectrum uncertainty & occupancy    |
|  Component 3: Deep PPO Agent             --> Learns optimal tuning policy under uncertainty |
|                                                                                         |
|  RESULT: Outperforms pure rule-based (Approach 1) on complex agile/periodic radars      |
|          Outperforms flat DQN (Approach 2) in sample efficiency and periodic tracking   |
+-----------------------------------------------------------------------------------------+
```

### Justification
1. **Handling Complex Emitter Behaviors**: Pure Multi-Armed Bandit algorithms (Approach 1) treat each time slot independently, failing to exploit temporal patterns of spatially scanning radars (mainlobe rotation) or periodic pulse trains [PS, INFERENCE].
2. **Sample Efficiency**: Standard flat DQNs (Approach 2) require millions of steps to learn periodic timing directly from raw frame histories. By feeding explicit periodicity features from Tier 1 into Tier 2, the RL agent converges dramatically faster [4.7, INFERENCE].
3. **Addressing Problem Statement Mandates**: The PS explicitly requests:
   - Handling spatially scanning and frequency-agile emitters [PS].
   - Optimally intercepting periodic scan receivers [PS].
   - Minimizing intercept time while training on hits and misses [PS].
   Approach 3 addresses all three requirements directly through its specialized dual-tier architecture [INFERENCE].

### Detailed Data Flow Narrative
1. **Simulation Step Initialization ($t$)**: The RF Environment Simulator updates the true state of all threat emitters in the theater. Emitter $i$ determines its current transmission frequency $f_i(t)$ and spatial illumination vector based on its rotation rate and hopping policy [PS, INFERENCE].
2. **RF Window Observation**: The ML Scheduler selects sub-band action $a_t \in \{1, \dots, N\}$. The Receiver Abstraction Layer applies a bandpass filter around sub-band $a_t$ with Instantaneous Bandwidth $IBW = \frac{B_{total}}{N}$ [PS, INFERENCE].
3. **Signal Detection**: The Receiver Front-End measures total received energy in sub-band $a_t$. If energy exceeds adaptive threshold $\gamma$, a "hit" ($1$) is declared; otherwise, a "miss" ($0$) is logged [PS, INFERENCE]. Noise processes generate false alarms ($P_{fa}$) if noise exceeds $\gamma$ [PS, INFERENCE].
4. **State & Periodicity Update**:
   - The timestamp and band index of the hit/miss are pushed into a rolling observation memory [INFERENCE].
   - The Lomb-Scargle Periodogram updates scan period estimates $\hat{T}_{scan}$ for sub-band $a_t$ [INFERENCE].
   - The Dynamic Spectrum Belief vector $b_t(f)$ updates occupancy probabilities and uncertainty metrics across all $N$ bands [INFERENCE].
5. **Policy Inference & Action Selection**: The PPO Policy Network evaluates state vector $S_t = [b_t, \hat{T}_{scan}, U_t, a_{t-1}]$ and outputs a probability distribution over sub-bands [INFERENCE]. Action $a_{t+1}$ is sampled (or selected greedily) and dispatched to the receiver synthesizer [INFERENCE].
6. **Reward Computation & Analytics**: The Reward Evaluator computes $R_t = +1.0$ for true hit, $-0.1$ for miss, $-0.5$ for false alarm [INFERENCE]. The Analytics Engine updates rolling metrics ($P_d$, $P_{fa}$, Intercept Rate, Time Error) and renders live updates on the React Dashboard [PS, INFERENCE].

## 13. AI/ML Justification

### Component 1: Cognitive Scan Policy Agent (Deep RL - PPO / DQN)

1. **What exact problem does AI solve?** Dynamically optimizes frequency band tuning sequences in an unknown, non-stationary RF environment without pre-mission intelligence [PS].
2. **What is the input?** State vector $S_t \in \mathbb{R}^{3N + 2}$: current belief vector $b(f)$, uncertainty vector $U(f)$, periodicity features $\hat{T}(f)$, and previous action $a_{t-1}$ [INFERENCE].
3. **What is the output?** Discrete action $a_{t+1} \in \{1, \dots, N\}$ representing the index of the sub-band to tune into for time slot $t+1$ [PS, INFERENCE].
4. **Why can a simpler rule/system not solve it?** Fixed rules (raster scanning) or static priority tables cannot adapt to non-cooperative, frequency-agile radars or unpredictable operational shifts [PS].
5. **What data is required?** Online stream of hit/miss binary feedback from energy detector + offline simulated training episodes [PS].
6. **How will it be evaluated?** Cumulative reward, Probability of Detection ($P_d$), Average Intercept Time, and Interception Ratio against benchmark sweeps [PS].
7. **What happens when it is wrong?** A "miss" occurs (receiver tunes to empty band). Cost is time delay ($\Delta t$ loss), mitigated by fall-back exploration bounds [PS, INFERENCE].
8. **Does it require training?** Yes, offline pre-training on diverse simulated RF scenarios + online lightweight policy updating [INFERENCE].
9. **Does it require fine-tuning?** Yes, hyperparameter tuning for learning rate, discount factor $\gamma$, and entropy coefficient [INFERENCE].
10. **Does it require RAG?** No [INFERENCE].
11. **Does it require computer vision?** No [INFERENCE].
12. **Does it require speech processing?** No [INFERENCE].
13. **Does it require forecasting?** Yes, implicit temporal forecasting of future emitter active states [PS, INFERENCE].
14. **Is human oversight required?** No for real-time microsecond scan scheduling; Yes for high-level tactical mission mode selection [INFERENCE].

### Component 2: Periodic Emitter Scan Rate Predictor (Lomb-Scargle / Fourier Estimator)

1. **What exact problem does AI/Signal Processing solve?** Estimates the exact scan period $T_{scan}$ and phase $\phi$ of periodically scanning radars from sparse, irregularly sampled "hit" timestamps [PS].
2. **What is the input?** Time-series vector of historical hit timestamps $T_{hits} = [t_1, t_2, \dots, t_k]$ for a specific sub-band $f$ [INFERENCE].
3. **What is the output?** Estimated dominant period $\hat{T}_{scan}$ and predicted next arrival time slot $t_{next}$ [PS, INFERENCE].
4. **Why can a simpler rule/system not solve it?** Standard FFT requires uniform time sampling. Hits on a scanning receiver are sparse and irregularly spaced due to incomplete sweeps [RESEARCHED].
5. **What data is required?** Timestamped hit logs from the receiver observation history [INFERENCE].
6. **How will it be evaluated?** Intercept time error $\Delta t = |t_{predicted} - t_{actual}|$ [PS].
7. **What happens when it is wrong?** Receiver tunes slightly early or late, resulting in a miss; Tier-2 RL agent adjusts confidence bounds [INFERENCE].
8. **Does it require training?** No, non-parametric mathematical spectral estimation (Lomb-Scargle Periodogram) combined with a Kalman Filter [RESEARCHED].
9. **Does it require fine-tuning?** Yes, threshold tuning for peak spectral power detection [INFERENCE].
10. **Does it require RAG?** No [INFERENCE].
11. **Does it require computer vision?** No [INFERENCE].
12. **Does it require speech processing?** No [INFERENCE].
13. **Does it require forecasting?** Yes, explicitly forecasts next pulse arrival time slot [PS, INFERENCE].
14. **Is human oversight required?** No [INFERENCE].

### Explicit Non-AI Components
- **Energy Detection Module**: Uses classical Constant False Alarm Rate (CFAR) or fixed SNR thresholding [INFERENCE].
- **Figures of Merit Analytics**: Pure deterministic mathematical formulas ($P_d = \frac{\text{hits}}{\text{total transmissions}}$) [PS, INFERENCE].
- **RF Bandpass Filtering**: Linear DSP filter abstractions [INFERENCE].

```sql
-- Dynamic Emitter Scenario Table
CREATE TABLE emitter_scenarios (
    scenario_id VARCHAR PRIMARY KEY,
    name VARCHAR,
    num_bands INT,
    num_emitters INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Intercept Log Table
CREATE TABLE intercept_logs (
    log_id BIGINT PRIMARY KEY,
    scenario_id VARCHAR,
    time_slot INT,
    band_selected INT,
    hit_status INT, -- 1 = Hit, 0 = Miss
    true_emitter_present INT, -- Ground Truth (1/0)
    snr_db DOUBLE,
    reward DOUBLE,
    FOREIGN KEY (scenario_id) REFERENCES emitter_scenarios(scenario_id)
);

-- Episode Metrics Summary Table
CREATE TABLE episode_metrics (
    episode_id VARCHAR PRIMARY KEY,
    scenario_id VARCHAR,
    total_time_slots INT,
    pd DOUBLE, -- Probability of Detection
    pfa DOUBLE, -- Probability of False Alarm
    avg_intercept_rate DOUBLE,
    avg_reward DOUBLE,
    correct_prediction_pct DOUBLE,
    avg_time_error_slots DOUBLE
);
```

### Offline & Low-Network Design
- **100% Air-Gapped Operation**: The entire stack runs locally on host hardware without external API calls or cloud dependencies [INFERENCE].
- **In-Memory Ring Buffer**: Receiver hit/miss logs are held in a lock-free C++ circular ring buffer (10,000 entries) to prevent disk I/O bottlenecks during microsecond scan loops [INFERENCE].
- **Columnar Storage Efficiency**: Intercept logs are dumped asynchronously to DuckDB in compressed Parquet format for post-mission debriefing and live UI visualization [INFERENCE].
